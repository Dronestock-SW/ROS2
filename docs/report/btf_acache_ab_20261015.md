# A-cache 설정 변경·재시작 A/B 결과
2026-10-15 Python 고정 기하 재사용 시험 기록이다.
설정 변경 지원과 성능·전환 비용을 확인할 때 읽는다.

**후속 상태:** 아래 본문은 시험 당시 기록이다.
이후 A-cache를 채택하고 운영 기준 0110da8에 적용했다.
현재 통합은 a029476 위에 같은 캐시만 이식한다.
시험 기준·최신 통합·운영 조합의 차이는 [제품 계약](../architecture/btf_acache.md)을 따른다.

## 판단
순간 XY wall p50의 사전 국소 참고선은 **통과**했다.
짝지은 4회 비교의 절감률은 69.65~71.19%다.
현재 배치·부분 입력의 결과이며 실기 검증이나 운영 승인이 아니다.
전처리 전체 p50은 27.09~30.87%, process p50은 4.33~7.12% 줄었다.
같은 조건에서 반복된 국소 개선과 낮은 추가 관리 비용을 확인했다.
시험 후보는 유지한다. 운영 반영은 이번에 수행하지 않는다.
process p95/p99와 최대 출력 공백은 비교 쌍마다 개선·악화가 섞였다.
전체 꼬리 지연을 해결했다거나 회귀가 없다고 단정하지 않는다.

설정 변경 후 새 프로세스에서 캐시를 다시 생성하는 조건은 통과했다.
기존 프로세스는 시작 때 읽은 설정을 계속 쓴다.
새 프로세스는 새 파일을 읽고 캐시·기존 C++ 핵심·모델 상태를 새로 만든다.
운영 파일 변경·배포 명령은 수행하지 않았다.

이번 C는 앞선 C++ 수치 준비 B와 다르다.
변경은 순간 XY 경로의 고정 기하 한 부분이다.
기하 행렬·상수항·잔차 분모·변환 계수를 인스턴스에 보관한다.

기존 호출과 같은 rcond=None으로 변환 계수를 구한다.
배열은 읽기 전용으로 보관하며 생성자 입력의 사본을 소유한다.

## 설정 변경과 재시작 검증

사용자가 A-cache 기각을 취소하고 이 조건을 승인했다.
현재 ROS 노드는 초기화 때 설정 파일을 한 번 읽는다.
기존 C++ 핵심도 생성 때 같은 설정으로 configure한다.
실행 중 그 설정 dict를 갱신하는 경로는 이번 기준에 없다.
따라서 캐시의 수명을 처리기 인스턴스에 맞췄다.
ClockMap·모델 reset은 앵커를 바꾸지 않아 같은 캐시를 유지한다.

별도 OS 프로세스에서 실제 MeasuredBtf와 기존 native backend를 생성했다.
첫 배치는 6.3×4.6m, 원점 (0,0)이었다.
파일을 8.1×5.2m, 원점 (1,2) 배치로 바꿨다.
같은 프로세스에 다시 질의하고 종료 뒤 새 프로세스로 질의했다.
이 수명 시험은 ROS 노드 전체 기동 시험과 구분한다.
ROS 재생에서는 각 실행이 별도 노드 프로세스를 생성했다.

| 확인 | 설정 변경 전 | 설정 수정 후 같은 프로세스 | 새 프로세스 재시작 |
| --- | --- | --- | --- |
| 기하 SHA 앞 12자리 | f9611f2cfa0d | f9611f2cfa0d | 9f49ff9336da |
| 인스턴스 생성 횟수 | 1 | 1 | 1 |

같은 프로세스의 결과는 파일 수정만으로 바뀌지 않았다.
재시작 후에는 기하 해시와 결과가 새 배치로 바뀌었다.
각 결과를 해당 배치의 기존 solve_xy와 비교해 1e-9 이내임을 확인했다.
표는 동일한 시험 거리로 구성한 수치 검증이다.
실제로 앵커를 옮겨 측정한 비행 결과나 위치 정확도 시험이 아니다.
유한하고 유효한 설정을 전제로 한다.
비유한 좌표의 초기화 실패 시점은 이번 동등성 주장 범위 밖이다.

## 동등성과 활성화

- 경계·수치 비교 2,763사례 통과.
- 유효 수치 2,103사례, 기하 거부 660사례.
- 최대 수치 차이 5.12e-12, 사전 허용 1e-9 이하.
- 실제 특이값 비율을 이분 탐색해 조건수 30 양쪽을 비교.
- 앵커 순서 변경·3앵커 조합·회전·이동 배치·잔차 변화 포함.
- 고정 시퀀스 4쌍의 결과·사유·메타데이터 차이 0.
- C 실행마다 cache builds=1, 호출 수=완료한 XY 계측 주기 수.
- 기하 SHA는 실제 config에서 계산한 값 및 C 4회 사이에 일치.
- A에는 캐시가 없고 두 버전 모두 이전 B의 numeric_preparation은 비활성.
- ROS 8회 probe 오류·누락·실행 실패 0.
- 각 실행의 스냅샷 기준 센서 선택 불일치 0.

고정 시퀀스는 기존 trace의 receive_id·epoch·시각·개수로 소속을 복원했다.
지상 참조 메타데이터와 enqueue 시각을 공통 입력으로 사용했다.
과거 ROS 실행 순서의 완전 재현은 아니다.
실제 ROS에서는 수신 순서가 달라져 판정·발행 수가 달라질 수 있다.
수치 동등성과 ROS 스케줄 동등성을 구별한다.
3앵커 사례는 계산 함수 수준의 검증이다.
이번 제품 경로의 4앵커 선택을 3앵커로 바꾼 것은 아니다.

## 검토와 증거
