# PX4 입력과 LiDAR 이동 추정 설계
2026-10-12 센서 입력 구조를 설명한다.
10초 호버 개선 전 설계를 확인할 때 읽는다.

후속 [회전 LiDAR 시간·정합 설계](spinning_lidar_timing_20261012.md)를 추가했다.
광선별 시각 보정은 격리 SITL에만 연결했다.
실물 장착·시계·공분산 검증은 남아 있다.

## 판단

UWB 위치와 LiDAR 상대이동을 함께 쓰는 방향은 타당하다.
현재 구현은 LiDAR 보조 속도 시제품이다.
지도 생성과 재방문 오차 보정은 구현하지 않았다.
따라서 완전한 LiDAR SLAM으로 부르지 않는다.
벽 회피는 추정기 뒤의 별도 이동 판단 로직이다.
이번 검증은 기존 외곽 여유 50cm를 유지한다.

## 좌표와 책임

UWB는 창고 앵커 좌표계의 위치 기준을 제공한다.
이 좌표를 WGS84 위도·경도라고 해석하지 않는다.
현재 미션은 로컬 Offboard 명령을 사용한다.
GPS 측정이나 가짜 지리 원점을 생성하지 않는다.

```text
UWB 앵커 거리·시각 -> companion H80/B_TF -> 앵커 map XY
                                            |
                              map -> ENU -> NED, 원본 시각
                                            |
                                ODOMETRY / EV XY 위치
                                            |
IMU 예측 + 광류 + 하방 거리계 + 기압계 ----> PX4 EKF2
                                            |
                                    로컬 XYZ·속도·자세
                                            |
                                     PX4 위치·자세 제어

수평 LaserScan -> 스캔 정합 -> LiDAR odom의 상대이동
                         -> 구간 평균 XY 속도
                         -> 시각·좌표·장착·불확실성 검사
                         -> 별도 LiDAR2D 보조 속도 입력 -> PX4 EKF2
```

LiDAR odom은 시작점 기준의 연속 이동 좌표다.
앵커 map은 창고에 고정된 기준이다.
후속 SLAM의 지도 보정은 두 좌표 사이 변환에 둔다.
재방문 보정 점프를 비행 위치 점프로 바로 보내지 않는다.
현재는 이 지도 보정 기능을 구현하지 않았다.

## 센서별 입력

각 센서는 서로 다른 상태 성분을 관측한다.
센서 값을 단순 합산하거나 전체를 교체하지 않는다.

| 입력 | PX4에서 사용하는 정보 | 현재 경계 |
|---|---|---|
| H80/B_TF | 앵커 기준 XY 위치 | EV 위치만, z·속도·yaw 미사용 |
| Pixhawk IMU | 가속도·각속도에 의한 상태 예측 | PX4 내부 경로 유지 |
| 하방 TFmini Plus | 바닥까지 거리, 높이 보정 | 기울기·범위·일관성 검사 필요 |
| 광류 | 하방 영상의 움직임 | 높이·자세와 함께 수평 운동 보조 |
| 기압계 | 높이 관측 | 기존 고도 기준과 융합 유지 |
| 자력계 | heading 기준 | UWB 위치는 정지 yaw를 제공하지 않음 |
| 수평 T-mini Pro | 스캔 사이 이동·회전 | 가상 스캔 정합을 SITL에 연결, 실물 FC 출력은 미배포 |

H80은 최근 0.8초 거리 이력에 이동 모델을 맞춘다.
B_TF는 H80 결과와 높이 조건으로 후보를 처리한다.
정상 동일 높이 4앵커 XY는 ToF 없이도 가능하다.
`btf_xyz`는 표시용 XY와 태그 높이의 결합이다.
비행용 PX4 EKF XYZ 출력과 구분한다.

## 파라미터와 운행 조건

아래 실기 값은 보존 run8 ULog의 기록이다.
현재 기체에 접속해 읽은 값으로 표기하지 않는다.
기준 펌웨어는 `d6f12ad1c4f70ad3230afd7d86e971421e02fef4`다.
실기 설정은 이번 작업에서 변경하지 않는다.

| 항목 | 보존 실기 기록 / 이전 SITL | 의미와 확인 사항 |
|---|---|---|
| `EKF2_GPS_CTRL` | 0 / 0 | GPS 융합 사용 안 함 |
| `EKF2_EV_CTRL` | 1 / 1 | bit 0: XY 위치만 융합 |
| `EKF2_EV_NOISE_MD` | 0 / 0 | 메시지 불확실성 사용, PX4 최소 noise도 적용 |
| UWB XY 표준편차 | 운영 설정 0.30m / 합성 메시지 0.03m | 동일한 센서 실험으로 취급하지 않음 |
| `EKF2_EVP_NOISE` | 0.10m / 이전 0.10m | 실기 메시지 0.30m가 더 크므로 그 값이 적용됨 |
| `EKF2_EV_DELAY` | 0ms / 0ms | 0은 실측 지연이 없다는 증명이 아님 |
| `EKF2_EV_POS_X/Y/Z` | -0.10/0/-0.10m / 0/0/0m | 기체 기준 센서 위치, 장착 실측과 대조 필요 |
| `EKF2_OF_CTRL` | 1 / 1 | 광류 활성, 실제 융합 상태도 확인 |
| `EKF2_RNG_CTRL` | 1 / 1 | 조건부 거리계 높이 보조 |
| `EKF2_BARO_CTRL` | 1 / 1 | 기압계 높이 보조 |
| `EKF2_HGT_REF` | 0 / 0 | 높이 기준은 기압계, 거리계는 별도 보조 |
| `EKF2_MAG_TYPE` | 0 / 0 | 기존 PX4 heading 경로 유지 |
| `EKF2_DELAY_MAX` | 200ms / 후속 50ms | 관측 지연을 수용하는 버퍼, 실제 수신 지연과 구분 |
| `EKF2_TAU_VEL` | 0.25s / 이전 후속 0.10s | 지연 상태를 현재 출력에 보정하는 응답 |
| `EKF2_LID2_EN/AGE` | 실기 미배포 / 1·150ms | 이번 전용 패치의 입력 활성·최대 나이 |
| `EKF2_AVEL_DELAY` | 5ms / SITL 0ms | LiDAR2D 보조 속도의 추가 지연 보정 |
| Offboard setpoint | 이전 SITL 약 20Hz | 지속 스트림과 유효한 로컬 추정 필요 |
| `COM_OF_LOSS_T` | 1s / 1s | Offboard 신호 만료 시간 |
| `COM_OBL_RC_ACT` | 0 / 0 | 신호 만료 시 Position 모드, 추정 유효성도 필요 |
| `COM_ARM_WO_GPS` | 1 / 1 | GPS 없는 ARM 허용, 다른 건강 검사는 유지 |
| `COM_RC_OVERRIDE` | 3 / 3 | Auto·Offboard에서 조종자 스틱 인계 |
| `IMU_INTEG_RATE` | 200Hz / 250Hz | 실기와 SIH의 입력 주기는 동일하지 않음 |
| `EKF2_PREDICT_US` | 10000 / 10000 | EKF 예측 간격 10ms |
| `MPC_XY_P` | 0.95 / 이전 0.95 | 위치 오차를 속도 요구로 바꾸는 이득 |
| `MPC_XY_VEL_P_ACC` | 1.8 / 이전 1.8 | 속도 오차를 가속도 요구로 바꾸는 이득 |

일반 Offboard 요구는 2Hz 초과 스트림이다.
진입 전 1초 이상 스트림을 제공한다.
위치 명령은 유효한 로컬 위치를 요구한다.
속도 명령은 유효한 로컬 속도를 요구한다.
우리 명령은 XY 속도와 Z 위치를 함께 사용한다.
따라서 수평 속도만 유효하다고 진입시키지 않는다.
시동·전원·센서 건강·조종자 우선권도 별도 조건이다.

GPS가 없어도 유효한 로컬 위치로 운행할 수 있다.
다만 `COM_ARM_WO_GPS=1` 하나로 조건이 끝나지 않는다.
위치·속도·높이·자세의 유효 상태를 확인해야 한다.
운영 경로의 RC와 수동 ARM 절차도 유지한다.
SITL의 RC 생략 값은 실기 권장값이 아니다.

`ODOMETRY`에는 측정 시각·좌표·공분산이 필요하다.
NED와 ENU, FRD와 FLU 변환을 각각 확인한다.
수신 시각을 측정 시각으로 바꾸지 않는다.
같은 관측을 새 관측처럼 반복 전송하지 않는다.
LiDAR 정합 reset과 좌표계 변경은 명시한다.
측정하지 않은 vz를 0으로 채우지 않는다.

## 현재 설계의 남은 항목

LiDAR 중심 이동 추정에는 실제 스캔 경로가 필요하다.
이전 비행 SITL은 truth에서 만든 속도를 사용했다.
실제 정합 알고리즘의 폐루프 성능 증거가 아니다.

1. 가상 스캔을 기존 정합 알고리즘에 연결했다.
2. 이동량·구간 평균 속도와 시각을 보존한다.
3. 불확실성과 오차를 SIH 원시 상태로 대조한다.
4. 고정 목표 10초의 FC·truth XY RMS를 함께 검사한다.
5. 실물 광선 시각·장착·공분산 검증은 남았다.

가상 센서만 SIH 원시 위치·자세를 사용한다.
정합기는 거리 배열과 FC 자세·하방 거리만 받는다.
UWB 위치나 정답 속도를 정합기에 넣지 않는다.
FC 자세는 기울기 투영과 최초 heading에 사용한다.
스캔의 상대 회전은 거리 형상에서 추정한다.
따라서 FC 자세와의 통계적 독립을 주장하지 않는다.

별도 2D 보조 속도 경로는 다른 수평 aiding을 요구한다.
UWB·광류까지 모두 잃은 LiDAR 단독 비행을 보장하지 않는다.
UWB 위치는 한 번만 융합한다.
같은 IMU를 재사용한 정합 결과는 독립 관측으로 과신하지 않는다.
지도·재방문 보정은 후속 SLAM 단계다.
