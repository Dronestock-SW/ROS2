# TFmini Plus 100/50Hz PX4 패치
FC 드라이버의 모델별 주기를 바꾸는 패치다.
펌웨어 담당자가 기존 수정본에 병합할 때 읽는다.

## 후속 확정 기준

이 디렉터리의 `-P` 패치는 이전 후보로 보존한다.
운영 기준은 [ToF r1 확정 기록](../../../../docs/report/tof_operational_baseline_20261014.md)이다.
확정 패치는 [px4_tfmini_plus.patch](../../tools/px4_tfmini_plus.patch)다.
`-T`와 명시적 `-T -C`를 사용한다.
R2 구성 위에서 전체 빌드·링크를 확인했다.
두 패치는 같은 드라이버를 바꾸므로 겹쳐 적용하지 않는다.
아래 `-P` 명령과 미빌드 상태는 당시 후보 기록이다.
실기 배포와 센서 설정 변경은 계속 보류한다.

## 이전 후보 기록

**소스 패치만 준비했다. FC 빌드·업로드는 미실시다.**
현재 기체의 20ms 수집을 확인한 결과가 아니다.
기준 소스는 `BASELINE.json`에 기록했다.
기존 LiDAR 수정 펌웨어에 이 패치만 병합한다.
기준 펌웨어 전체로 덮어쓰면 다른 수정이 사라진다.

| 경로 | 구현 |
|---|---|
| 센서 내부 | `-P -C`: 일반 전력·100Hz 설정 ACK 확인·저장 |
| FC 읽기 | `-P`: 요청 직후 읽기, 다음 요청까지 20ms |
| 재시도 | 읽기 실패 시 1ms 간격, 최대 2회 추가 |
| 거리 무결성 | 9바이트 헤더·checksum·100~12000mm |
| 신호 강도 | 100 이상, 포화값 65535 제외 |
| 기존 TF02-Pro | `-P` 없으면 기존 동작 유지 |
| companion 전달 | 기존 서비스의 MAVLink 요청 50Hz |
| B_TF | ToF 100ms·IMU 20ms 기준 유지 |

설정·거리 명령과 수치는 제조사 설명서에 근거했다.
[TFmini Plus 설명서 §5.4–5.6·§7.4](https://en.benewake.com/uploadfiles/2025/04/20250430175221028.pdf).
센서는 하드웨어 측정 시각을 제공하지 않는다.
패치는 요청 시각을 호스트 기준으로 기록한다.
최대 한 센서 주기 등의 실제 지연은 별도 측정 대상이다.
이 패치가 `EKF2_EV_DELAY` 보정값을 결정하지 않는다.

## 병합 절차

기존 FC 수정본의 별도 브랜치에서 적용한다.

```bash
git apply --check /path/to/tfmini_plus_50hz.patch
git apply /path/to/tfmini_plus_50hz.patch
```

실제 보드 대상 빌드를 완료해야 한다.
현재 서비스나 FC를 이 문서만으로 재기동하지 않는다.
기체 DISARM·지상과 기존 드라이버 중지를 확인한다.
펌웨어 업로드 후 유지보수 시작 명령은 다음과 같다.

```text
tf02pro start -X -b 2 -a 16 -f 400 -R 25 -P -C
```

`-C`는 센서 설정 저장용으로 한 번만 사용한다.
일반 부팅 명령은 `-C`를 제거한다.
설정 저장을 부팅마다 반복하지 않기 위해서다.

```text
tf02pro start -X -b 2 -a 16 -f 400 -R 25 -P
tf02pro status
```

`requested_poll_hz=50`은 요청값이다.
`distance_sensor`와 MAVROS 간격으로 실제 주기를 확인한다.
ACK 성공도 실제 유효 거리 50Hz의 증거는 아니다.
현재 워크스페이스에서는 패치 적용 가능 여부만 확인했다.
