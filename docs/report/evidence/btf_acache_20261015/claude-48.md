## 3. activate.sh

**수정 필요 ①: 신호를 받아 중단되면 롤백되지 않습니다.**
- `trap rollback ERR`은 명령 실패에만 반응합니다. override를 쓴 뒤 검증이 끝나기 전 약 25초 사이에 SSH가 끊기면(이전 SSH timeout 사례가 있습니다) HUP이나 TERM으로 스크립트가 종료되고, **검증되지 않은 새 슬롯이 그대로 활성 상태로 남습니다.**
- **수정:** `trap rollback ERR INT TERM HUP`으로 바꾸거나, 스크립트 전체를 `systemd-run --user`나 `setsid`로 분리 실행해서 세션이 끊겨도 끝까지 실행되게 하세요.

**수정 필요 ②: "3개 파일만 변경"이 활성화 시점에 강제되지 않습니다.**
- source-lock은 변경한 파일만 대조하는 것으로 보입니다. 서비스가 실제로 실행하는 `run_observe_slot.sh`, launch 파일, 나머지 Python 모듈이 이전 슬롯과 같은지는 확인하지 않습니다.
- **수정:** 후보 소스 트리 전체를 이전 슬롯과 비교하세요. 차이가 정확히 그 3개 파일(그리고 의도한 신규 파일)뿐이어야 통과로 처리합니다. 실행 엔트리인 `run_observe_slot.sh`는 해시 일치를 반드시 확인하세요.

**권장 ③: 롤백 후 상태를 확인하지 않습니다.**
- `rollback()`은 이전 상태로 재시작만 하고, 이전 슬롯이 정상으로 돌아왔는지는 확인하지 않습니다.
- 재시작 후 readiness 검사를 한 번 실행하고(`--require-backend cpp`), 결과를 evidence에 남기세요. 실패하면 사람이 개입해야 한다는 표시도 남기세요.

**확인 ④: `tof_valid>100` 조건이 지상에서 거짓 실패할 수 있습니다.**
- 착륙 상태에서는 TFmini Plus의 0~10cm 맹역 때문에 유효 ToF가 적거나 0일 수 있습니다. 그러면 정상인데도 롤백됩니다.
- pre-switch.json에 기록된 지상 ToF 유효 수를 보고 이 기준이 성립하는지 먼저 확인하세요. 성립하지 않는다면 기준을 낮추지 말고, "전환 전과 같은 수준"을 비교 기준으로 쓰세요.

- 검증 단계에 서비스 상태가 `active`이고 `NRestarts`가 전환 전보다 늘지 않았음을 **확인(assert)하는 조건**을 추가하세요. 지금은 기록만 합니다.
