# UWB 기능 시험·모델 비교·선정 절차

개별 기능을 시험하고 최종 비교 모델을 고르는 절차다. 구현 검증과 데이터 기반 모델 선정에 사용한다.

## 현재 상태

2026-09-27에 A/B 파일 비교를 완료했다.
[B 결과 기록](../../report/uwb_h80_b_20260927.md)을 따른다.
공통 유효 시각의 오차와 전체 수신 가용률을 분리했다.

[C/D 결과 기록](../../report/uwb_subsets_cd_20260927.md)을 따른다.
여섯 모델 쌍과 네 모델 공통 시각의 오차를 구분했다.
후속 [시뮬레이터 실행](../../report/uwb_cd_simulation_20260927.md)에서
같은 합성 여섯 상황을 재생하고 경로·오차 그림을 추가했다.
전체 기능을 조합하는 범용 실행기는 후속 작업이다.

**아직 최적 모델을 선택하지 않았다.**
초기 작업에서는 명세만 작성했다.
후속 요청에서 A 동일 가중 풀이를 비교 기준선으로 확정했다.
기존 Python A/H80 함수로 제한된 합성 샘플을 실행했다.
[로그와 샘플 확인 결과](../../report/uwb_h80_readiness_20260926.md)를 참고한다.
후속 요청으로 A 전용 파일 실행기를 구현했다.
[A 합성 로그 계산](../../report/uwb_baseline_a_20260926.md)을 재현했다.
전체 모델 실행기와 동적 실측 성능 시험은 미실시다.
후속 [실측 정지 A 시험](../../report/uwb_baseline_a_static_20260926.md)은 완료했다.
수기 기준점을 사용해 서로 다른 두 수신 로그를 나눴다.
한 로그는 편향 후보 산출, 다른 로그는 평가에 썼다.
9월 26일 비행 로그의 거리·자세는 입력 후보로 확인했다.
실측 연결에는 동시 UWB와 시간·장착 확인이 필요하다.
Z가 들어오는 것과 정확도 평가 자료가 갖춰지는 것은 별개다.
XY 정확도에는 독립적인 기준 위치도 필요하다.

## 공통 실행기

입력 재생·모델 실행·평가를 다른 책임으로 나눈다.

```text
RunManifest → 입력 재생기 → 공통 전처리 → 모델 레지스트리
                                         | 모델별 독립 상태
                                         v
                              매 틱 ModelResult 기록
                                         |
기준 위치 파일 ───────────────────────────> 평가기
                                         |
                          시나리오별 비교표 → 선정 기록
```

제안 함수는 다음과 같다. 현재 실행 가능한 CLI가 아니다.

| 함수 | 책임 |
|---|---|
| `load_manifest(path)` | 필수 설정·입력 파일 hash 확인 |
| `replay_events(dataset, cutoff)` | 수신 순서·시각 유지 |
| `build_model(profile)` | 모델 ID·모듈 조합 생성 |
| `process_tick(model, observations)` | 성공·실패 포함 결과 기록 |
| `evaluate(results, truth)` | 위치·가용률·지연·고장 지표 |
| `compare_runs(manifests)` | 같은 조건끼리 비교 |

현재 `uwb_pipeline`의 계산 제한을 해제해 재사용하지 않는다.
새 파일 시험 실행기가 독립 수식 함수를 호출하도록 구현한다.
ROS·PX4·LoRa 송신 의존성은 시험 실행기에 넣지 않는다.

## RunManifest 필드

결과를 보기 전에 비교 조건을 고정한다.

| 필드 | 형식·조건 |
|---|---|
| `schema_version`, `run_id`, `profile_id` | string |
| `dataset_id`, `dataset_hash`, `split` | 원본·교정/조정/평가 구분 |
| `map_id`, `calibration_id`, `z_dataset_id` | 입력 버전. 없는 입력은 null |
| `evaluation_truth_id`, `truth_frame`, `truth_reference_point` | 평가기에만 제공 |
| `module_configs` | M01~M17 중 사용 모듈·variant·파라미터 |
| `parameter_origins` | 참고값/시험 후보/실측 출처 |
| `grid_period_s`, `time_origin_us` | 공통 평가 시각 격자 |
| `warmup_interval_s`, `scenario_intervals` | 시작·단절·가림·이동 구간 |
| `seed`, `code_revision`, `dirty_patch_hash` | 실행 재현 정보 |
| `selection_criteria` | 허용 오차·최소 coverage·최대 지연·최소 개선폭 |
| `hardware_id`, `runtime_versions` | 계산 성능을 비교할 장치·환경 |

미확정 선정 기준은 null로 남기고 `selection_ready=false`다.
그 상태에서도 지표는 계산할 수 있으나 승자를 확정하지 않는다.
추후 자료를 본 뒤 평가 세트에 맞춰 임계값을 바꾸지 않는다.
기준 변경 시 새 실험 버전과 별도 평가 자료를 사용한다.

## 데이터 분리

센서 교정·파라미터 조정·최종 평가 자료를 나눈다.

| 구분 | 사용 목적 | 금지되는 사용 |
|---|---|---|
| 교정 자료 | 거리 편향·분산·RF 품질표 | 같은 표본으로 일반화 주장 |
| 조정 자료 | 가중치·게이트·창 길이 선택 | 최종 평가 결과로 간주 |
| 평가 자료 | 설정을 잠근 뒤 비교 | 정답을 모델 입력에 전달 |

세션·태그·위치·가림 조건 단위로 나눈다.
인접 표본을 임의 분할해 같은 시간창을 양쪽에 넣지 않는다.
합성 자료의 난수 seed도 조정·평가군에서 분리한다.
같은 합성 입력을 모든 모델에 전달한다.
원본 UWB가 앵커별 순차 측정이면 원래 시각을 유지한다.

## 시험 순서

기능의 오류와 센서 성능을 구분해 검증한다.

| 단계 | 시험 | 통과 조건 |
|---|---|---|
| T0 | 계약·null·단위·프레임·시각 검사 | 잘못된 입력에 명시적 실패 |
| T1 | 알려진 답의 수식·행렬·교점 검사 | 사전 수치 허용오차 만족 |
| T2 | 상태·공백·boot·중복·재획득 | 과거값을 새 관측으로 만들지 않음 |
| T3 | 합성 직접 경로·움직임·가림·편향 | 시나리오별 지표와 실패율 기록 |
| T4 | 동일 실측 입력의 파일 재생 | 같은 설정에서 결정적 수치 결과 |
| T5 | 독립 기준 위치로 비교 | 선정 기준을 잠근 평가 결과 |
| T6 | 선택 후보의 다른 세션·장치 검증 | 개선의 재현 여부 확인 |

T1 허용오차는 구현 전 수치 정밀도에 맞춰 정한다.
보류된 물리 임계값을 테스트 통과용으로 임의 채우지 않는다.
T4는 계산 시간 필드를 제외한 의미 결과의 동일성을 본다.
계산 시간·실행 시각은 반복 실행마다 달라질 수 있다.

## 시나리오

정상 이동과 관측 이상을 함께 시험한다.

| 상황 | 조작·관측 항목 |
|---|---|
| 정지·저속 이동·가속·정지 | 잡음·추종 지연·위치 고착 |
| 한 앵커 단발 튐 | 검출·보류·복귀 |
| 한 앵커 지속 양의 편향 | NLOS 대응과 잘못된 자신감 |
| 여러 앵커 편향·공통 오차 | 단일 고장 가정의 한계 |
| 거리 누락·중복·역순 | 수용률·입력 품질 사유 |
| 단절 임계값 전후·긴 단절 | H80 창 초기화·Q 호출 조건 |
| 앵커 배치 불량·지도 오차 | 기하 영향과 교정 의존성 |
| Z 변화·오차·누락·시각 지연 | 수평 위치에 전파되는 영향 |
| LiDAR/GNSS 부재·오류 | 추가 센서 의존성과 fallback |

단절 길이·주입 오차 크기는 실행 manifest에 남긴다.
실측 구간의 고장 라벨은 근거와 불확실성을 함께 기록한다.

## 공통 평가 지표

정확도와 관측 제공 능력을 함께 비교한다.

| 지표 | 정의 |
|---|---|
| 수평 오차 | `sqrt((x-x_truth)^2+(y-y_truth)^2)` |
| median/p95/max/RMSE | 같은 기준점·측정 시각의 수평 오차 |
| A 대비 RMSE 감소율 | `100*(RMSE_A-RMSE_model)/RMSE_A`. 같은 평가 틱 사용 |
| coverage | 공통 평가 틱 중 새 수용 관측이 있는 틱 비율 |
| 공통 유효 구간 오차 | 두 모델이 모두 출력한 틱에서의 짝 비교 |
| 전체 입력 구간 상태 | blocked/rejected/failed/held/predicted 비율 |
| source age | 출력 시점−관측 시각 |
| 추종 지연 | 기준 움직임의 전환에 대한 응답 지연 |
| 최대 점프 | 연속 새 관측 사이의 위치 변화와 시간 간격 |
| 복구 시간 | 단절 종료→새 관측의 정상 수용 시점 |
| 오검출·미검출 | 고장 라벨이 있을 때만 계산 |
| 공분산 일관성 | 예측 오차 영역과 실제 오차 빈도 대조 |
| 계산 비용 | 처리 시간 p50/p95/max·메모리·출력 주기 |

한 틱에 여러 결과가 있어도 coverage는 한 번만 센다.
A의 오차가 사실상 0이면 비율 대신 절대 오차를 보고한다.
감소율이 음수이면 A보다 악화된 결과로 기록한다.
old hold나 예측 전용 결과를 새 관측으로 세지 않는다.
정답 시각 보간은 평가기에서만 하고 방식·최대 간격을 남긴다.
정답이 없으면 정확도 지표는 null이다.
잔차·산포·DOP를 정확도 대신 보고하지 않는다.
워밍업 포함 전체 구간과 워밍업 제외 구간을 모두 보고한다.

## 최종 선정

요건을 통과한 모델 중 오류·가용률·지연을 비교한다.

1. 필수 계약과 T0~T2를 통과하지 못한 모델은 제외한다.
2. 최소 coverage와 최대 지연 등 사전 기준을 적용한다.
3. 시나리오별 p95·최대 오차·복구 시간을 비교한다.
4. 개별 세션의 개선 방향과 편차를 함께 확인한다.
5. 개선이 작거나 불안정하면 더 단순한 모델을 우선한다.
6. 선택 이유·한계·설정 hash·미선택 이유를 기록한다.

같은 틱의 표본이 시간적으로 상관될 수 있다.
불확실성 비교는 표본 하나씩이 아닌 세션/연속 구간 단위로 한다.
가중 점수를 쓸 경우 지표 정규화와 가중치를 사전 고정한다.
선정 대상은 위치 모델과 보조 모듈의 조합이다.
자동 온라인 모델 전환은 이번 명세에 포함하지 않는다.

## 산출물

실행별 새 디렉터리에 원문과 결과를 보존한다.

```text
<run_id>/
  manifest.json
  input_index.json
  results.jsonl
  metrics.json
  scenario_metrics.csv
  failures.jsonl
  comparison.md
```

`comparison.md`는 실제 수행한 검증만 기록한다.
선정 전 `selected_model=null`을 유지한다.
모델 채택이 외부 출력 게이트 개방을 뜻하지 않는다.
