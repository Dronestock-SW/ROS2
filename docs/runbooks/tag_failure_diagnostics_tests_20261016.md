# 태그 최초 실패 진단 검증 절차
진단 구현을 검증하고 실물 시험을 준비하는 절차다.
로컬 검사와 실물 적용을 구분할 때 읽는다.

## 완료 범위

**로컬 검사는 실물 RF 성능을 입증하지 않는다.**
기준은 상원 통합 `70da279`다.
추가 진단 계약은 [진단 기준](../reference/tag_failure_diagnostics_20261016.md)을 따른다.
R4 검사 결과와 해시는 [진단 구현 기록](../report/tag_failure_diagnostics_20261016.md)에 있다.
현재 R5는 재시도 대기와 빠른 첫 복구를 바꾼다.
새 검증 결과는 [R5 후속 기록](../report/tag_retry_recovery_20261016.md)에 분리한다.
이 문서의 실물 시험 항목은 아직 미실시다.
태그·앵커 플래싱과 운영 서비스 변경도 미실시다.

| 검사 | 기존 R4 확인 범위 / R5 판정 |
|---|---|
| Python 분석기 검사 | R4 합성 JSONL 13개 통과. R5는 후속 기록 참조 |
| schema 2 수신 호환 검사 | R4 합계 9개 통과. R5는 후속 기록 참조 |
| native fake-DW 검사 | R4 main 31개·runtime 5개 통과. R5를 따로 실행 |
| PlatformIO 빌드 | R4 두 50Hz 환경 성공. R5 이미지 해시 별도 확인 |
| 실제 50Hz 주기·마감·간섭 | 미실시 |
| 자연 RF 장애·실물 복구 시간 | 미실시 |
| 실제 거리 정확도·PX4 융합·비행 | 미실시 |

## 1. 로컬 분석기를 검사한다

**최초·최종 결과와 누락을 구분하는지 확인한다.**
저장소 루트에서 실행한다.

```text
python -m unittest discover -s src/uwb_single_tag_firmware/tools -p test_tag_diagnostics.py -v
```

| 사례 | 기대 결과 |
|---|---|
| 첫 실패 후 재시도 성공 | 최초 3/4, 최종 4/4, 실제 시도 5 |
| 미시도 두 앵커 | 기회 4, 실제 첫 시도 2, 미시도 2 |
| 중복과 내용 충돌 | 분모 중복 증가 없음, 충돌 수 표시 |
| session·boot 변경 | 다른 회차 식별자로 집계 |
| 상세 사건만 수신 | 전체 성공률 분모를 만들지 않음 |
| 진단 drop·TTL 만료 | 누락 경고와 boot별 누적 표시 |
| 카운터 역행 | 거대한 증가량으로 오인하지 않음 |
| 과거 RAW와 잘못된 진단 | 누락 계약·검사 실패를 별도 집계 |
| 자연·강제 복구 혼합 | reason별 시간을 분리 |
| UTF-8 원본과 출력 충돌 | SHA-256 보존, 원본 덮어쓰기 거절 |
| 부팅 전 RF session=0 | startup 초기화 사건에만 허용 |
| 재시도 거래·판본 | 다른 거래 순번과 정수 진단 판본 요구 |
| 중복 JSON 키·NaN | 파싱 실패로 집계 |

원본 JSONL을 다음처럼 요약한다.
출력은 존재하지 않는 새 파일이어야 한다.

```text
python src/uwb_single_tag_firmware/tools/summarize_tag_diagnostics.py events.jsonl --output diagnostic-summary.json
```

여러 파일은 기록 순서대로 전달한다.
direct 메시지와 `message`/`value` 봉투를 지원한다.
같은 RAW를 담은 ROS 토픽은 중복을 제외한다.
host_to_tag 명령은 수신 진단으로 세지 않는다.
구형 로그에 없는 진단값을 추정하지 않는다.

## 2. 실제 태그 코드를 가짜 장치로 검사한다

**복사한 알고리즘 대신 실제 함수 경로를 검사한다.**
가짜 시각·상태 레지스터로 입력을 제어한다.
SPI 물리 지연이나 전파 환경은 모형에 없다.
FreeRTOS 동시 실행과 실제 UART도 모형에 없다.

```text
python src/uwb_single_tag_firmware/tools/run_tag_native_tests.py --report native-tag-diagnostics.json
```

Windows에서 g++가 없으면 WSL g++를 사용한다.
`--suite main`과 `--suite runtime`으로 나눌 수 있다.
각 사례는 별도 프로세스에서 실행한다.
실제 보드·직렬 포트·네트워크는 사용하지 않는다.

| 사례 | 확인할 계약 |
|---|---|
| 정상 네 앵커 | 거리·시각 유지, 상세 첫 성공 사건 없음 |
| 첫 실패·재시도 성공 | 최초 실패·거래 보존, 두 사건 구분 |
| RX timeout / RX error | 기존 failure는 유지, cause만 구분 |
| RF deadline / MCU guard | 반환 경로와 관측 시각을 분리 |
| MCU 가드 종료 + RF 기한 경과 | 교환 시간초과만 처리, 가드 복구 예약 없음 |
| MCU 가드 종료 + RF 기한 미도달 | McuGuard 기록과 복구 예약 |
| 길이·identity·REPORT 거절 | 단계와 cause가 각각 맞음 |
| 준비 안 됨·예산 부족 | attempts=0, 거래 순번 0 |
| 첫 자연 오류 | 감지 뒤 다음 loop에서 첫 재초기화 |
| 빠른 재발 | 이전 초기화 종료부터 1500ms 전에는 재시도 없음 |
| 오래 정상 뒤 재발 | 1500ms가 이미 지났으면 바로 시도 |
| 초기화 지속 실패 | 실패 함수 종료부터 1500ms 간격 유지 |
| bench 복구 | 자동 대기 우회를 별도 reason으로 기록 |
| 진단 큐 포화·만료 | 계수 증가, RAW 결과를 바꾸지 않음 |
| 완료 비트와 기한 경계 | 기존 기한 우선 판정 유지 |
| RX 성공·오류 비트 동시 발생 | 기존 성공 비트 우선 판정 유지 |
| 시각 대응 실패 | 재시도 제외 조건 유지 |
| JSON 최댓값·부분 송신 | 2048B 안의 완결 메시지, 줄 혼합 없음 |
| A4 첫 실패·TX 완료 확인 | 확인 시각 + 2500us 전에 A4 POLL 없음 |
| POLL 시작 성공·TX 완료 미확인 | 강제 idle 완료 + 2500us 전에 같은 앵커 POLL 없음 |
| TX 완료 대기 중 긴 MCU 선점 | 시작 시각의 650us 대신 실제 강제 idle 이후 하한 적용 |
| 재시도 대기 뒤 예산 부족 | 재시도 생략, attempts는 1 유지 |
| 재시도 대기 중 MCU 선점 | 실제 시작 직전 18ms 예산 재검사 |
| TX 시간초과 연속 두 번 | RF 기한이 지났어도 기존 TX streak 복구 유지 |

검사 결과에는 하네스 판본과 컴파일 명령을 남긴다.
실제 main.cpp를 포함했는지도 기록한다.
모형 통과를 자연 무선 고장 재현으로 표현하지 않는다.
이유: 가짜 상태에는 RF 원인의 다양성이 없기 때문이다.

## 3. 빌드와 크기를 확인한다

**시험용·release 환경을 구분해 빌드한다.**
이 단계에서 실물 upload 명령을 실행하지 않는다.

```text
python -m platformio run -d src/uwb_single_tag_firmware/tag -e tag_b_50 -e tag_b_release
```

성공한 환경·도구 판본·앱 크기를 남긴다.
변경 전과 같은 환경으로 크기를 비교한다.
보조 40Hz 후보는 필요하면 별도로 빌드한다.
40Hz 결과를 기본 50Hz 결과로 대체하지 않는다.
빌드 성공은 운영 배포 완료가 아니다.

## 4. 실물 정상 경로를 비교한다 — 미실시

**재시도 회복과 정상 주기 영향을 함께 확인한다.**
태그·앵커·거리·배치·전원을 고정한다.
펌웨어 해시와 기록기 설정을 함께 남긴다.
R4와 R5의 동일 조건 구간을 비교한다.
초기 비교안은 변경 전후 각각 30분씩 3회다.
실제 시간과 관측 수를 명시한다.
실제 승인된 구간이 더 짧으면 그 범위만 보고한다.

| 비교 조건 | 함께 기록할 항목 |
|---|---|
| 정상 USB·정상 LoRa | 최초·최종 성공률과 분모 |
| A4 첫 실패 구간 | 최초 실패 수·재시도 수·최종 회복 수·예산상 생략 |
| USB 읽기 지연·정지 | RAW drop, 진단 drop·stale, 호스트 누락 |
| 긴 불량 입력 | input 시간, 회차 마감 초과, skipped |
| LoRa 최대 길이·수신 부하 | LoRa service 시간, UWB 주기와 최초 실패 |
| 회복 후 적체 해제 | 오래된 RAW 재생 여부와 원본 시각 |

50Hz 평균만 비교하지 않는다.
주기 p50·p95·p99·최대와 18ms 초과를 함께 센다.
회차 누락·재시도·자연 복구 횟수도 비교한다.
재시도로 최종 탈락이 줄어도 최초 실패와 구분한다.
재시도 경계를 늦춘 것만으로 RF 첫 실패가 줄지는 않는다.
진단의 `cause`는 실패 경로 분류에만 사용한다.
실제 앵커 관측이 없으면 물리 원인은 미판정이다.

## 5. 고장 주입과 복구를 분리한다 — 미실시

**강제 명령과 자연 오류는 서로 다른 시험이다.**
원본 사건을 같은 MCU 시간축에서 연결한다.
서로 다른 장치 시각은 검증한 대응만 사용한다.

| 시험 | 필요한 대조와 판정 |
|---|---|
| MCU 선점 지연 | RF 기한 경과 여부와 TX streak를 함께 비교 |
| RF 시각 변화 미관측 | SPI·MCU 진행 근거도 함께 기록 |
| 첫 연속 POLL/FINAL TX 실패 | 기존 R4 대기와 R5 첫 자연 복구 비교 |
| 초기화 지속 실패·빠른 재발 | 이전 초기화 종료→다음 시작 간격 1500ms 확인 |
| 특정 앵커 응답 중지 | 다른 앵커 첫 시도가 계속되는지 확인 |
| `uwb_recover` 명령 | reason=bench_request, 대기 우회 표시 |
| 동일 boot 새 session | 이전 진단의 ID 보존, 새 RAW와 혼합 금지 |
| 실제 MCU 재부팅 | boot 변경과 누적 카운터 초기화를 분리 |

복구 시간은 다음 경계를 각각 보고한다.

```text
이상/명령 감지
  → 초기화 시작 → 초기화 완료 → 첫 RAW
  → 첫 시각 승인 RAW → 첫 B_TF 승인 → 새 LoRa 좌표
```

복구 사건만으로 B_TF·LoRa 시간을 채우지 않는다.
해당 수신·승인·송신 기록과 직접 연결한다.
각 경계의 미관측은 null 또는 미측정으로 남긴다.

기존 강제복구 219.6ms와 자연 대기를 혼동하지 않는다.
`<0.3s` 하나로 대기 단축을 검증하지 않는다.
기존 명령 자체가 1500ms를 우회하기 때문이다.
R5는 첫 자연 복구의 선대기를 제거한다.
재발 제한 간격과 100ms 새 session 대기는 유지한다.
실제 원인별 시간의 개선은 실물 대조 뒤 판정한다.
재시도 횟수와 20ms·18ms 설정은 그대로다.

## 6. 근거와 남은 항목을 기록한다

**관측 사실과 원인 가설을 분리해 인계한다.**
다음 항목을 같은 시험 기록에 남긴다.

| 분류 | 필수 기록 |
|---|---|
| 소스 | 커밋·이미지 해시·빌드 환경·진단 판본 |
| 원본 | 파일 경로·SHA-256·시간 범위·기록 누락 |
| 분모 | RAW 회차·4앵커 기회·실제 시도·재시도 |
| 진단 손실 | 큐 drop·TTL stale·호스트 기록 손실 |
| 판정 | 최초 실패 경로·최종 결과·원인 가설 |
| 검증 범위 | 단위·native 모형·빌드·실물 여부 |
| 미확인 | 거리 정확도·상대 장치 상태·PX4·비행 |

원본과 분석 결과를 별도 파일로 보존한다.
이유: 분석기를 바꿔도 최초 기록을 다시 읽어야 한다.
