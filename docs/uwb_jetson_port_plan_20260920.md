# UWB 선행 필터 companion 이식 계획

이 문서는 HW팀의 ESP32 필터를 옮기는 계획이다.
구현 순서와 이식 후 검증 범위를 정할 때 읽는다.

## 1. 목표와 범위

**기존 Python 초안을 완성하고 실시간 수신에 연결한다.**
HW팀의 시험 방식과 결과를 비교 자료로 쓴다.
ESP32 실물 재시험을 착수 조건으로 삼지 않는다.
정확도와 지연은 companion 이식 후 재검증한다.
구현 중 수식·상태 전이 단위시험은 함께 만든다.

사용자는 2026-09-20에 TFmini Plus 확보를 확인했다.
현재 다른 드론에서 사용하며 이 기체로 옮길 예정이다.
따라서 실제 ToF 입력 경로까지 구현 범위에 넣는다.
장착 전에도 기록·합성 입력으로 개발할 수 있다.
실시간 입력이 없으면 누락 상태를 출력한다.
이유: 가상 높이를 실측 높이로 취급할 수 없다.

| 구분 | 이번 이식의 경계 |
|---|---|
| ESP32 | RAW 사선거리·시각·RF 진단 수집 |
| companion 내부 | 시간 정렬, 거리 보정, ToF Z, H80, Q_S10, 판정·로그 |
| 내부 위치 출력 | 창고 좌표계로 표현한 FC 원점 XYZ |
| PX4 입력 | 검증한 수평 위치 관측 x·y |
| 고도·자세 제어와 비행 상태추정 | 기존 PX4 담당 유지 |
| AI·LOO·별도 비행 EKF | 이번 범위에 포함하지 않음 |

FC 원점 보정은 위치의 기준점을 바꾸는 작업이다.
좌표를 기체 좌표계로 바꾼다는 뜻은 아니다.
ToF 거리와 자세도 서로 다른 입력이다.
ToF는 광선 방향 거리이고 자세는 FC 회전값이다.

## 2. 코드에서 확인한 출발점

초안은 있지만 실행 경로와 연결되지 않았다.
점검 기준은 `87431bc`와 2026-09-20 작업트리다.
기존 매핑 문서는 v1.1과 고정 높이를 전제한다.
이번 구현에서 v1.2와 실제 코드 기준으로 갱신한다.

| 영역 | 현재 코드 | 이식 작업 |
|---|---|---|
| RAW 수신·기록 | `node.py`, `serial_io.py`, `core.py` | 기존 수신기를 재사용. 기록 기본 활성화 |
| 입력 검증 | `preimu/inputs.py` 초안 | 최신 상태 메시지·RF 필드·재시작 처리 보완 |
| 시간 정렬 | `preimu/clock.py` 초안 | 앵커별 시각과 FC·ToF 시각 연결 |
| 단일 cycle XY | `preimu/rawxy.py` 초안 | 실시간 Z·장착 오프셋 연결 |
| H80 | `preimu/h80.py` 초안 | 최신 4앵커 기준과 계산 차이 정리 |
| Q_S10 | `preimu/qs10.py` 초안 | 시각별 Z·속도 규제·경계 처리 보완 |
| 거리·위치 게이트 | 기존 core에 다른 방식만 있음 | HW 기준 게이트를 별도 구현 |
| ToF·자세·Z 필터 | 선행 필터 입력 경로 없음 | 수신 버퍼와 Z 처리 신규 구현 |
| 전체 상태·출력 | 실행 노드는 기존 `Processor` 사용 | 공통 처리기·valid·reason·출력 연결 |
| 재생 | `replay.py`는 기존 경로만 실행 | 새 공통 처리기로 확장 |
| PX4 경계 | `bridge.py`, `frames.py` | FC 원점·시각·유효 관측 연결 |

### 먼저 해결할 구체적인 차이

기존 설정을 그대로 켜면 입력부터 맞지 않는다.

| 발견 사항 | 계획 |
|---|---|
| parser는 `clock_domain`을 요구함. 전달 소스의 상태 메시지는 생략함 | 펌웨어별 명시적 입력 계약을 둔다 |
| 상태 메시지는 부팅·복구 때만 나옴. parser는 10초 후 만료시킴 | 장치 식별 상태와 cycle 생존 감시를 분리한다 |
| 현재 A2는 약 `(5.810,-0.430,2.20)` | HW 참고 배치 `(5.80,0,2.20)`를 별도 설정으로 추가한다 |
| 초안은 고정 높이 1.2m와 미교정 bias를 기본값으로 사용 | 실시간 경로는 ToF를 사용한다. 시험 설정을 분리한다 |
| 초안 H80·Q는 3앵커 참여도 허용 | HW 기준 경로는 4앵커 각각 3개 이상을 요구한다 |
| H80 반복 횟수·가중 스케일·잔차 계산이 다름 | 기준 재현 계산과 진단 잔차를 구분한다 |
| 초안 Q의 속도 규제는 상수 1 | source span에 따른 HW 수식을 반영한다 |
| MAVROS allowlist에 거리 센서 plugin이 없음 | 설치 버전의 거리 센서 경로를 확인해 설정에 추가한다 |
| 감시 기준이 마지막 RAW 수신 시각임 | 통신 생존과 마지막 valid 위치 시각을 따로 감시한다 |

## 3. 목표 처리 구조

수신·계산·재생이 하나의 처리 계약을 공유한다.

```text
ESP32 RAW ─ 기존 수신기 ─ 입력 검사·원본 기록 ─┐
                                             │
TFmini Plus ─ Pixhawk ─ MAVROS ─ ToF 버퍼 ────┤
Pixhawk 자세 ─ MAVROS ─ 자세 버퍼 ────────────┤
                                             v
                           공통 시각·측정시각별 입력 정렬
                                             │
                거리 bias·거리 게이트 ────────┤
                ToF·자세·장착 오프셋 → Z ─────┤
                                             v
                     raw XY 진단 / 정상 H80 / 복귀 Q_S10
                                             │
                            FC 원점 보정·위치 게이트
                                             │
                            valid·fresh·reason·로그
                                      ┌──────┴──────┐
                                      v             v
                               Shadow XYZ     검증 후 x·y
                                              /uwb_pose
                                                  │
                                           MAVROS → PX4
```

ROS와 무관한 계산부는 `preimu/`에 둔다.
기존 Python·NumPy 구성을 사용한다.
계산부와 ROS 수신부를 분리해 재생에 재사용한다.
처리 시간은 이식 후 companion에서 측정한다.
C++ 전환은 측정 결과가 필요성을 보일 때 검토한다.

## 4. 구현 순서와 완료 조건

입력과 정상 경로부터 만든 뒤 복귀 경로를 연결한다.
각 단계는 독립적으로 기록·재생할 수 있게 끝낸다.

| 단계 | 구현 내용 | 완료 조건 |
|---|---|---|
| 1. 설정·입력 계약 | 최신 설정, 펌웨어 식별, 배열·mask·failure 검사, 기록 | 새 RAW 형식을 손실 없이 수용. 누락·재시작 구분 |
| 2. 거리 게이트·H80 | bias 차감, 거리 재획득, 0.8초 이력, 4앵커 H80 | HW 수식과 상태 전이를 재현. 안테나 XY 진단 출력 |
| 3. 시각·ToF·자세 | UWB/FC 시각 정렬, 자세 보간, ToF 선택, Z 필터 | 측정시각별 Z와 장착 보정값 산출. 누락은 명시 |
| 4. Q·최종 판정 | 복귀 상태, Q_S10, 위치 게이트, hold, 실패 감시 | 정상·차폐·단절·복귀의 valid/reason 전이 재현 |
| 5. ROS·재생 통합 | 새 처리기 연결, 내부 출력, 공통 재생·집계 | 같은 기록에서 같은 좌표·판정 재현 |
| 6. companion 실측 | 실물 이전, 교정, 정지·이동·차폐·복귀 시험 | 정확도·가용률·지연 보고서 작성 |
| 7. PX4 관측 연결 | 좌표 변환, 장착 오프셋, 시각·공분산 확인 | 유효 x·y만 전달. 무효 관측 차단 확인 |

### 단계 1~2: 참고 기준을 코드로 고정

HW 시험값은 별도 설정 파일로 보존한다.
실제 기체 교정값과 같은 이름으로 저장하지 않는다.
이유: 시험 태그의 편향을 다른 태그에 확정 적용하면 안 된다.

| 항목 | HW 참고 기준 |
|---|---|
| 앵커 A1~A4 | `(0,0,2.2)`, `(5.8,0,2.2)`, `(0,4.63,2.2)`, `(6.11,4.36,2.2)` m |
| 거리 bias | `[-0.08733,+0.41107,-0.11148,+0.15125]` m |
| 거리 게이트 | `0.20 m + 1.20 m/s × Δt` |
| 거리 재획득 | 0.15m 군집, 3회 확인 |
| H80 | 0.8초 창, Huber 0.12m, 앵커별 3개 이상 |
| 계산 주기 | 먼저 RAW 3 cycle마다. 이후 20Hz 이상 비교 |
| 위치 게이트 | `0.08 m + 0.80 m/s × Δt` |
| 위치 재획득 | 0.12m 군집, 3회 확인 |
| 위치 fit RMS | 0.10m 이하 |

H80은 같은 높이의 앵커를 전제한다.
ToF 없이도 안테나 XY 진단은 개발할 수 있다.
이 단계의 출력은 완성된 FC 원점 XYZ가 아니다.
기존 core의 다른 게이트를 중복 적용하지 않는다.
이유: 검증한 수용·재획득 특성이 바뀐다.

### 단계 3: ToF·자세·시간을 연결

실시간 센서 입력을 기본 경로로 구현한다.
실물 연결 전 시험 입력은 재생 경로로 넣는다.

1. ToF 원거리와 FC 자세를 각각 구독한다.
   `/mavros/imu/data`는 자세 입력 후보다.
   거리 토픽명과 타입은 MAVROS 설정에서 확정한다.
   `/tof/range`라는 데모 이름을 실측 경로로 단정하지 않는다.
2. 헤더 시각의 clock과 변환 여부를 확인한다.
   MAVROS가 변환한 시각을 다시 변환하지 않는다.
   FC 전달 ToF의 원시 표본 시각 보존 여부도 확인한다.
3. ESP32의 scale·offset과 재시작 처리를 완성한다.
   호스트 monotonic·ROS 시각 대응도 기록한다.
   편도 수신만으로 고정 전송 지연은 확정하지 못한다.
   이 불확실성과 잔차를 로그에 남긴다.
4. 각 거리 source 시각에 자세를 맞춘다.
   도착한 앞뒤 자세가 있으면 SLERP한다.
   없으면 직전 자세와 age를 사용한다.
   미래 ToF 표본은 사용하지 않는다.
5. 바닥 높이·광축·장착 오프셋으로 FC Z를 계산한다.
   Median3와 Alpha-Beta 내부 상태를 각각 유지한다.
   Z spike의 최초 보류·확정·폐기·stale을 구현한다.
6. Q의 각 거리 표본에 해당 시각의 안테나 Z를 붙인다.
   창 전체에 최신 Z 하나를 복사하지 않는다.
   이유: 높이가 변하는 구간에서 거리 모델이 달라진다.

자세는 거리와 장착 위치를 보정하는 입력으로 쓴다.
FC의 융합 위치를 UWB 풀이의 정답으로 되먹이지 않는다.
이유: UWB 관측과 비행 상태추정의 경계가 사라진다.

### 단계 4: 복귀와 무효 출력을 완성

계산 가능 여부와 외부 사용 가능 여부를 분리한다.

| 상황 | 동작 |
|---|---|
| source gap > 0.15초 | 이전 풀이 이력을 끊고 복귀 상태로 진입 |
| 복귀 초기 | 0.10초 warmup 적용 |
| 4앵커 자료·span·fresh·Z 조건 충족 | Q_S10 시도 |
| Q 임시 bias ≥ 0.08m | 0.80초 hold 연장 |
| Q 미수렴·비유한·조건 불량 | 성공으로 표시하지 않음 |
| 위치 게이트 hold | 후보와 이력은 기록. 새 유효 위치 발행 차단 |
| solver 없음 | 최종 x·y·z는 null. Z 중간값은 별도 보존 |
| 마지막 valid·fresh 위치 후 0.5초 | 위치 unavailable/failed 표시 |

hold 시간도 0.5초 실패 감시에 포함한다.
별도의 승인 예외가 없어도 구현할 수 있는 기본 정책이다.
RAW가 계속 와도 valid 위치가 없으면 실패 시간이 흐른다.
H80의 40ms fresh 한계는 연구 초기값으로 기록한다.
실측 지연을 근거로 확정하며 임의로 완화하지 않는다.

### 단계 5·7: 내부 출력과 외부 연결

내부에는 XYZ·중간값을, PX4에는 수평 관측을 연결한다.

- `/uwb/preimu`에 `jetson_uwb_preimu` 진단을 발행한다.
  현재 구조와 맞춰 JSON 스키마를 먼저 사용한다.
- RAW, 보정 거리, gate, Z, 후보·최종값을 기록한다.
  입력 시각, 도착 순서, 설정, 코드 버전도 보존한다.
- 수신기의 단일 입력을 기존 경로와 Shadow에 배분한다.
  동일 UART를 두 노드가 경쟁해서 읽지 않는다.
  이유: 프레임이 나뉘면 두 경로를 비교할 수 없다.
- 검증 후 선택한 경로 하나만 `/uwb_pose`를 발행한다.
  외부 발행 조건은 valid와 fresh를 모두 요구한다.
- FC 원점 보정은 companion에서 한 번 적용한다.
  PX4의 센서 위치 설정과 중복 보정 여부를 확인한다.
- 기존 MAVROS 경로는 ROS ENU 입력을 유지한다.
  문서의 LOCAL_FRD 변환을 그 앞에 중복 적용하지 않는다.
  실제 설치 버전의 축 변환과 공분산 회전을 시험한다.
- PX4 전달 공분산은 fit RMS 하나로 정하지 않는다.
  이식 후 위치 오차와 시간 상관을 함께 확인한다.

## 5. 이식 후 검증 계획

HW팀 시험을 재사용하고 이동·시각 검증을 추가한다.
정지 기준점은 같은 창고 좌표계로 측량한다.
교정에 사용한 구간과 점검 구간을 분리한다.

| 시험 | 방법 | 확인할 결과 |
|---|---|---|
| 기록 재생 | 같은 UWB·ToF·자세·도착 순서를 반복 | 좌표와 reason 재현. 계산 소요시간은 별도 집계 |
| 정지 | 5점 이상, 각 3~5분 | bias, SD, P50/P95/max, 7·10cm 초과율 |
| 높이·자세 | 상승·하강, roll/pitch 변화 | Z 부호·장착 보정·상태 전환 |
| 차폐 | 고정 태그 주변 5분, 단일·복수 경로 차폐 | 튐·완만한 bias·valid 가용률 |
| 이동 | 저속 이동→정지→스캔→이동 | 오차·추종 지연·정지 후 수렴 |
| 단절·복귀 | 220ms와 1초 입력 공백 | Q 진입·hold·첫 valid 지연·500ms 실패 |
| 입력 고장 | null, mask 충돌, 중복, 역행, 재부팅 | 잘못된 관측 차단과 상태 초기화 |
| 처리 성능 | 실제 companion 실시간 구동 | RAW/valid Hz, source age, 지연·CPU P95/P99/max |
| consumer | valid/fresh 조합과 축별 이동 | 무효 전송 0건, 축·원점·시각 일치 |

이동 정확도는 독립 위치 기준이 있을 때 평가한다.
기준이 없으면 연속성과 지연만 평가했다고 기록한다.

참고 비교값은 다음과 같다. companion 결과와 별도 표기한다.

| HW팀 보고 시험 | 중앙 오차 | P95 | 최대 |
|---|---:|---:|---:|
| 보정 후 30초 정지 | 1.74cm | 3.54cm | 5.31cm |
| 5분 정지 태그·사람 차폐 | 2.45cm | 6.01cm | 20.84cm |
| 복구 후 20초 정지 | 3.29cm | 5.05cm | 5.79cm |

초기 정확도 목표는 정지·저속 XY P95 7cm 이하다.
valid 가용률과 최대 오차도 반드시 함께 보고한다.
HW 자료에는 가용률 합격 하한이 정해져 있지 않다.
이를 임의의 인증 수치로 만들지 않는다.
과도한 거부로 P95만 낮아진 결과는 별도 표시한다.

## 6. 실물 이전 때 채울 설정

구현은 먼저 진행하고 실측값을 설정으로 채운다.

| 항목 | 현재 상태 | 완료 시점 |
|---|---|---|
| TFmini Plus | 확보, 다른 드론 사용 중 | 이전 후 거리·시각·센서 ID 확인 |
| ToF 광축·장착 오프셋 | 새 기체 값 미확정 | 기체 장착 후 실측 |
| UWB 안테나↔FC 오프셋 | 과거 예정치만 존재 | 기체 장착 후 실측 |
| 앵커 좌표 | HW 참고값과 저장소 값이 다름 | 해당 시험장 배치에 맞춰 선택·확인 |
| 거리 bias | HW 시험 태그 1점 임시값 | 이식 후 해당 태그로 교정 |
| 바닥·창고↔ROS 원점·방향 | 현장 확인 필요 | PX4 관측 연결 전 확정 |
| fresh 한계·지연·공분산 | 초기값과 미확정값 혼재 | companion 실측 결과로 확정 |

펌웨어 재빌드는 이번 이식의 선행조건이 아니다.
ZIP에 없는 드라이버는 알고리즘 이식을 막지 않는다.
RAW 로그가 추가로 오면 회귀 입력으로 활용한다.
현재 없는 HW팀 원본 로그도 착수를 막지 않는다.

정책 문구는 구현 단계 3에서 함께 정리한다.
`altitude_policy.md`의 z 검사 보류 조항을 구체화한다.
UWB 입력 Z의 신뢰도 검사와 비행 고도 제어를 구분한다.
`roadmap.md`에는 H80·Q를 관측 전처리로 명시한다.
별도 비행 EKF를 추가한다는 의미로 확장하지 않는다.
