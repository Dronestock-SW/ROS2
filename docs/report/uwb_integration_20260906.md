# UWB 관측 통합 점검 결과
이 문서는 2026-09-06 구현·점검 결과 기록이다.
완료 항목과 다음 현장 시험을 판단할 때 읽는다.

## 결론

태그에 새 앵커 좌표를 반영하면 된다.
직접 갱신할 명령·소스는 아직 확보하지 못했다.
companion의 RAW 거리 계산은 구현·실측했다.
PX4로의 UWB 융합은 아직 켜지 않았다.

| 항목 | 확인 결과 |
|---|---|
| 앵커 배치 | 불규칙. 높이는 모두 2.2m |
| 새 좌표 설정 | 문서와 companion 설정에 반영 |
| 태그 내부 배치 | 기존 `warehouse-5x4p5-z2p2-v2` 수신 |
| 태그 갱신 경로 | USB 명령 규격·펌웨어 소스 미확보 |
| 관측 노드 | 실제 RAW 수신·x·y 발행 확인 |
| 태그 x·y 모드 | 구현. 기존 배치의 좌표 거부 확인 |
| PX4 전달 브리지 | 구현. 기본 비활성 확인 |
| 비행 추정기 | PX4 EKF2 하나 |

설정값은 [태그 좌표 사전](../uwb_tag_layout_update.md)에 있다.
소스는 [drone_uwb](../../src/drone_uwb)에 있다.
태그 갱신과 거리 교정을 구분했다.
안테나 지연 16385 DTU는 교정 완료 증거가 아니다.

## 실제 연결 결과

지상에서 ROS 메시지를 직접 수신했다.
현재 태그 위치를 기준점으로 다시 확인하지 않았다.
따라서 이번 실기 수신으로 정확도를 산출하지 않았다.

| `/mavros/imu/data_raw` | 1,980 | 50.00Hz | 82.4ms |

| `/mavros/vision_pose/pose_cov` | 0 | 브리지 비활성 | 해당 없음 |

관측 창은 40.02초다. 노드 종료 일부도 포함했다.
첫·마지막 메시지 간 주기와 전체 창의 평균은 다르다.
전체 창의 `/uwb_pose`는 40.73건/초였다.
위 표의 간격은 companion 수신 간격이다.
긴 간격만으로 센서 내부 샘플 누락을 확정하지 않는다.

상태는 `connected=true`, `armed=false`였다.
모드 문자열은 `AUTO.LOITER`였다.
이 문자열은 정상 위치 유지나 비행 가능 판정이 아니다.
odom 수신 역시 수평 위치의 정확도 증거가 아니다.
`/scan` 미수신은 이번 기동 상태의 결과다.
LiDAR 고장으로 단정하지 않았다.

## 방향 측정

UWB→ENU 회전 후보는 −0.5837°다.
사용자는 보드 앞쪽을 A1→A3로 맞췄다.
이 상태의 IMU 방향을 30초 읽었다.

| 항목 | 결과 |
|---|---:|
| 방향 메시지 | 1,493개 |
| ROS ENU yaw 평균 | 89.4163° |
| 방향 표준편차 | 0.0377° |
| 최대·최소 차이 | 0.1615° |
| UWB→ENU 회전 후보 | yaw − 90° = −0.5837° |
| 마지막 roll·pitch | 약 0.45°, 4.82° |
| 독립 방향 검증 | 아직 없음 |

낮은 표준편차는 반복 안정성을 뜻한다.
정확한 북쪽이나 지자기 건전성을 보증하지 않는다.
끝 메시지에는 약 4.8°의 기울기도 있었다.
정확한 수평 배치·직선 이동으로 재확인한다.
원점 이동과 장착 위치도 별도로 확인한다.
후보 각도는 실행 기본값으로 활성화하지 않았다.

근거: [방향 측정 원본·요약](evidence/uwb_heading_20260906/summary.json).

## 기존 정지 로그 재생

큰 이상치는 줄었지만 평균 오차는 남았다.
같은 RAW 기록을 새 배치로 다시 계산했다.
기준점은 사용자 보고 (2.09m, 1.68m)다.
독립 측량값은 아니다.

| 항목 | 첫 정지 기록 | 가림 포함 기록 |
|---|---:|---:|
| RAW 주기 수 | 2,533 | 2,540 |
| 원시 측정률 | 42.23Hz | 42.34Hz |
| 전처리 통과 수 | 2,372 | 2,267 |
| 전체 대비 통과율 | 93.64% | 89.25% |
| 상태 대기 수 | 127 | 142 |
| 품질 검사 전 후보 RMSE | 19.97cm | 26.20cm |
| 통과 관측 RMSE | 19.96cm | 24.70cm |
| 후보 최대 오차 | 24.13cm | 75.21cm |
| 통과 관측 최대 오차 | 24.13cm | 32.62cm |
| 통과 관측 평균 오차 거리 | 19.94cm | 24.63cm |
| 통과 관측 x·y 표준편차 | 1.20cm, 1.40cm | 2.39cm, 2.32cm |
| 최대 통과 관측 공백 | 0.136초 | 1.145초 |

후보 통계도 상태 수신 전 자료는 제외한다.
전체 원시 재계산 통계와 표본 수가 다르다.
가림 기록에서 거리 불일치 52개를 거부했다.
추가 급변 13개와 회복 확인 구간도 제외했다.
통과율에는 초기 상태 대기와 시각 준비도 포함한다.

전처리 후 표본을 고른 효과가 포함된 비교다.
별도 시험 자료에서 같은 효과를 재검증해야 한다.
필터가 모든 NLOS를 식별했다는 뜻은 아니다.
공백을 메우려면 PX4 예측·회복 시험이 필요하다.
이것은 실제 UWB 측정률 향상이 아니다.

기존 태그 x·y 모드의 통과 관측은 0개였다.
새 배치와 불일치한 2,346개를 거부했다.
나머지는 상태 대기·거리 불일치로 거부했다.
이는 태그 배치 갱신 필요성을 뒷받침한다.

## 현재 장착 상태와 중단 지점

사용자 요청으로 여기까지 기록하고 중단했다.
이번에 기동한 UWB·MAVROS 점검 프로세스는 종료했다.

| 항목 | 사용자 확인 |
|---|---|
| 현재 상태 | 태그와 Pixhawk를 따로 놓고 시험 중 |
| 향후 구성 | 같은 기체에 고정 예정 |
| 태그 높이 차이 | Pixhawk 위 약 30cm |
| 태그 앞뒤 차이 | Pixhawk 앞 약 5~7cm |
| 태그 좌우 차이 | 미확인 |
| 측정 정확도 | 장착 전 대략값. 안테나 기준점 미확인 |
| PX4 설정 적용 | 없음. EV_POS_X/Y/Z는 여전히 0 |

이 값을 확정 장착 치수로 쓰지 않는다.
이유: 두 장치가 아직 함께 고정되지 않았다.
현재 따로 둔 센서로 기체 이동 일치를 검증하지 않는다.
이유: IMU와 UWB가 같은 물체의 움직임을 보지 않는다.

다음에는 실제 고정 후 안테나 기준으로 치수를 잰다.
그 뒤 방향·원점·지연 검증을 이어간다.
태그 배치 갱신 경로 확인은 별도로 진행할 수 있다.
근거: [사용자 후속 확인](evidence/uwb_ros_integration_20260906/manual_checks.json).

## 중단 지점과 다음 시작점

사용자 요청으로 문서화 후 작업을 멈췄다.
점검용으로 실행한 UWB·MAVROS 노드는 종료했다.
태그 펌웨어와 PX4 융합 설정은 바꾸지 않았다.

| 장착 관련 사용자 회신 | 기록 |
|---|---|
| 최종 구성 | 태그와 Pixhawk를 같은 기체에 탑재 예정 |
| 마지막 확인 당시 | 서로 따로 놓고 시험 중 |
| 태그의 예정 높이 | Pixhawk보다 위 약 30cm |
| 태그의 예정 앞뒤 위치 | Pixhawk보다 앞 약 5~7cm |
| 좌우 거리 | 미확인 |
| 고정 후 안테나 기준 실측 | 아직 없음 |
| FC 장착 위치 설정 적용 | 하지 않음 |

위 값은 사용자의 근사값이다.
기체 고정 후 안테나 기준점으로 다시 잰다.
현재 따로 놓인 두 장치를 같은 움직임으로 취급하지 않는다.
이유: IMU가 측정한 움직임과 태그의 움직임이 다르다.

다음 핵심 작업은 PX4 EKF2에 UWB x·y를 연결하는 일이다.
IMU 두 개의 운용·선택은 PX4가 담당한다.
companion은 UWB 관측만 공급한다.
IMU 두 개를 직접 평균 내는 필터를 추가하지 않는다.
이유: PX4의 센서 선택과 비행 추정을 중복하지 않는다.

다음 재개 때는 장착 상태부터 다시 확인한다.
이어서 좌표축·원점·시각·지연을 검증한다.
그 후 수평 관측만 PX4 EKF2에 입력한다.
UWB 공백 중 예측과 복귀 후 보정은 지상에서 시험한다.
예측 출력률을 실제 UWB 측정률로 기록하지 않는다.
이유: 공백 중에는 새 UWB 측정이 없기 때문이다.

2026-09-10 질의 기준으로도 이 작업이 다음 단계다.
9월 6일 기록 이후 장비 상태를 새로 점검하지 않았다.
