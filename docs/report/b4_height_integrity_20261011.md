# B4 실측 높이 교차검사 — 2026-10-11
거리·높이 불일치를 차단한 구현·재생 결과다.
운영 배포 여부와 남은 거리 보정을 판단할 때 읽는다.

후속 [배치 복원 후 중립 호버](neutral_hover_20261011.md)를 확인했다.
이전 배치는 사용자가 오류 가능성을 알렸다.
이전 잔차를 거리 보정값의 정답으로 쓰지 않는다.
복원 후 38.5초 재생도 최대 공백이 1.678초다.
높이 검사의 운영 배포 보류는 유지한다.

## 결론

불일치 차단은 구현했다. 정확한 좌표 복구는 미완료다.
실제 호버 75초의 승인 발행은 2,961→0개다.
검사를 통과시키려고 오차 한계를 늘리지 않았다.
현재 기록의 거리·높이 불일치가 지속된 결과다.
운영 관측 서비스에는 배포하지 않았다.
FC 파라미터·ARM·모드·재부팅 명령은 보내지 않았다.

## 변경한 검사

B4 XY 계산은 유지하고 물리적 거리 검사를 추가했다.
같은 높이의 앵커를 쓰는 H80은 공통 항을 적합한다.
이 공통 항은 실측 높이의 일치까지 보장하지 않는다.

```text
원시 거리·앵커별 시각 → 기존 점프 검사 → B4 적합
                                         │
ToF·IMU·장착 보정 → 앵커 시각별 높이 ─────┤
                                         ▼
                B4 실측 높이 교차검사
                  │                │
                일치             불일치
                  │                ├─ 기존 유일 B3·연속성 검사
                  ▼                │           │
               B4 XY 발행          │         통과 시 B3
                                   └─ 통과 못하면 새 XY 없음
```

`b4_integrity.py`가 검사와 복구 상태를 맡는다.
각 시각의 XY는 `xy + velocity × dt`로 구한다.
고정 출발점으로부터의 이동량은 검사하지 않는다.
서로 다른 앵커를 동시 측정으로 취급하지 않는다.
각 높이는 기존 100ms ToF 신선도 검사를 통과해야 한다.
기존 IMU 시각·장착·평면 바닥 조건도 유지한다.

| 조건 | 처리 |
|---|---|
| B4 fitting RMS < 6cm | 실측 높이 거리 검사로 진행 |
| 실측 높이 거리 RMS < 6cm | 기존 B4 좌표 유지 |
| 실측 높이 거리 RMS ≥ 6cm | B4 거부. 기존 B3 경로만 검토 |
| 불일치 후 정상 B4 | 0.15초·4표본 이상 확인 후 복구 |
| 복구 중 표본 간격 > 0.1초 | 확인 이력 초기화 |
| 불일치 후 높이 누락 | 거부 상태 유지 |
| 처음부터 높이 미관측 | 기존 XY 전용 경로. 미검증 표시 |
| 지상 높이 참조 | 실측으로 취급하지 않음 |
| fitting·큐·시계 초기화 | 확인된 불일치를 지우지 않음 |
| 명시적 지상 관측 세션 초기화 | 기존 DISARM·정지 조건 뒤 새 관측 시작 |

기존 6cm 기준을 사용한다. 새 완화 한계는 없다.
거부 중 이전 XY를 새 관측처럼 반복하지 않는다.
복구는 좌표 값을 수정하거나 원점을 옮기지 않는다.
기존 raw 점프 보호와 이륙 freeze도 유지한다.
검사 결과는 `models.B_TF.b4_height_check`에 남는다.
`unavailable`은 실측 검증 성공이 아니다.
모든 실측 경로의 비행 권한 false는 그대로다.

B3 재선택으로 이전 B4와 다른 좌표가 나올 수 있다.
기존 높이 잔차·유일성·연속성 검사를 그대로 요구한다.
같이 승인된 B4끼리의 좌표 차이는 0이었다.
B3를 포함한 전후 차이는 최대 0.279m였다.
이는 동일 표본의 두 알고리즘 결과 차이다.
실제 이동이나 연속 출력의 순간 점프라는 뜻은 아니다.

## 테스트용 점프와 센서 주기 조사

현재 ROS 수신 경로에 좌표를 주입하는 코드는 없었다.
`run_manual_capture.sh`는 `manual_observe.launch.py`를 실행한다.
`raw_ranges` 수신 → `MeasuredBtf` → `btf_node` 경로다.
시뮬레이터나 인위적 공백 도구를 호출하지 않는다.
`probe_recorded_motion_gaps.py`는 별도 파일 분석 도구다.
그 도구는 좌표를 바꾸지 않고 표본 일부만 숨겨 시험한다.
`jump` 검사는 이상값을 거부한다. 위치를 튀게 하지 않는다.
앞선 원본 재계산에서도 입력 거리와 출력이 재현됐다.
태그 펌웨어 바이너리 검증·재업로드는 수행하지 않았다.

서로 다른 Hz 자체는 오류가 아니다.
실측 시각·신선도·비동기 측정을 함께 다뤄야 한다.
호버 monotonic 1630~1705초를 확인했다.

| 스트림 | 수신 주기 | 근거 |
|---|---:|---|
| UWB 원시 cycle | 40.00Hz | 3,000개 |
| UWB B4 XY | 39.48Hz | 2,961개. 기존 거부 공백 포함 |
| IMU | 100.00Hz | 7,500개 |
| 하방 ToF | 9.85Hz | 739개. header 간격 약 102ms |
| PX4 odom | 30.00Hz | 2,250개 |
| LiDAR | 9.97Hz | 748개 |

ToF 선택 11,972건 중 209건이 만료됐다.
한 cycle의 4개 앵커별 선택을 각각 센 숫자다.
ToF 102ms와 유효 한계 100ms의 경계 영향이 있었다.
한계는 변경하지 않았다. 높이를 새로 만들지 않았다.
높이가 유효한 동안에도 거리 불일치는 지속됐다.
따라서 이 만료만으로 45cm 변화를 설명하지 못한다.
정상 B4 XY 계산에 ToF 값을 직접 더하지도 않는다.
앵커 시각 간격 중앙값은 6.95ms였다.
ToF–IMU 시각 차이 p95는 11ms였다.
UWB 수신 큐 지연 최대는 4.8ms였다.
고정 물리 지연을 실측 확정한 결과는 아니다.

## 기존 로그 재생

동일 원본을 변경 전·후 코드로 각각 재생했다.
변경 전 기준은 `04e1f19`다.
collector 순서 재생은 원래 callback 순서와 다를 수 있다.
각 수집 조각에서 새 processor를 시작했다.
실제 연속 운영이나 SITL 시험과 구분한다.
공중 판정이 끊긴 구간을 가로질러 공백을 계산하지 않았다.
마지막까지 복구되지 않은 공백도 포함했다.

| 기록 | 공중 발행 전→후 | 경계 포함 최대 공백 전→후 |
|---|---:|---:|
| 10/11 이륙 조각 | 684→236 | 0.053→9.550초 |
| 10/11 호버·착륙 조각 | 3,343→3 | 2.175→84.149초 |
| 10/10 C1 | 880→310 | 12.350→23.849초 |
| 10/10 C2 | 372→289 | 16.450→30.400초 |
| 10/10 C3 | 1,667→1,038 | 8.701→13.875초 |

75초 호버 부분만 보면 발행은 2,961→0개다.
관측 구간 내 약 74.974초 전체가 거부됐다.
전후 원시 거리·시각·B 적합·raw 점프 검사는 같다.
이것은 정확한 좌표를 새로 만든 결과가 아니다.
지속 불일치를 더 이상 정상 B4로 승인하지 않은 결과다.
공백이 해결됐다고 보고하거나 운영에 바로 적용하지 않는다.

원본의 0.824초 공백은 A3 급변·이력 영향이었다.
파일 재생의 대응 공백은 약 0.826초다.
수신된 pose 시각과 재생 decision 시각의 차이를 구분한다.
지속 거리 불일치와 순간 A3 이상치는 다른 문제다.

## 검증 범위

합성 정상 이동과 기존 보호의 회귀 시험은 통과했다.

| 검증 | 결과 |
|---|---|
| Windows 관련 기존 시험 | 77개 통과 |
| 최종 새 검사·공백 분석 시험 | Windows·Jetson 각각 21개 통과 |
| Jetson 격리 관련 묶음 | 305개 통과. 이후 주기 변형 3개를 추가 확인 |
| Jetson `colcon build --symlink-install` | drone_uwb 성공 |
| Windows 넓은 묶음 | 536 통과·7 skip·5 환경/자료 오류 |
| 실제 비행·SITL | 이번 수정으로는 미실시 |
| 운영 서비스 배포 | 미실시. 기존 `be36248` 유지 |

합성 시험은 약 0.76m/s 수평 이동을 포함한다.
0.4m/s 상승과 40Hz UWB도 함께 시험했다.
높이는 10Hz·약 9.8Hz와 100ms 만료를 적용했다.
정지·이동·상승의 정상 기하 출력은 유지됐다.
느린 거리 편향, ToF 만료 뒤 재승인 우회는 차단됐다.
기하적으로 완벽한 가짜 이동은 이 검사도 구분하지 못한다.
이를 드러내는 한계 시험도 포함했다.

Windows 격리 사본은 Git 링크를 파일로 풀어 시험했다.
ROS launch 시험은 해당 Windows 환경에서 제외했다.
남은 5건은 경로 구분자 3건과 사본 밖 data 자료 2건이다.
경로 3건은 수정 전 `04e1f19`에서도 재현했다.
운영 코드나 센서 동작의 실패로 해석하지 않는다.
다만 전체 묶음 통과라고도 보고하지 않는다.
Jetson 시험은 별도 `/dev/shm` 작업공간·domain 172를 썼다.
기존 관측·수집·LiDAR 서비스는 계속 active였다.
