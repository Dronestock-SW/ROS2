# 10월 9일 수동 Position 시험과 설정 비교
수동 시험의 흐름 현상을 조사한 기록이다.
기존 호버 설정으로 복구 범위를 정할 때 읽는다.

## 결론

**광류 회전·배율과 제어 게인은 기존 파일과 같다.**
사용자는 Position에서 기체가 흐른다고 보고했다.
기존 파일은 `perfect_holdv2.params`로 확인했다.
전체 1,095개를 읽고 같은 이름 1,095개를 비교했다.
float32 값으로 비교한 실제 차이는 22개다.
이번 조사에서 FC 파라미터를 쓰지 않았다.
원인 하나나 호버 복구 성공을 확정하지 않는다.

## 설정 근거

원본은 `data/raw/flight/20260927/perfect_holdv2.params`다.
루트의 동명 파일은 원본 경로를 가리킨다.
Windows에서는 그 경로를 직접 읽어 비교했다.
원본 SHA256은 다음과 같다.
`389b802cb7cecad0c71c4f70745c9c125959da9e3fe146cfb22ca44725c8fd46`

FC 펌웨어 커밋은 과거 비행 기록과 같았다.
`d6f12ad1c4f70ad3230afd7d86e971421e02fef4`
하드웨어는 `PX4_FMU_V6C`, 버전은 1.17.0이다.

첫 비교는 DISARM 상태의 MAVROS shell 읽기였다.
Jetson·FC 재부팅 뒤에는 포트 소유자가 없었다.
DISARM heartbeat를 확인하고 전체 파라미터를 읽었다.
`PARAM_REQUEST_LIST` 응답 1,095개를 PC에 백업했다.
정수의 bytewise 해석은 shell 값과 대조했다.
shell의 소수 네 자리 출력 오차도 제외했다.
비교 가능한 546개 shell 값과 모순은 없었다.
재부팅 전후 자료를 하나의 부팅으로 취급하지 않는다.

현재 파라미터에 광류 부호 전환 차이는 없다.
이 사실만으로 실제 센서 방향이 맞다고 확정하지 않는다.

MAG_TYPE 변경은 이전 통합 기록에 명시돼 있다.

Automatic(0)은 그 정책과 다르다.

## 실제 기록과 한계

세션은 `manual-flight-20261009T111438Z`다.
433.454초를 기록했고 PC 복사 해시가 일치했다.
원본은 330,762,327바이트다.

FC 공중·착륙 상태는 약 69.5초였다.
이는 외부 영상으로 확인한 궤적이 아니다.
이 시행의 ToF 최대 실측 거리는 0.85m였다.
1.3m 자동 이륙이나 미션 완료 시험은 아니다.
RC 모드 채널은 해당 모드 전환 때 함께 바뀌었다.
말미에는 RC kill·arm 채널 변화도 기록됐다.
수집기는 ARM·모드·LAND·파라미터 쓰기를 하지 않았다.

UWB bridge와 mission execute는 모두 꺼져 있었다.
EV pose 토픽도 이 기록에 없었다.
UWB가 이 시행의 FC 위치를 안정화했다고 볼 수 없다.
FC 출력 측 odometry reset counter는 10에서 16이 됐다.
각 변화의 위치·속도·방위 원인은 ULog가 필요하다.
현재의 지상 융합 상태를 비행 중 상태로 소급하지 않는다.

광류 원본은 비행 중 수신됐다.
IN_AIR부터 착륙 시작 전까지 품질 중앙값은 124였다.
품질 숫자만으로 융합 성공이나 부호를 확정하지 않는다.
같은 구간의 수평 위치 innovation 값은 NaN이었다.
이것을 오차 0으로 치환하지 않았다.

UWB 원본은 34,754개, 최대 수신 간격은 약 48ms였다.
250ms를 넘는 원본 토픽 간격은 없었다.
따라서 모든 좌표 공백을 USB 단절로 설명할 수 없다.
ARM 표본 구간에서 B_TF 발행은 340/2,919회였다.
시간 매핑 미성립·거리 불일치·좌표 점프 등이 거부 원인이다.
Tag boot/session 식별은 기록 전체에서 하나였다.
후반 좌표 공백을 태그 재부팅으로 확정할 근거는 없다.

Position·수평/요 스틱 중립 구간도 별도로 골랐다.
길이는 약 1.4~3.5초로 짧다.
PX4 추정 XY 변화는 각 구간 약 7~9cm였다.
외부 실측이 없어 실제 기체 흐름과 같다고 보지 않는다.
사용자의 실제 이동 방향·거리 기준도 확보되지 않았다.
이번 자료로 창고 좌표·시간 보정을 확정하지 않는다.

## 복구 범위 제안 — 미적용

먼저 수동 호버의 추정기 기준을 분리해 복원한다.
검토 후보는 MAG_TYPE 6→0, EV_CTRL 1→0이다.
이는 기존 수동 광류 비행과 같은 융합 정책 비교다.
호버가 복구된다고 보장하거나 원인 확정으로 쓰지 않는다.
EV_CTRL=1은 앞서 사용자가 지정한 값이다.
반대로 바꾸는 범위를 확인하기 전에는 쓰지 않는다.

RC 입력·인계 설정과 이륙 높이는 유지한다.
측정한 EV 장착값은 보존한다.
CAL 교정값·편각·누적값은 일괄 원복하지 않는다.
이유: 변경 시점과 교정의 유효성이 확인되지 않았다.
과거 전체 params를 덮으면 RC 정책도 되돌아간다.

적용 시에는 새 DISARM·지상 상태부터 확인한다.
현재 백업을 보존하고 두 값만 저장·재조회한다.
MAG_TYPE의 재부팅 요구도 반영한다.
재부팅 뒤 읽기와 관측 복구를 마쳐야 적용 완료다.
자동 미션·UWB bridge는 이 비교에서 활성화하지 않는다.
MAG_TYPE=0으로 바꾸면 현장 미션 예상값도 달라진다.
그 차이를 숨기거나 시작 조건을 자동 통과시키지 않는다.

현재까지 완료한 것은 수집·분석·읽기·비교다.
후속 파라미터 적용·호버 재시험·보정 확정은 미실시다.
동일 시행 ULog는 아직 확보하지 못했다.
FC SD의 날짜 목록만으로 로그 존재를 판단하지 않는다.
