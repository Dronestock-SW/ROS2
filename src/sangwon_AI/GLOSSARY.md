# sangwon_AI 용어
이 문서는 sangwon_AI 설계에서 쓰는 용어를 정의한다.
행동·로그·좌표계 문서를 함께 읽을 때 참고한다.

| 용어 | 정의 | 비유 | 이 설계에서의 의미 |
|---|---|---|---|
| HOST_OBSERVE | 장치·웹 조회만 하는 서비스 프로파일 | 연결 점검 모드 | 비행 권한 없음, 새 START 실행 불가 |
| IPC | 같은 장치 안의 프로세스 간 통신 | 내부 연락 통로 | Python↔C++ private Unix socket v1 |
| 원장(Ledger) | 재시작에도 남는 명령·실행 기록 | 접수/처리 기록장 | SQLite로 중복 실행·자동 재개 방지 |
| outbox | 아직 서버 저장 확인을 받지 못한 발신 기록 | 발송 대기함 | key·원문 SHA가 맞는 durable receipt 후 ACK |
| durable receipt | 서버 DB 저장 완료 응답 | 저장 확인증 | HTTP 성공과 구분, stored/key/sha256 확인 |
| RECOVERY_LOCK | 실행 중 core 재시작 후 자동화 잠금 | 상태 확인 전 재출발 금지 | 기존 결과 조회 허용, 자동 재개/START 거부 |
| capability | 구현이 지원한다고 명시한 기능 | 지원 기능 목록 | 미지원 scan/지도 기능을 조용히 생략하지 않음 |
| 행동 트리(BT) | 조건을 반복 평가해 행동을 고르는 계층 | 상황별 작업 절차표 | 호버·이동·복귀·착륙 선택 |
| 공유 상태(Blackboard) | 노드가 함께 읽는 최신 상태 묶음 | 현재 상황판 | PX4·센서·임무 값의 시각과 유효성 보관 |
| 행동 계약 | 행동별 입력·완료·실패·중단 조건 | 작업 지시서 | 행동 전환의 성공과 실패 판정 |
| 선점 | 상위 행동이 진행 행동을 중단함 | 긴급 정차 | 출력 소유권 회수와 이전 목표 폐기 |
| 실행 경로 재계획 | 같은 목적지로 가는 경로를 다시 계산 | 막힌 길 우회 | 필수 경유점은 유지 |
| 목표 yaw | 지도에 그린 절대 방향 | 도착해 바라볼 쪽 | 경유점 도착 자세, 시작 목표는 별도 선택값 |
| 현재 heading | 센서로 추정한 현재 방향 | 나침반 눈금 | PX4 자력계 기반 추정값 |
| yaw 변환본 | 지도 방향을 PX4 목표로 바꾸는 사전 측량값 | 두 나침반의 눈금 차이 | 지도·기체 설정·검증 결과와 함께 버전 보관 |
| ULog | PX4 비행 기록 파일 | 비행 계기 기록장 | 상태·센서·명령 재생과 검증 |
| 정규화 추력 명령 | 내부 범위로 표현한 추력 요청 | 액셀 눈금 | 물리 힘(N)으로 해석하지 않음 |
| 검증 구역 | 시험을 통과해 운용을 승인한 영역 | 검사 통과 구역 | 웹 지도와 Jetson에 보관하는 yaw 운용 범위 |
| 명령 중복 방지 | 같은 요청을 여러 번 받아도 동작을 반복하지 않음 | 같은 접수번호의 재조회 | control_request_id별 처리 결과 보관 |
| 임무 실행 ID | 한 번 수락한 임무 실행의 식별자 | 같은 작업지시서의 실행 회차 | 재접속·요청 재시도에도 유지 |
| 비행 ID | 실제 이륙부터 착륙까지의 식별자 | 한 번의 운행 번호 | PX4·Jetson·웹 기록 연결 |
| 제어 세션 | 새 웹 요청을 적용할 연결 문맥 | 현재 유효한 접수 창구 | 재연결 뒤 이전 미수락 요청 차단 방식의 후보 |
| 임무 묶음 | 함께 검증할 임무·지도·승인 자료 | 출발 전 준비한 작업 자료 | 전체 수신·검증 후 실행 중 개정 고정 |
| 수락 ACK | 요청을 받았다는 처리 결과 | 작업 접수증 | 실제 이륙·복귀·착륙 완료와 구분 |
| 사건 | 실행 상태가 바뀐 기록 | 시각이 붙은 작업 일지 | 재전송해도 같은 사건 ID로 저장 |
| 입력 어댑터 | 장치 형식을 내부 의미로 바꾸는 연결 모듈 | 규격에 맞춘 연결 부품 | UWB 전체 사양 수령 뒤 설계 |
| 목표 lease | 행동 판단이 목표 사용을 허용한 유효기간 | 갱신이 필요한 사용 허가 | 송신기만 살아도 낡은 이동 목표는 만료 |
| 행동 세대 | 선점 전후 출력을 구분하는 번호 | 취소된 작업과 새 작업의 접수 차수 | 늦은 계획·서비스 응답의 재사용 차단 |
| 준비 ID | 검증한 임무·상태를 가리키는 식별자 | 출발 전 검사 결과 번호 | START 적용 시 현재 조건을 재검증 |
| ENU/NED | 동·북·상/북·동·하 축의 좌표계 | 같은 위치를 적는 두 축 표기 | 지도→MAVROS ENU→PX4 NED로 한 번씩 변환 |
| 실행 프로파일 | 같은 로직에 적용할 대상·값·승인 묶음 | 시험 설정표와 운용 설정표 | REPLAY/SITL/FLIGHT를 구분, 모의값 실기체 상속 금지 |
| flight_guard | 비행 출력·유효기간·제어권을 검사하는 독립 프로세스 | 출력 전 마지막 확인 담당 | C++ BT가 멈춰도 낡은 목표를 만료시키고 PX4 대응 연결 |
| uXRCE-DDS | PX4와 ROS2 간 데이터 전달 경로 | PX4 상태를 읽는 추가 통로 | 품질 정보 수신 전용, 제어 출력은 MAVROS로 유지 |
| 속도 프로파일 | 시간별 목표 속도·위치 곡선 | 출발·가속·감속 시간표 | PX4에 줄 위치 목표를 만들며 기체 PID를 대신하지 않음 |
| REPLAY fixture | 시험을 위해 정한 합성 입력 | 모의 상황 카드 | 실측 기체 성능·경로 승인으로 해석하지 않음 |
| preflight | 시동 전에 상태·설정·임무를 확인하는 검사 | 출발 전 점검표 | 호스트 진단과 실제 PX4/임무 준비를 구분 |
| linger | 로그인 없이 사용자 서비스 관리자를 유지하는 설정 | 로그인 없이 열리는 작업실 | 호스트 점검의 전원 투입 자동 실행에 사용 |
| venv | 프로젝트별 Python 패키지 실행 환경 | 도구별 작업 상자 | ROS 보조용 .venv와 ULog 분석용 .venv-log를 분리 |
| ArUco 정렬 | 마커 상대 관측으로 작업 목표를 보정 | 라벨 앞에서 위치 맞추기 | PX4 위치·yaw 목표로 미세 조정, 호버 안정 뒤 QR 판독 |
| 불변 snapshot | 수락할 자료를 고정한 배포본 | 봉인한 작업 지시서 | 지도·라벨·작업·승인 참조를 하나의 ID와 바이트 해시로 검증 |
| 임무 배정 | 기체에 배포본을 연결하는 준비 작업 | 담당 차량에 배차 | 자료 수신·검증을 시작하며 이륙은 새 START를 기다림 |
| 운영 확인서 | 특정 계획과 출발 상태의 운영자 확인 | 출발 전 확인 서명 | 상부 공간·현재 방향 확인을 plan/launch 문맥에 결합 |
| 접근 앵커 | 스캔 진입/이탈의 기준 위치 | 작업 전 대기 장소 | LAUNCH 또는 직전 작업 출구, 지도 객체와 임무 참조 분리 |
| operation_id | API 의미를 가리키는 고유 이름 | 업무 절차 번호 | URL 합의 전에 브라우저·서버·Jetson 책임을 연결 |
