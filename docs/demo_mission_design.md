# 데모 임무 상태 판단 기준
이 문서는 도착·수신 공백의 판단 기준이다.
데모로 임무 로직을 개발할 때 읽는다.

## 결론

도착은 거리·속도·지속 시간으로 판단한다.
입력이 오래되면 도착 판정을 취소한다.
복구 뒤에는 새 입력의 연속 수신을 확인한다.

```text
/target_pose ---- 목표 x·y -----+
                              |
/demo_pose ----- 위치·시각 ----+--> 상태 판단 --> /demo_mission_state
                              |
/uwb_pose ------ 관측 시각 -----+
```

위치는 데모 생성기의 정답을 사용한다.
가상 위치의 차분으로 수평 속력을 구한다.
UWB는 새 관측이 들어오는지만 확인한다.
이 두 값을 융합하는 추정기는 만들지 않는다.
이유: 실제 비행 상태추정은 PX4 EKF2의 책임이다.

## 입력과 출력

이 노드는 데모 상태만 발행한다.

| 경계 | 형식 | 의미 |
|---|---|---|
| `/target_pose` | `PoseStamped` | 목표 x·y. 동일 좌표 재수신은 유지 |
| `/demo_pose` | `PoseStamped` | 데모 위치. 연속 두 표본으로 속력 계산 |
| `/uwb_pose` | `PoseWithCovarianceStamped` | 전처리를 통과한 관측의 시각 |
| `/demo_mission_state` | `String` JSON | 상태·사유·거리·속력·입력 나이 |

좌표계는 `uwb_map`이어야 한다.
다른 좌표계의 목표는 거부하고 기존 목표를 해제한다.
이유: 다른 축의 좌표로 도착을 판단할 수 없다.
NaN과 무한대 좌표도 거부한다.
이유: 거리·속력을 유한한 수로 계산할 수 없다.

현재 z는 판단에 사용하지 않는다.
고도 제어 명령도 만들지 않는다.
이유: 이번 개발은 수평 위치의 상태 판단이다.

상태 출력은 `demo=true`를 포함한다.
`flight_output=false`도 함께 기록한다.
상태 변경이 실제 기체 정지·감속을 뜻하지 않는다.
이유: MAVROS와 비행 명령 연결이 없다.

## 전환 조건

아래 수치는 데모용 초기 조건이다.
실기 운용 기준으로 검증한 값은 아니다.
[설정 파일](../src/drone_demo/config/mission.json)에서 바꾼다.

| 조건 | 기본값 | 목적 |
|---|---:|---|
| 접근 진입 / 해제 | 0.50 / 0.60m | 경계 부근 상태 왕복 억제 |
| 정착 진입 / 해제 | 0.15 / 0.20m | 작은 위치 변화 허용 |
| 정착 중 수평 속력 | 0.10m/s 이하 | 목표를 빠르게 지나치면 도착 거부 |
| 정착 지속 시간 | 1.0초 | 잠깐 가까워진 상태 제외 |
| 데모 위치의 최대 나이 | 0.20초 | 오래된 위치로 판단하지 않음 |
| UWB 관측의 최대 나이 | 0.25초 | 수신 공백 탐지 |
| 복구 대기 | 0.50초 | 일시 복구와 연속 수신 구분 |
| 복구 중 새 표본 | 각 입력 3개 이상 | 같은 값을 반복해서 복구하지 않음 |
| 상태 발행 | 20Hz | 입력이 없어도 시간 초과 검사 |

## 상태표

현재 상태와 전환 이유를 함께 읽는다.

| 상태 | 뜻 | 다음 상태의 조건 |
|---|---|---|
| `WAITING_TARGET` | 목표 없음 또는 목표 거부 | 올바른 목표 수신 |
| `WAITING_DATA` | 필요한 입력을 아직 못 받음 | 위치·UWB 수신 |
| `DEGRADED` | 입력 나이·형식·속력 계산 불량 | 새 정상 입력 수신 |
| `RECOVERING` | 연속 수신 확인 중 | 0.5초 및 각 입력 3개 충족 |
| `MOVING` | 목표까지 0.5m보다 멂 | 접근 반경 진입 |
| `APPROACHING` | 목표 근처 | 정착 거리·속력 충족 |
| `SETTLING` | 정착 시간 확인 중 | 조건을 1초 유지 |
| `ARRIVED` | 현재 도착 조건 충족 | 이탈·가속·수신 공백이면 해제 |

초기 입력 확보 때도 `RECOVERING`을 거친다.
어느 상태에서도 입력이 오래되면 판정을 중단한다.
UWB 공백만으로 항상 실제 정지를 명령하지는 않는다.
이유: 실기는 PX4 위치의 유효성도 함께 봐야 한다.

## 시간과 연속성

새 측정의 시각으로만 정착 시간을 늘린다.
타이머 호출 횟수로 도착을 완성하지 않는다.
이유: 같은 위치를 반복 평가해도 새 측정은 없다.

입력 나이는 수신 시점의 지연을 포함한다.
그 뒤의 경과 시간은 monotonic 시계로 센다.
오래된 시각과 중복 시각은 새 입력으로 세지 않는다.
미래 시각의 입력도 거부한다.
이유: 현재 시점에 사용할 수 있는 측정인지 불명확하다.

상태 발행 사이에 잠깐 이탈해도 정착을 초기화한다.
수신 콜백에서 거리·속력 위반을 함께 확인한다.
복구 중 다시 끊기면 복구 시간을 처음부터 센다.

## 실기 전환 시 남는 작업

이번 결과는 임무 판단의 기능 시험이다.

| 다음 항목 | 필요한 작업 |
|---|---|
| 현재 위치·속력 | PX4 출력과 유효성의 입력 계약 확정 |
| UWB 공백 | PX4 예측·관측 나이·상태 불확실성 함께 검토 |
| 목표 좌표계 | 서버·UWB·PX4의 방향·원점 정합 |
| 감속·정지 | 수평 제어와 실패 시 동작을 SITL에서 검증 |
| 거리·속력 제한 | 실제 기체·오차·통로 조건으로 정하기 |

새 UWB가 들어왔다는 사실은 정확도를 보장하지 않는다.
금속·가림에 의한 편향은 별도 검증이 필요하다.
기존 [공용 데모 기준](demo_design.md)을 함께 따른다.
