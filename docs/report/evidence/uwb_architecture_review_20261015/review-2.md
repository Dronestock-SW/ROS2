# 2차 검토: 정정 반영과 설계 구체화

**표기:** [사실] 제공 기록·소스 기준 / [추정] 미검증 판단 / [제안] 설계안. 실행·재생·설정 변경은 모두 향후 작업 후보입니다. 새 실기 수치는 만들지 않았고, 임계값은 이름 붙은 파라미터로만 둡니다.

## (a) 1차 주장 정정

| 1차 주장 | 정정 |
|---|---|
| NLOS는 거리를 늘리기만 한다 | "단순 초과 전파경로만으로는 음의 부족을 설명하지 못한다"로 한정합니다. 수신기 leading-edge, 보정, 복합오차 경유의 NLOS 영향은 배제하지 않습니다. 364~384ms 사건과 원인이 같다고 보지 않습니다. |
| 비공면 2고·2저 배치 | 철회합니다. 현재 B4 XY 경로는 같은 높이의 공통 수직항을 제거하는 수학 계약이므로, 배치 변경은 작은 설정 수정이 아니라 알고리즘 변경입니다. |
| ±3cm, 삼각부등식 위반 0건 | 철회합니다. 잡음 통계(분포, 표본 수, 신뢰구간)를 먼저 정의해야 합격선이 됩니다. |
| EV_DELAY = 통신지연 중앙값 | 틀렸습니다. 측정시각이 FC 시계로 정확히 매핑되면 0이 맞고, 지연을 다시 빼면 이중 보정입니다. [사실] EV_DELAY 0, EV_CTRL 1(XY), EVP_GATE 5, HGT_REF baro는 이미 설정되어 있습니다. 이를 새 기능처럼 제안한 것은 오류입니다. |
| EV_GATE 거부 → timeout reset 경로 | 이름을 EVP_GATE로 정정합니다. 700ms 사건은 d6f12ad의 noGNSS EV start 분기와 함께 소스로 확인할 대상이며, 원인으로 추정하지 않습니다. |
| framejump 0.3m 고정 | [사실] 실제 조건은 `0.3 + 1m/s × pose_dt`입니다. |
| 보정량 ≤ D_pred이면 정상 | 철회합니다. 일관된 UWB 편향을 통과시킬 수 있습니다. HOLD라는 이유로 보호를 해제하지 않습니다. |
| flow 필수 AND, eph 임계 | 철회합니다. 검증된 가용 보조수단(EV, flow, 독립 LiDAR 속도) 중 어느 것으로든 판단합니다. eph는 상관오차가 없다는 증명이 아닙니다. |
| 공백 중 10cm 비현실적 | SIH 1건으로는 단정할 수 없으므로 철회합니다. |
| 속도 상한 0.5~0.75 | 제공된 계산(0.5m/s에서 47.5cm > 30cm)과 충돌하므로 철회합니다. 초기 후보는 0.25이며, 모드별 영향과 수동 회수를 평가한 뒤 결정합니다. |
| 정지거리에 reset D를 가산 | 철회합니다. reset은 물리적 이동이 아니므로 e_est와 이중 계상됩니다. |
| gc.freeze 권고 | 정지·메모리 효과 미확인이므로 별도 후보로 강등합니다. |
| 모든 작업을 기하 완료까지 보류 | 정정합니다. 튜닝을 섞지만 않는다면 ClockMap 분석과 실시간 출력 C++ 설계는 병행할 수 있습니다. |

## (b) 후속 작업과 의존 순서

```
T1 ─┐
T2 ─┼─> T3 ─> T4 ─> T5
T6 (병행, T1·T2 튜닝과 분리)
```

**T1. 세션 기하·신원 계약** [제안]
- 내용: 기존 기록을 정적 분석합니다. `anchor_geometry`(ID↔좌표, 높이, 측정 방법)를 세션별 해시로 묶어 로그 헤더와 bridge 시작 조건에 고정합니다.
- log49 20묶음에서 볼 것: 앵커별 부족분의 부호와 크기 일관성, ID 교차 가능성, 단위.
- 합격기준: 판정 통계를 먼저 문서화합니다. 이 문서가 없으면 수치 합격선을 두지 않습니다.

**T2. 명세 정합표 (값 변경 없음)**
- 경로 0.25 ↔ MPC_XY_VEL_MAX 2.0
- 레버암 소유자: EV_POS_Z −0.10 ↔ FRD −0.07, 그리고 ToF 기준 0.15 기준점
- EV_DELAY=0의 근거: ClockMap이 FC 시계로 매핑되는 경로의 증빙
- 도착 판정: 15/25cm ↔ 10cm
- 각 항목마다 "진실 출처(소스/실물/설정)"와 결정권자를 기입합니다.

**T3. 상태·신뢰 계약 구현 명세** — (c)의 내용입니다. 대상은 `field_mission.hpp`, `field_executor.hpp`, bridge 상태 토픽입니다.

**T4. 참조 생성기** — BRAKE/HOLD/REENTRY 연속 참조와 reset 연속성 처리를 맡습니다 ((d)). mask 2552는 1단계에서 유지합니다.

**T5. framejump 판정 재설계** — T4의 "설명된 delta"를 사용합니다. 판정 요소는 다음의 조합입니다.
- 미설명 이동
- 관측의 물리 적합성
- geometry hash와 clock epoch
- 제어 상태

**T6. 병행 후보**
- ClockMap 조건부 보존을 별도 커밋으로 이식 평가
- 실시간 출력 C++ 계약 설계
- 서비스 수명 분리: BTF 갱신이 MAVROS 재시작을 일으키지 않도록 함
- 이전 슬롯 native.so 자급화

## (c) 계약 정의

**1. 측정 공백 계약 (bridge → mission)** [제안]
- ODOMETRY와 별도로 매 주기 `uwb_obs_status`를 발행합니다.
- 필드: `{geometry_hash, clock_epoch, seq, t_source(FC clock), t_arrival, t_compute, t_publish, status}`
- `status` 값: `OK | NO_OBS | QUALITY_REJECT(reason) | EXPIRED | CLOCK_INVALID | GEOMETRY_MISMATCH`
- 오래된 좌표에 새 timestamp를 붙이는 것을 금지합니다.
- mission은 수신 간격이 아니라 status와 연속 이력으로 판단합니다. 이것이 0.7초 일률 실패를 배제하는 근거입니다.

**2. 현재 상태 신뢰 계약 (FC → executor)**
- `aid_ok = OR(EV, flow, LiDAR속도)`
- 각 항목은 아래 세 가지를 모두 만족해야 참입니다.
  - `time_last_fuse`가 증가 중
  - 현재 시각 기준 신선함
  - 해당 cs 플래그가 활성
- `fused=True` 단독은 무효입니다. [사실] 입력이 중지된 뒤에도 남아 있었습니다.
- `aid_ok`가 거짓이거나 판정 불확실하면 기존 PX4 fallback으로 넘깁니다. 고정 Tmax를 발명하지 않습니다.

**3. 융합 확인 계약 (REACQ → REENTRY)**
- 조건: EV `time_last_fuse` 증가 + innovation 비거부 연속 + 같은 `geometry_hash`/`clock_epoch` + 마지막 reset 이후 안정 구간
- 연속 횟수와 구간 길이는 파라미터로 두고, 근거 자료가 생긴 뒤 설정합니다.

**4. 명령 송신 계약**
- 50ms 연속 송신을 유지합니다.
- 각 setpoint는 `{ref_epoch = xy_reset_counter, phase, ref_source}`를 내부 기록합니다.
- 한 tick은 하나의 스냅샷(local_position + reset_counter + aid + obs_status)으로만 계산합니다.

## (d) 복귀 좌표변환과 추정 reset을 분리하는 최소 구현

**핵심:** reset 처리는 피드백 연속성만 담당하고, 물리적 교정은 재진입 궤적만 담당합니다.

**1. 프레임 분리**
- 목표는 고정 지도 프레임 M에만 저장합니다 (`goal_M`, 불변).
- BRAKE/HOLD 참조는 PX4 로컬 프레임 L에서 둡니다.

**2. reset 이벤트 처리** (`xy_reset_counter` 변화)
- L 프레임의 모든 활성 참조에 `delta_xy`를 더해 이동시킵니다.
- 결과: 추정치와 참조의 상대관계가 보존되어 P항에 계단 입력이 들어가지 않습니다. 물리적 HOLD 지점은 그 순간 바뀌지 않습니다.
- reset이 "실제 drift 교정"인지 "순수 frame 변경"인지는 여기서 판정하지 않습니다.
- delta는 framejump의 "설명된 이동"으로만 사용하고, 크기의 타당성은 T5가 판정합니다.

**3. 첫 적격 UWB 처리와 보호의 양립**
- bridge는 첫 적격 관측을 즉시 FC로 보냅니다 (추정 측).
- executor는 REACQ에서 2번의 shift-hold만 수행합니다 (제어 측).
- 즉 추정은 즉시, 임무 재개는 3번 계약 충족 후로 분리하므로 두 원칙이 충돌하지 않습니다.

**4. 재진입**
- 융합 확인 후 `goal_L = T_LM(현재) · goal_M`을 다시 계산합니다.
- 현재 추정 위치에서 재시드한 속도 0.25 이하의 연속 경로로 이동합니다.
- 실제 drift 교정분은 이 저속 경로로만 물리적으로 해소됩니다.
- T_LM은 같은 시각·같은 기준점의 EV 관측과 추정의 관계로 구하며, reset delta로 구하지 않습니다.
- EV_CTRL XY로 L이 M에 정렬되어 있다면 T_LM은 상수에 가깝다는 것이 [추정]입니다. T2에서 확인합니다.

**잔여 위험 (확인 필요)**
- **무-reset 점진 교정:** reset 없이 Kalman 이득으로 점진 교정되면 shift가 일어나지 않아 P항이 직접 반응합니다. 기존 기록에서 재획득 직후의 innovation 크기와 속도 반응을 분석해야 합니다.
- **reset과 setpoint 경합:** setpoint 도착 사이에 reset이 끼면 최대 1 tick 동안 계단이 생길 수 있습니다. d6f12ad의 offboard 경로가 외부 trajectory_setpoint를 reset 보상하는지 소스 확인이 필요합니다 [미확인].
- **p/v/a feedforward:** 위 두 결과를 본 뒤 `ref_epoch`를 묶은 인터페이스 변경 후보로 검토합니다.
