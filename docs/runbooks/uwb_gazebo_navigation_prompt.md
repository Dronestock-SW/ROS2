  → 허용 구역·형식 검사

  → 측위 오차·추종 오차·실제 도착 오차 평가

6. 단계별 개발·검증

① 좌표·장착·시간 기준 확정

UWB 수평 원점은 A1이다.
+y는 A1→A3, +x는 A3를 볼 때 오른쪽이다.
A1→A2 선을 x축으로 간주하지 않는다.
앵커 좌표는 `config/anchors/anchors_20261004.json`을 기준으로 삼는다.
가로 6.3m, 세로 4.6m의 직사각형이다.
실물의 잠정 지도와 Gazebo에서 정의한 정답 지도를 구분한다.

사용자 장착 보고:
- FC·LiDAR: 기체 중심보다 전방 14cm.
- UWB·ToF: 수평으로 기체 중앙.
- ToF 방향: 아래.
- 실제 질량: 대략 2kg 이하.

센서 높이·관성 등 미측정 값은 시험 설정으로 표시한다.
기체 중심·FC·안테나·질량중심을 같은 점으로 간주하지 않는다.
장착 오프셋은 좌표 변환 또는 PX4 설정에서 한 번만 반영한다.
관측과 목표가 최종적으로 어느 기준점을 뜻하는지 명시한다.

원점 이동·축 회전과 ENU/NED 변환을 구분한다.
선택한 통신 경로에서 누가 변환하는지 표로 기록한다.
목표·관측의 변환 왕복과 공분산 회전을 검증한다.
PX4 위치·방향 reset 시 정렬을 어떻게 유지할지도 정의한다.
27일 로그의 방향 관련 미확인 사항도 필요 범위에서 확인한다.

Gazebo 시각·PX4 측정시각·수신시각을 구분한다.
시뮬레이터 정지·재시작·시간 역행을 처리한다.

② 비행과 분리한 다점·축별 측정 시험

가상 RAW를 짧게 기록해 실제 표본 수와 수신률을 확인한다.
그 뒤 중앙과 여러 위치에서 정지 측정을 한다.
+x/−x/+y/−y 이동·정지·반전도 시험한다.
알려진 이동량과 방향이 계산값에 나타나는지 확인한다.
필요하면 제어와 분리된 알려진 궤적으로 먼저 시험한다.
그 결과를 PX4가 실제 비행한 결과로 표시하지 않는다.

거리 보정식은 corrected_range = raw_range - bias다.
생성기의 편향과 보정기의 추정 편향을 따로 설정한다.
한 지점에서 얻은 값을 전체 위치의 확정값으로 쓰지 않는다.
교정용 위치·시드와 평가용 위치·시드를 분리한다.
평가 결과를 본 뒤 같은 평가 자료에 맞춰 재조정하지 않는다.
현재 벽 배치는 UWB 전파 차폐를 자동 구현하지 않는다.
차폐성 편향은 명시적으로 주입하고 물리 전파 모사와 구분한다.

ToF 거리·자세·장착 위치에서 높이를 계산한다.
하방 센서 거리를 안테나 높이로 바로 대입하지 않는다.
평면 바닥 등 산식의 전제와 입력 실패 처리를 기록한다.

③ A/B/C/D 비교·선정·보조기능 보완

A를 비교 기준선으로 보존하고 실시간 경로를 먼저 확인한다.
파일 재생과 실시간 계산의 같은 입력 결과를 비교한다.
RAW→보정→계산→변환 각 단계의 값을 기록한다.
관측 시각·품질·공분산·거부 사유도 남긴다.
오래된 위치를 새 측정처럼 반복 발행하지 않는다.

A/B/C/D는 동일 입력·교정·지도·평가 시각으로 비교한다.
각 모델의 상태·시간창을 독립적으로 유지한다.
이후 WLS와 보조기능은 각 역할에 맞는 추가 비교군으로 둔다.
B는 정지 실측에서 개선됐지만 반전 합성에서 불리한 기록이 있다.
정지 오차와 동적 지연을 함께 평가한다.
D가 항상 우수하다고 전제하지 않는다.

비교 지표는 중앙값·RMS·p95·최대 오차,
출력 가능 비율·지연·급변·단절 후 복구 시간이다.
같은 시각의 공통 표본 비교와 전체 가용률을 함께 보고한다.

- M08: C/D 후보 결합이면 품질·순위 가중을 비교한다.
  공유 거리를 사용한 후보를 독립 측정으로 취급하지 않는다.
- M09: 앵커별 오차 분산이 준비되면 거리 가중 WLS를 비교한다.
  위치 후보 가중과 거리 가중은 별개의 변경으로 기록한다.
- M10: 불량 배치·조건수 문제면 추가 품질 판정을 비교한다.
  계산에 필수인 rank 검사 등은 원래대로 유지한다.
- M11: 잔차 이상 검출부터 시험한다.
  앵커 제외·재계산은 별도 실험이며 기본으로 켜지 않는다.
- M05: B H80의 단절 후 복구 구간에서 Q_S10을 비교한다.
  유효한 높이 입력 등 명세의 실행 조건을 먼저 만족한다.
  A/C/D에 공통으로 붙이는 필터로 취급하지 않는다.
- M13: 흔들림이 문제면 관측 평활을 비교한다.
  정지 개선뿐 아니라 급정지·반전의 지연도 확인한다.
  PX4 상태를 되먹이는 별도 비행용 추정기를 만들지 않는다.
- M14: 최종 위치 급변이면 위치 게이트를 비교한다.
- M12: RF/CIR 진단 자료와 교정 근거가 있을 때 시험한다.
  현재 가상 RAW만으로 해당 정보가 있다고 가정하지 않는다.
- M15/M16: LiDAR·GNSS 보조는 입력·정렬을 갖춘 별도 비교군이다.
  센서를 추가한 결과를 기존 UWB 계산만의 개선으로 집계하지 않는다.

직접 거리 UKF는 기본 계산을 바꾸는 별도 후보다.
기존 모델 뒤에 보조 필터 하나를 붙인 것으로 취급하지 않는다.
D의 교점 생성 정책 변경도 별도 variant로 관리한다.
입력이 없는 기능은 미실시 사유를 적고 가능한 시험을 계속한다.

[한 시행의 순서]

1) 오차 원인과 이번에 해결할 문제를 기록한다.
2) 추가할 기능 하나 또는 조정할 파라미터 하나를 정한다.
3) 예상 개선 지표·회귀 확인 지표·비교 조건을 먼저 적는다.
4) 이전 채택 구성에서 해당 변경만 적용한다.
5) 같은 자료로 A, 이전 채택 구성, 새 구성을 비교한다.
6) 정지·다점·이동·정지·반전·단절/복구 결과를 확인한다.
7) 채택·기각·보류 중 하나와 이유를 기록한다.
8) 채택한 구성에만 다음 기능을 더한다.

최신 시도와 가장 좋은 채택 구성을 따로 보관한다.
오차가 줄어도 가용률·지연 기준을 위반하면 채택하지 않는다.
필요하면 추가한 기능을 다시 꺼서 기여를 확인한다.
파라미터 탐색도 값마다 시행 ID와 결과를 남긴다.
여러 기능의 상호작용 비교는 단독 효과 확인 뒤 별도 시행한다.

7cm 미만을 만족할 때까지 가설·구현·비교·기록을 반복한다.
조정 자료에서 목표에 도달하면 설정을 잠근다.
미사용 위치·궤적·시드의 독립 평가로 다시 확인한다.
평가 결과를 보고 수정하면 그 자료는 이후 조정 자료로 표시한다.
최종 판정에는 새로운 독립 평가 자료를 사용한다.

반복해도 목표에 못 미치면 현재 최선과 남은 원인을 기록한다.
교정·앵커 지도·높이·시각 오차 등 입력 한계도 검토한다.
기능 추가만으로 해결된다고 단정하지 않는다.
필요한 입력 보완이나 다른 기본 모델의 시험으로 이어간다.
현재 조건에서 진행할 수 없다면 목표 미달과 필요한 조건을 알린다.
7cm를 달성한 것처럼 종료하거나 기준을 사후 완화하지 않는다.

목표 이동 연결의 준비·제한된 진단 시험은 함께 진행할 수 있다.
측위 목표 달성과 목표 이동 검증의 완료 여부는 따로 기록한다.

④ 수평 관측의 PX4 융합

WSL에 ROS2가 없다는 조건과 기존 브리지를 함께 검토한다.
MAVLink 직접 연결 또는 ROS2/MAVROS 경로를 선택한다.
중복 송신 없이 가장 작은 실행 구성을 마련한다.
선택 이유·의존성·메시지·좌표계·단위를 설명한다.
사용자 PX4 버전의 코드와 공식 문서로 API를 확인한다.

검증 전 관측 연결은 Shadow로 기록한다.
검증 조건을 갖추면 SITL 전용 설정에서 연결을 진행한다.
실제 기체의 송신·설정은 변경하지 않는다.
이 프롬프트는 시뮬레이션 구현과 시험 진행을 요청하는 것이다.
과거 보류 기록을 읽되 이번 요청의 범위를 반영한다.

수신 메시지 수만으로 융합 성공을 판정하지 않는다.
EKF 사용 상태·관측 기각·innovation·위치 reset을 확인한다.
측정하지 않은 높이·방향을 유효 관측으로 보내지 않는다.
GNSS와 광학흐름 등 다른 위치원의 사용 상태도 기록한다.

⑤ 한 목표로 이동·정지·유지

현재 목표 송신·도착 판단·비행 명령 구현을 먼저 확인한다.
부족한 부분만 SITL 어댑터로 연결한다.
기존 데모 모니터의 상태 출력만으로 자동 비행을 완료 처리하지 않는다.
데모의 벽시계·위치 입력을 그대로 SITL에 붙이지 않는다.

처음에는 앵커 내부에서 짧은 축별 이동을 시험한다.
이동 거리·속도·시간은 실행 전에 설정 파일로 기록한다.
현재 모델과 오차를 보고 보수적인 시험값을 선택한다.
제어 게인과 위치계산 방법은 동시에 바꾸지 않는다.
A로 먼저 이동을 검증하고 선정 후보로 같은 목표 시험을 반복한다.
실제 비행 궤적은 달라질 수 있으므로 같은 조건과 시드를 기록한다.
파일 비교의 동일 입력 시험과 비행 피드백 시험을 구분한다.

도착 조건은 다음을 모두 만족해야 한다.
- 목표와 PX4 추정 위치의 수평 거리 조건.
- 수평 속도 조건.
- 위 조건의 연속 유지시간.
- 입력 신선도와 PX4 위치·속도 유효성.

도착 반경 진입·이탈에 서로 다른 기준을 둘 수 있다.
목표를 빠르게 통과한 것을 도착으로 판정하지 않는다.
판정은 최신 PX4 위치·속도를 사용한다.
독립 평가기는 Gazebo 정답으로 실제 도착 여부를 별도 확인한다.

⑥ 순회·복귀·반복과 이상 상황

한 목표 시험 뒤 여러 목표를 순서대로 연결한다.
각 목표에서 정지·유지한 뒤 다음 목표를 보낸다.
출발점 복귀와 착륙까지 기록한다.
다른 난수 조건과 반복 실행에서 재현성을 확인한다.

다음 실패를 구분해서 주입한다.
- UWB 단절·지속 편향·갑작스러운 위치 변화.
- 오래된 측정·시각 역행.
- 목표 명령 스트림 단절.
- PX4 위치 무효·원점 또는 방향 reset.

UWB 단절과 PX4 위치 무효를 같은 상태로 취급하지 않는다.
유효한 PX4 위치가 남아 있는지에 따라 대응을 정의한다.
위치가 무효한데 위치 유지 명령만 보내면 해결된다고 가정하지 않는다.
SITL에서 정한 대응과 실제 모드·움직임을 로그로 대조한다.
복구 시 새 관측의 연속성을 확인하고 도착 판정을 다시 시작한다.

7. 시험 전에 정할 평가 기준

7cm 목표는 UWB 보정 결과의 수평 측위 오차에 적용한다.
PX4 목표 추종 오차나 위치 후보들의 산포로 대신하지 않는다.
안테나 또는 변환한 기준점의 추정과 정답을 같은 기준으로 비교한다.

e_xy(t) = sqrt((x_est(t)-x_truth(t))^2
               +(y_est(t)-y_truth(t))^2)

사용자가 최대값·p95·RMSE 중 지표를 지정하지 않았다.
따라서 이 초안의 엄격한 기본안은 다음과 같다.
“사전에 정한 필수 평가 구간에서 최대 e_xy < 0.07m”.
이것은 이번에 제안한 판정 기준임을 명시한다.
평균·RMSE·p95만 7cm 미만이면 전체 목표 달성으로 표시하지 않는다.
반올림한 cm 값이 아닌 원래 m 값으로 판정한다.

모든 시행에서 7cm 초과·동일 표본 수와 비율도 기록한다.
정상 수신·이동·복구 등 시나리오별 통계를 분리한다.
미출력·거부·실패·이전 값 유지·예측 전용은 별도로 센다.
새 관측이 없는 틱을 오차 0 또는 7cm 이내로 처리하지 않는다.
게이트로 나쁜 출력을 버린 결과만 보고 달성으로 판정하지 않는다.
최소 새 관측 가용률·최대 지연·최대 연속 공백도 함께 통과해야 한다.
이 기준들이 미정이면 선정과 최종 달성 판정은 보류한다.

7cm 판정 구간·평가 격자·워밍업·반복 횟수를 시험 전에 기록한다.
의도한 단절 구간은 정확도 평가와 고장 대응 평가를 구분한다.
단절·복구·워밍업을 포함한 전체 구간 결과도 함께 공개한다.
사후에 불리한 구간을 제외하거나 잡음을 낮춰 달성하지 않는다.
시나리오별 결과를 평균해 실패한 필수 시나리오를 감추지 않는다.
달성은 시험한 조건·시간·반복 범위에 한정한다.
모든 환경·실기에서 항상 7cm 미만이라는 보장은 아니다.

목표 좌표·속도·도착 반경·속도 한계·유지시간,
입력 만료시간·반복 횟수를 먼저 설정 파일에 적는다.
현재 데모 기본값은 참고만 하며 비행 검증값으로 간주하지 않는다.
미정인 값은 근거가 있는 SITL 초기값을 정하고 시험값으로 표시한다.
처음부터 실기 성능 보장치로 해석하지 않는다.

좌표계·시각·기준점을 맞춘 뒤 세 오차를 분리한다.

측위 오차:
  UWB 관측 또는 PX4 추정과 Gazebo 정답의 차이.

추정 위치 기준 추종 오차:
  PX4 추정 위치와 시간별 목표의 차이.

실제 도착·이동 오차:
  Gazebo 정답 위치와 시간별 목표의 차이.

도착시간·초과 이동·유지 중 이탈·실패 횟수도 기록한다.
PX4 추정값과 목표가 가깝다는 이유만으로 절대 정확도를 판정하지 않는다.
UWB 융합을 확인하고 다른 위치원의 영향을 밝혀야 한다.
보조 위치원만으로 유지된 비행을 UWB 검증으로 보고하지 않는다.
필요하면 GNSS 수평 융합을 제외한 SITL 조건을 별도로 만든다.
광학흐름 등 유지한 보조 관측과 UWB의 기여를 함께 기록한다.

완료는 다음 세 항목으로 따로 판정한다.
- 측위 완료: 독립 다점·동적 평가에서 7cm와 가용률·지연 기준 통과.
- 연결 완료: 좌표·시각·실시간 관측·EKF 융합 검증 통과.
- 이동 완료: 목표 이동·정지·순회·복귀·이상 대응 반복 통과.

일부만 통과하면 통과 범위와 남은 항목을 구분한다.

8. 진행 방식과 산출물

[시행별 기록]

성공한 결과뿐 아니라 악화·실행 실패·중단한 시행도 기록한다.
시행 ID는 iter_0001처럼 부여하고 재사용하지 않는다.
run_id와 parent_run_id로 어떤 구성에서 갈라졌는지 연결한다.
실행 전에 입력·가설·설정을 기록하고 종료 후 결과를 추가한다.
재시도는 새 ID로 남긴다. 원본과 이전 기록은 덮어쓰지 않는다.

각 시행에 반드시 남길 내용:
- 날짜·기본 모델·변형 이름·활성 보조기능·연결 순서.
- 추가/제거 기능 또는 파라미터의 변경 전후 값.
- 해결할 문제·예상 효과·해당 보조기능 명세 경로.
- 원본/정답 해시·지도·교정·장착·높이 출처.
- 코드 커밋·미커밋 변경 해시·실행 환경·재현 명령·시드.
- 교정/조정/최종 평가 자료 구분과 시나리오별 평가 범위.
- 중앙값·RMS·p95·최대 수평 오차·7cm 이상 표본 수/비율.
- 전체 새 관측 가용률·거부/누락·지연·최대 공백·복구 시간.
- 같은 틱의 A 대비·이전 채택 구성 대비 개선/악화량.
- 채택/기각/보류와 근거, 다음 시험, 7cm 판정 상태.
- 실행하지 못한 경우 실패 지점·오류 원문·미실시 항목.

시행별 디렉터리의 기본 산출물:
- manifest.json: 입력·버전·설정·가설·판정 기준.
- input_index.json: 원본 RAW·ToF·자세·정답 파일 경로와 해시.
- results.jsonl: 시각별 후보·채택값·품질·판정 사유.
- metrics.json, scenario_metrics.csv: 전체·상황별 지표.
- failures.jsonl: 계산 실패·기각·누락과 이유.

WSL 명령은 작은 묶음으로 안내한다.

설치 재시작이나 반복적인 허락 요청으로 작업을 되돌리지 않는다.
실행 결과가 필요한 단계에서 추측으로 성공 처리하지 않는다.

각 기능 변경 후 관련 docs를 갱신한다.

구현·시험·문서 기록까지 끝난 범위를 완료로 보고한다.

먼저 아래 네 가지를 보여주고 시작해줘.
1) 기존 성과, 코드 존재, 실행 미검증을 나눈 상태표.
2) 목표 이동까지 실제로 빠진 모듈과 연결 관계.
3) 가상 UWB 기록을 확인할 첫 WSL 명령 묶음.
4) A/B/C/D 선정·첫 보조기능 비교 계획과 시행 기록 양식.

후속 요청으로 7cm 목표와 시행별 기록을 추가했다.
사용자가 오차 지표를 지정하지 않아 최대값을 초안 기준으로 제안했다.

이번에 제어 코드·설정·장비 파일은 변경하지 않았다.
현재 단계는 프롬프트 개정이며 비행 완료 판정은 바꾸지 않는다.
