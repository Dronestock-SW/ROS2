# 단일 태그 UWB·LoRa 재설계 기준
멀티태그 제거 후의 입력·출력과 책임을 정한다.
Tag B·앵커·companion의 새 계획을 작성할 때 읽는다.

## 최신 범위

**단일 태그가 측정을 시작하고 LoRa는 독립 동작한다.**
2026-10-15 후속 사용자 지시를 반영했다.
기존 앵커 보존을 전제로 한 40Hz 계획을 대체한다.
새 목표는 RAW 50Hz·20ms와 독립 LoRa 1Hz다.
이는 설계 목표이며 구현·실기기 검증은 미실시다.

| 대상 | 새 기준 |
|---|---|
| 태그 | Tag B 한 대, ID 6 |
| 태그 역할 | 네 앵커 거리·원본 시각·유효성 전달 |
| 앵커 역할 | A1~A4 모두 태그 요청에 응답 |
| A1 변경 | 주기적 SYNC·ID별 슬롯 수락 제거 |
| companion | 시간 정합·위치·공분산·PX4 전달 |
| PX4 | 상태 추정·고도·자세·비행 제어 |
| LoRa | 자체 타이머 1Hz, UWB 상태와 독립 |
| 식별 | 기존 ID·순번·boot_id 재사용, 측정 session 의미는 새 schema에 명시 |
| 좌표(m) | A1=(0,0,.15), A2=(6.3,0,.15), A3=(0,4.6,.15), A4=(6.3,4.6,.15) |

현재 장치는 여전히 이전 TDMA40 펌웨어로 동작한다.
이번에 장치·FC 설정·운영 서비스는 변경하지 않았다.
새 설계는 같은 앵커를 여러 태그가 쓰는 기능을 포함하지 않는다.

[현재 좌표](../reference/uwb_anchor_layout.md)를 사용한다.
0.15m는 앵커 높이이며 비행 고도가 아니다.
장착·거리 편향·위치 정확도 교정은 별도다.

## 구조와 제거 대상

**A1이 주는 시간표 대신 태그 자체 주기로 측정한다.**

```text
태그 단조 시계 → A1 → A2 → A3 → A4 → 완결된 RAW
                                       ↓
                    companion 시간 정합·위치 → PX4

companion pose → 태그 최신값 보관 → 독립 LoRa 1Hz → 지상국
지상국 하향 → LoRa → USB lora_rx → companion
```

| 제거 | 유지 |
|---|---|
| A/B 교대·멀티태그 가입·슬롯 대기 | ID·주소·순번·패킷 검증 |
| A1 주기적 SYNC·태그 SYNC 대기 | DS-TWR의 무선 왕복 시각 계산 |
| sf_seq·schedule_id의 새 경로 의존 | protocol version·측정 세션 식별 |
| RAW/TDMA 별도 메시지 대기 | 한 프레임의 유효성·시간·식별 |
| LoRa 교대 회차·SYNC 승인 | 기존 무선 설정·지상국 메시지 |
| 태그의 XY 계산·시간 필터 | 원본 거리·실패 코드 |
| 화면·상세 로그의 측정 경로 점유 | 저우선순위 표시·RAM 경량 진단 |

A1에는 실제 수신 시간 창이 있다.
태그만 고쳐서는 새 구조가 완성되지 않는다.
A1을 응답기로 바꾸는 작업을 계획 범위에 포함한다.
A2~A4도 주소만 다른 공통 응답기로 정리한다.
실제 업로드는 후속 구현 작업에서 진행한다.

검증된 드라이버와 radiofix3 하드웨어 처리는 보존한다.
전체 재작성은 라이브러리를 모두 다시 쓰는 뜻이 아니다.
새 기능에 맞춰 스케줄과 책임을 단순화한다.

## 주기와 성능 판정

**RAW 50Hz를 목표로 여유 있는 시간 예산을 만든다.**

기존 정상 4거리 교환 중앙값은 9.424ms였다.
p95는 9.583ms, 관측 최대는 9.728ms였다.
20ms에서 나머지 시간을 재시도·정리·서비스에 둔다.
단순 역수 약 106Hz를 성능 보장으로 사용하지 않는다.

| 초기 예산안 | 목표 |
|---|---|
| 네 앵커 첫 측정 | 최대 약 3ms씩, 합계 약 12ms |
| 재시도 | 첫 측정 뒤 남은 시간에 최대 1회, 약 3.2ms 검토 |
| UWB 완료 | 오버헤드를 포함해 18ms 이내 목표 |
| 주기 시작 | 20ms 절대 단조 시각 기준 |
| USB·LoRa | 비동기 처리, 전체 송신 완료를 기다리지 않음 |

현재 timeout·SPI·앵커 종료 대기로 예산을 검산한다.
기한을 놓치면 누락을 기록하고 다음 회차로 이동한다.
성공률과 지연이 나쁘면 같은 조건의 40Hz와 비교한다.
검증된 고정 주기를 운영값으로 채택한다.
50Hz 달성에 필요한 검증은 아직 하지 않았다.

| 지표 | 판정 원칙 |
|---|---|
| RAW | 새 측정 시도 수와 유효 4거리 수를 별도로 집계 |
| companion | 새 유효 위치가 생기면 즉시 전달 |
| PX4 | 송신·수용·실제 융합을 구분 |
| 지연 | 원본 나이·동기 오차·전송 지연·공백을 구분 |
| 초기 지상 시험 | 정상 1초 창마다 새 유효 위치 30개 이상 목표 |
| 공백 조사 | 정상 조건 100ms 이상이면 원인 분석 후 재시험 |

공식 PX4 외부 위치 안내는 30~50Hz다.
공분산이 있는 경우 30Hz를 제시한다.
RAW 자체에 고정 Hz를 강제하는 뜻이 아니다.
200/400ms EV 조건은 정상 지연 예산이 아니다.
Offboard 2Hz 생존 신호는 별도 경로다.
지상 시험 제안은 비행 안전 보증이 아니다.

근거:
[PX4 공식 안내](https://docs.px4.io/main/en/ros/external_position_estimation),
[실제 배포 소스 조사](../report/evidence/esp32_raw_rebuild_20261015/px4_ev_source_readback.json),
[이전 통신 조사](../report/esp32_tag_b_rate_audit_20261015.md).

## 시간과 RAW

**실제 측정 시각을 보존해 companion 시간축에 한 번 대응시킨다.**

| 대상 | 기준 |
|---|---|
| RAW | 간결한 JSONL, 921600 baud, 새 schema |
| 식별 | ID·순번·boot_id·측정 session |
| 거리 | A1~A4 사선거리(m), 실패는 null·무효 비트 |
| 시각 | cycle 시작·끝·앵커별 원본 측정 시각 |
| 시각 대응 | ESP32↔companion 양방향 교환, 속도 차이·이상치·만료 처리 |
| 시각 의미 | DS-TWR 대표 시점과 RF↔MCU 대응 오차 명시 |
| 큐 | 고정 상한·만료·최신 완결 프레임 우선 |
| 진단 | 작은 실패 코드·누적 카운터·고정 RAM 버퍼 |

A1에서 받던 session을 태그 세션으로 바꾸면 명시한다.
원본 시각과 변환 세대는 보존한다.
변환된 값에 ClockMap을 다시 적용하지 않는다.
DW 시계를 companion 시각으로 강제로 변경하지 않는다.
수신 시각을 실제 측정 시각으로 바꾸지 않는다.

RAW/TDMA 대기는 새 모드에서 제거한다.
시간·중복·역순·세션 검사는 새 모드에서도 유지한다.
이전 거리를 현재 값으로 채우지 않는다.
부분 관측 사용 여부는 companion이 판단한다.
이미 전송 중인 JSON 줄은 중간에 교체하지 않는다.

## 독립 LoRa 계약

**무선·메시지를 보존하고 UWB SYNC 의존을 제거한다.**

[사용자 명세](../report/evidence/esp32_raw_rebuild_20261015/LORA_TAG_REBUILD.md)는
무선 설정·핀·메시지·기존 복구 처리의 근거다.
이번 사용자 지시가 그 문서의 교대 일정 부분을 대체한다.

| 유지 | 대체·개선 |
|---|---|
| 915MHz, BW125kHz, SF7, CR4/5, 10dBm | 자체 단조 타이머 1Hz |
| private 0x1424, CRC, 최대 255바이트 | SYNC·sf_seq 위상·24.5ms 승인 제거 |
| jetson_pose·ACK·drone.status | 원본 pose 나이·중복·역순 검사 |
| lora_rx·RSSI·SNR | UWB 고장 중에도 서비스 유지 |
| SPI·TCXO·RF 스위치·IRQ·타이머 처리 | UWB와 LoRa의 복구를 분리 |

LoRa 자체가 준비됐으면 상태 전송을 계속 시도한다.
유효한 최신 companion pose가 없으면 fix:false다.
UWB가 끊겼다고 옛 좌표를 유효하게 되살리지 않는다.
500ms 표시 신선도를 비행 위치 지연 상한으로 쓰지 않는다.

약 399.616ms의 최대 길이 RF 송신도 비동기로 진행한다.
그 시간 동안 UWB 측정을 멈추지 않는다.
LoRa 송신 중에는 하향 수신을 보장하지 않는다.
송신 완료 뒤 RX 복귀와 수신 가능 창을 명시한다.

SPI는 드라이버 지원을 확인해 별도 호스트를 검토한다.
공유 시 단일 소유권과 최대 점유 시간을 정한다.
두 작업이 같은 전역 SPI를 동시에 조작하지 않는다.
UWB 중단과 LoRa 복구를 각각 독립 시험한다.

## 계획 산출물

**구현 전에 태그·앵커·companion 변경을 한 계약으로 정리한다.**

[최신 계획 프롬프트](../runbooks/esp32_tag_b_rewrite_plan_prompt_20261015.md)를 따른다.
20ms 예산·새 schema·상태 전이·시험 기준을 구체화한다.
원본 백업과 주소별 앵커 전환·복구 순서를 포함한다.
현재 Physical AI·제어 알고리즘을 새로 넣는 작업은 아니다.
새 펌웨어 구현·빌드·업로드·비행 시험은 미실시다.

후속 사용자 정정으로 실행 목표를 확대했다.
[실행 프롬프트](../runbooks/esp32_tag_b_rebuild_execution_prompt_20261015.md)는
구현·지상 실기기 시험·최종 ESP32 재설정까지 지시한다.
이 문서는 기술 기준이며 계획 단계에서 멈추라는 뜻이 아니다.
이후 실행 요청으로 상태 조회와 빌드 환경을 준비했다.
앵커 기록용 USB 확인 중 사용자가 중단을 요청했다.
새 펌웨어 코드·장치·운영 서비스는 변경하지 않았다.
LoRa 지상국 실물 시험은 보류했다.
재개 준비와 다른 장소의 시험 안내는 실행 프롬프트를 따른다.
