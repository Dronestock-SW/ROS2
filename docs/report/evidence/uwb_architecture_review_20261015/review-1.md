# 1차 검토: 핵심 반론과 개선안

표기 기준은 다음과 같습니다.
- **[사실]**: 제공된 기록과 소스에서 확인된 내용입니다.
- **[추정]**: 근거는 있으나 아직 검증되지 않은 판단입니다.
- **[제안]**: 설계 변경안입니다.

이번 범위는 검토만이며, 재생·비행·설정 변경 언급은 모두 향후 작업 후보입니다.

## A. 최우선 반론: 문제의 중심이 GC·지연보다 UWB 기하에 있을 가능성

**[사실]**
- seq4572는 A1+A2 = 6.103m로, 설정상 앵커 간격 6.3m보다 짧습니다.
- 1m/s 이동을 허용해도 19.5cm가 부족합니다.
- 20묶음의 RMS 하한은 6.8~9.9cm이고, 앵커 높이가 0.15m인 세션과 2.2m인 BOM이 공존합니다.

**[추정, 논리적으로 강함]**
- NLOS는 경로를 늘리는 쪽으로만 작용합니다. 따라서 두 거리의 합이 기준선보다 짧은 현상은 NLOS로 설명하기 어렵습니다.
- 남는 후보는 네 가지입니다.
  1. 실제 앵커 간격이 설정과 다름 (survey 미완료)
  2. 음(−)의 거리 편향 (antenna delay 보정 오류)
  3. 앵커 ID와 좌표의 매핑 오류
  4. 단위·전처리 오류
- 이 중 무엇이든 "애매한 앵커조합 3건, 높이 일관후보 없음 9건" 거부와 21개 부분프레임 잔차 7.6~23.3cm를 함께 설명할 수 있습니다.
- 그렇다면 ClockMap, cache, C++ 분리를 아무리 다듬어도 10cm 목표에는 도달하지 못합니다.

**[추정]** 앵커 4개가 모두 0.15m 높이의 거의 같은 평면에 있으면 두 가지 문제가 생깁니다.
- 태그가 그 평면 근처일 때 Z 관측성이 나쁘고, 위/아래 거울해 모호성이 생깁니다.
- 바닥 반사와 사람·기체에 의한 차폐에도 취약합니다.

**[제안] 우선순위 1**
1. 세션별 `anchor_geometry.yaml`(좌표, 높이, ID, antenna delay, survey 방법·일자)을 만들고, 그 해시를 모든 로그 헤더와 bridge 시작 조건에 고정합니다. 해시가 불일치하면 발행을 거부합니다.
2. 향후 작업 후보: 독립 측량(줄자·레이저 거리계로 앵커 간 6쌍 모두), 정지 태그로 앵커별 거리 편향 추정, 비공면 배치(예: 2개 고·2개 저) 비교.
3. 합격기준 초안: 정지 상태에서 앵커쌍 삼각부등식 위반 0건, 앵커별 편향 추정치 ±3cm 이내. 이 수치는 예시이며 확정값이 아닙니다.

## B. 재획득 시점의 위험이 정지(FREEZE)보다 큽니다

**[사실]**
- 송신 mask 2552는 위치와 yaw만 사용하며, PX4 MPC가 속도를 생성합니다.
- MPC_XY_P = 0.95/s, MPC_XY_VEL_MAX = 2.0m/s입니다.
- raw offboard 경로에는 MPC_ACC_HOR/JERK가 적용되지 않습니다.
- `stream`은 가속도·jerk 없이 0.25×dt씩 전진합니다.
- framejump 판정은 0.3m 초과 시 abort입니다.

**[추정]** 흐름은 다음과 같이 예상됩니다.
1. UWB 공백 중 flow/LiDAR 드리프트가 누적됩니다. SIH 기준 18.6cm가 이미 관측됐습니다.
2. 재획득 시 EKF가 위치를 보정합니다.
3. 추정 위치가 점프하면 위치 오차가 그대로 P항 속도로 변환됩니다.
4. 0.3m를 넘으면 framejump LAND로 이어집니다.

결국 "실제 드리프트 교정"이 "프레임 점프 안전정지"로 오분류됩니다. 사용자 요구(재획득 후 재개)와 현재 구현이 정면으로 충돌합니다.

**[제안]**
1. **재획득 상태 전용 판정을 둡니다.** HOLD 진입 시점부터 예상 드리프트 상한 D_pred를 누적합니다(경과시간×flow 드리프트율 + 거리 오차 예산).
2. 재획득 후 보정량은 `vehicle_local_position.delta_xy` / `xy_reset_counter` 또는 EV innovation으로 판단합니다.
   - 보정량 ≤ D_pred: 정상 교정으로 처리합니다.
   - 보정량 > D_pred: 이상으로 보고 abort 후보로 분류합니다.
3. 고정 0.3m 임계는 HOLD가 아닌 정상 비행 상태에서만 적용합니다.
4. **재진입 궤적을 재생성합니다.** 재획득과 융합 확인 후에는 `stream`을 과거 지점에서 이어가지 않습니다. 대신:
   - **현재 추정 위치**를 새 시작점으로 재시드합니다.
   - 고정 UWB 지도상의 원래 물리 목적지까지 가속도·jerk 제한 궤적을 companion에서 생성합니다.
   - 위치와 함께 velocity feedforward를 보내는 mask로 변경하는 것을 검토합니다. 이 경우 PX4 측 속도 피드포워드 처리를 d6f12ad 소스로 확인해야 합니다.
5. **[제안·설정 후보]** MPC_XY_VEL_MAX를 2.0에서 임무 상한과 정합되는 값(예: 0.5~0.75)으로 낮추는 것을 검토합니다.
   - 하드 물리 상계는 아니지만, 재획득 오차를 P항이 키우는 경로의 상한을 직접 줄입니다.
   - PID 게인을 낮추는 것보다 부작용이 작습니다.
   - 단, Position 모드 수동 조작 감각도 바뀌므로 수동 회수 시나리오와 함께 판단해야 합니다.

## C. 0.25s 관측 timeout과 "0.7초 일률 실패 아님" 사이의 공백

**[사실]**
- UWB 0.25s 이상 공백이나 거부가 발생하면 hold로 전환됩니다.
- 도착 판정은 FC 15cm / UWB 25cm입니다.

**[반론]** "정지 후 대기"의 종료 조건이 정의되어 있지 않습니다. 무기한 hover를 막는 조건은 시간 하나가 아니라 아래 세 가지의 결합이어야 합니다.
- PX4 추정 신뢰도 (eph, flow 융합 활성 여부)
- 누적 드리프트 상한
- 배터리와 전체 임무시간

**[제안]** 상태기계를 명시합니다.

| 상태 | 진입/의미 | 종료/전이 조건 |
|---|---|---|
| NORMAL | 정상 비행 | — |
| BRAKE | jerk 제한 감속 | 정지 확인 시 HOLD |
| HOLD_DR | 추정 기반 위치 유지 | 아래 조건 중 하나라도 위반 시 FALLBACK |
| REACQ_CHECK | 재획득 검사 | 연속 N개 적격 관측과 융합 확인 시 REENTRY |
| REENTRY | 저속 재진입 | 정상 복귀 |
| FALLBACK | PX4 fallback | — |

HOLD_DR 유지 조건은 다음과 같습니다.
- `cs_opt_flow` 활성이고, flow 융합 `time_last_fuse`가 갱신 중이어야 합니다.
- eph < 임계여야 합니다.
- D_pred < (30cm − 정지거리 − 추종오차)여야 합니다.
- HOLD 누적시간 < T_max여야 합니다. 사용자 기준이 필요합니다.

또한 다음을 별도 요건으로 문서화합니다.
- 도착 판정 10cm 목표와 15/25cm 구현의 불일치
- 공백 중 허용 이탈(10cm가 아님)

SIH에서도 공백 중 18.6cm 이탈이 났으므로, 공백 중 10cm 유지는 현 구조에서 비현실적일 가능성이 큽니다 **[추정]**.

## D. 융합 확인 신호의 구체화

**[사실]** 입력이 중지된 뒤에도 `fused=True`가 남아 있었습니다.

**[제안]** 임무 재개 조건으로 `estimator_aid_src_ev_pos`를 사용합니다.
- `time_last_fuse`가 증가 중인지 확인합니다.
- `innovation_rejected`가 연속 false인지 확인합니다.
- `estimator_status_flags.cs_ev_pos`가 true인지 확인합니다.
- 위 세 가지를 **현재 시각 기준 신선도와 함께** AND로 판정합니다.

토픽명과 필드는 d6f12ad 기준으로 재확인이 필요합니다.

## E. 누락된 PX4 설정 검토 항목

아래는 모두 **[제안]** 이며, 확인 전 변경을 금지합니다.

- **EKF2_EV_DELAY**
  - 측정된 [source event → FC receive] 지연의 중앙값과 일치해야 합니다.
  - 현재 값이 목록에 없습니다.
  - 지연 편향은 0.25m/s에서 100ms당 2.5cm의 고정 오차가 됩니다.
- **EKF2_EV_GATE**
  - 재획득 시 정당한 대형 교정이 게이트에 반복 거부되는지 확인해야 합니다.
  - 그러다 timeout 기반 reset으로 넘어가는지도 확인 대상입니다. 이는 "700ms 거부 후 EV 재시작 XY reset" 사건과 연결될 수 있는 경로로, 소스 확인이 필요합니다 **[추정]**.
- **EKF2_EV_NOISE_MD / EKF2_EVP_NOISE**
  - companion 공분산을 쓰는지 확인합니다.
  - 상관된 H80 중첩 출력을 독립 관측으로 넣으면 과신이 생깁니다. 출력 주기 대비 실효 독립 표본 수로 분산을 부풀리는 방안을 검토합니다.
- **COM_POS_FS_EPH, EKF2_NOAID_TOUT**
  - HOLD_DR 종료 조건과 수치적으로 정합해야 합니다.
- **EKF2_HGT_REF / EKF2_RNG_CTRL**
  - EV Z와 ToF 중 높이 기준을 명시합니다.
  - 앵커가 저고도 공면이라면 EV Z를 높이 기준으로 쓰지 않는 쪽이 타당할 가능성이 큽니다 **[추정]**.
- **EKF2_EV_POS_Z (−0.10 vs −0.07)**
  - 태그 레버암 보정을 companion과 FC 중 **한 곳에서만** 수행하는지 소스로 먼저 확정합니다.
  - 기준점이 ToF 기준 0.15와 FC 기준 0.07로 두 개이므로, 단일 기준점 문서가 필요합니다.

## F. 과도한 재설계로 보이는 부분

- **전체 항법경로 C++ 프로세스 분리**
  - GC 두 사건은 150ms 안에 발행되었습니다.
  - 반복 거부의 주원인은 기하·품질이었습니다.
  - 따라서 지금 단계에서 분리의 효익은 근거가 약합니다.
  - 더 작은 대안: 초기화 후 `gc.freeze()`와 gen2 임계 조정. 이는 GC를 끄는 것과 다르며, 별도 계측이 필요합니다 **[제안]**.
- **ClockMap 보존 후보의 운영 이식**
  - 출력공백 개선은 확인됐지만 실제 FC 융합 검증이 없습니다.
  - A항(기하) 해결 전에 이식하면 효과 분리가 불가능합니다.
- **세 코드 기준선(0110da8 / a029476 / 563960e) 병행**
  - 이식 순서보다 **비교 매트릭스(기능 × 기준선 × 검증 수준)**를 먼저 만드는 것이 비용이 작습니다.

## G. 정지거리 식에 대한 보정

**[사실]** 22.5~19.4cm(0.25m/s)와 47.5cm(0.5m/s)는 설계 비교용입니다.

**[반론]** 두 가지가 빠져 있습니다.
1. **재획득 교정 점프 자체.**
   - 추정 위치가 D만큼 이동하면, 실제 기체는 정지 상태에서 D만큼 "새 오차"를 갖고 출발합니다.
   - 30cm 여유 계산에 D_pred를 항으로 추가해야 합니다.
2. **현재 실속도 상한 근거.**
   - VEL_MAX 2.0인 상태에서는 0.25를 가정할 근거가 없습니다.
   - B-5의 설정 정합, 또는 실측 속도 로그가 선행되어야 합니다.

## 1차 결론: 우선순위 초안

1. **앵커 기하·거리편향 확정 + geometry hash 고정.** 다른 모든 정확도 논의의 전제입니다.
2. **속도 상한·레버암·EV_DELAY·높이기준 명세 정합.** 문서와 소스를 대조하며, 값 변경은 이후입니다.
3. **HOLD_DR / REACQ / REENTRY 상태기계**
   - framejump 판정을 HOLD 문맥과 D_pred 기반으로 수정합니다.
   - 재진입 궤적을 재시드하고 jerk 제한을 둡니다.
4. **융합 확인 신호 정의** (D항)
5. 그 다음 ClockMap 분리 이식
6. C++ 분리는 측정 근거가 생길 때만 진행합니다.

## 2차를 위해 필요한 결정사항

- 공백 중 허용 이탈과 HOLD 최대시간 T_max
- 실제 운용 앵커 배치를 0.15m와 2.2m 중 무엇으로 할지
- 레버암 보정의 소유 위치(companion 또는 FC)
- velocity feedforward mask 변경 수용 여부

외부 실기 인증은 없으며, 위 판단은 제공 자료에 근거한 기술 검토입니다.
