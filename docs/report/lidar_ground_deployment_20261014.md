# LiDAR 통합본 배치와 지상 융합 확인
2026-10-14 통합본 배치·실측 시험 기록이다.
이륙 전 남은 FC 제약을 확인할 때 읽는다.

## 결론

이 문서는 R2 설치본에서 수행한 첫 지상 시험이다.
후속 수정은 [R3 독립 융합 후보](lidar_independent_aiding_20261014.md)에 기록했다.
R3의 실제 설치·융합은 아직 수행하지 않았다.

**FC 수신은 확인했지만 실제 EKF 융합은 0회다.**
설치된 PX4는 다른 수평 보조를 먼저 요구한다.
LiDAR만으로 수평 보조를 시작하지 못한다.
UWB 복구 전 호버링의 실기 조건은 미충족이다.
비행용 LiDAR 설정과 임무 실행은 보류했다.

통합 커밋 `19cdb8b`를 새 Jetson 경로에 배치했다.
Python 패키지 4개를 빌드했다.
검증한 C++ 실행기와 의존 라이브러리를 배치했다.
기존 실행 파일·서비스·원본은 보존했다.
기존 센서 서비스의 실행 경로 전환은 하지 않았다.

## 어제 회전 기록의 재분석

4m 범위 제한이 첫 기록의 불일치에 영향을 줬다.
같은 RAW에 4·8·12m 범위를 적용했다.
IMU 공백·양방향 정합 검사는 유지했다.
실제 드라이버 범위와 이륙 예제는 12m다.

| 기록 | 범위 | 정합 회전 상관 | 공통 정합 쌍 | 보정 후 시간차 후보 |
|---|---:|---:|---:|---:|
| 회전 1 | 4m | −0.413 | 37 | −45ms |
| 회전 1 | 8m | 0.994 | 84 | +5ms |
| 회전 1 | 12m | 0.994 | 92 | 0ms |
| 회전 2 | 4m | 0.952 | 24 | −10ms |
| 회전 2 | 8m | 0.995 | 56 | −10ms |
| 회전 2 | 12m | 0.996 | 64 | −5ms |

범위마다 정합에 남은 쌍은 서로 다르다.
상관을 위치 정확도로 해석하지 않는다.
12m 두 기록의 후보 차이는 5ms다.
첫 기록 재표집 구간은 −15~+5ms다.
두 번째 구간은 −15~0ms다.
재표집 구간은 체계적 오차 보증값이 아니다.
원래 IMU 최대 공백 192ms·338ms도 남아 있다.
공백에 걸친 정합은 기존 검사로 제외했다.

지상 전용 후보에 −5ms를 사용했다.
20ms 불확실성은 공학적 여유값으로 표시했다.
실측으로 보증한 오차 상한이 아니다.
새 수동 회전은 사용자가 현장에 없어 미실시다.
공중 시각 검증·독립 이동 정확도는 미완료다.

원본 두 파일의 SHA256을 대조했다.
PC 복사본과 Jetson 원본이 일치했다.
분석 도구에 `--range-max-m`를 추가했다.
기본 4m는 어제 분석을 그대로 재현한다.

## 지상 전용 입력

`ground_static`은 현재 높이의 지상 시험 전용이다.
상승 구간의 수직 구조물을 확인했다고 주장하지 않는다.
최대 60초의 명시적 실행 시간이 필요하다.
매 송신 직전 DISARM·지상·상태 나이를 확인한다.
ARM이 관측되면 같은 프로세스에서 송신을 재개하지 않는다.
이유: 시험 설정이 비행 중 입력으로 이어지면 안 된다.
이륙 실행기는 이 정책을 준비 조건에서 거부한다.

장착·수평면·시각 참조 검사는 유지했다.
스캔 정합·IMU 공백·기울기·관측 나이도 검사했다.
수직 속도와 높이는 계속 미관측이다.
`vz=0`이나 고정 높이를 생성하지 않았다.
현재 ToF 2cm는 선언 최소거리 10cm보다 작다.
수평 지상 관측에는 ToF 높이 환산이 필요하지 않다.

## 실제 융합을 막은 조건

현재 보조 속도 경로에는 독립 시작 조건이 없다.
설치 펌웨어의 기반 커밋은 아래와 같다.
`d6f12ad1c4f70ad3230afd7d86e971421e02fef4`

`src/modules/ekf2/EKF/aid_sources/auxvel/auxvel_fusion.cpp`
51–52행은 다음 조건을 사용한다.

```cpp
if (isHorizontalAidingActive()) {
    fuseHorizontalVelocity(_aid_src_aux_vel);
}
```

저장한 하드웨어 패치도 이 함수를 바꾸지 않는다.
파라미터 설명에 같은 선행 조건을 명시한다.
과거 높이 공백 SIH는 UWB XY 보조를 계속 유지했다.
그 결과를 LiDAR 단독 시작의 근거로 쓸 수 없다.

현재 FC에서 EV·GNSS·광류 수평 보조는 꺼져 있었다.
UWB USB heartbeat는 들어왔다.
그러나 거리 cycle과 B_TF XY는 없었다.
이를 UWB 안정화 시간이 길다고만 해석하지 않는다.
현재 원시 거리 입력이 없는 상태다.
앵커 전원·무선 동기 부재의 원인은 미확인이다.
가상 UWB나 관측 0값으로 융합 조건을 만들지 않았다.
