# Tag B RAW 주기 조사
기존 앵커를 유지할 때의 주기 근거다.
Tag B 재작성 범위와 시험 조건을 정할 때 읽는다.

2026-10-15 후속 지시로 새 설계 범위가 바뀌었다.
사용자는 멀티태그 제거와 독립 LoRa를 요청했다.
새 목표는 앵커 변경을 포함한 RAW 50Hz다.
[최신 기준](../architecture/esp32_raw_rebuild_20261015.md)을 따른다.
아래 40Hz 결정은 기존 앵커 유지 조건의 기록이다.
소스 분석·실측 수치는 이전 장치의 근거로 보존한다.

## 결정

**이번 재작성의 RAW 목표는 40Hz, 주기는 25ms다.**
Tag B 한 대와 기존 A1~A4를 대상으로 한다.
각 주기에 새 거리 네 개를 한 번씩 시도한다.
실패한 거리는 결측으로 전송한다.
이는 무손실 40Hz나 물리적 최대 속도 보장이 아니다.

| 경로 | 선택한 기준 | 의미 |
|---|---|---|
| Tag B → companion | RAW 40Hz, 25ms | 기존 SYNC·ID 6 슬롯과 호환 |
| companion → PX4 | 새 유효 위치마다 전달, 정상 목표 40Hz | 공분산 포함. 반복 전송으로 횟수를 채우지 않음 |
| 위치 관측 시험 목표 | 정상 조건의 완전한 1초 창마다 30개 이상 | 프로젝트 시험 목표. PX4 코드의 절대 문턱이 아님 |
| 태그 → 지상국 | LoRa 명목 1Hz | 유효 UWB SYNC와 배정 회차가 있어야 송신 |

기존 40/35Hz 검사 수치를 그대로 복사하지 않았다.
앵커 코드와 PX4 입력 안내를 대조해 40Hz를 선택했다.
유효 관측률·최대 공백은 별도로 검증해야 한다.

## 앵커가 허용하는 통신

**A1의 ID별 수신 창이 균일한 고속 측정을 막는다.**
태그 A를 꺼도 A1의 ID 6 수신 창은 변하지 않는다.

| 항목 | 코드 값·동작 |
|---|---|
| 하드웨어 | nRF52 DK / nRF52832 + DWM3000 |
| UWB 무선 | 채널 5, 6.8Mbps, preamble 128, PAC8, code 9, STS off |
| 거리 교환 | POLL → RESPONSE → FINAL → REPORT |
| 주소 | PAN 0xDECA, 앵커 0x00A1~0x00A4, 태그 5 또는 6 |
| SYNC | A1이 매 25,000µs 송신. schedule 0x4001 |
| ID 6 슬롯 | SYNC 후 12,500~23,500µs |
| 태그 측 완료 기한 | SYNC 후 23,200µs 미만. 마지막 300µs는 정리 시간 |
| A1 새 요청 수락 | 슬롯 안이며 남은 시간이 2,300+300µs 이상이어야 함 |
| A1 수락 창의 끝 | 조건식상 약 20,900µs. 처리 지연만큼 더 앞당겨짐 |
| A2~A4 | ID·PAN·주소를 검사. A1과 같은 슬롯 검사 코드는 없음 |
| 앵커 거래 예산 | POLL 수신부터 최대 2,300µs |
| 앵커 FINAL 대기 | 하드웨어 1,200 UUS, REPORT용 600µs 별도 확보 |
| 앵커 수신 재개 지연 | RESPONSE 송신 후 200 UUS |
| 태그 거래 예산 | 3,000µs. RESPONSE 대기 1,200µs |
| 태그 재시도 | 기존 최대 2회, 재시도 간격 200µs |

UUS와 실제 µs는 같은 단위가 아니다.
공통 헤더의 일정 상수는 실제 µs다.
하드웨어 RX timeout에 쓰는 UUS와 혼용하지 않는다.

근거 위치는 공통 헤더 20~40행이다.
앵커의 289~312행은 SYNC를 만든다.
앵커의 340~355행은 요청 수락을 검사한다.
이 슬롯 검사는 `ANCHOR_PROFILE == 1`에만 적용된다.

```text
SYNC 0ms       A 슬롯          B 슬롯                 다음 SYNC
|----1ms----------------12.5ms================23.5ms----25ms
                              |-- 네 거리 약 9.42ms --|
                              완료 목표 <23.2ms
                              LoRa 승인 마감 <24.5ms
```

50Hz의 20ms 주기는 A1 수신 창 밖으로 이동한다.
80Hz의 12.5ms 간격도 같은 ID 6으로 유지할 수 없다.
ID를 5/6으로 번갈아 위장하는 설계는 채택하지 않는다.
사용자가 유지하라고 한 ID와 관측 식별을 깨기 때문이다.

A1에는 주기당 POLL 횟수 제한 카운터가 없다.
따라서 모든 형태의 측정이 최대 40회라는 뜻은 아니다.
같은 창에 A1 측정을 몰아넣는 실험은 별개다.
이는 균일한 새 4거리 관측률과 같지 않다.
시간이 다른 거리 묶음과 추가 지연이 생긴다.
현재 한 SYNC당 한 관측 계약으로 검증된 속도는 40Hz다.

## 이번 수신 측정

**현재 RAW 39.98Hz와 새 위치 약 34.71Hz를 관측했다.**
2026-10-15 20:30~20:31 KST의 수신 결과다.
측정 프로그램은 약 60초 실행했다.
연결 준비 뒤 RAW의 첫~마지막 구간은 57.454초다.
ROS `/uwb/received`를 구독했다.
독립 UART 또는 RF 분석기로 측정한 것은 아니다.

| 항목 | 결과 |
|---|---:|
| RAW 수 | 2,298 |
| 네 거리 유효 RAW 수 | 2,001 |
| RAW 속도 | 39.9798Hz |
| 네 거리 유효 비율 | 87.08% |
| 네 거리 유효 속도 | 약 34.8278Hz |
| B_TF 새 timestamp 관측 속도 | 약 34.7105Hz |
| 정상 4거리 사이클 중앙값 | 9,424µs |
| 정상 사이클 p95 / 최대 | 9,583 / 9,728µs |
| 정상 개별 교환 중앙값 / 최대 | 2,257 / 2,379µs |
| 정상 네 표본 시각 간격 중앙값 | 6,946µs |
| 태그 측 사이클 간격 중앙값 / 최대 | 25.000 / 50.028ms |
| companion 수신 간격 p95 / 최대 | 26.686 / 48.452ms |

4거리 속도는 유효 개수를 RAW 구간으로 나눈 값이다.
관측 경계 한 표본의 영향이 있는 근삿값이다.
B_TF 속도는 새 timestamp를 가진 pose만 셌다.
FC 수용률이나 융합률을 측정한 값은 아니다.
정상 4거리 표본은 모두 각 앵커를 1회 시도했다.

9.424ms의 역수는 약 106Hz다.
이는 교환 시간만 뒤집은 산술값이다.
SYNC·수신 창·실패·SPI·출력 시간을 포함하지 않는다.
앵커나 태그의 지속 가능한 최대 Hz로 제시하지 않는다.

RAW와 진단 JSON은 합쳐 약 863바이트다.
이는 수신 JSON을 재직렬화한 크기 추정치다.
40Hz에서는 약 34.5kB/s다.
921600 baud, 8N1의 명목 용량은 92.16kB/s다.
평균 대역폭보다 메시지 분리·큐 지연도 조사해야 한다.

이 구간의 LoRa timeout·watchdog·recovery는 0이었다.
송신 완료 누계는 399회였다.
이는 지상국 수신 성공이나 RF 공존 보증이 아니다.
측정 시 FC는 연결됐고 모터가 정지해 있었다.
B_TF 상태의 `timestamp_calibrated`는 false였다.

[측정 원문](evidence/esp32_raw_rebuild_20261015/tag_b_passive_60s.json).
이 짧은 정지 측정은 비행·장시간 성능 검증이 아니다.

## PX4에 맞춘 선택

**PX4에는 RAW 빈도보다 새 위치의 도달 품질이 중요하다.**
공식 안내는 외부 위치를 30~50Hz로 보낸다.
공분산을 포함할 때 30Hz를 제시한다.
현재 40Hz 입력에서 약 34.7Hz의 새 위치를 관측했다.
따라서 기존 앵커를 바꾸며 속도를 올릴 근거는 아직 약하다.
우선 전송 손실·실패·시각 오차를 줄인다.

출처: [PX4 외부 위치 안내](https://docs.px4.io/main/en/ros/external_position_estimation).
실제 배포 기준 소스는
[기존 PX4 조사](evidence/esp32_raw_rebuild_20261015/px4_ev_source_readback.json)를 따른다.
200/400ms 중단 조건을 정상 지연 목표로 쓰지 않는다.
Offboard의 2Hz 조건은 위치 입력 조건과 별개다.

새 관측은 준비되는 즉시 한 번 보낸다.
40Hz 타이머를 맞추려고 옛 좌표를 재포장하지 않는다.
시험에서는 RAW·위치 승인·FC 수용·융합을 따로 센다.
1초 창 관측 수와 최대 공백도 함께 보고한다.
현재 출력 경로의 공분산·좌표계·시각 변환을 확인한다.

## LoRa 유지 조건

**최신 LoRa 명세를 보존하며 UWB 처리를 우선한다.**
399.616ms는 255바이트의 최대 RF 점유 계산값이다.
그 시간 동안 MCU나 UWB를 기다리게 해서는 안 된다.
SX1262 송신과 DW3000 수신을 비동기로 진행한다.
실제 공존 여부는 하드웨어 시험으로 확인한다.

| 대상 | 유지·개선 기준 |
|---|---|
| 무선 | 915MHz, BW125kHz, SF7, CR4/5, 10dBm, private sync 0x1424 |
| 일정 | B는 `sf_seq % 40 == 20`. 명목 1Hz |
| 송신 승인 | 유효 SYNC, 재획득 대기 1초, 24.5ms 마감, 중복·늦은 재송신 없음 |
| 좌표 | companion의 `jetson_pose`만 사용. 태그 계산 XY로 대체하지 않음 |
| 무효 좌표 | `fix:false`, x/y null. SYNC가 없으면 상태 송신도 없음 |
| USB | 921600 baud JSONL, pose·ACK·lora_rx 유지 |
| 하향 | payload와 RSSI/SNR만 companion으로 전달. 비행 명령 실행 기능을 추가하지 않음 |
| SPI | CS 비활성화·장치 전환 순서 유지. TCXO·RF 스위치 처리 보존 |
| 서비스 | UWB RX를 먼저 열고 USB 입력·SYNC 대응·LoRa 서비스를 수행 |
| 복구 | IRQ/timer 처리, timeout 3초, watchdog 3.5초, 재초기화 3초 |
| 개선 | 원본 시각·순번·시계 구간을 검사. 오래된 pose의 반복으로 신선도를 갱신하지 않음 |

현재 500ms freshness는 USB 수신 후 경과 시간이다.
원본 pose가 500ms 이내라는 보증이 아니다.
새 양방향 시각 대응으로 원본 나이를 검사한다.
시계가 불명확하면 임의로 유효 fix를 만들지 않는다.
기존 지상국의 `drone.status` 형식은 유지한다.

## 다음 구현에서 검증할 것

**40Hz를 유지하며 실제 관측 손실을 줄이는지 판정한다.**
RAW/진단을 한 프레임으로 묶는 파서를 함께 설계한다.
무효 마스크와 시간 초과 원인은 구분한다.
현행 `deadline_valid`는 4거리 유효 여부도 포함한다.
이를 순수 시간 초과 플래그로 오해하면 안 된다.

재시도는 남은 앵커의 첫 시도 예산을 먼저 확보한다.
기존 코드는 한 앵커의 재시도가 뒤 앵커를 밀 수 있다.
부분 RAW는 살리되 위치 사용 여부는 companion이 판정한다.
유효성이 부족하면 이전 거리로 채우지 않는다.

정지·이동·차폐·앵커 누락·USB 지연을 따로 시험한다.
LoRa 최대 길이 송수신과 복구도 동시에 시험한다.
100ms 이상 관측 공백은 우선 조사 실패 조건으로 둔다.
이는 제안한 지상 시험 기준이며 비행 안전 보증은 아니다.
비행용 지연 예산은 최고 속도와 오차 예산으로 확정한다.

50/80Hz가 필요하면 A1 시간표부터 변경해야 한다.
그때에는 새 schedule ID와 LoRa 위상도 함께 설계한다.
이번 범위는 태그와 companion의 재작성 계획이다.
펌웨어 업로드·앵커 수정·FC 설정 변경은 하지 않았다.
