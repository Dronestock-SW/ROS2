## 3. 구조를 확정하고 바로 구현으로 이어간다

**RAW의 필수 정보는 보존하고 멀티태그 TDMA를 제거하라.**

Tag B 한 대가 A1→A2→A3→A4 순서로 측정을 시작한다.
A1~A4는 주소만 다른 공통 요청 응답기로 구성한다.
A1 SYNC와 A/B 교대 슬롯, 태그의 슬롯 대기를 제거한다.
Jetson의 RAW/TDMA 별도 메시지 짝 맞추기를 제거한다.

다음 RAW 정보는 한 완결 프레임에 보존한다.
- 태그 ID, 순번, boot_id, 측정 session.
- 앵커별 RAW 사선거리와 원본 측정 시각.
- cycle 시작·종료 시각.
- valid_mask, 앵커별 짧은 실패 코드.
- 동기화 상태와 필요한 기한 준수 정보.

TDMA 진단에 있던 필수 정보도 RAW로 옮겨라.
sf_seq·schedule_id는 가짜 값으로 유지하지 마라.
A1 session의 의미 변경은 새 schema에 명시하라.
새 무선 판본과 구형 앵커 응답을 구분할 수 있게 하라.

DS-TWR의 POLL→RESPONSE→FINAL→REPORT를 유지한다.
주소·PAN·길이·순번·세션·신선도 검사는 유지한다.
검증된 SYS_TIME·리셋·SPI 드라이버 수정을 보존한다.
실패 거리는 결측이며 이전 거리나 0m로 채우지 않는다.

ESP32는 측정·시각·통신을 담당한다.
Jetson은 시간 정합·위치·공분산을 계산한다.
PX4는 기존 상태 추정과 비행 제어를 담당한다.
새 학습 모델이나 멀티태그 확장 구조는 만들지 마라.

절대 단조 시각으로 주기를 유지하라.

## 5. LoRa를 독립 동작시킨다

**UWB가 고장 나도 LoRa가 상태를 전달하도록 구현하라.**

제공한 LoRa 명세의 무선 설정과 메시지 형식을 유지한다.
915MHz, BW125kHz, SF7, CR4/5, 10dBm을 사용한다.
private sync 0x1424, CRC, 최대 255바이트를 유지한다.

UWB SYNC와 교대 회차 의존을 제거한다.
자체 단조 타이머로 명목 1Hz 상태 송신을 수행한다.
LoRa 자체가 준비되면 UWB 중단 중에도 송신을 시도한다.

좌표는 Jetson의 최신 유효 pose만 사용한다.
원본 시각·순번·세션을 검사한다.
중복 메시지가 pose 만료 시각을 연장하지 않게 한다.
좌표가 만료되면 fix:false와 null 좌표로 보낸다.

하향 payload·RSSI·SNR을 Jetson으로 전달한다.
새 비행 명령 실행 기능은 태그에 추가하지 않는다.
RF 송신 완료를 기다리며 UWB를 멈추지 않는다.
송신 중 하향 수신 제한과 송신 후 RX 복귀를 검증한다.

SPI 소유권·CS·TCXO·RF 스위치를 명확히 관리한다.
별도 SPI 호스트는 실제 드라이버 지원을 확인해 적용한다.
공유 SPI를 두 작업에서 동시에 조작하지 않는다.
IRQ·timer·watchdog와 모듈별 복구를 구현한다.

## 6. 빌드와 시험 배포를 직접 수행한다

**코드 검증 뒤 실제 장치에서 동작을 확인하라.**

태그·앵커·Jetson의 변경 파일과 계약을 먼저 짧게 정리하라.
이후 같은 작업에서 구현과 필요한 시험으로 진행하라.
계획 승인을 받기 위해 이미 허용된 작업을 중단하지 마라.

기존 빌드 버전·라이브러리를 기준으로 재현 빌드한다.
라이선스와 vendor 수정 내역을 보존한다.
메시지·세션·시각 순환·timeout·큐 정책을 검사한다.
부트로더·파티션·앱 이미지 주소표를 생성한다.

지상에서 FC로 새 관측을 보내는 경로를 통제한다.
이전 태그 송신을 중단한 뒤 앵커들을 새 판본으로 기록한다.
각 앵커를 검증하고 새 태그·Jetson 수신기를 적용한다.
혼합 판본의 응답을 정상 관측으로 수용하지 않는지 검사한다.

실패하면 증거를 남기고 원인을 수정해 재시험하라.
복구가 필요하면 백업한 호환 조합으로 되돌려라.
불안정한 시험 판본을 정상 운용본으로 남기지 마라.

## 7. 실기기 검증을 완료한다

**시뮬레이션·로그 재생·실물 시험을 각각 구분하라.**

같은 배치와 조건에서 40Hz와 50Hz를 비교하라.
각 후보에서 정상 지상 10분 이상 측정하라.
최종 후보는 LoRa를 함께 켜고 30분 연속 관찰하라.
짧은 시험 성공을 장시간 안정성으로 확대하지 마라.

필수 시험이다. 아래 LoRa 실물 송수신은 사용자 요청으로 보류한다.
보류한 시험을 통과로 기록하지 않는다.
다른 장소에서의 절차는 문서 끝의 안내를 따른다.

- 정상 4거리, 부분 실패, 각 앵커의 응답 중단·복구.
- A1 중단 중 다른 앵커 측정과 LoRa 서비스 유지.
- USB 지연·분리·재연결, 잘못된 메시지·과도한 입력.
- 태그 재부팅, UWB 복구, LoRa 복구와 시간 재동기화.
- 최대 길이 LoRa 송신과 실제 지상국 수신: 보류.
- 실제 지상국 하향 송신과 Jetson lora_rx 수신: 보류.
- 화면·진단·USB 입력이 겹친 부하.
- 옛 세션·중복·역순·만료 데이터의 거부.

앵커 전원 차단이나 지상국 조작이 원격으로 불가능하면
해당 물리 조작만 사용자에게 요청하고 수집·판정은 직접 하라.
소프트웨어에서 값을 숨긴 시험을 물리 차단 시험으로 쓰지 마라.

다음 지표를 구분해 보고하라.
- 새 RAW 시도율, 전체 수신율, 유효 4거리 비율.
- Jetson의 새 유효 위치율.
- 원본 나이·간격·지연의 p50/p95/p99/최대.
- 최대 연속 누락과 완전한 1초 창의 최소 관측 수.
- LoRa 송신 완료와 실제 지상국 수신·하향 수신.
- PX4 관측 송신·실제 수용·융합.

50Hz 운영 후보의 초기 정상 시험 기준:
- RAW 수신 평균 49~51Hz.
- 새 유효 위치가 완전한 1초 창마다 30개 이상.
- 정상 조건에서 100ms 이상 관측 공백 발생 시 원인 분석.
- 옛 데이터를 새 관측으로 채택한 사례 0회.
- 정상 30분 중 비정상 재부팅·교착·지속 메모리 증가 없음.

이 기준은 프로젝트 지상 시험 기준이다.
비행 안전 보증이나 PX4 코드의 절대 문턱은 아니다.
50Hz가 통과하지 못하면 원인을 수정하고 40Hz와 비교하라.
40Hz 채택 시 수신 기준은 39~41Hz로 바꿔 판정하라.
주기 저하로 결함을 숨기지 말고 채택 이유를 기록하라.

PX4 검증은 지상·모터 정지 상태에서 수행한다.
기존 관측 입력 경로와 설정을 먼저 확인한다.
FC 파라미터를 바꿔야 한다면 필요 변경을 별도로 설명하라.
기존 입력과 시험 입력을 중복 송신하지 마라.
비행 성능은 별도 시험이며 완료 주장에 포함하지 않는다.

## 8. 최종 ESP32 초기화·재설정으로 마무리한다

**검증한 릴리스로 Tag B를 새로 구성하고 다시 확인하라.**

검증이 끝난 소스·이미지·빌드 환경을 고정한다.
최종 초기화 직전 장치 식별과 백업을 다시 확인한다.
유일한 정상 이미지나 설정을 잃은 상태에서 지우지 마라.

대상 ESP32 Tag B의 flash를 초기화한다.
eFuse·보안 퓨즈는 변경하지 않는다.
빌드 주소표에 따라 부트로더·파티션·앱을 모두 기록한다.
app 이미지 하나만 임의 주소에 올리지 마라.

ID 6, 앵커 주소·배치, 확정 주기, LoRa 설정을 적용한다.
옛 멀티태그 NVS를 통째로 복원하지 마라.
필요한 장치별 보정값은 백업에서 선별해 이관한다.
보정값의 의미와 출처를 기록하라.

기록 후 읽기 검증 또는 도구의 검증 결과를 확인한다.
설정 저장과 MCU 재부팅 후 재조회도 확인한다.
전원 재인가 후 부팅·RAW·시각 동기·LoRa를 확인한다.
최종 재기록 후 정상 지상 10분 확인을 추가 수행한다.
시험용 상태가 최종 초기화로 사라져도 정상 동작해야 한다.

Jetson의 최종 수신 서비스와 자동 시작을 확인한다.
포트 별칭과 단일 점유 상태를 확인한다.
한시적 복구 장치와 불필요한 시험 프로세스를 정리한다.
필요한 백업·로그·릴리스 산출물은 보존한다.

## 9. 최종 인계

**실제로 적용된 상태와 검증 증거를 제출하라.**

- 최종 태그·앵커·Jetson 소스 판본과 변경 파일.
- 이미지 SHA-256, 장치별 기록·검증 결과.
- RAW·시각 교환·LoRa 명세와 실제 수신 예시.
- 확정 운영 주기와 40/50Hz 비교 결과.
- 지상 시험 결과와 남은 미검증 항목.
- 초기화·재설정·전원 재인가 후 확인 결과.
- 서비스 상태, 백업 경로, 복구 절차.

“구현 완료”, “기록 완료”, “실물 검증 완료”를 구분하라.
필수 장치 접근이나 시험이 막혔다면 완료로 표시하지 마라.
실행 가능한 나머지 작업은 끝낸 뒤
막힌 항목·확인된 원인·필요한 사용자 조작만 알려라.

## 10. 다른 장소에서 진행할 LoRa 시험 안내

**실제 지상국 송수신은 보류 상태로 인계한다.**
펌웨어 구현·기록 완료와 이 시험 완료를 구분한다.
아래 절차는 새 단일 태그 구현을 적용한 뒤 실행한다.
현재 기존 펌웨어가 이미 이 조건을 만족한다는 뜻은 아니다.

1. 태그와 지상국의 펌웨어 판본을 기록한다.
   기체를 지상에 놓고 모터 정지를 확인한다.
   태그·지상국의 포트와 ID를 각각 대조한다.
2. 양쪽 무선 설정을 맞춘다.
   915MHz, BW125kHz, SF7, CR4/5, 10dBm이다.
   private sync 0x1424, CRC, 가변 길이를 사용한다.
   태그 USB는 921600 baud다.
   지상국 USB 속도는 실제 지상국 설정을 확인한다.
3. companion RAW와 지상국 수신을 함께 기록한다.
   정상 상태에서 명목 1Hz `drone.status`를 확인한다.
   태그의 TX-done과 지상국 수신을 따로 센다.
4. 최신 유효 companion pose를 공급한다.
   좌표·순번을 확인한 뒤 pose 공급을 중단한다.
   정한 유효기간 뒤 `fix:false`, x/y null을 확인한다.
   같은 옛 pose를 반복해도 유효기간이 연장되면 실패다.
5. A1 또는 UWB를 실제 중단하고 복구한다.
   LoRa가 자체 타이머로 상태 전송을 이어가는지 확인한다.
   소프트웨어 입력 차단과 실제 전원 차단을 구분한다.
6. 지상국에서 고유 시험 문자열을 하향 송신한다.
   companion의 `lora_rx`에 같은 payload가 있는지 확인한다.
   RSSI·SNR도 함께 기록한다.
   태그 RF 송신 중에는 하향 수신이 제한된다.
   송신 완료 뒤 RX 복귀와 다음 하향 수신을 확인한다.
7. 지원되는 시험 경로로 최대 255바이트를 송신한다.
   무선에 종료 NUL을 넣지 않는다.
   실제 수신 길이를 확인하며 RAW 공백도 함께 측정한다.
   시험 경로가 없으면 먼저 구현하고 미실시를 통과로 쓰지 않는다.
8. 최종 후보를 LoRa 동시 부하로 30분 관찰한다.
   RAW·유효 위치율·원본 나이·최대 공백을 기록한다.
   LoRa 송수신·timeout·복구·재부팅 횟수를 구분한다.
   로그 경로·조건·판본·통과 여부를 결과 문서에 남긴다.

원격으로 할 수 없는 연결·전원 조작만 사용자에게 요청한다.
비행·arming·모터 구동은 이 시험에 포함하지 않는다.
목적은 지상 통신 검증이며 비행 성능 확인이 아니기 때문이다.
