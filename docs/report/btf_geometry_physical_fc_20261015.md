## 높이를 바꿔도 남는 거리 불일치

사용자는 당시 실측 배치가 설정과 같았다고 확인했다.
가로 6.3m, 세로 4.6m, 앵커 높이 0.15m다.
태그 실측 위치·거리 보정 자료는 없다고 최종 답변했다.

| 원본 seq 4572 | 값 |
|---|---:|
| A1 거리 | 3.08936m |
| A2 거리 | 3.01360m |
| 두 거리 합 | 6.10296m |
| A1–A2 간격 | 6.3m |
| 두 측정 시각 차이 | 2.360ms |
| 1m/s 이동을 허용한 부족분 | 19.468cm |

태그가 어느 높이에 있어도 두 거리 합은 충분히 길어야 한다.
두 거리의 측정 시각 차이도 계산에 반영했다.
위 19.468cm 부족을 이동만으로 설명하려면 약 83.5m/s가 필요하다.
이는 기체의 해당 시험 속도 가정과 맞지 않는다.
따라서 ToF 높이·IMU 지연만으로 설명하지 못한다.

최대 공백의 20개 프레임 모두 같은 문제를 보였다.
이동 허용 후 최대 쌍 부족분은 19.127~27.891cm다.
이 값으로 계산한 물리 거리 RMS 하한은 6.762~9.861cm다.
높이를 몰라도 기존 6cm 기준을 넘는다는 뜻이다.
4거리 전체를 물리적인 XYZ에 적합하면 약 20.8~23.9cm가 남았다.
후자는 정지 모델의 수치 적합값이다. 위치 정답은 아니다.

H80 내부 RMS 6.0~6.6cm와 위 물리 RMS는 다르다.
H80은 수평 이동과 공통 제곱거리 항을 맞춘다.
그 공통 항이 실제 높이와 일치함을 보장하지 않는다.
그러므로 발행이 연속돼도 물리적 정확성은 별도다.

거리 편향·태그/앵커 보정·수신 전 값 처리 중 원인은 미확정이다.
NLOS나 하드웨어 고장으로 단정하지 않는다.
기체의 정답 XY가 없어 앵커별 보정값을 역으로 확정하지 않았다.

## ToF와 태그의 장착 높이

장착 높이는 이미 기울기 보정과 XYZ 계산에 들어간다.
실제 실행 파일은 `evening-20261014-1815/field-btf-cpp.json`이다.
실행 인자와 파일을 SSH로 직접 확인했다.
`tof_to_tag_body_flu_m=[0,0,0.15]`였다.
사용자가 이번에 약 17cm라고 알렸다.

```text
태그 높이 = 바닥 높이
          + ToF 거리 × IMU 수직 투영
          + (IMU 회전행렬 × ToF→태그 벡터)의 Z 성분
```

수평일 때는 ToF 거리 + 15cm다.
이 높이는 B3 거리 검사와 XYZ 산출에 쓰인다.
같은 높이 앵커의 B4 XY는 공통 수직항을 분리한다.
FC로 보내는 EV는 XY 전용이다. 고도는 FC가 추정·제어한다.
FC의 태그 레버암과 ToF→태그 간격은 서로 다른 기준점이다.

| 원본 재생 | 승인 발행 | 최대 공백 |
|---|---:|---:|
| 원래 +15cm | 2,765 | 526.079263ms |
| +17cm 감도 시험 | 2,765 | 526.079263ms |

2cm 높이 차이는 상승한다고 계속 누적되지 않는다.
각 거리로의 영향은 기체 자세와 배치에 따라 달라진다.
이번 20cm 이상 거리 불일치의 설명은 되지 않는다.
운영 장착 설정과 FC 레버암은 변경하지 않았다.
저장소의 다른 기체용 12cm 기본 파일과 혼동하지 않는다.

## 실제 FC 지상 주입

사용자가 지상·DISARM·모터 격리·단독 작업을 확인했다.
SSH로 DISARM·착륙 상태를 다시 확인했다.
기존 `/uas1/mavlink_sink`에만 가상 ODOMETRY를 보냈다.
FC 직렬 포트를 추가로 열지 않았다.
실제 관측 토픽이나 운용 서비스를 바꾸지 않았다.

```text
기록 RAW/ToF/IMU → 파일 재생 C++ B_TF → 승인된 XY
  → 지상 시험용 좌표·시각 변환 → 기존 ODOMETRY 인코더
  → 기존 MAVROS 라우터 → 물리 FC → EKF 조회
```

파일 재생 결과를 입력했다. 실시간 RAW→운영 브리지 전체 시험은 아니다.
좌표 원점과 시각을 시험 시작 때 한 번 옮겼다.
원본의 관측 나이와 공백은 유지했다.
FC 위치를 계속 되먹임하거나 과거 관측을 반복하지 않았다.

| 확인 항목 | 결과 |
|---|---|
| 30초 시험 송신 | 1,024개, 송신 전 만료 0개 |
| 송신 최대 간격 | 526.585907ms |
| FC `vehicle_visual_odometry` | 4회 좌표 샘플 대조 일치 |
| FC 측정 시각 변환 잔차 | 356.75~520.75µs, 위 4회 |
| EV 융합 | 두 EKF 모두 `fused=True` |
| 융합 시간 | 2·8·14·20·26초 조회에서 증가 |
| 해당 조회의 innovation 거부 | 두 EKF 모두 False |
| EV 상태 | 시험 중 조회에서 True |
| 입력 중지 뒤 EV 상태 | 34·40초 조회에서 False |
| ARM·모드·목표·파라미터 쓰기 | 0회 |
| 종료 상태 | 송신기 제거, DISARM·착륙 유지 |

모든 패킷의 수신·융합을 1:1로 증명한 결과는 아니다.
526ms 공백 내부의 모든 순간을 조회한 것도 아니다.
공백 전후에 융합했다는 근거다. 실비행 유지 성능은 미검증이다.
입력 중지 후 오래된 aid 메시지의 `fused=True`가 남았다.
하지만 `time_last_fuse`는 멈추고 `cs_ev_pos=False`였다.
따라서 오래된 `fused` 값만으로 현재 융합을 판정하면 안 된다.

`EKF2_EV_CTRL=1`, `EKF2_GPS_CTRL=0`을 읽었다.
`EKF2_EV_DELAY=0ms`를 유지했다.
PX4의 [외부 위치 입력 문서](https://docs.px4.io/v1.15/en/ros/external_position_estimation)에 따라
수신 토픽과 실제 EKF 융합을 구분했다.

`pair_range_rms_lower_bound_m` 계산은 다음과 같다.

한계를 넘지 않은 경우도 물리적 일치라고 단정하지 않는다.

## 남은 해결 작업

526ms 원본 공백을 제거했다고 보고할 수는 없다.
없는 높이나 과거 좌표를 새 측정으로 채우지 않았다.
FREEZE는 승인 목표를 유지하며 새 위치 관측을 만들지 않는다.

다음 필요한 입력은 알려진 태그 안테나 위치의 거리 기록이다.
앵커를 켜고 X·Y·높이를 잰 정지 지점에서 기록한다.
각 앵커의 기준거리는 그 실측 XYZ로 계산한다.
`bias_i = 측정 거리_i − 기준거리_i`를 구한다.
다른 실측 지점에서도 보정 잔차가 줄어드는지 확인한다.
그 뒤 같은 로그 재생과 FC 지상 시험을 이어간다.
FC 추정 XY나 목표 XY를 거리 보정의 정답으로 쓰지 않는다.

요약 근거는 [검증 JSON](evidence/btf_geometry_physical_fc_20261015/verification.json)에 있다.
전체 원본과 시험 자료는 Git 밖에 보존했다.
PC 경로는 `outputs/uwb_gap_resolution_20261015/`다.
원본 로그는 수정하지 않았다.
