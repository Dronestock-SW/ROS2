# 태그 재시도·첫 복구 개선 기록
2026-10-16 R5 후보의 동작 변경을 설명하는 기록이다.
R4와 차이를 검토하고 실물 비교를 준비할 때 읽는다.

**같은 앵커 재시도 간격과 첫 자연 복구를 바꿨다.**
기준은 상원 통합 `70da279`와 진단 R4 `ea4ec5b`다.
작업 브랜치는 `codex/tag-first-failure-diagnostics-20261016`이다.
후보 펌웨어 표식은 `r5-recovery`다.
태그·앵커·운영 서비스에는 적용하지 않았다.
실제 A4 탈락 감소와 복구 시간 개선은 미측정이다.

## 바꾼 동작

**첫 실패의 원인 규명과 재시도 회복을 구분한다.**
이번 변경은 재시도가 너무 이르게 시작할 가능성을 줄인다.
A4의 물리적 첫 실패 원인을 해결했다고 주장하지 않는다.

| 항목 | R4 | R5 후보 |
|---|---|---|
| 같은 앵커 재시도 | 남은 예산에서 200us 정리 뒤 시작 | 이전 POLL의 앵커 기한과 200us 여유 뒤 시작 |
| MCU 시간 가드 종료 | 곧바로 UWB 복구 예약 | RF 시각 재확인 후 기한이 지났으면 교환만 종료 |
| 첫 자연 복구 | 감지 뒤 1500ms 대기 | 감지 뒤 다음 loop에서 시도 |
| 재발·초기화 실패 | 기존 1500ms 간격 | 이전 초기화 종료부터 최소 1500ms |
| 진단 | 최초·최종 실패와 단계 보존 | 재시도·복구 가능 MCU 시각 추가 |

기본 50Hz·20ms 시작 간격을 유지한다.
회차 완료 목표 18ms도 유지한다.
재시도는 네 앵커 첫 시도 뒤 최대 한 번이다.
새 RF session의 100ms 대기도 유지한다.
거리·원본 측정 시각·LoRa·앵커·FC 설정은 그대로다.
같은 boot의 RF session 변경 시 시계 초기화도 유지한다.

## 같은 앵커의 이전 교환이 끝날 때까지 기다린다

**앵커의 기한은 POLL 수신부터 2300us다.**
[응답기 코드](../../src/uwb_single_tag_firmware/anchor/src/anchor_nrf52dk_ref_1to1.c)는
실제 POLL 수신 시각을 기한의 기준으로 사용한다.
[태그 코드](../../src/uwb_single_tag_firmware/tag/src/main.cpp)는
POLL TX 완료를 확인한 MCU 시각을 보수적 기준으로 쓴다.

| 관찰 조건 | 재시도 하한 |
|---|---|
| POLL TX 완료 확인 | 확인 MCU 시각 + 2300us + 200us |
| 송신 시작 성공·TX 완료 미확인 | 강제 idle 완료 MCU 시각 + 2300us + 200us |
| POLL 시작 API 거절 | 위 하한은 미설정, 기존 정리 여유 적용 |

```text
A1 첫 시도 → A2 첫 시도 → A3 첫 시도 → A4 첫 시도
                                            ↓ 실패
                       같은 앵커의 재시도 하한까지 대기
                                            ↓
                       3ms 교환 + 200us 여유가 18ms 안에 있나?
                              ├─ 예 → 재시도 한 번
                              └─ 아니오 → 이번 회차 재시도 생략
```

A4는 마지막 첫 시도라 뒤에 다른 앵커 대기가 없다.
기존에는 실패 뒤 짧은 정리만으로 재시도할 수 있었다.
앵커가 이전 FINAL을 기다리는 상태일 가능성이 있다.
현재 구현은 그 가능성에 대응한 소프트웨어 수정이다.
실제 A4의 실패 원인이 그 상태였는지는 미확인이다.

TX 완료를 못 봤다면 강제 idle을 마친 시각을 쓴다.
MCU 선점 중에는 TX 대기 650us를 상한으로 못 쓴다.
이 경우 강제 idle 뒤 재시도 하한을 다시 기록한다.

대기 중 태스크 선점이 발생할 수 있다.
따라서 실제 재시도 직전 예산을 다시 검사한다.
예산이 부족하면 `attempts=1`을 유지한다.
`retry_eligible_us`는 하한이며 실제 재시도 시각이 아니다.
상세 사건의 재시도 `start_us`와 직접 비교한다.

## MCU 지연 뒤의 복구 판정을 좁힌다

**RF 기한이 지났으면 해당 교환만 종료한다.**
MCU 시간 가드가 끝났을 때 RF 시각을 다시 읽는다.
기한이 지났으면 `RadioDeadline`으로 기록한다.
기한이 남았으면 `McuGuard`로 복구를 예약한다.
이는 관찰한 시계 관계로 판정 경로를 나눈 것이다.
DW3000 물리 고장을 확정하는 검사는 아니다.

POLL/FINAL TX 실패 연속 두 번 정책은 유지한다.
따라서 TX 완료 시간초과가 두 번이면 복구할 수 있다.
모든 MCU 선점에 의한 복구가 사라진다고 표현하지 않는다.
현재 RF 시각 읽기 자체가 멈추는 경우도 별도 검증 대상이다.

## 첫 복구와 반복 복구의 간격을 나눈다

**첫 자연 이상에는 1500ms 선대기를 두지 않는다.**
감지된 회차를 마친 뒤 다음 loop에서 초기화한다.
복구를 한 번 시도한 뒤에는 반복 초기화를 제한한다.

| 상황 | 다음 초기화 가능 시점 |
|---|---|
| 정상 부팅 뒤 첫 자연 이상 | 감지 뒤 다음 loop |
| 직전 복구 후 1500ms 안에 재발 | 직전 초기화 종료 + 1500ms |
| 직전 복구 후 1500ms 넘게 정상 | 새 이상 감지 뒤 다음 loop |
| 초기화 실패 | 그 초기화 종료 + 1500ms |
| bench 복구 명령 | 대기 우회, reason으로 별도 표시 |

1500ms는 재발 감지부터 새로 세는 고정 대기가 아니다.
이전 초기화 종료와 다음 시작 사이의 하한이다.
부팅 초기화 실패도 종료 뒤 1500ms를 기다린다.
`eligible_us`와 `init_start.at_us`로 판정한다.

RF 초기화가 빨라져도 좌표가 바로 복구되지는 않는다.
새 session 대기·상태 알림·시계 교환이 남아 있다.
B_TF 승인·LoRa 송신도 서로 다른 시점이다.
강제복구 219.6ms는 이전 자동 대기 개선의 근거가 아니다.
기존 강제 명령은 이미 1500ms를 우회했기 때문이다.

**R5 결과는 R4 검증 기록과 분리한다.**
R4의 검사 숫자와 이미지 해시는 [기존 기록](tag_failure_diagnostics_20261016.md)에 보존한다.
