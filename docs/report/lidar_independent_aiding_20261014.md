# LiDAR 독립 수평속도 융합 후보
2026-10-14 PX4 수정과 배포 준비 기록이다.
어제 설치본과 새 후보의 차이를 확인할 때 읽는다.

## 결론

**LiDAR 독립 융합을 추가한 R3 후보를 만들었다.**
실제 FC에는 13일 설치한 R2가 남아 있다.
R3의 실제 FC 융합·제자리 이륙은 미실시다.
현재 비행 가능 판정으로 사용하지 않는다.
후속 [웹 폐루프 진단](web_vertical_takeoff_20261014.md)에서도
제자리 호버링의 이동량·속도 기준을 아직 통과하지 못했다.

| 구분 | R2 실제 설치본 | R3 새 후보 |
|---|---|---|
| `EKF2_LID2_VER` | 1 | 2 |
| 관측 축 | 북·동 속도 | 북·동 속도 |
| 다른 수평 보조 없이 시작 | 불가 | 구현·격리 검증 |
| 실제 FC 수신 | 확인 | 미실시 |
| 실제 FC 융합 | 조회 당시 false·마지막 시각 0 | 미실시 |
| CRSF 수신기 | 포함 | 유지 |
| FC 설치 | 10월 13일 | 미실시 |

R2는 업데이트 누락이나 실패 상태가 아니다.
14일 FC 조회의 빌드 시각은 13일 19:30:32다.
전용 수평 입력은 정상 설치되어 있다.
다만 기존 보조 속도의 선행 조건이 남아 있었다.
[실제 지상 결과](lidar_ground_deployment_20261014.md)를 따른다.

## 독립 융합의 범위

LiDAR가 수평속도를 관측하면 EKF가 이를 직접 쓴다.

```text
수평 LiDAR → 점별 시각·IMU 보정 → 북·동 속도
                                    ↓
PX4 전용 수신 → 품질·나이·좌표 검사 → EKF 수평속도 융합
                                    ↓
                              PX4 위치·자세 제어
UWB 절대 XY ────────────────────────↗
```

| 처리 | 새 동작 |
|---|---|
| 시작 | tilt·yaw 정렬과 200ms 일관된 관측 요구 |
| 융합 | 북·동 속도 혁신 검사를 통과한 관측만 적용 |
| 활성 표기 | 실제 융합 성공 뒤 `aux_vel` 활성 |
| 수평 유효성 | 독립 수평속도를 수평 보조 개수에 포함 |
| 나이·수신 공백 | 기존 `EKF2_LID2_AGE=180ms` 유지 |
| 잘못된 수신·reset 변경 | 버퍼 폐기와 융합 활성 철회 |
| EKF 내부 공백 | 500ms 관측·융합 만료 시 철회 |
| 복구 | 다시 일관된 관측을 확인한 뒤 융합 |
| 수직 속도·높이 | 미관측 유지. 가상 0값·큰 분산 대체 없음 |
| 상태 리셋 | LiDAR 시작·복구 자체는 평균·공분산 리셋 없음 |
| 기존 landing-target 경로 | 전용 LiDAR 비활성 시 기존 동작 유지 |

전용 status에 `fusion_active`를 추가했다.
`fused`, `time_last_fuse`도 실제 EKF에서 읽는다.
수신 카운터만으로 융합 성공을 판정하지 않는다.

속도만으로 창고의 절대 위치는 알 수 없다.
초기 임무 좌표를 정하는 UWB 준비 조건은 유지한다.
UWB 복구 때 기존 EV 위치 리셋이 생길 수 있다.
실제 좌표 불일치·이동 목표 반응은 추가 확인 대상이다.
이 시험은 위치 리셋이 항상 0이라고 주장하지 않는다.

## companion 변경

관측이 준비된 이벤트에서 처리를 시작한다.
스캔 도착과 마지막 IMU 도착에서 처리기를 호출한다.
20ms 타이머는 보조 호출로 유지한다.
IMU 대기 끝 시각에도 센서 시간 보정을 적용한다.
기존 품질·관측 나이 기준은 완화하지 않았다.

| 45초 지상 기록 | 기존 호출 | 이벤트 호출 |
|---|---:|---:|
| 스캔 수신 | 407 | 428 |
| 유효 motion | 277 | 380 |
| 실제 송신 | 174 | 364 |
| 유효 후 나이 검사 보류 | 103 | 16 |
| 송신 관측 처리시간 p50 | 37.38ms | 39.38ms |
| 송신 관측 처리시간 p95 | 46.38ms | 47.43ms |
| 실제 EKF 융합 | false·시각 0 | false·시각 0 |

서로 다른 시간의 정지 기록이다.
계산 자체가 빨라졌다는 결론은 아니다.
관측 준비 뒤 타이머 대기를 줄인 결과다.
두 시험 모두 실제 FC는 R2였다.
이벤트 시험의 FC 최종 수용 카운터는 371이다.
최종 거부 카운터는 67이다.
이는 여러 시험에 걸친 누적 조회값이다.
364개 전송의 배타적 분류로 해석하지 않는다.
송신 속도 크기 p95는 0.01687m/s다.
독립 참조가 없어 속도 정확도 수치는 아니다.

`ground_static`은 VER 1·2 조회를 허용한다.
비행용 `metric_scan`과 새 이륙 준비는 VER 2를 요구한다.
VER 2만으로 실기 검증 완료를 뜻하지 않는다.
장착·상승 장면·시간 보정·융합 근거가 계속 필요하다.

## 검증과 한계

집계는 [증거 파일](evidence/lidar_independent_20261014/)을 따른다.

| 검증 | 결과 |
|---|---|
| Pixhawk 6C 펌웨어 빌드 | 성공. board 56 |
| SIH 실행 파일 빌드 | 성공 |
| EKF 회귀 | 6개 실행 파일, 52개 사례 통과 |
| 신규 독립 융합 사례 | 위 52개 중 8개 |
| 패치 재적용 | 깨끗한 고정 커밋에 적용 성공 |
| 재생성 소스 | 19개 파일의 UTF-8 내용 일치. CRLF/LF 정규화 |
| 반복 SIH | 1배속 130초 × 6개, 모두 통과 |
| companion Python 회귀 | 523개 통과. C++ 연계 8개 포함 |
| C++ 실행기 계약 | 최종 54개 통과. WSL·Jetson 각각 확인 |
| 격리 ROS 연계 | R3 수신 4개 통과. 최종 이륙 시간 제한 반영 후 UWB 복구 1개 추가 통과 |
| 실제 R3 FC 수신·융합 | 미실시 |
| 실제 동적 시간 보정 | 기존 회전 RAW 재분석만 수행 |
| 독립 속도·위치 정확도 | 미확인 |
| 실기 이륙·POSITION 호버 | 미실시 |

EKF 신규 시험은 다음을 포함한다.
독립 시작, 기존 보조 경로 유지, 공백·복구를 검사한다.
reset, 수평 이동, UWB 복구·재소실도 검사한다.
혁신 거부와 모든 높이 센서 소실도 검사한다.

SIH는 정지·DISARM 상태의 합성 관측이다.
센서 렌더링과 비행 제어 폐루프 시험은 아니다.
기체와 분리한 loopback 네트워크만 사용한다.
실행마다 130초를 기록한다.
25~120초 구간에서 융합 시각의 증가를 집계한다.
LiDAR 단독·UWB 추가·소실·복구를 순서대로 넣는다.
두 수평 입력의 동시 소실과 복구도 넣는다.
높이 소실에서는 수직 유효성 철회를 따로 검사한다.

최종 SIH는 관측 시각에 시뮬레이터 시계를 쓴다.
이는 실제 Jetson↔FC 시계 동기 검증이 아니다.
모든 임계값은 실패 전후 동일하게 유지했다.

6개 모두 LiDAR 단독 15초에 150회 융합했다.
UWB 소실 13초에는 130회 융합했다.
수평 입력 동시 소실 구간에는 0회였다.
일반 경우 수직 위치·속도 리셋은 0회다.
높이 전체 소실 경우 수직 위치 2회·속도 1회다.
모두 수평 위치 4회·속도 1회 리셋이 있었다.
이는 UWB 전환·전체 수평 입력 소실을 포함한 집계다.
LiDAR 독립 시작 자체의 리셋 여부는 EKF 단위 시험으로 구분했다.

웹 제자리 이륙용 C++ 시간 제한도 수정했다.
LiDAR 필수 이륙에서는 UWB 공백이 상승 제한 시간을 늘리지 않는다.
정해진 시간 안에 높이·XY·속도가 안정되지 않으면 착륙한다.
지상 초기 UWB·FC 상태 확인과 조종자 우선권은 유지한다.
추가 계약 시험은 UWB 공백과 계속되는 수평 이동을 함께 넣었다.
30초 제한 뒤 착륙하고 최초 XY를 유지하는 것을 확인했다.

| 이전 시도 | 보존한 실패와 조치 |
|---|---|
| runtime-v1 | PX4 명령 alias 누락. 패키징 수정 |
| runtime-v2 | 긴 ULog 형식 오류. 전용 status 메시지 사용 |
| matrix-v3 | 로그 꼬리 부족. 전체 창 검사·130초 수집 |
| matrix-v4 | 10배속 입력 지연. 6개 중 3개 가용성 기준 실패 |
| matrix-realtime-v5 | 호스트·SIH 시계 속도 차이. 합성 시각 계약 수정 |
| matrix-realtime-v6 | 실행 instance 충돌. 별도 번호로 재실행 |

실패 결과를 성공 집계에 섞지 않았다.
180ms를 넘긴 입력에서 보조 철회는 유지한다.
현장의 같은 입력 공백도 비행 검증 대상이다.
