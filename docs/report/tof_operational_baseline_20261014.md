후속 사용자 승인으로 [R3·ToF 결합본](../report/r3_tof_deployment_20261014.md)을 실제 FC에 적용했다.

## 확정한 기준본

**`tof-100-50-50-20261014-r1`을 운영 기준본으로 확정한다.**

운영 코드와 펌웨어 내용은 추가 변경하지 않았다.
실기 설치·설정 변경·배포는 보류한다.

[확정 명세와 파일별 SHA256](evidence/tof_operational_baseline_20261014.json)을 보존했다.
소스 압축본·overlay·패치·펌웨어·빌드 증거17개를 고정했다.
overlay25개는 빌드 당시 파일과 모두 일치한다.
현재 코드·PX4 소스·패치도 빌드 해시와 일치한다.
빌드 당시 문서는 역사적 증거로 묶음 안에 보존한다.
이 확정 기록은 그 뒤의 상태 갱신이다.
기준본을 고정한 시점에는 커밋·푸시 전이었다.

확정 뒤 사용자 요청으로 커밋·통합 병합을 진행했다.

## 기록 ON/OFF 시험 처리

**원본 부재로 시험을 건너뛰고 이번 요청을 마무리했다.**
사용자는 원본 확인부터 격리 비교를 승인했다.
원본이 없음을 보고한 뒤 아래와 같이 지시했다.
“없으면 제끼고 마무리”

|---|---|
| SSH | `bluewak-host` 접속 성공 |
| 전체 원본 | `events.jsonl` 부재. 현재 해시 검증 불가 |
| 필요한 원본 | 124,382,507바이트. SHA256은 아래 참조 |
| 복구된 자료 | manifest·summary·25초 구간의 주제별 발췌 두 개 |
| 복구 기록 | `RESTORATION_PARTIAL.json`도 전체 원본 부재를 명시 |
| 대체 입력 | 사용하지 않음. 전체 입력 비교와 다른 시험이 되기 때문 |
| 새 계측·합성 검사 | 미실시 |
| ON/OFF 실제 재생 | 0회. 기록 기여 여부는 미판정 |
| 운영 프로세스 | 읽기 전용 조회. 중단·재시작하지 않음 |

## Claude 검토

Claude17차는 제공 자료로 확정 범위와 시험안을 검토했다.
ON→OFF→OFF→ON과 구간별 계측은 타당하다고 봤다.
운영 기준본 확정은 B1 지연 해결 판정이 아니다.
이 구분을 본 기록과 진행표에 반영했다.

후속 계측 때는 스레드별 사전 할당 버퍼를 사용한다.
실제 파라미터 차이는 trace_directory만 남긴다.
OFF에서도 만드는 진단 객체의 비용을 구분한다.
64~66초는 원본의 상대 시각으로 고정한다.
배경 부하 판정 기준은 실행 전에 정한다.
이번에는 계측 구현과 실행을 진행하지 않았다.

[Claude17차 원문](evidence/claude_tof_baseline_trace_review_20261014.txt)을 보존한다.
