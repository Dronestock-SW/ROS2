## 추가 검증과 수정

Jetson ARM64 C++ 빌드와 ROS 4개 패키지가 성공했다.
웹·플랫폼 링크·C++·가상 FC에서 X, Y, XY 왕복이 END에 도달했다.
원래 출발점 복귀·착륙·DISARM도 모사 FC에서 확인했다.
이 결과는 실제 비행 성능을 증명하지 않는다.

후속 Python 정지 시험에서 LAND ACK가 누락됐다.
이전 기록만으로 fsync와 전달 문제를 확정하지 않는다.
초기 실패 기록을 별도 디렉터리에 보존했다.

LAND 전달이 디스크 동기화를 기다리지 않게 했다.
ARM·모드 진입은 기존처럼 기록을 먼저 확정한다.
FC가 AUTO.LAND로 바뀔 때까지 승인 목표 송신을 유지한다.
명령 전달의 중복 150ms 판단 만료 검사를 제거했다.
현재 FC·RC 권한과 ARM 전 새 관측 검사는 유지한다.

지상 웹 상태는 실제 FC 입력을 받았다.

## FC 기록 설정

SDLOG_PROFILE을 1에서 129로 변경했다.
기본 항목을 유지하고 EV 기록 bit 7을 추가했다.
FC의 저장 표시와 readback 129를 확인했다.
logger만 지상에서 재시작해 적용했다.
FC 재부팅·ARM·모드 변경은 하지 않았다.
SDLOG_MODE=1과 EKF2_EV_DELAY=0ms를 유지했다.
새 ULog는 약 0.23MiB에서 0.42MiB로 증가했다.
변경 전 SD 여유 공간은 1,664,352,256바이트였다.

새 파일은 `/fs/microsd/log/2026-10-11/22_42_14.ulg`다.
PC 기준으로는 13일 13:44 KST에 만든 파일이다.
FC 파일명 시계가 PC와 달라 날짜만으로 분류하지 않는다.
실제 EV 표본은 앵커 전원을 켠 뒤 확인해야 한다.
[PX4 1.17 프로파일 설명](https://docs.px4.io/v1.17/en/advanced_config/parameter_reference#SDLOG_PROFILE)을 근거로 했다.

## EV_DELAY의 의미

현재 송신기는 B_TF 관측 header stamp를 쓴다.
이를 마이크로초로 바꿔 ODOMETRY.time_usec에 넣는다.
송신 순간의 현재 시각으로 덮어쓰지 않는다.
따라서 전체 통신 지연을 다시 EV_DELAY에 넣지 않는다.
실제 측정 시각과 stamp 사이의 잔여 오차를 구한다.
현재 B_TF는 timestamp_calibrated=false로 보고한다.
잔여 지연이 0이라고 실측한 상태도 아니다.

ESP32→Jetson 시각 환산은 수신 시간의 하단을 맞춘다.
`processing/timing/clock.py`의 ClockMap이 담당한다.
변동 대기 지연은 진단하지만 고정 전달 지연은 남는다.
최신 앵커의 실제 측정 시각을 이 환산식에 넣는다.
평활 결과의 동적 시차도 별도로 확인해야 한다.
이 잔여 시차가 EV_DELAY의 보정 후보다.
FC 도착 시각과 stamp의 차이만으로 값을 확정하지 않는다.

[PX4 설명](https://docs.px4.io/main/en/ros/external_position_estimation#tuning-ekf2-ev-delay)은
관측 stamp와 IMU 기준 실제 측정 시각의 차이를 설명한다.
단위는 ms이며 관측 만료 허용시간과 다르다.
저녁에 실제 UWB·FC ULog·연속 기록을 맞춘 뒤 정한다.
FC 값·관측 송신기·미션의 예상값을 함께 바꾼다.

| 비교 항목 | 확인할 값 |
|---|---|
| UWB 원본 | 앵커별 sample time, cycle end, host 수신 시각 |
| B_TF | 대표 stamp, 시각 환산 잔차, 처리·발행 나이 |
| FC 전달 | ODOMETRY.time_usec, 송신 시각, timesync offset·RTT |
| FC 내부 | visual odometry timestamp_sample, EV innovation·융합 상태 |
| 별도 이동 근거 | 유효 광류·IMU 기록 또는 시각이 맞는 영상 |

정지 자료만으로 동적 시차를 식별할 수 없다.
현재 UWB 입력은 XY 전용이며 EV 각속도는 제공하지 않는다.
따라서 공식 문서의 각속도 비교를 그대로 적용하지 않는다.
FC의 UWB 융합 결과끼리 비교한 시차도 독립 검증이 아니다.
가감속 자료와 독립 이동 근거로 후보를 검증한다.
평활·NLOS에 따른 변동 지연은 고정값 하나로 해결하지 않는다.

## LiDAR SLAM 연결 경계

웹 미션 계약과 FC 명령 실행기를 분리한 구조를 유지한다.
추후 SLAM은 관측 어댑터에서 연결한다.
오늘의 입력 계약은 B_TF와 uwb_map이다.
SLAM을 지금 대체 센서로 승인한 상태는 아니다.

| 계층 | 후속 SLAM 통합 조건 |
|---|---|
| 관측 어댑터 | 원래 stamp, 좌표계, 공분산, 출처, reset 번호 |
| 좌표 정렬 | SLAM map과 앵커 좌표의 변환·부팅 신원 |
| FC 관측 송신 | 단일 송신기, 측정 시각 보존, EV 파라미터 일치 |
| 미션 판단 | FC 추정과 독립 관측을 구분, 공백 때 승인 목표 유지 |
| 웹·기록 | 출처와 상태를 전달, 관측 바뀜을 숨기지 않음 |

기존 FC 추정 위치를 독립 SLAM 관측으로 재사용하지 않는다.
LiDAR 연구 브랜치와 현재 센서 서비스의 변경 파일은 보존했다.
