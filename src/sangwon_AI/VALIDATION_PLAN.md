상태: 내부 v1.0 검수 계획 / 2026-10-02.
합성 REPLAY 일부 시험은 [구현 현황](IMPLEMENTATION_STATUS.md)에 기록했다.
웹·PX4 SITL·실기체 통합 시험은 아직 수행하지 않았다.
기준 설계: [DESIGN.md](DESIGN.md).

교정·관측 지연·잘못된 마커·RC 선점·결과 중복도 검사한다. 아직 실행하지 않았다.

## 1. 통과 원칙

각 단계는 앞 단계의 증거가 있어야 시작한다.
합성 입력의 단위·REPLAY 시험은 센서 제작과 병행한다.
합성 시험 통과를 실장·통합 단계의 통과로 대체하지 않는다.
수동 RC 로그 한 건은 자동 이동의 합격 근거가 아니다.
수치 기준은 UWB·PX4 실측 뒤 확정한다.
UWB 정확도와 PX4 융합을 입증하기 전에는 자율 좌표 이동 실비행을 하지 않는다.

| 단계 | 시험 대상 | 남길 증거 | 다음 단계 조건 |
|---|---|---|---|
| 0 | 설계·웹 계약 | 좌표계·지도·명령 스키마 합의본 | 모호한 입력 없음 |
| 1 | 센서·상태추정 | UWB 기준점 비교, PX4 융합 로그 | 위치·높이·yaw 변환 검증 |
| 2 | 지상·시뮬레이션 | BT 상태 재생, Offboard·RC·고장 시험 | 출력 권한·실패 순서 확인 |
| 3 | 제한 비행 | 호버·높이 변경·경유점 추종 ULog | 반복 도착 오차와 안정성 확인 |
| 4 | 장애물·복귀 | 우회·차단·홈 복귀·현 위치 착륙 기록 | 모든 실패 경로가 종료됨 |
| 5 | 로그 운영 | 자동 수집·검증·72시간 정리 기록 | 복구·보존 정책 확인 |

## 2. 센서와 좌표계

실제 비행 제어 좌표의 정확도를 독립 기준점으로 확인한다.

| 항목 | 확인 방법 | 불합격 처리 |
|---|---|---|
| UWB XY | 창고 기준점에서 반복 측정·오차 분포 | 자동 좌표 이동 보류 |
| UWB 입력 장치 | 전체 사양 수령 뒤 실제 장치·프로토콜·유효성·시각 확인 | 의미 검증 실패 시 좌표 발행 중지·시작 거부 |
| UWB hold 프레임 | 실제 사양의 유지값·신규 관측 구분 재생. 과거 fresh/held 키는 참고만 함 | PX4 신규 관측 금지·품질 기록·유효 관측 시간 미갱신 |
| UWB 예비 오차 | 기존 HW팀 시리얼 보고 약 0.66m를 독립 기준점에서 재측정 | 새 실측 전 좌표 성능 승인 금지 |
| PX4 융합 | ULog 설정·융합·혁신값과 PX4 위치 비교 | 절대 좌표 임무 보류 |
| 지도 변환 | 전체 UWB 사양·기준점 측량으로 실제 축과 웹 직교 좌표 대조 | 웹 좌표 거부 |
| 비행 경계 | 웹 경계·금지 구역 수신과 이탈 차단 확인 | 자동 우회 보류 |
| 상부 공간 | 임무·지도 개정에 대한 운영자 승인 확인 | 자동 임무 보류 |
| 바닥 기준 z | 바닥·선반 위 ToF와 PX4 높이 비교 | 높이 변경 보류 |
| 바닥 높이 차이 | 임무 구역의 바닥 기준면을 실측 | 변환 근거 없으면 좌표 임무 보류 |
| 선반 위 비행 | 바닥 기준 고도와 ToF 반사면 영향 검증 | 검증 전 선반 위 경로 거부 |
| 사전 측량 yaw 변환 | 지도 절대 방향 표식·PX4 heading을 여러 위치·기체 방향에서 독립 비교 | 자동 임무 거부 |
| 시작 방향 확인 | 웹 화살표와 측량본으로 환산한 PX4 heading 비교 | 불일치 시 측량·센서 점검 후 재검증 |
| 창고 자력계 | 선반 주변과 비선반 위치에서 방향 오차·reset 확인 | yaw 목표 임무 보류 |
| PX4 heading 품질 | 새 ULog에서 `heading_good_for_control`과 estimator 상태 원인 확인 | 원인 불명 시 yaw 목표 임무 보류 |
| yaw 운용 구역 | 독립 기준 오차가 시험값 ±10° 안인지 구역별 확인 | 구역 밖 자동 임무 거부 |
| 관측 시간 | UWB·LiDAR 수신 지연과 시간 정렬 확인 | 낡은 값을 새 관측으로 사용 금지, 센서별 상실 정책 적용 |

오차 한도와 반복 횟수는 기준 위치 실측 뒤 정한다.
yaw ±10°는 잠정 시험 기준이며 결과에 따라 조정한다.
기체 폭·속도·제동 거리도 경로 여유 계산 전에 측정한다.
현재 외형 50×50cm는 잠정값이다.
PX4 실제 속도 설정과 제동 성능을 따로 확인한다.

## 3. 행동과 실패 주입

Jetson은 같은 입력에 같은 행동 전환 결과를 내야 한다.

| 상황 | 기대 결과 |
|---|---|
| 웹의 모든 경유점 | 순서대로 XYZ·지정/기본 yaw 도착을 확인 |
| yaw 없는 수직 이동 경유점 | 수평 구간이 없으면 현재 방향 유지 확인 |
| 단일 좌표 임무 | 경유점 1개 실행·복귀·착륙 확인 |
| 기본 Jetson 자동 이륙 | 출발점·방향 확인 뒤 이륙·호버·임무 전환 확인 |
| 선택 시작 목표 yaw | 이륙 후 안전 공간에서 PX4 회전·도착 확인 뒤 첫 이동 |
| 시작 yaw 회전 공간 부족 | 자동 이륙 전 또는 RC 인계 전 임무 거부 |
| 출발 방향 복원 | 이륙 직전 방향 기록·복귀 후 착륙 전 회전·오차 확인 |
| 복귀 지점 회전 공간 막힘 | 현재 방향으로 PX4 착륙·원인 기록 |
| 별도 이륙 높이 | 첫 경유점 z와 달라도 수직 상승·안전 지점 고도 변경 확인 |
| 예외 RC 이륙 후 인계 | 웹 시작·PX4 상태 확인 뒤 Offboard 인계 확인 |
| RC 이륙 뒤 웹 시작 전 | RC 조종자가 호버링·제어권 유지 |
| RC 예외 이륙 뒤 수평 이탈 | 웹 시작 인계 거부·RC 제어권 유지 |
| RC 예외 인계 전 yaw 변경 | 웹 방향 화살표 재확인·사전 측량 변환의 유효성 검증 |
| RC 예외 이륙의 현 높이와 웹 이륙 높이 차이 | 인계 뒤 안전 지점에서 높이 조정 |
| RC 예외 이륙에 안전 경로 없음 | 인계 거부·RC 제어권 유지 |
| 웹 취소 | 진행 중단·출발점 복귀·착륙 확인 |
| 지상 준비 중 취소 | 이륙 중단·PX4 지상/시동 상태 확인 |
| 자동 이륙 상승 중 취소 | 목표 이륙 높이를 기다리지 않고 현 위치 PX4 Land |
| 웹 긴급 착륙 | 복귀 없이 PX4 착륙 요청·결과 확인 |
| 다음 지점 z 변경 | 안전 지점에서 먼저 높이 변경 |
| 새 장애물 | 정지·우회 후 같은 필수 경유점 방문 |
| LiDAR 수신만 중단 | 경고·검증된 웹 경로 계속·자동 우회 중지 |
| 웹 비행 경계 없음 | 자동 우회 금지·10초 대기 뒤 복귀 |
| 경계 없는 복귀 | 기록한 진행 경로 역추적·장애물 재검사 |
| 지도 밖 우회 후보 | 경로 선택 거부·대체 경로 또는 복귀 |
| 우회 불가 | 10초 대기 뒤 출발 지점 복귀 |
| 복귀도 불가 | PX4 현 위치 착륙 요청·위험 기록 |
| 위치 관측 중단 | 정지·최대 8초 복구 대기 |

| 수동 인계 뒤 재개 요청 | 같은 비행에서 거부·착륙 뒤 새 임무만 허용 |

| 시작 방향 불일치 | 임무 거부·웹에 방향 재측량·센서 점검 요청 |
| 검증 yaw 구역 밖·선반 위 웹 임무 | 경로 자동 수정 없이 사유를 반환·거부 |
| 웹 출발 표시와 유효 PX4 위치 불일치 | 웹 위치 표시 자동 갱신·좌표 변환 상태 확인 |
| PX4 융합 위치와 UWB 원시값 불일치 | 표시 수정만으로 통과 금지·임무 거부 |
| 비행 중 PX4 yaw 기준 변경 | 이동 중단·PX4 Land 요청 |
| 비행 중 PX4 yaw 품질 상실 | 검증한 품질 신호에서 이동 중단·PX4 Land 요청 |
| 웹 Wi-Fi 단절 | 저장된 유효 임무 계속 수행 |
| 활성 비행 중 새 임무 시작 | 거부·착륙 후 새 명령으로만 시작 |
| 활성 비행 중 새 지도 개정 | 현재 임무의 저장된 지도 유지·새 개정은 다음 임무로 넘김 |
| Wi-Fi 단절 중 yaw 검증 구역 | 저장된 같은 지도 개정의 승인 구역으로 경로 검사 |
| Jetson→PX4 송신 중단 | PX4 Land 전환과 1초·5초 지연 확인 |
| 행동 계층만 정지·송신기는 생존 | 오래된 이동 목표 차단·정지·PX4 Land 확인 |
| 정상 호버 목표값 불변 | 생존 신호가 갱신되면 거짓 정지 없이 유지 |
| Jetson 재시작 | 이전 목표 자동 재송신 금지·PX4 착륙 상태 확인 |
| 일시정지 | 재개·취소까지 호버, 저전력은 선점 |
| 복귀·착륙 중 일시정지/재개 | 요청 거부·기존 단계 유지 |

시뮬레이션에서 전환과 중복 명령을 먼저 확인한다.
그 뒤 안전한 제한 비행에서 PX4 실제 모드를 검증한다.
명령 ACK와 물리적 완료를 각각 기록한다.
ULog·rosbag2·행동 전환 기록을 비행 ID로 연결한다.

## 4. 로그 수집과 삭제

비행 종료 뒤 Jetson 수집을 별도로 시험한다.

| 경우 | 기대 결과 |
|---|---|
| 정상 종료 | Pixhawk ULog 다운로드·파싱·SHA256 기록 |
| 전송 중 연결 중단 | 미완료 표시·재시도, 검증 성공 오표시 없음 |
| ULog 수집 실패 후 새 임무 | 웹 경고를 띄우고 임무 시작 허용 |
| 행동·센서 기록 공간 부족 | 새 임무 거부·공간 복구 후 시작 |
| 잘린 파일·파싱 실패 | 자동 삭제 대상에서 제외·운영 경고 |
| 종료 72시간 경과 | 검증된 Jetson 비행 로그만 정리 |
| UTC 시계 불명확 | 시각 기반 삭제 보류·운영 경고 |
| Pixhawk SD 원본 | Jetson 정리 과정에서 변경하지 않음 |

처음 검증에는 72시간을 실제로 기다리지 않는다.
시험용 시계를 주입해 경계 전후를 확인한다.
운영 시에는 실제 UTC 종료 시각을 사용한다.

## 5. 웹 v1 확장 연동 검증

합성 입력으로 계약을 먼저 확인한다.
요청 ID는 [웹 개발 요청서](WEB_REQUIREMENTS.md)의 W 번호다.
의미 기준은 [계약 초안](WEB_CONTRACT_DRAFT.md)이다.
아래 항목은 시험 계획이며 아직 실행하지 않았다.
합성 시험에는 비행 출력을 연결하지 않는다.
이 시험의 성공을 UWB·실기체 승인으로 쓰지 않는다.

| 시험 | 요청 | 입력·상황 | 통과 증거 |
|---|---|---|---|
| WT01 | W01 | 확장 기능을 모르는 v1 클라이언트 | 부분 실행 없이 미지원 응답 |
| WT02 | W02 | 지도 일부 누락·임무와 개정 불일치 | 준비 거부·누락 항목, 이륙 요청 없음 |
| WT03 | W02·W09 | 같은 지도 개정으로 다른 내용 전송 | 충돌 거부·현재 임무 묶음 보존 |
