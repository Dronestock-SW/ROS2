# 현행 웹 화면 조회 결과
이 문서는 제공된 DroneStock 웹의 실제 조회 결과다.
전체 개편 요청의 기존 화면 대응 근거를 확인할 때 읽는다.

확인일: 2026-10-04, 약 14:42~14:47 KST.
접속: 사용자 제공 `http://203.247.41.82:8876/platform/`.
사용자 PC의 브라우저에서 제공 계정으로 로그인했다.
계정 비밀은 문서·fixture·배포 묶음에 저장하지 않는다.

## 1. 결론

기존 지도·라벨·경로·관제·재고 UI를 확장할 수 있다.
다만 현재 화면의 라벨 z·공통 고도·접근 오프셋·출발 승인 의미를
새 Jetson 계약에 맞추는 작업이 필요하다.
구체적 변경은 [전체 요청서 §4.0](WEB_REDESIGN_REQUEST_2026-10-04.md)을 따른다.

## 2. 조회한 화면

아래는 화면에서 확인한 내용이다. 서버 구현의 유무를 단정하지 않는다.

| 경로 | 관측 |
|---|---|
| `/platform/` | 전체 드론/비행 중/스캔 완료/오류, 재고 진행률, 드론 현황·이벤트 |
| `/platform/drones/routes/` | 기체별 실시간 조회·경로 편집 진입, 창고 배정/LoRa/UWB 표시 |
| `/platform/drones/5/planner/` | 경로·장애물/운영 제어/라벨·앵커 탭, 지도 클릭 추가, 이동 Z 120cm, 경로 적용 |
| 위 라벨 탭 | 포인트 ID·이름·순서·필수/선택·‘작업 Z=드론 스캔 고도’·도착 반경·북동남서·XY |
| 위 운영 제어 | 출발 승인·긴급 복귀·즉시 착륙. 현재 활성 미션 없어 비활성 표시 |
| `/platform/warehouse/editor/?warehouse_id=1` | 창고/앵커/장애물/라벨 탭, cm 크기·셀·비행 고도·라벨 접근 오프셋 50cm |
| `/platform/drones/5/` | 실시간 지도, 배터리/고도/속도, 위치, UWB 삼각측량/Z, LoRa/UWB/Companion 연결 |
| `/platform/drones/5/scan-flow/` | CSI Camera→QR Decode→Retry Buffer→Server API/DB→Live Web, accepted/rejected 누적 |
| `/platform/qr-label/` | QR·ArUco 동시 인쇄 UI, DICT_4X4_50/ID 0 시험 고정, 크기 px·약 mm, QR JSON 예시 |
| `/platform/inventory/` | 품목 기준 완료/미완료/오류, 구역별 현황, 스캔 이력 |
| `/platform/system/ground-station/` | PC 시리얼·브리지 관리, COM 포트/baud, 브리지 로그 |

조회 시 Drone-5는 오프라인·UWB/Companion 미연결로 보였다.
SIM 기체와 실제 기체가 같은 목록에 있다.
목록만으로 SIM/실기체 출력 권한을 판단하지 않게 명시 배지가 필요하다.

라벨 QR 예시는 `schema=drone-stock-item/v1`와
code/name/zone/shelf/slot/location/date를 포함한다.
QR 라벨 생성 화면에는 실제 인쇄 크기와 다를 수 있다는 안내가 있다.
따라서 px→mm 환산 표시를 실측 캘리브레이션으로 사용하지 않는다.

지도 기준 앵커 선택의 A3 표시는 1999cm였고,
라벨·앵커 요약의 A3 절대 Y는 500cm로 보였다.
좌표 기준/개정/표시 변환 차이인지 코드·원본 자료 대조가 필요하다.
이번 검토에서는 UWB 설정·앵커 좌표를 변경하지 않았다.

지상국 화면에는 실제 접속 사이트와 별도 업로드 대상도 표시됐다.
Jetson 계약 서버·PC 브리지·미러 전송의 책임을 구분해야 한다.
별도 대상에는 접속하거나 자료를 전송하지 않았다.

## 3. 현행 흐름과 개편 연결

```text
현재 관측 가능한 메뉴 흐름
창고 맵 편집 → 기체 경로 설정 → 경로 적용/출발 승인 UI
                               → 실시간 조회 → 스캔 흐름/조사 진행률

요청 흐름
지도/라벨 개정 → 임무 초안 → 불변 배포본 → 기체 배정
→ Jetson 검증/계획 → 운영 확인 → 임무 READY → 새 START
→ 비행/스캔/RC 관제 → 착륙 확인 → 작업/업무 결과
```

첫 줄은 메뉴와 버튼의 관측이다.
버튼 저장·전송·실행 순서의 서버 동작을 시험한 것은 아니다.

## 4. 이번 확인 범위와 남은 검수

- 로그인·메뉴 이동·조회·탭 전환으로 확인했다.
- 경로/지도/라벨 저장, 브리지 시작/중지, 승인/비행 명령은 실행하지 않았다.
- 실제 활성 미션·비행 중 상태는 이번 화면에서 확인하지 못했다.
- 프런트엔드 소스·DB·인증 API 구현은 받지 않았다.
- 신규 API의 존재, 10초 만료, 내구성 원장, 재고 중복 방지 등은 공동 시험이 필요하다.

웹팀은 UI-D01~14에 실제 코드 경로와 변경안을 대응해 회신한다.
이 보고서가 신규 계약 구현 완료나 기체 준비 완료를 뜻하지 않는다.
