# B_TF 계산과 목표 FREEZE
C++ 이식 범위와 책임을 설명한다.
센서 어댑터나 실행기에 연결할 때 읽는다.

**FREEZE 대상은 관측값이 아닌 승인 목표 XY다.**
예전 UWB 좌표를 새 측정처럼 보내지 않는다.
이유: 이동 중에도 같은 자리에 있다는 오관측이 된다.

```text
UWB 원시 + ToF + IMU
        |
        v
기존 어댑터: 태그 / 시계 / 장착 / 높이
        |
        v
Frame -> H80 B4 -> ToF B3 후보 -> 연속성 / 재획득
                                      |
                              Decision(ok / reason)
                               /              \
                      새 승인 관측         FREEZE 정책
                          |                  ^
                     원본 시각             주기 tick
                          |                  |
                     기존 FC 브리지     승인 목표 / FC 상태
                                             |
                                      기존 실행기 송신 작업
```

## 이식 범위

| 구성 | C++ 상태 |
|---|---|
| 앵커별 0.8초 거리 이력 | 구현 |
| 7계수 H80·열 정규화·SVD·Huber IRLS | 구현 |
| B4 적합도와 B3 네 후보 | 구현 |
| 앵커별 시각·높이를 쓴 물리 거리 RMS | 구현 |
| 후보 간 점수 차이·이전 후보 추적 | 구현 |
| 근거리·이동 중 재획득 | 구현 |
| 선택형 지상 B3 초기화 | 구현 |
| 선택형 B4 높이 검사·복구 | 구현, 기본 비활성 |
| 목표 FREEZE·입력 무수신 판정 | 독립 API로 구현 |
| 원시 프로토콜·TDMA·시계 보정 | 기존 어댑터 책임 |
| ToF·IMU 장착 변환·시각별 높이 | 기존 어댑터 책임 |
| ROS·MAVLink·PX4 제어 | 이번 이식 범위 밖 |

SVD에는 [Eigen JacobiSVD](https://libeigen.gitlab.io/eigen/docs-3.4/classEigen_1_1JacobiSVD.html)를 사용한다.
역행렬이나 정규방정식으로 바꾸지 않았다.
NumPy와 같은 상대 rank 기준을 적용한다.
라이브러리 차이에 따른 수치 오차는 대조 시험으로 확인한다.

## 계산 기준

| 값 | 기본값·의미 |
|---|---|
| 이력 창 | 0.8초, 고정 출력 지연이 아님 |
| B4·B3 거리 RMS | 0.06m 미만 |
| B3 최선·차선 점수 차이 | 0.015m 이상 |
| 연속성 기준의 이전 관측 나이 | 0.1초 이하 |
| 후보 이동 허용 | 0.1m + 1.0m/s × 간격 |
| 입력 간격에 따른 창 초기화 | 0.15초 초과 |
| FREEZE 관측 만료 | 기본 150,000µs, 생성자에서 지정 |

설정은 Python 기준값을 유지했다.
FREEZE 정책은 추가 복구 대기시간을 두지 않는다.
B_TF 자체의 승인·재획득 결과를 사용한다.
복구 전환 한 tick은 고정 목표를 유지한다.
그 다음 tick부터 경로 진행을 허용한다.

이력 저장 순서도 기준 코드와 동일하다.
이상값의 이력 격리를 새로 적용한 것은 아니다.
따라서 0.824초 공백 해소를 주장하지 않는다.
공백 중 목표와 미션 진행의 동작을 명확히 했다.
이력 격리 후보는 정상 가감속 오거절 검증이 남았다.

## Frame 입력 계약

거리·좌표는 m, source 시각은 µs다.
각 Processor는 한 태그·한 시계 세션만 담당한다.

| 필드 | 계약 |
|---|---|
| `cycle_start_us` | 현재 측정 cycle 시작 |
| `time_us` | 네 `sample_time_us` 중 최대 |
| `sample_time_us` | A1~A4 실제 측정시각 4개 |
| `raw_slant_m` | bias 적용 전 거리 4개 |
| `sample_height_m` | 각 시각의 안테나 높이 또는 null |
| `height_source` | measured_tof_imu / ground_antenna_reference / missing |

ToF 광축 거리를 높이로 바로 넣지 않는다.
이유: 자세·장착·바닥 기준 변환이 필요하다.
높이를 모르면 null을 보존한다.
정상 B4에는 기존 높이 미관측 예외를 유지한다.
B3에는 유효 높이와 후보 검사를 요구한다.
관측 XY 기준은 UWB 안테나·uwb_map이다.
FC 기준 변환과 lever arm은 기존 경계에서 처리한다.

## FREEZE 상태

관측 승인과 목표 송신은 서로 다른 API다.
`last_observation_xy`는 진단용 보존값이다.
새 관측 출력으로 사용할 수 없다.
이유: 보존값에는 새 측정 근거가 없다.

| 조건 | 목표·미션 동작 |
|---|---|
| 승인 관측이 신선함 | 승인 목표 송신·미션 진행 |
| 최신 후보 거절 | 직전 송신 목표 고정·진행 정지 |
| 패킷 무수신·원본 시각 만료 | 같은 목표 고정·진행 정지 |
| 오래된 좌표 재전달 | FREEZE 유지 |
| 정상 관측 복구 | 고정 목표 한 tick 유지 후 재개 |
| FC 보고만 불명확 | 목표 송신 유지·진행 보류 |
| FC 추정 명시적 무효 | FC 보호·조종자 인계에 위임 |
| 승인 목표가 한 번도 없음 | 목표 생성 없이 대기 |

관측 시각과 tick 시각은 같은 host 단조 시계다.
source 장치 시각을 host 시각과 직접 빼지 않는다.
`observe()`에는 시계 보정한 원본 시각을 준다.
수신 시각을 측정 시각으로 덮어쓰지 않는다.

FREEZE는 OFFBOARD 목표 유지 계약이다.
POSCTL로 자동 전환하는 명령이 아니다.
home·미션 시작점도 변경하지 않는다.
FC 추정 XY를 새 UWB 입력으로 사용하지 않는다.
지속 가능 시간은 FC 추정·센서 상태에 달려 있다.
고성능 FC라는 이유만으로 호버 성공을 보장하지 않는다.

## 실행 구조

Processor 인스턴스는 한 계산 작업에서 호출한다.
FreezePolicy 인스턴스는 한 실행기 작업에서 호출한다.
두 객체 자체는 동시 호출을 지원하지 않는다.
작업 사이에는 시각이 포함된 Decision을 전달한다.
기존 목표 송신 작업은 별도로 계속 실행한다.
계산·파일 저장 완료를 기다리지 않는다.
원시 자료와 결정 사유 기록은 비동기로 처리한다.

원시 프로토콜 오류·태그 변경·부팅·시계 변경은
어댑터가 별도 오류로 알리고 필요 시 reset한다.
한 태그의 이력에 다른 태그를 섞지 않는다.
이유: 서로 다른 위치의 거리가 한 경로로 적합된다.
