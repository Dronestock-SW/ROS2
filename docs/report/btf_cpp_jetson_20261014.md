## 연결 범위

수치 계산과 ROS·FC 책임을 분리했다.

```text
기존 UWB 수신 -> TDMA / 원본 시계 / 앵커 시각 검증
                         |
IMU·ToF 전용 실행기 -> 고정 센서 스냅샷
                         |
              MeasuredBtf -> libbtf_native.so
                         |    H80 / B4 / B3 / 연속성
                         v
                기존 발행 검사 / 원본 stamp
                    /                  \
          /uwb/btf_pose          /uwb/btf_decision
                |                       |
          기존 FC 관측 브리지       C++ 실행기
                |               마지막 승인 목표 유지
              PX4 EKF             미션 진행 보류
```

Python은 장비 라이브러리·시각·높이·발행 경계를 맡는다.
C++ 호출 중 인터프리터 잠금을 해제한다.
IMU·ToF 전용 실행기는 계산과 독립적으로 입력을 받는다.
기본 설정은 Python이며 배포 설정에서 C++를 명시한다.
라이브러리가 없거나 ABI가 다르면 시작 실패를 보고한다.
비행 중 조용히 다른 계산기로 전환하지 않는다.

`models.B`의 새 앵커 수·원본 시각·mask도 유지한다.
이 값은 ToF 없는 B4 XY의 발행 검사에 필요하다.
모델 초기화는 높이 충돌 기록을 보존한다.
명시적인 지상 초기화만 그 충돌 상태를 지운다.

## FREEZE 동작

새 목표 진행을 멈추고 마지막 승인 목표를 계속 보낸다.

| 상황 | 처리 |
|---|---|
| 새 후보 거절 | 마지막 pose 나이 만료 전에도 진행 보류 |
| 관측 무수신 | 기존 UWB 만료 판정 뒤 같은 목표 유지 |
| 상태 보고만 지연 | 보고 지연만으로 LAND하지 않음 |
| 정상 pose 복구 | 거절 표본보다 최신 원본 시각 확인 후 재개 |
| 오래된 거절 보고 | 더 최신인 승인 pose를 무효화하지 않음 |
| 실제 FC 추정 불가·좌표 리셋 | 기존 실행기 보호 처리 유지 |
| RC 개입·배터리·전체 미션 제한 | 기존 우선순위 유지 |

새 승인 pose가 와야 보류를 해제한다.
거절 표본과 같은 시각의 pose도 복구로 인정하지 않는다.
`ok=true` 상태 보고만으로 해제하지 않는다.
목표를 떠밀린 현재 위치로 다시 잡지 않는다.
정상 미션 시작점은 기존 POSITION 5초 정책을 따른다.
완료 후 복귀점은 원래 이륙점이다.

오래된 UWB 좌표에 새 시각을 붙이지 않는다.
FC 추정 좌표를 UWB 관측으로 되먹이지 않는다.
FREEZE는 센서 관측이나 유효한 FC 추정을 만들어내지 않는다.

## ToF 100/50/50Hz 반영 범위

이 절은 당시 `-P` 후보 준비 기록이다.
후속 [운영 기준본 r1](tof_operational_baseline_20261014.md)은 `-T` 패치를 채택했다.
두 패치를 겹쳐 적용하지 않는다. 실기 배포는 별도다.

companion의 DISTANCE_SENSOR 요청을 40→50Hz로 바꿨다.
센서 서비스와 미션 노드의 요청값을 맞췄다.
ToF 100ms·IMU 20ms 제한을 유지했다.
현재 FC의 약 100ms 읽기는 이 요청만으로 바뀌지 않는다.

[TFmini Plus 전용 패치](../../src/drone_uwb/firmware/tfmini_plus_50hz/README.md)를 준비했다.
`-P`는 요청 직후 읽기와 20ms 주기를 선택한다.
`-P -C`는 내부 100Hz·일반 전력 설정을 저장한다.
헤더·체크섬·신호 강도·실제 모델 범위를 검사한다.
기존 TF02-Pro 동작은 별도 선택으로 보존했다.
패치 적용 검사는 통과했다.
FC 빌드·업로드와 실제 50Hz 계측은 미실시다.
진행 중인 다른 펌웨어 작업을 덮어쓰지 않았다.

후속 시험은 150ms 이상 모의 생성 지연 시 스택을 남긴다.

진단 재실행의 재진입 공백 시험은 통과했다.

150ms watchdog은 동작하지 않아 원인은 미확정이다.

반응 시점 검사를 디스크 표본 대신 실시간 상태로 고쳤다.

최종 B_TF 웹 재실행은 START HTTP 10초 시간 초과였다.
미션 시작 전 실패이며 통과로 기록하지 않았다.
사용자 요청에 따라 종합 시험 반복을 멈췄다.

## 저녁에 남은 확인

현재는 비행 가능 판정까지 완료한 상태가 아니다.
UWB는 heartbeat만 있고 실제 XY가 없다.
지상 ToF는 약 0.02m를 보고했다.
보고된 유효 하한 0.10m보다 작다.
충분한 거리가 확보됐을 때 유효 측정 여부를 확인한다.
실제 FC 조회에서 `cs_ev_pos=false`였다.
`cs_opt_flow=false`, `cs_rng_hgt=true`였다.
설정값 EV_CTRL·OF_CTRL·RNG_CTRL은 모두 1이었다.
설정 활성화와 실제 융합을 구분한다.
`EKF2_EV_DELAY=0ms`와 상승 제한 0.5m/s를 읽었다.
이번 작업은 FC 파라미터를 쓰지 않았다.
원본 수집기는 inactive였다.
디스크 여유는 약 18GiB다.

조종기·앵커·현장 조종자 준비 후 입력을 확인한다.
현재 부팅·기수로 지상 정렬을 다시 수행한다.
EV·광류 실제 융합과 기록 파일 증가를 확인한다.
그 뒤 웹의 TAKEOFF → POSITION → START를 시험한다.
왼쪽 밀림 해결과 실제 임무 정확도는 아직 미검증이다.

PC 근거는 채팅 작업공간의 다음 폴더에 있다.
`outputs/btf_cpp_20261014/`
