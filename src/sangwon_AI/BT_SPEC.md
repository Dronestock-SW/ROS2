# 행동 트리 상세 명세
이 문서는 노드의 입력·출력·전환·중단·복구 계약이다.
행동 계층을 구현하기 전 상태 전이와 시험 사례를 검토할 때 읽는다.

상태: 내부 구현 명세 v1.0 / 2026-10-02.
사용자 합의 정책은 [DESIGN.md](DESIGN.md)를 따른다.
BT·임무·경로계획은 C++, BehaviorTree.CPP 4 계열을 사용한다.
입출력·프로세스·모의 시험값은 [IMPLEMENTATION_BASELINE.md](IMPLEMENTATION_BASELINE.md)를 따른다.
수치와 미결정 정책은 [MEASUREMENT_REGISTER.md](MEASUREMENT_REGISTER.md)에 모은다.
2026-10-04 보완: [QR_SCAN_SPEC.md](QR_SCAN_SPEC.md)의 스캔 행동을 추가 설계했다.
도착 뒤 ArUco 정렬·호버·스캐너 3회·카메라 판독을 수행한다.
스캔 결과 기록 후 접근 대기점 복귀·안정을 확인하고 다음 목표로 진행한다.
최종 QR 실패·마커 획득 한도 실패·카메라 고장도 같은 처리이며 이동 실패·안전 선점 규칙은 유지한다.
아래 비행 노드와 C++에는 아직 연결되지 않았다.

## 1. 공통 실행 규칙

| 항목 | 규칙 |
|---|---|
| 노드 반환 | RUNNING, SUCCESS, FAILURE. 거부/선점/취소 원인은 결과에 별도 기록 |
| 시작 | 활성화될 때 한 번 enter. 매 tick에 명령·타이머를 다시 만들지 않음 |
| 평가 | 같은 시점의 불변 상태 묶음을 읽음. 오래된 관측은 별도 유효성 검사 |
| 비동기 처리 | API·경로계획·저장은 tick을 막지 않음. 응답의 실행/행동 세대를 확인 |
| 출력 | BT는 의도만 생성. 단일 중재기가 PX4 출력 권한을 가짐 |
| 선점 | 기존 세대 권한 폐기→비동기 결과 무효화→다음 의도 적용 |
| 복구 | 명시된 노드만 재개 가능. 비행 FAILURE 뒤 필수 이동점을 건너뛰지 않음. 스캔 실패는 별도 작업 결과로 기록·대기점 복귀 후 다음 목표 진행 |
| 시간 | 경과 시간은 단조 시각. 웹 만료 UTC·PX4 측정 시각과 구분 |
| 사건 | enter/exit/선점/거부/모드 관측을 실행·비행·행동 ID로 기록 |

### 공유 상태의 최소 의미

| 묶음 | 내용 |
|---|---|
| mission_snapshot | 실행 ID, 고정된 임무·지도·변환·승인본, 순서별 방문 상태 |
| vehicle_state | PX4 연결·모드·armed·landed, 위치·속도·yaw 및 유효성·나이 |
| observation_health | 신규 관측 여부, 위치/yaw 품질, 센서·배터리 상태 |
| control_state | 소유자, 행동 세대, RC 잠금, 복귀/착륙 잠금, 중단 원인 |
| progress | 활성 경유점/구간, 출발 기록, 실제 지나온 검증 경로 |
| scan_context | 라벨 pose·작업 ID, 기체 대기점/판독 후보, 작업 공간·진입/이탈 구간, 시도·결과·복귀 상태. 라벨 pose는 ControlIntent 금지 |
| command_state | 현재 세션, 요청 ID별 수락/실행 결과, 선점 관계 |

목표 의도는 execution_id·action_id·generation·transform_revision,
kind·XYZ/yaw·생성 단조 시각·lease 만료·재검증 상태를 가진다.
출력기는 송신 시각만 새로 써서 lease를 연장하지 않는다.
호버 목표 숫자가 같아도 정상 판단·생존 확인으로 lease를 갱신할 수 있다.
이동 중 planner가 멈추면 BT tick만 살아 있는 것으로 갱신하지 않는다.
계속 쓸 경로의 유효성을 누가 확인했는지 남긴다.
정지 상태의 경로 계산 대기에는 유효한 HOLD 의도를 유지하며 T_plan을 별도로 감시한다.
이동 계획의 정지를 단순한 planner busy로 숨겨 POSITION lease를 계속 갱신하지 않는다.

## 2. 우선순위와 잠금

```text
매 tick의 안전·제어권 평가
  1 RC 인계 / PX4 자체 비상 제어 -> 권한 반환
  2 LAND 잠금 -> LandSequence: 요청 중 B16 / 실제 전환 후 B17
  3 웹 긴급 착륙 / 상승 중 취소 / yaw 상실 / 목표 lease 상실 / PX4 배터리 자체 상실 -> Land
  4 위치 상실 -> RecoveryWait 또는 Land
  5 배터리 30% / 필수 기록 실패 / 목표 도달 실패 -> ReturnHome, 불가하면 Land
  6 RETURN 잠금 -> ReturnHome
  7 취소 -> 지상 중단 / 상승 중 Land / ReturnHome
  8 일시정지 -> Pause
  9 활성 임무 -> Takeoff/RC 인계 -> 시작 yaw -> 순서대로 경유점 -> ReturnHome
 10 지상 대기 / RC 비행 감시
```

동일 tick에 여러 사유가 있으면 모두 기록하고 높은 우선순위 출력을 선택한다.
PX4 자체 배터리 센서 상실은 복귀 대신 Land다.
LAND 잠금은 요청·모드 확인·착륙 감시 전체를 유지한다.
아직 Land 모드가 아닌데 잠금만으로 B17에 건너뛰지 않는다.
이미 PX4가 독립 착륙 중이면 출력 권한을 반환한 채 B17의 종료 감시를 공유한다.
RETURN/LAND 잠금은 잔량 회복·낮은 우선순위 재개로 풀지 않는다.
Land를 시작하면 위치 복구·장애물 해소로 임무를 되살리지 않는다.
지상 이상은 이륙 거부로 처리한다. 지상에서 복귀·회복 호버를 시작하지 않는다.
LiDAR 단절은 병렬 경고와 우회 비활성화다. 명령 평가를 가로막지 않는다.

## 4. 전환·timeout·중단·복구

T_*·E_*는 측정표에 선언된 값이다. 미정값을 0이나 무한대로 대입하지 않는다.

| 노드 | SUCCESS 및 다음 단계 | FAILURE·timeout | 중단·재진입 규칙 |
|---|---|---|---|
| B01 | 모든 준비 검사 통과→B02/B05 | T_prepare 또는 누락→시작 거부 | 새 시작 ID만 재평가. 임무 개정 고정 |
| B02 | 이륙 전 기록 가능→B03, 실제 이륙 때 고정 | 위치/방향/기준점 미확인→시작 거부 | 이후 목표·웹 표시로 home 덮어쓰기 금지 |
| B03 | 실제 OFFBOARD·armed 확인→B04 | T_mode/T_arm·거부→지상 종료, 이미 공중이면 Land | 선점된 arm 응답으로 상승 금지. 늦은 상태까지 확인 |
| B04 | takeoff z·정지 안정→B09 또는 B06 | T_takeoff·유지 불가→Land | 상승 중 취소→현 위치 Land. 재이륙 재시도 없음 |
| B05 | 실제 인계 확인→B06/B07로 안전 고도 조정 | 인계 전 실패→RC 유지·거부 | 인계 이후 RC 조작은 B18, 같은 비행 재개 금지 |
| B06 | 구간 승인→B07/B08 | T_plan/경로 없음→B12, 복귀 경로면 Land | 취소된 계획 결과 폐기, 필수 점 변경 금지 |
| B07 | 목표 z·속도 안정→B08/후속 단계 | 시간 초과→해당 목표 실패·B15, 공간 차단→B12 | 진행 재개 전 수직 공간 재검사. 복귀 단계에서 실패하면 B16 |
| B08 | XYZ 도달·정지→B09/B10 | 장애물→B12. T_progress/T_segment 초과→해당 목표 실패·B15 | 원래 필수 점 유지. 복귀 단계에서 실패하면 B16 |
| B09 | 위치·yaw 안정→B10 또는 시작/착륙 후속 | T_yaw/회전 불가: 임무·시작 yaw는 실패·B15, 복귀점은 현재 yaw로 B16 | yaw 품질 상실은 즉시 B16. 억지 회전 없음 |
| B10 | 모든 조건 T_arrival 연속 충족→B11 | 오차 이탈 시 안정 타이머 리셋, 전체 이동 예산 유지 | pause/복구 후 안정 판정부터 다시 |
| B11 | hover_s 충족→일반 이동점 방문 확정·다음 점/B15. scan은 대기점 준비 후 B21 | 유지 불가→상위 안전 처리 | 선점/조건 이탈 시 체류 완료 금지. 재개 후 안정 판정·체류를 처음부터 계산 |
| B12 | 10초 안 유효 경로·정지 상태→저장한 구간 재검증 후 B06/B21 | 차단 지속 10초→B15, 이미 출발점 복귀 중 차단→B16 | 재계획 반복으로 10초 갱신 금지. scan 접근/이탈 문맥·결과 보존 |
| B13 | 재개 요청·재검증 통과→저장 단계 | 위치/전력/상위 비상→해당 행동 | 시간 무제한, 복귀·착륙 중 진입 거부 |
| B14 | 8초 안 연속 정상·PX4·좌표계·경로 재검증 통과→저장 단계 자동 재개 | 8초 만료 또는 PX4 유지 불가→B16 | 복구 후보 흔들림으로 8초 초기화 금지. PAUSED/RETURN 문맥 보존 |
| B15 | home 도착·정지→B09(이륙 전 yaw)→B16 | home/경로/위치 사용 불가→B16 또는 위치 안전 처리 | pause/resume 거부, 긴급 Land/RC는 선점 |
| B16 | 실제 AUTO.LAND 진입→B17 | T_mode/연결 실패→송신 중단·PX4 failsafe 확인 | OFFBOARD 재진입 금지, 재시도는 N_mode 범위 |
| B17 | 유효 landed=ON_GROUND·armed=false→B19 | T_land 초과→확인 불가 경고·모드 감시 유지 | timeout으로 공중 disarm/성공 선언 금지 |
| B18 | 실제 권한 반환 확인→수동/PX4 감시 | 상태 불명→출력 차단·권한 불명 기록 | 착륙 후 새 임무만. 수동 뒤 웹이 강제 회수 못 함 |
| B19 | 최종 기록 확정·지상 준비→IDLE | 저장 실패→결과 불명/기록 경고, 새 시작 준비 재평가 | 같은 종료 사건/ULog 작업을 중복 생성하지 않음 |
| B20 | 실제 지상·disarmed·미해결 arm 없음→B19 | 상태 확인 실패→종료 미확인, 실제 상승이면 B16 | 늦은 arm 성공 뒤에도 상승 금지, 지상 조건 재확인 후 disarm |
| B21 | 성공/실패 영속 기록→기록 접근 경로 재검사→대기점 복귀·도착 확인→다음 목표/B15 | 판독/정렬 실패·카메라 고장은 작업 실패. 이탈 차단은 B12, 이동 한도 초과는 B15, 귀환 불가 B16 | RC/복귀/Land 선점은 다음 목표 진행 금지. 시도·시간·결과·대기점 보존 |

정상 방문 순서는 B06→필요한 B07→B08→선택 B09→B10→B11이다.
scan 작업은 라벨에서 유도한 기체 대기점에 B06~B11로 도착한 뒤 B21을 수행한다.
라벨 위치 통과를 요구하지 않는다. 대기점 도착·판독 결과·작업 이탈 완료를 분리한다.
B21의 작업 종료는 QR 성공을 뜻하지 않는다. 결과 필드를 별도로 확인한다.
대기점 복귀 정책(RV05)과 웹에 라벨별 허용 구역 요청(RV03)은 확정이다. 구역 형식·자료는 QS-W8 회신 후 검증한다.
접근 정보/작업 공간이 없으면 B01에서 scan 임무 시작을 거부하며 라벨 XYZ로 대체하지 않는다.
비행 중 필수 기록 실패·PX4 위치 상실은 단순 scan 실패로 다음 목표에 넘기지 않는다.
scan 이탈 차단 해소 뒤에는 같은 RETURN_STAGING을 재개한다. 스캔 횟수 초기화·라벨 재방문·다음 작업 전환을 하지 않는다.
시작 yaw와 복귀 yaw는 방문 점을 생성하지 않는다.
일반 이동점 방문 확정에는 같은 기체 목표의 위치·방향 안정 및 hover_s 완료가 필요하다.
hover_s=0이어도 B10 안정 판정은 생략하지 않는다.
지상 취소는 단순한 대기열 삭제가 아니다. 진행 중 arm 요청의 실제 결과까지 B20에서 확인한다.
착륙이 확인되지 않은 상태에서 취소 완료를 선언하거나 disarm하지 않는다.

## 5. 도착·정지·시간의 정의

```text
arrival = valid_pose AND valid_velocity AND valid_yaw
          AND norm(xy - target_xy) <= E_xy
          AND abs(z - target_z) <= E_z
          AND abs(wrap(yaw - resolved_target_yaw)) <= E_yaw
          AND horizontal_speed <= V_arrival_xy
          AND abs(vertical_speed) <= V_arrival_z
          continuously for T_arrival
```

E_yaw는 ±10° 시험 시작값이며 E_xy/E_z·속도·T_arrival은 실측 전이다.
미지원 yaw 관측이나 낡은 데이터로 조건을 통과시키지 않는다.
정지 목표를 만들었다는 사실과 실제 감속·정지 완료는 구분한다.
충돌 여유 검사는 현재 속도에서 제동할 공간까지 포함한다.

일시정지는 경유점 진행 타이머를 멈추고 호버 연속 체류 시간을 초기화한다.
위치 상실·장애물 대기·watchdog 같은 안전 시간은 pause로 늘리지 않는다.
임무의 T_segment는 활성 이동 시간, T_progress는 진행 개선 없는 시간을 측정한다.
개선의 기준·한도는 선택한 실행 프로파일에서 받는다.
정체/완료 한도를 넘으면 해당 목표를 실패로 기록하고 복귀한다. 복귀 자체가 실패하면 착륙한다.

### 복구와 중첩 명령

8초는 위치 상실 사건을 감지한 순간부터 단조 시각으로 센다.
연속 정상 관측 시간과 재계획/재검증까지 8초 안에 끝나야 복구 성공이다.
기한 경계에서는 timeout을 먼저 판정한다. 한 프레임 정상만으로 재개하지 않는다.
회복 전 상태가 PAUSED이면 PAUSED로 돌아간다. 위치 복구가 웹 RESUME을 대신하지 않는다.
RETURN 중 복구되면 RETURN을 계속하고, LAND/RC 잠금은 복구로 해제하지 않는다.
복구 대기 중 취소/저전력/기록 실패가 발생하면 복귀 의도를 저장한다.
위치가 유효해지기 전에는 좌표 복귀를 실행하지 않고, 8초 안 복구 실패면 Land다.

공중 이륙 상승 중 일시정지는 유지 가능할 때 현재 높이에서 정지한다.
재개 시 남은 상승 구간을 검증하고 진행한다. 이 문맥에서 취소는 현 위치 Land다.
지상 준비·인계 전 제어권 미확보 상태에서는 PAUSE/RESUME을 INVALID_PHASE로 거부한다.
복귀·착륙 중 PAUSE/RESUME 거부는 기존 정책대로 유지한다.

### 기록 실패

필수 행동 사건·센서 기록의 쓰기 실패 또는 기록 프로세스 생존 상실은 복귀를 잠근다.
기록 기능이 다시 살아나도 그 비행의 임무를 자동 재개하지 않는다.
복귀가 불가능하면 현재 위치에서 Land를 요청한다.
기록 경고 전송이 실패해도 실제 복귀 판단을 지연시키지 않는다.
일시적인 큐 대기는 허용된 큐/지연 범위에서 감시하며 실패 판정값은 프로파일에 둔다.
비행 후 ULog 수집 실패와 선택 진단 화면 오류만으로 이 비행 중 실패 사건을 만들지 않는다.

## 6. 비행 종료와 로그 작업

마지막 경유점 방문만으로 임무 성공을 선언하지 않는다.
정상 복귀·착륙·시동 해제를 확인한 뒤 최종 성공을 기록한다.
취소·실패·수동 인계 사유는 실제 착륙 여부와 별도 유지한다.
ULog 다운로드는 실제 landed·disarmed 확인 뒤 별도 작업으로 실행한다.
수집 실패는 이미 완료한 비행 결과를 다시 비행 실패로 바꾸지 않는다.
새 임무 시작 시 진행 중 ULog 전송을 중단·재개 대기로 두며 비행 중 다운로드하지 않는다.

새 비행에서는 진행 인덱스·home·시작 yaw·단기 타이머·RC 잠금을 재검증 후 초기화한다.
과거 명령 결과·실행/비행 ID 이력은 지우지 않는다.
Jetson 재시작 후에는 이전 비행을 자동 재개하지 않는다.
