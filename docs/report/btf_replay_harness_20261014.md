# B_TF 외부 재생 시험기 확인 기록

2026-10-14 시험기 검증 결과다. 측정 근거를 확인할 때 읽는다.

## 결론

외부 시험기를 검증하고 A1·B1까지 수행했다.
이후 사용자 요청으로 실행을 정지했다.
정지 직전 원본 capture 폴더가 기존 경로에 없었다.
B2는 입력 확인에서 멈췄고 측정은 시작하지 않았다.
시험 대상 A/B의 처리 코드는 변경하지 않았다.
실기 배포와 현장 서비스 변경도 수행하지 않았다.

비교 절차는 [독립 재생 절차](../runbooks/btf_isolated_replay_20261014.md)를 따른다.
입력 대응 근거는 [원본 감사](btf_replay_identity_20261014.md)에 있다.

## 시험 결과

합성 시험은 실제 B_TF 성능과 구분한다.

| 시험 | 결과 |
|---|---|
| Windows 오프라인 시험 | 22개 통과 |
| Windows ROS 시험 | 환경 차이로 1개 건너뜀 |
| Jetson 합성 시험 01 | 실패. 일부 온도 파일 읽기 예외 |
| Jetson 합성 시험 02 | 통과. 입력 7개·pose 1개 대응·오류 0 |
| Jetson 합성 시험 03 | 실제 import 검증을 추가한 뒤 통과 |
| CPU 누적 tick 환산 | 2초 동안 100tick/100Hz = 50% 확인 |
| PID 재사용 검사 | 시작 tick이 바뀐 구간을 계산에서 제외 |

온도 파일 실패는 `thermal_zone2/3/4`에서 발생했다.
해당 항목은 `cv0/1/2-thermal`이다.
CPU·GPU 온도는 별도로 읽을 수 있었다.
읽기 불가 항목을 0도로 바꾸지 않는다.
실패 시험의 기록도 보존했다.

## 소스·저장 공간 확인

커밋의 원본 바이트로 시험 사본을 고정했다.

| 대상 | 확인 |
|---|---|
| A | Python 파일 157개가 Git blob과 일치 |
| B | Python 파일 158개가 Git blob과 일치 |
| 기존 B 작업본 | 157개 파일이 CRLF. LF 정규화 시 내용 일치 |
| 새 시험 사본 | Git blob 바이트 그대로 `subjects/A`, `subjects/B`에 보존 |
| 이전 결과 압축 | 세 파일 모두 압축 해제 SHA가 원본과 일치 |
| 공간 확보 후 | 약 429MiB. 시작 하한 416MiB 충족 |

원본 비행 기록은 수정하지 않았다.
현장 서비스 기록도 압축·삭제 대상에서 제외했다.

### B1의 외부 환경 변화

기록과 압축본은 보존했다. 변경 주체는 미확인이다.

| 시각·구간 | 관측 |
|---|---|
| 13:16:44~47 KST·입력 전 | 여유 공간 약 420→6,169MiB |
| 13:18:25~29 KST·입력 후 48.6~52.6초 | 여유 공간 약 6,153→7,462MiB |
| B1 회수 중 이후 확인 | A1·B1 원격 디렉터리의 일부 기록 파일 없음 |
| Windows 보존본 | A1 11개·B1 13개 파일 SHA 확인 |

시험기는 이 구간에 대용량 파일을 삭제하지 않는다.
다른 작업의 종류와 영향은 확인하지 못했다.
원격 파일을 추가로 삭제하지 않는다.
동시 작업 여부를 사용자에게 확인했다.
증거는 작업 폴더의 아래 파일에 있다.

- `outputs/abba-environment-anomaly.json`
- `outputs/abba-A1-transfer-verified.json`
- `outputs/abba-B1-transfer-verified.json`

B1 수치는 외부 변화가 겹친 진단 자료로 보존한다.
원인 분리 시험은 재비교 조건을 정한 뒤 진행한다.

## Claude 검토 반영

총 다섯 차례 텍스트 검토를 수행했다.
Claude의 의견을 소스와 실측으로 대조했다.

| 지적 | 반영 또는 정정 |
|---|---|
| RAW→pose 대응 가능성 | 원본과 합성 시험에서 확인 |
| 두 시계의 혼동 | UWB ClockMap과 MAVROS 준비 경로를 구분 |
| RAW/TDMA의 다른 토픽 가정 | 같은 토픽·같은 발행기로 정정 |
| 디스크 부족에 따른 trace 중단 | 416MiB 시작 조건 적용 |
| 실제 import 경로 | 시험 대상 프로세스 내부에서 검증 |
| 시스템 시각 변동 | 행별·1Hz 시계 쌍과 원본 offset 변동을 기록 |
| 회수 작업의 다음 실행 간섭 | 회수·검증·정리 후 기동 대기 시작 |

주된 원인 가설은 입력 만료 뒤 초기화 연쇄다.
정확한 처리 지연 원인은 아직 미확정이다.
전체 비교 뒤 유력 후보부터 분리한다.

5차 검토는 외부 변화가 겹친 B1을 구분했다.
조건 확인 뒤 B2→A2부터 보자는 의견이다.
사용자의 정지 요청으로 후속 재생은 보류했다.
재개 시 원본 위치·해시부터 확인한다.
