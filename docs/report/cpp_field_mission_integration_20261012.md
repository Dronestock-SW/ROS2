# 테스트 웹 미션의 C++ AI 통합
2026-10-12 C++ AI를 현장 시험 경로에 연결한 기록이다.
FINAL-TEST1-SANGWON 설치와 검증 때 읽는다.

12일 후속 [C++ 실행기](cpp_executor_ground_20261012.md)를 추가했다.
아래는 기존 Python 실행기 경로의 검증 기록이다.
`--cpp-executor-binary` 선택 경로는 실행 단계도 C++다.

테스트 웹의 XY·호버 미션도 C++ 판단을 필수로 거친다.
C++가 목표·도착·연속 호버·복귀·착륙 필요성을 판단한다.
Python은 PX4 명령의 응답과 실제 적용을 확인한다.
실물 비행 성공이나 밀림 해결의 기록은 아니다.

## 연결과 책임

FC 명령 송신자는 기존 Python 실행기 하나다.
C++ 프로세스는 ROS·FC 포트를 열지 않는다.

```text
시험 웹 START -> 요청 원장·좌표 계약
                  -> C++ FieldMission BT
                     입력: PX4 위치·속도·높이·상태
                           UWB 위치·나이·브리지 상태
                     출력: 수평 목표·미션 단계·완료 판단
                  -> 단일 Python 명령 실행기
                  -> MAVROS -> PX4
                  <- 명령 응답·실제 목표·실제 기체 상태
                  -> flight_state -> WebSocket -> 웹
```

| 역할 | 구현 |
|---|---|
| 실제 C++ 판단 | sangwon_field_mission_ai |
| 행동 트리 | 기존 BehaviorTree.CPP 4.6.2를 사용한 FieldMission |
| C++ 입력·출력 연결 | CppMissionAI의 별도 I/O 스레드 |
| 명령 전달·응답 확인 | 기존 FlightNode·LocalXYMission |
| 상태 추정·위치·고도·자세 제어 | PX4 |
| 웹 결과 | 실제 AI 세션·단계·결정 순번을 전달 |

기존 sangwon_companiond·Runtime은 REPLAY 전용이다.
모사 기체를 실물로 위장해 이 서비스를 켜지 않았다.
같은 C++ 패키지·핵심 라이브러리에 현장용 판단 경로를 추가했다.
현장용 C++는 모사 위치를 생성하지 않는다.
높이를 비교하지만 고도 궤적이나 자세 명령은 만들지 않는다.
Python은 지상에서 정한 기존 고도 참조만 PX4에 전달한다.

## 적용 범위

현재 범위는 앵커 좌표의 XY·호버·복귀 시험이다.
hover·x·y·xy 네 시험 경로를 사용한다.
새 FINAL 예제의 mission_ai는 cpp_bt다.
실기 local_xy 실행에서 python_test 경로를 거부한다.
Python 단독 단위시험은 회귀 비교용으로 남긴다.
C++ 연결 실패를 Python 실행으로 대체하지 않는다.

이 범위에는 실측 장애물 지도 승인이 없다.
계획 결과에 BOUNDED_LOCAL_XY_ONLY를 기록한다.
obstacle_map_checked=false도 보존한다.
일반 미션의 기존 C++ 지도 검사 연결은 유지한다.
ArUco·QR 실물 스캔 adapter와 전체 미션 실기는 미완료다.
기존 REPLAY의 스캔·회피 시험과 현장 검증을 구분한다.

## 실행 계약

C++와 Python은 한 실행·계획·세션에 묶인다.
다른 계획·세션·역행 순번·두 번째 실행은 거부한다.
바이너리 SHA256과 C++ 계획 참조를 기록한다.
AI 응답의 측정 시각을 수신 시각으로 바꾸지 않는다.
결정의 유효시간은 원래 입력 시각부터 0.15초다.
I/O 응답 대기는 별도 스레드에서 최대 0.1초다.
시작 시 hello 확인만 최대 2초를 기다린다.
그 확인 중에는 기체 명령을 제출하지 않는다.
대기 입력은 최신 한 개로 제한한다.

이륙 완료·도착·호버의 시간 판정은 C++가 소유한다.
Python은 C++의 목표와 작업 순번을 반영한다.
출발점은 이륙 전에 고정한다.
밀린 위치로 home·목표를 다시 정하지 않는다.
UWB 0.25초·브리지 0.35초·FC 위치 0.2초 기준을 유지한다.
RC 인계와 명령 효과 미확인은 재개할 수 없다.
C++는 착륙·DISARM과 실행기의 명령 적용 확인 뒤 END를 승인한다.
실행기가 실패·인계를 선언하면 C++ 판단도 종료한다.

웹 START·ARM도 C++ 연결을 요구한다.
텔레메트리가 만료되면 AI 연결 정보도 표시에서 제외한다.
원장 저장·ARM·명령 응답·END 저장 보호를 유지했다.
FC 센서 융합이나 가짜 UWB 재발행은 추가하지 않았다.
후속 LiDAR 상대 관측은 미션의 제한된 공백 대응에 사용한다.
[LiDAR 구현과 한계](lidar_gap_support_20261012.md)를 따른다.

## 검증

Jetson의 별도 source·build·install에서 검증한다.
ROS 시험은 domain 99·localhost로 분리한다.
FC는 모사 입력이다. 실제 비행 명령은 보내지 않는다.

| 항목 | 결과 |
|---|---|
| C++ 판단 바이너리 | 빌드 성공 |
| 실제 C++ 계약 시험 | 최종 미션 11개·LiDAR 10개 통과 |
| 초기 HTTP·실제 C++·실행기 시험 | 2개 통과 |
| ROS 패키지 | 4개 빌드 성공 |
| 초기 미션·웹·ROS·플랫폼 회귀 | 291개 통과 |
| 최종 인계·C++ 중단·WebSocket 포함 회귀 | 300개 통과 |
| 새 실비행 | 미실시 |

초기 C++ 재시험에서 갱신되지 않은 바이너리를 발견했다.
전송 archive의 0인 mtime이 증분 빌드를 막았다.
전송 완료 뒤 현재 mtime으로 다시 추출·빌드했다.
최종 소스 해시와 빌드 출력도 함께 확인한다.
이 전송 문제를 현장 UWB 공백 원인으로 소급하지 않는다.

정상·0.6초 UWB 공백은 HTTP·WebSocket을 거쳐 END를 확인했다.
C++ 종료는 UNCONFIRMED·LiDAR 손실은 FAILED로 끝났다.
RC 전환은 PILOT_OVERRIDE와 송신 중단을 확인했다.
모두 모사 FC 입력이다.
LiDAR 공백 시험의 최대 AI 왕복은 15.48ms였다.

기존 CTest 전체 묶음의 간헐 지연은 별도 미해결이다.
새 C++ 판단 경로의 통과와 구분한다.
[이전 전체 검증](final_cleanup_20261012.md)의 한계를 유지한다.
