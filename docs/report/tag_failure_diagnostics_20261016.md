# 태그 최초 실패 보존 구현 결과
2026-10-16 진단 구현과 로컬 검증 기록이다.
작업 브랜치를 검토하거나 실물 시험을 준비할 때 읽는다.

**첫 실패를 보존하고 원인별 진단을 추가했다.**
실기 플래싱·운영 서비스 변경은 하지 않았다.
기준은 상원 통합 `70da279`다.
작업 브랜치는 `codex/tag-first-failure-diagnostics-20261016`이다.

| 손실 표시 | 큐 drop·stale·관찰 최대 점유와 원인별 누적 |
| 분석 CLI | 최초·최종·재시도 분모와 기록 손실을 구분 |

[진단 계약](../reference/tag_failure_diagnostics_20261016.md)에 필드와 원인을 정의했다.

## 유지한 동작

**기본 주기와 복구 정책은 그대로다.**
RAW 시작 간격은 20ms, 처리 예산은 18ms다.
네 앵커 첫 시도 뒤 재시도는 최대 한 번이다.
자연 복구는 1500ms 대기를 유지한다.
새 session 대기 100ms도 유지한다.
시험 명령의 자연 대기 우회도 그대로다.
RF 패킷·거리 계산·원본 시각·승인 규칙을 유지했다.
앵커·LoRa·FC 설정과 시계 복구 정책은 바꾸지 않았다.

## 남은 검증

**진단을 켠 실물의 50Hz 성능은 미측정이다.**
호스트 검사는 실제 FreeRTOS 동시 실행을 재현하지 않는다.
실제 SPI·UART 지연과 무선환경도 모형 밖이다.
실물 주기·최장 공백·계측 부하를 비교해야 한다.
앵커의 같은 거래 기록과 원인을 대조해야 한다.
현재 cause는 관찰한 소프트웨어 경로다.
DW3000 고장이나 A4 물리 원인을 확정하지 않는다.
실제 거리 정확도·PX4 융합·비행 검증도 미실시다.
