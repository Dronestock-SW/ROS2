# 10월 10일 자동 수집·생성물 정리
부팅 수집 구현과 실제 지상 확인 결과다.
다음 수동 비행 기록을 준비할 때 읽는다.

## 결과

자동 수집 서비스를 설치·활성화했다.
서비스 재시작 뒤 새 기록이 생기는 것도 확인했다.
실제 전원 차단 후 부팅 시험은 아직 미실시다.
ARM·모드·파라미터 쓰기는 하지 않았다.
수동 호버 회복·UWB 융합 완료를 선언하지 않는다.

사용자는 흐름 현상이 MAG 복원 전임을 확인했다.
MAG_TYPE=0 저장·FC 재부팅은 9일 완료했다.
10일 부팅 수집 설치 때 읽기에서도 0이었다.
FLOW_ROT=4, EV_CTRL=1도 유지됐다.

## 구현과 배포

관측과 수집을 독립 사용자 서비스로 등록했다.
`dronestock-manual-observe.service`는 센서만 연결한다.
`dronestock-manual-capture.service`는 영구 기록한다.
두 서비스 모두 enabled·active를 확인했다.
계정 Linger=yes도 확인했다.
기존 sangwon 서비스 5개는 active를 유지했다.

관측은 MAVROS·UWB·B_TF·고정 주기 요청으로 구성한다.
임무 실행기·EV bridge·vision/setpoint plugin은 없다.
센서 기록용 511 요청은 DISARM 연결 때만 보낸다.
5초마다 반복하던 전역 원점 조회는 포함하지 않는다.
관측 종료 시 서비스가 다시 시작한다.
포트 소유자가 있으면 대기하며 강제로 종료하지 않는다.
MAVROS heap 오류의 근본 원인을 고친 것은 아니다.

수집 파일은 저장소 밖 영구 경로에 둔다.
3분·256MiB 단위이며 저장장치 1GiB를 남긴다.
정상 지상 대기 조각은 최근 3개를 보존한다.
ARM·불명·미완료·오류 조각은 삭제하지 않는다.
그 직전 지상 조각도 보존한다.
부팅별 FC 고정 읽기 결과도 별도 보관한다.
설치·회수 명령은 [절차](../runbooks/manual_capture_boot.md)에 있다.

## 생성물 정리

종료된 큰 로그 128개를 PC에 백업했다.
원본 합계는 2,966,879,595 bytes다.
압축본은 568,346,351 bytes다.
압축본과 내부 파일 128개의 SHA256을 대조했다.
삭제 직전 Jetson 원본 해시도 다시 대조했다.
열린 파일·최근 수정 파일은 대상에서 제외했다.
검증한 파일만 개별 삭제했다.

압축본 SHA256:
`063b06bf9f08bfcb9a67589887dc0b2a37c76645d86d7cac771631b1a469b248`

Jetson 여유 공간은 약 495MiB에서 3.3GiB가 됐다.
소스·현장 설정·Git·원래 사용자 workspace는 보존했다.
기존 실제 수동 비행 원본도 보존했다.
수정된 PX4 SITL 소스와 빌드도 건드리지 않았다.
`.review/`는 생성물 제외 경로로 명시했다.

PC의 기존 압축본 13개도 보관 폴더로 옮겼다.
합계 1,166,679,850 bytes이며 이동 전후 해시가 같다.
이는 삭제가 아니라 증거 파일의 위치 정리다.
기본 보관 폴더는 `Documents/Drone5-evidence/20261010`이다.
원래 위치는 `previous-archives/relocation-manifest.json`에 있다.
공유 Git에는 장치 원본과 개인 경로 목록을 올리지 않는다.

## 남은 순서

1. 실제 전원 재인가 뒤 자동 수집·FC ULog 확인.
2. MAG_TYPE=0 상태에서 수동 호버 복구 확인.
3. 같은 시행의 ROS 기록·ULog·실측 방향 확보.
4. UWB 좌표·시각 보정과 PX4 융합 검증.
5. 기존 C++ 임무 설계로 실행 경로 이식.
6. 이후 사용자 요청에 맞춰 웹 UI 수정.

FC ULog는 부팅 전 2GB 상한으로 멈춘 상태였다.
SDLOG_MODE=1·PROFILE=1은 이번에 바꾸지 않았다.
ROS 자동 수집 성공과 FC 내부 로그 성공은 다르다.
다음 전원 재인가 뒤 logger 파일 증가를 확인해야 한다.
그 전에는 내부 EKF 로그 수집 완료라고 말하지 않는다.
