# PX4 수동 기준값과 자율비행 설정 관리

2026-10-07 Jetson의 실제 Pixhawk에 사용자가 요청한 세 값을 적용했다.
`COM_RC_OVERRIDE=2`, `EKF2_EV_CTRL=1`, `MIS_TAKEOFF_ALT=1.3`이다.
DISARM에서 저장·FC reboot·새 연결의 값 유지까지 확인했다.
자동 임무용 파라미터 적용기는 여전히 미구현이다.
이 일회성 적용은 HOST_OBSERVE의 비행 권한을 켜지 않는다.
RC 16채널은 관측 시 모두 0이었다. 실기 인계는 미검증이다.
세부 근거는 [낮은 앵커 시험 기록](../../docs/report/anchor_low015_bench_20261007.md)을 본다.
아래 2026-10-04 파일 분석과 설계는 당시 자료로 보존한다.

## 1. 확인한 기준 자료

- 사용자 제공 펌웨어: `PX4_v1.17.0_Pixhawk6C_CRSF.px4`.
- 내부 식별: PX4 `v1.17.0`, FMUv6C, board_id=56.
- Git: `d6f12ad1c4f70ad3230afd7d86e971421e02fef4`. 기존 분석 ULog의 해시와 같다.
- 파일 내부 `version=0.1`은 패키지 형식 값이며 PX4 버전이 아니다.
- CRSF 코드 문자열과 파라미터 정의가 포함되어 있다. 실제 드라이버 작동과 커스텀 변경 전체는 소스·실기체 검증이 필요하다.
- 현재 수동비행 기준은 사용자가 현 기체에서 추출했다고 제공한 `FC_praameters.params` 1,095개다.
- [원본 사본](references/px4/FC_praameters_2026-10-04.params)은 참고·복구 검토용이며 자동 전체 로드 대상이 아니다.
- 전체 이름이 펌웨어 내 정의 2,040개에 존재한다. 이것만으로 조합의 유효성이나 실제 장치 적용 여부를 증명하지 않는다.
- 과거 `2026_09_26.params`와 타입 기준 차이는 15개다. RC 보정·모드 매핑·센서 방향·상승 설정·누적값이 포함된다. 과거 파일로 덮어쓰지 않는다.
- 소수점 출력 차이는 FLOAT32 값으로 정규화했다. 상세 값·차이·SHA256은 [검사 보고서](reports/PX4_FIRMWARE_REFERENCE_2026-10-04.json)에 있다.

파일은 전달받은 시점의 스냅샷이다. 실제 연결 후 기체 식별·펌웨어·현재 파라미터를 다시 읽어야 한다.

## 2. Jetson의 책임

Jetson이 검증된 자율비행 설정 프로파일을 읽고, 현 기체와 대조하고, 허용된 차이만 지상에서 적용하도록 구현한다.
BT가 매 임무마다 임의의 파라미터나 PID를 계산하는 방식은 사용하지 않는다.
정상 임무의 목표 좌표·고도·yaw·속도는 PX4 목표 메시지로 전달한다.
속도 프로파일은 PX4의 검증된 제한을 따르며 목표 속도를 바꿀 때마다 영구 파라미터를 바꾸지 않는다.
추력 로그의 정규화 값은 시험 참고 자료다. 모터 힘(N)이나 자동 PID 조정 근거로 직접 변환하지 않는다.

| 구분 | 처리 |
|---|---|
| RC 채널·트림·스위치·CRSF·센서 보정·모터 구성·기존 PID | 현 기체 값을 보존하고 예상치 못한 차이는 점검 항목으로 보고 |
| 자율비행 연결·Offboard·인계 설정 | 해당 펌웨어에서 검증한 작은 변경 목록으로 관리 |
| 배터리 전역 failsafe·실패 지연 | 수동비행 영향까지 시험한 뒤 프로파일 승인 |
| UWB 융합·고도 기준 변경 | UWB 전체 사양 수령 및 실측 전 보류 |

## 3. 현재값과 시험 후보

열거형과 비트 의미는 제공 펌웨어에 내장된 parameter XML로 확인했다.
아래 후보는 적용 완료 값이 아니며, 실기체용 승인 프로파일 파일도 아직 생성하지 않는다.

| 항목 | 현재값 | 설계와 시험 후보 |
|---|---:|---|
| COM_RC_OVERRIDE | 1 | Auto 스틱 인계만 켜짐. Offboard bit 1 추가 후보 `1 → 3`. 기존 bit 보존, 실제 Position/Altitude 인계 확인 |
| COM_RC_STICK_OV | 30% | 초기 유지. 스틱 인계 임계값 실기체 검증 |
| COM_OBL_RC_ACT | 0 Position | Offboard 상실 시 Land 후보 `4` |
| COM_OF_LOSS_T | 1초 | 초기 시험 기준 유지 |
| COM_FAIL_ACT_T | 5초 | 전역 실패 반응 지연. 실제 경로에서 추가 지연 측정 후 단축값 결정. 지연 중 스틱 override 제약도 시험 |
| COM_RCL_EXCEPT | 0 | Offboard RC loss 예외 bit 2 추가 후보 `0 → 4`. RC 스틱 인계 기능과는 별개. 다른 모드의 예외 비트는 임의 변경하지 않음 |
| COM_LOW_BAT_ACT | 0 경고 | 위험 잔량 Land 후보 `2`. 수동 모드에도 영향이 있으므로 기존 RC 비행에서의 결과까지 확인 |
| BAT_LOW/CRIT/EMERGEN_THR | 15% / 7% / 5% | 현 설정의 기록이며 승인된 안전 임계값이 아님. Land 동작과 함께 시험·확정 |
| EKF2_EV_CTRL | 0 | UWB 융합 미설정. 전체 사양 및 융합 검증 전 유지; 없는 z·yaw를 만들어 활성화하지 않음 |
| EKF2_HGT_REF / EKF2_RNG_CTRL | 0 / 1 | 현재 고도 설정 기록. range=1은 조건부 보조이며 ToF만으로 고도를 유지한다는 뜻이 아님 |
| MPC_THR_HOVER / MPC_USE_HTE | 0.35 / 1 | 기준값 보존. PX4 호버 추정 사용 설정, 현재 비행의 실제 호버 추력 확정값은 아님 |
| MPC_XY_VEL_MAX / MPC_Z_VEL_MAX_UP / DN | 2 / 1.2 / 0.5 m/s | 계획 상한 검토 자료. 모든 모드·모든 메시지 경로에서 동일하게 강제된다고 가정하지 않고 출력 경로 시험 |
| RC_CRSF_PRT_CFG / RC_CRSF_TEL_EN | 101 / 1 | TELEM1 사용 설정 보존. Jetson용으로 같은 포트를 덮어쓰지 않음 |
| MAV_0/1/2_CONFIG | 0 / 0 / 0 | 해당 MAVLink 인스턴스 설정. USB MAVLink까지 없다는 뜻은 아님. 실제 배선·채널 확인 후 연결 설정 |

Jetson의 잔량 30% 복귀 판단은 별도 임무 정책이다. PX4 BAT_CRIT_THR에 30%를 그대로 대입하지 않는다.
RC 미연결 이륙 허용을 위해 RC 입력을 비활성화하거나 arming 검사를 일괄 해제하지 않는다.
현 COM_RC_IN_MODE=3 및 RC 설정을 기반으로 무RC 시작·RC 연결 복구·수동 인계 경로를 별도 시험한다.

## 4. 적용기 계약 — 구현 예정

### 입력·출력

- 입력: 실기체 UID/버전/부팅 식별, 최신 armed·landed 상태, 현재 파라미터, 승인 프로파일 ID·해시.
- 프로파일: 대상 기체/펌웨어, 승인 시험 근거, 항목별 이름·타입·허용 이전값·목표값·재부팅 필요 여부.
- 출력: 현재값/목표값 차이, 실제 적용·재조회 결과, 실패 원인, 재부팅 필요, 준비 차단 여부.
- 원본 파일 또는 웹 임무에 임의 파라미터 쓰기 권한을 부여하지 않는다. C++ 설정 관리기가 적용 권한과 상태를 소유한다.
- Python은 오프라인 검사·보고서 작성 보조만 가능하다. 임무 수신 어댑터에서 PARAM_SET을 발행하지 않는다.

### 순서

1. 부팅 자동 연결·진단은 읽기 전용으로 시작한다. 알 수 없는 기체/펌웨어는 설정 적용을 거부한다.
2. 승인 프로파일이 배포되고 지상 설정 작업이 허용된 장치에서만 `PARAMETER_CONFIGURING` 단계에 들어간다.
3. 지상·disarmed·최신 상태, START/비행 출력 잠금, 다른 설정 도구와의 쓰기 충돌 방지 조건을 확인한다.
4. 현재 전체 파라미터를 완전하게 수집·백업한다. 누락·타입 불일치·예상 밖 현재값은 자동 덮어쓰기 대신 차단 사유다.
5. 승인 목록의 필요한 차이만 순차 적용한다. 매 쓰기 직전에도 지상·disarmed 조건을 다시 검사한다.
6. PARAM_VALUE 응답을 대상 기체·이름·타입으로 식별하고 재조회해 값 일치를 확인한다. 송신 성공만으로 적용 성공을 표시하지 않는다.
7. 타임아웃·횟수 제한을 둔다. 구체 재시도 수·시간은 실제 링크 시험 후 설정한다. 비정상 상태·무응답이면 더 쓰지 않는다.
8. 재부팅 필요 항목은 `REBOOT_REQUIRED`로 차단한다. 자동 부팅 루프를 만들지 않고 정비 재부팅 후 식별·현재값을 재검사한다.
9. 모든 적용 및 독립 preflight/임무 검사가 통과해야 READY가 가능하다. 새 웹 START 없이 arm·이륙하지 않는다.

MAVLink 파라미터 쓰기는 원자적 묶음 작업이 아니다. 중간 실패 시 적용된 항목을 기록하고
`PARAMETER_PARTIAL_APPLY`로 자율 시작을 차단한다. 공중에서 원복하거나 원본 전체를 재주입하지 않는다.
기체가 재시작되거나 통신이 끊기면 이전 응답을 신뢰하지 않고 재연결 후 읽기부터 재개한다.
정수/실수 형식과 전송 인코딩은 AUTOPILOT_VERSION capability 및 사용 SDK로 확인한다.
근거: [MAVLink Parameter Protocol](https://mavlink.io/en/services/parameter.html).

### RC 인계와의 관계

비행 시작 전에 자율·수동 비상 인계가 함께 동작하는 설정을 검증해 둔다.
RC가 개입하면 Jetson은 기존 RC 정책대로 제어 출력을 반환한다. 그 순간 파라미터를 바꾸거나 수동 프로파일로 복원하지 않는다.
착륙 후 새 임무 전까지 자율 권한 회수는 금지한다. 수동 모드의 입력·스위치 기능은 현 설정을 따른다.
전역 failsafe 변경은 수동비행에도 남으므로, 이를 숨겨서 “수동 동작 전체가 동일하다”고 표현하지 않는다.

## 5. 검증 완료 조건

- 오프라인: 최신 파일의 타입·누락·차이 검출, 보호 항목 변경 차단, 승인되지 않은 프로파일 거부.
- SITL/모의 링크: ACK 값 불일치·중간 실패·지연 응답·재연결·재부팅·다른 기체 응답·armed 전환 시 쓰기 중단.
- 지상: RC 채널/스위치 유지, Offboard 스틱 인계, RC loss 예외, Offboard loss Land, 배터리 failsafe와 지연의 실제 동작.
- 실기체 연결 시: 제공 바이너리와 설치 펌웨어 식별 대조, UID·파라미터 전체 readback, 배선 충돌 없음.
- UWB: 전체 사양 수령 후 별도 융합 검증. 현재 조건에서 자율 좌표 비행 준비를 승인하지 않는다.

현재 완료 범위는 파일 검사·기준값 보존·이 명세 작성이다. FC 쓰기·펌웨어 설치·자율 설정 적용은 수행하지 않았다.
