# B_TF 독립 재생 비교 절차

처리 지연 회귀를 비교하는 절차다. A–B–B–A 실행 전에 읽는다.

## 범위

시험 대상 A/B는 고정하고 외부에서 관측한다.
실제 FC·센서·현장 서비스 설정은 변경하지 않는다.
제어 경로와 섞이면 지연 원인을 구분할 수 없다.

```text
13일 capture -> 발행기 -> B_TF 시험 대상 -> 독립 수신기
                           |
                  별도 1Hz 자원 관측기
```

네 구성은 각각 별도 프로세스다.
B_TF의 기존 내부 스레드 구성은 유지한다.

## 고정한 입력과 소스

입력 전체와 동일한 현장 설정을 사용한다.

| 항목 | 고정값 |
|---|---|
| A | `19cdb8b975b2d56107d7e470289da6e7779bec2a` |
| B | `d586e836402066269b1d7e85d4c803f2f748a724` |
| 입력 SHA-256 | `829d1055c8d7e49b3c4e019560cb5bf4b278b885496b06c030412da5cc30c91e` |
| 설정 | capture manifest의 `field-btf.json` |
| 재생 속도 | 수집기 관측 순서 전체, 1배속 |
| 메시지 격리 | `ROS_DOMAIN_ID=99`, `ROS_LOCALHOST_ONLY=1` |
| 시험 토픽 | `/btf_replay` 아래로 remap |
| 임계값 | 현장 설정 유지. ToF 100ms·IMU 20ms |
| 기록 | B의 기본 trace 유지. A에 추가하지 않음 |
| 원본 위치 | 이전 [검증 기록](../report/btf_sensor_timing_20261014.md) 참조 |

소스 기준은 Git blob의 원본 바이트다.
`git archive`의 줄바꿈 변환을 기준으로 쓰지 않는다.
각 `.py`의 SHA-256을 `source-lock-A/B.json`에 저장한다.
실행기는 파일 목록·해시·revision을 대조한다.
파일이 다르면 재생 전에 종료한다.
실제 시험 대상 프로세스에서도 import 경로를 확인한다.
불러온 모듈의 경로와 해시를 기록한다.

원격 시험 소스는 `subjects/A`, `subjects/B`에 둔다.
기존 재생 작업본과 과거 결과는 보존한다.

## 시각과 대응 규칙

소스 나이와 처리 지연은 따로 계산한다.

| 값 | 정의 |
|---|---|
| 주 지연 | RAW 발행 호출 직전 단조 시각 → pose 수신 콜백 진입 단조 시각 |
| TDMA 보조 지연 | 대응 epoch 발행 직전 → pose 수신 |
| 발행 간격 | RAW 발행 직전 → 대응 epoch 발행 직전 |
| 발행 시 소스 나이 | 실제 발행 ROS 시각 − 이동된 원본 수신 ROS 시각 |
| 발행기 지연 | 실제 발행 직전 단조 시각 − 예정 단조 시각 |
| 기존 `processing_ms` | 기존 노드의 측정값. 순수 fit 시간으로 해석하지 않음 |

전체 입력에 한 개의 ROS 시각 이동량을 적용한다.
이동 대상은 유효한 header stamp와
envelope의 `host_received_ros_ns`다.
센서값·센서 시각 간격·원본 단조 시각은 보존한다.
TimesyncStatus의 remote timestamp와 offset도 보존한다.
해당 코드의 준비 판정은 offset 변화량을 사용한다.

150ms 입력 만료는 노드의 ROS 시각으로 판정한다.
원본 단조 시각을 실행 host의 단조 시각에서 빼지 않는다.

RAW와 TDMA는 같은 `/uwb/received` 토픽이다.
같은 발행기가 원본 행 순서로 발행한다.
다른 센서 토픽의 콜백 순서까지 복원하지 않는다.

대응 규칙과 한계는 [입력·출력 감사](../report/btf_replay_identity_20261014.md)를 따른다.
대응 불명확 자료는 지연 백분위에 넣지 않는다.
개수와 이유는 그대로 남긴다.

## 실행 전 준비

각 실행에 같은 절차와 저장 공간 조건을 적용한다.

1. 전원·클록 정책과 실행 환경을 유지한다.
   앞 실행의 압축·회수·정리를 먼저 마친다.
2. 입력·설정 해시와 소스 해시를 대조한다.
3. 새 결과 디렉터리를 만든다.
4. 저장 공간 416MiB 이상을 확인한다.
5. 발행기·수신기·시험 대상·자원 관측기를 기동한다.
6. 입력 구독자와 출력 발행자가 각 1개인지 확인한다.
7. 예상하지 않은 domain 참여자가 있으면 시작하지 않는다.
8. 입력 없이 60초 동안 자원 상태를 관측한다.
9. 시작 5초 전 시각을 기준으로 메시지를 변환한다.
10. 변환이 시작 100ms 전까지 끝나지 않으면 시작하지 않는다.

60초 대기는 첫 sync를 강제로 만드는 과정이 아니다.
센서나 timesync를 미리 발행하지 않는다.
발행기에서만 재생 중 GC를 비활성화한다.
시험 대상의 GC 정책은 변경하지 않는다.

416MiB의 산정은 다음과 같다.

| 용도 | 예산 |
|---|---:|
| B trace의 최소 여유 기준 | 256MiB |
| trace 회전 최대 공간 | 128MiB |
| 압축된 외부 산출물 | 16MiB |
| 추가 여유 | 16MiB |

이전 작업 산출물은 무손실 압축할 수 있다.
압축 해제 SHA가 원본과 같은지 먼저 확인한다.
원본 비행 로그와 현장 서비스 기록은 대상에서 제외한다.
각 실행 후 대용량 산출물을 Windows로 회수한다.
파일 해시가 같은 것을 확인한 뒤 원격 복사본을 정리한다.

## 재생과 관찰 종료

전체 입력을 한 번 재생하고 2초를 더 관찰한다.

1. A1 → B1 → B2 → A2 순서로 실행한다.
2. 동시에 두 시험 대상을 실행하지 않는다.
3. 행별 예정·발행 직전·발행 직후 시각을 남긴다.
4. 마지막 발행 뒤 2초를 고정 관찰 창으로 둔다.
5. 시험 대상을 종료하고 최종 상태를 수집한다.
6. 수신기를 종료한 뒤 파일을 압축 저장한다.
7. 관찰 창 뒤 도착한 출력은 별도 분류한다.
8. 입력 발행 구간과 2초 관찰 포함 구간을 따로 보고한다.

수신 콜백은 시각·문자열·pose 필드만 보관한다.
문자열의 JSON 해석은 관찰 후 수행한다.
수신 기록 한도를 넘으면 계측 오류로 남긴다.
미관측 자료를 조용히 제외하지 않는다.

## 산출물과 판정

한 실행의 결과를 다른 실행으로 덮어쓰지 않는다.

| 파일 | 내용 |
|---|---|
| `manifest.json` | 소스·도구·입력 해시, 프로세스, 환경, 기동·종료·오류 |
| `config.json` | 사용한 현장 설정 |
| `feeder.jsonl.gz` | 원본 행별 식별자와 실제 발행 시각 |
| `observed.jsonl.gz` | 외부 수신 시각과 원문 출력 |
| `links.jsonl.gz` | 입력·판정·pose의 대응 결과 |
| `summary.json` | 지연·처리시간·개수·분기·공백 |
| `observer.json` | 연결 상태, 1Hz 참여자 관측, 기록 오류 |
| `resources.jsonl.gz` | 1Hz CPU·메모리·온도·주파수·여유 공간 |
| `sampler.json` | 자원 관측 오류와 단위 |
| `subject.log` | 시험 대상 표준 출력·오류 |
| `imported-source.json` | 실제 시험 대상 프로세스가 불러온 모듈·경로·해시 |
| `internal-trace/` | B에 원래 존재하는 내부 기록 |

표본 사이의 CPU 사용량은 누적 tick 차이로 계산한다.
PID/TID 재사용과 관찰 범위를 확인한다.
CPU 시간만으로 GIL 원인을 확정하지 않는다.
읽을 수 없는 온도 파일은 null과 오류명으로 남긴다.

결과는 아래 세 범주로 구분한다.

| 범주 | 예 |
|---|---|
| 실험 오염 | 입력·해시 오사용, 확인된 외부 참여자, 시험기 오류 |
| 해당 구성의 실패 | 시험 대상 crash, trace 실패, 만료·거부·출력 공백 |
| 원인 미분리 | 시험 대상 부하와 함께 나타난 발행 지연·발열·디스크 압박 |

실패 실행도 보존한다.
느린 실행을 수치만 보고 삭제하지 않는다.
첫 네 번은 회귀 방향을 확인하는 비교다.
버전당 두 번으로 통계적 확정을 주장하지 않는다.

## 도구 확인 상태

합성 확인은 실제 B_TF 성능 검증과 구분한다.

| 확인 | 결과 |
|---|---|
| 식별·중복·미관측·시각 불변성 | 오프라인 시험 통과. 최신 개수는 검증 기록 참조 |
| Jetson 첫 합성 시험 | 온도 파일 읽기 오류로 실패. 기록 보존 |
| 오류 처리 보완 후 합성 시험 | 7개 입력, pose 1개 대응, 오류 0 |
| 13일 원본 전체 A–B–B–A | 아직 미실시 |
| 실제 기체·FC 배포 | 보류 |
