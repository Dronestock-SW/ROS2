# 현장 웹 설정과 RC 인계
천장·자동 출발점·시험 경로를 준비하는 절차다.
현장이 바뀌거나 첫 비행을 준비할 때 읽는다.

## 1. 지상 세션에서 천장을 저장한다

웹의 천장 입력 또는 다음 명령을 사용한다.

```json
{"action":"set_ceiling","ceiling_height_m":3.0}
```

`POST /local/command`에 JSON으로 보낸다.
값은 공통 바닥에서 천장까지의 m다.
필요하면 가장 낮은 장애물 높이를 적용한다.
이 값만으로 지도 측량을 완료 처리하지 않는다.
실측 지도의 낮은 상한을 더 높이지 않는다.
기체 바닥 높이·수직 여유를 C++ 검사기에 전달한다.
실측 높이가 없으면 경로를 거부한다.

저장 응답의 `flight_command_sent`는 false다.
PX4 이륙 높이와 고도 제어는 바뀌지 않는다.
`--site-config` 파일에 기체·배치와 함께 저장한다.
생략 시 사용자 상태 폴더의 `site-<ID>.json`을 쓴다.
시험 환경은 반드시 별도 파일을 지정한다.
이유: 가상 환경 설정과 실물 설정을 섞지 않아야 한다.

START 후에는 천장을 바꿀 수 없다.
지상 상태가 오래됐거나 공중이면 변경을 거부한다.
새 현장은 착륙·disarm 확인 뒤 새 세션으로 준비한다.

## 2. 출발점을 자동 확인한다

PX4 EKF2 위치를 검증된 창고 좌표로 변환한다.
안테나 XY를 기체 위치로 대신 사용하지 않는다.
지상·최신 상태·좌표 정렬·추정기 유효성이 필요하다.
값이 없으면 `(0,0)`이나 과거 좌표로 채우지 않는다.
이유: 복귀점이 실제 출발점과 달라질 수 있다.

웹에서 시험 종류와 `시험 경로 만들기`를 선택한다.
시작 명령에서도 출발점을 다시 읽는다.

```json
{"action":"start","trial_case":"hover"}
```

| trial_case | 시작점 기준 계획 |
|---|---|
| hover | PX4 이륙·안정화·2초 체류·복귀 확인·착륙 |
| x | X +1m·출발점 복귀·착륙 |
| y | Y +1m·출발점 복귀·착륙 |
| xy | X +1m·Y +1m·역순 복귀·착륙 |

축은 A1→A2=X, A1→A3=Y다.
1m 구간은 직선 위 0.5m 경유점을 거친다.
이유: 도착 오차가 실제 명령 거리 제한을 넘지 않게 한다.
기체 heading 방향의 앞·옆 이동이 아니다.
계획 후 PX4 출발점이 0.1m 넘게 바뀌면 거부한다.
전체 미션은 지상 정지 3초도 확인한다.
실행 시작 위치를 home으로 고정한다.
상승 목표는 PX4 `MIS_TAKEOFF_ALT`다.
정확히 2초 뒤 강제로 착륙시키지 않는다.
안정화·목표 적용·도착을 확인한 뒤 체류를 센다.

## 3. 실제 RC 인계를 검증한다

RC는 수신기에서 PX4로 직접 연결된다.
companion이나 웹을 경유하지 않는다.

```text
RC 스틱 / 모드 스위치 ──────> PX4 제어·failsafe
                                   │ 모드 관측
                                   v
웹 START -> 단일 미션 실행기 -> PILOT_OVERRIDE
                                   │
                          명령 중단·스캔 취소
                          자동 재개 없음
```

현재 읽힌 매핑은 모드 CH5·시동 CH8·킬 CH7이다.
2026-10-09 모드 스위치의 실제 전환을 확인했다.
사용자 승인으로 중앙 OFFBOARD를 Position으로 바꿨다.
현재 배치는 Altitude / Position / Land다.
`COM_FLTMODE4=2`를 저장·재조회했다.
이후 실제 ALTCTL→POSCTL 전환도 확인했다.
설정 변경 뒤 스위치를 한 번 전환해 실제 모드를 확인한다.
웹 START 전에 Position에서 대기한다.
웹 실행은 PX4 native 자동 모드를 요청한다.
RC OFFBOARD 위치는 필요하지 않다.
시동·킬 스위치와 공중 인계 시험은 아직 남았다.
프로펠러를 제거하고 수신·매핑·보정을 먼저 확인한다.
모드 스위치로 Position/Altitude 전환을 확인한다.
실제 stick override 비행 검증은 조종자가 별도로 수행한다.
RC가 꺼져 있으면 이 단계는 통과할 수 없다.

`COM_RC_OVERRIDE=3`은 AUTO·Offboard 비트를 켠다.
`COM_RC_STICK_OV=30`은 현재 PX4 문턱이다.
작은 잡음이나 모든 보조 버튼을 수동 인계로 해석하지 않는다.
실제 할당된 모드·시동·킬 기능은 PX4 설정을 따른다.
실행기는 FC가 지정한 스위치 채널을 읽는다.
시작값에서 100μs 이상 바뀌면 미션을 중단한다.
이는 새 모드 이름을 수신하기 전에도 적용된다.
보조 채널·10μs 흔들림은 수동 인계로 보지 않는다.
이 감시는 PX4에 가짜 RC 값을 주입하지 않는다.
인계 뒤 웹 START·복귀·착륙으로 RC를 덮지 않는다.
공중 프로세스 재시작도 명령을 보내지 않는다.
이미 보낸 명령의 전달 자체를 취소할 수는 없다.
늦은 응답을 후속 미션 명령의 근거로 쓰지 않는다.

새 비행은 착륙·disarm 뒤 새 지상 세션에서 시작한다.
설정·물리 검증 구분은 [현장 기록](../report/field_readiness_20261009.md)을 따른다.
