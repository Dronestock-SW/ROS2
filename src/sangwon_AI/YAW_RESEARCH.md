# sangwon_AI 목표 yaw·방향 기준 검토
이 문서는 웹 목표 yaw와 PX4 heading의 관계를 연구한다.
방향 입력·좌표계·센서 검증을 합의할 때 읽는다.

상태: 지도 절대 yaw·사전 측량 변환 채택, 각도 수치 계약·실기체 검증 전 / 2026-09-27.
기준 설계: [DESIGN.md](DESIGN.md).

## 1. 서로 다른 세 값

| 값 | 뜻 | 상태 |
|---|---|---|
| 목표 yaw | 지도에 그린 절대 방향. 경유점 도착 후 요구하는 기체 앞 방향 | 의미 확정, 수치 기준 협의 중 |
| 현재 heading | PX4가 추정한 기체 앞 방향 | 자력계만 확인됨, 품질 검증 필요 |
| 지도↔PX4 변환 | 웹 목표 방향을 PX4 목표로 바꾸는 관계 | 사전 측량해 버전 보관, 매 비행 유효성 확인 |

목표 yaw가 있어도 현재 heading과 좌표계 변환이 틀리면
PX4가 목표 수치에 맞춰 회전하더라도 지도상 방향은 틀릴 수 있다.
웹의 시작 방향 화살표는 현재 기체가 놓인 방향의 확인값이다.
화살표로 변환값을 매 비행 다시 계산하지 않는다.
화살표 자체가 경유점의 목표 yaw는 아니다.
웹에서 기체 위치를 PX4/UWB 값으로 수정하는 것도
기체가 향한 방향을 측정하는 일과 다르다.
기존 `UWB_ANCHOR_LOCAL`의 A1→A2축과 A1→A3축은
실측상 직교하지 않는다. 이 좌표에서 각도를 바로 구해
목표 yaw로 쓰기 전에 직교 좌표 변환을 합의해야 한다.

## 2. 현재 로그에서 확인한 것

제공 ULog는 RC 수동 호버링 기록이다.
`EKF2_MAG_TYPE=0`, `EKF2_EV_CTRL=0`, `EKF2_GPS_CTRL=0`이다.
기록된 두 estimator_status_flags 인스턴스에서
`cs_mag_hdg=1`, `cs_ev_yaw=0`이었다.
즉 이 로그에서 확인되는 heading 원천은 자력계이고,
외부 yaw 융합의 증거는 없다.
`vehicle_local_position.heading_reset_counter`는
기록 구간 709개 표본에서 모두 3이었다.
같은 표본의 `heading_good_for_control`은 모두 false였다.
원인과 자동 모드에서의 의미를 지상 시험으로 확인해야 한다.
비행 이전 reset 횟수나 지도 기준 yaw 정확도는 알 수 없다.
사용자가 현재 방향 센서는 PX4 자력계뿐이라고 확인했다.
UWB의 현재 계획은 XY 위치 융합이며 yaw 관측은 없다.
기존 저장소의 [UWB·SLAM 선행 검토](../../docs/prior_art_uwb_slam.md)는
철제 선반 주변 자력계 오차와 yaw 소스 부재를 최우선 위험으로 지적했다.
이것은 비행 가능 판정이 아니라 창고 실측이 필요한 이유다.

[PX4 EKF2의 heading·외부 yaw 설명](https://docs.px4.io/v1.17/en/advanced_config/tuning_the_ecl_ekf),
[PX4 Offboard 위치 목표 설명](https://docs.px4.io/v1.17/en/flight_modes/offboard).

## 3. 제안하는 목표 표현

웹 yaw는 **지도 좌표계의 절대 목표 방향**이다.
Jetson이 검증된 지도↔PX4 변환을 적용해 목표를 송신하고,
PX4가 회전과 yaw 유지를 제어한다.
회전 속도나 추력을 웹 yaw 값으로 직접 제어하지 않는다.
MAVROS를 쓰면 ENU/NED 변환이 중복되지 않게 확인한다.

사전 측량한 변환에는 지도 yaw 기준·회전 부호·PX4 프레임
기준과 기체 설정을 포함한다. 양쪽 각도를 같은 부호로
정규화할 수 있을 때의 표현은 아래와 같다.

```text
PX4 목표 yaw = wrap(지도 목표 yaw + 사전 측량한 방향 오프셋)
```

부호가 다르면 변환에 그 부호도 명시한다.
PX4/MAVROS의 각도 단위·ENU/NED 변환을 포함해 중복 변환을 막는다.
기체 방향을 바꿔 놓아도 유효한 변환이어야 하며, PX4 좌표계가
재설정되거나 자력계 보정·장착 상태가 달라지면 재검증한다.
고정 변환은 비행 중 위치별 자력계 오차를 보정하지 못한다.
웹 각도 계약과 실측 검증 전에는 실제 명령에 쓰지 않는다.

| 선택할 의미 | 장점 | 결정할 점 |
|---|---|---|
| 도착 yaw | 해당 좌표에서 바라볼 방향 명확 | 사용자 확정, 회전 공간 검증 필요 |
| 구간 yaw | 이동 중 바라볼 방향 고정 | 현재 임무 범위에서 제외 |
| yaw 생략 시 경로 접선 | 웹 입력을 줄일 수 있음 | 기존안 유지, 코너 검증 필요 |

선택 yaw는 도착 자세로 사용한다.
없으면 이동 방향을 바라보는 기존안을 유지한다.
도착점의 기본 yaw는 마지막 수평 경로 구간 방향이다.
수평 구간이 없으면 현재 방향을 유지한다.
별도 시작 목표 yaw는 선택 항목이다.
있으면 이륙 후 첫 이동 전에 회전 공간을 확인하고 목표 방향으로 돈다.
RC 이륙 예외는 인계 전 안전 경로와 회전 공간을 확인한다.
회전 공간이 없으면 해당 시작 임무를 거부한다.
이륙 직전의 실제 방향을 출발 기록에 저장한다.
복귀 뒤 착륙 전 안전 공간에서 그 방향으로 다시 돈다.
복귀 지점에서 회전이 안전하지 않으면 현재 방향으로 착륙하고
방향 복원 실패를 기록한다.
웹 각도의 0°·부호·단위와 PX4 변환 수치는 미확정이다.

## 4. 정렬과 검증 후보

1. 웹 지도와 UWB/PX4 위치 좌표의 축·원점 관계를 확인한다.
2. 지도에서 방향이 측량된 지상 표식으로 PX4 heading과의
   변환을 측정한다. 웹 시작 화살표는 현재 놓인 방향의 확인에 쓴다.
3. 기체를 지상에서 서로 다른 방향으로 두고 PX4 heading과
   독립 기준의 차이를 반복 측정해 변환의 재현성을 확인한다.
4. 창고 선반·전류가 자력계 방향을 바꾸는지 확인한다.
5. 시뮬레이션과 제한 비행에서 목표 0°/90°/180°,
   ±180° 경계, 제자리 회전, 경로 코너를 시험한다.
6. 매 비행 전 웹 확인 방향과 변환된 PX4 heading을 비교한다.
   허용 오차를 넘으면 임무를 거부하고 측량값·센서를 점검한다.
   화살표만 바꿔 보정한 것으로 간주하지 않는다.
7. 목표·실제 yaw, PX4 heading 품질·reset,
   웹 지도 개정과 변환 버전을 같은 비행 ID로 기록한다.

단일 UWB 위치값만으로 기체가 향한 방향을 직접 측정할 수 없다.
현재는 두 번째 방향 센서가 없다.
자력계만으로 충분한지는 창고 실측 후 결정한다.
창고 내 한 위치의 정렬 성공을 전체 구역으로 일반화하지 않는다.
선반 근처를 포함한 운용 구역에서 방향 오차를 측정한다.
도착 yaw 오차 ±10°를 잠정 시험 기준으로 사용한다.
독립 방향 실측으로 검증한 구역 안에서만 자동 임무를 허용한다.
출발·경유·복귀 경로 전체가 그 구역 안에 있어야 한다.
구역의 기록은 지도 개정과 기체·자력계 설정에 묶는다.
웹 지도에 구역 경계·승인 결과를 저장하고 Jetson이 검증본을 보관한다.
PX4 yaw 기준이 비행 중 재설정되면 이동을 중단하고
PX4 Land를 요청한다는 실패 동작은 이미 합의했다.
PX4가 yaw 추정 품질 상실을 명확히 보고해도 같은 동작을 한다.
품질 판정에 사용할 PX4 신호는 지상 시험으로 확정한다.
검증 전에는 지도 기준 목표 yaw를 성공했다고 선언하지 않는다.
