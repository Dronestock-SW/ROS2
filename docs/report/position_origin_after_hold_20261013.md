# POSITION 뒤 미션 시작점 확정
13일 사용자 요청으로 바꾼 시작점 정책과 검증 기록이다.
저녁 웹 시험 또는 다음 노트북 세션 전에 읽는다.

미션 시작점과 원래 이륙점을 분리했다.
브랜치는 `이번에-상원-한거-통합-브랜치`다.
실제 비행과 왼쪽 밀림 해결은 아직 미검증이다.

## 현재 흐름

```text
웹 TAKEOFF → 원래 이륙 XY / 높이 1.7m
    → 실제 POSCTL 확인 → 연속 5초 안정
    → 그 순간의 FC XY를 미션 시작점으로 한 번 저장
    → 별도 웹 START → 저장한 XY 송신 / OFFBOARD 재진입
    → 호버·좌표 작업 → 원래 이륙 XY 복귀 → 착륙·DISARM → END
```

| 좌표 | 결정 시점 | 용도 |
|---|---|---|
| `home_xy_m` | 지상 TAKEOFF 접수 | 이륙 목표·최종 복귀·착륙 |
| `mission_start_xy_m` | POSCTL 연속 5초 안정 뒤 | 별도 START와 상대 시험 경로의 기준 |
| `goal_xy_m` | C++ 경로 실행 | 현재 FC에 송신하는 목표 |

저장하는 값은 공통 지도 좌표의 FC 추정 XY다.
독립 UWB XY·각 입력 나이·원본 stamp도 함께 기록한다.
UWB와 FC 추정 위치를 같은 측정이라고 해석하지 않는다.
캡처 기록은 `mission_start_capture`에서 확인한다.
웹은 C++ 시작점이 없을 때 현재 XY로 대체하지 않는다.

## 5초와 복귀의 의미

실제 POSCTL 확인 뒤부터 안정 시간을 센다.
FC 위치·UWB·속도·높이 조건을 함께 확인한다.
5초가 끝난 순간의 XY를 저장한다. 평균 좌표가 아니다.
관측 공백이나 200ms 초과 처리 공백은 누적을 초기화한다.
확정 후에는 움직임에 따라 시작점을 다시 저장하지 않는다.
확정 후 공백은 START 준비를 다시 확인하게 한다.

이륙 단계의 원래 XY 목표와 기존 보호 기준은 유지한다.
POSITION 전환 전 안정 확인은 기존 3초다.
POSITION 뒤 5초 안정 확인이 이번 변경이다.
상승 제한은 0.5m/s다. 수평 목표 제한은 0.25m/s다.
자세·높이·위치 제어는 PX4가 담당한다.

| 단계 | 유지한 조건 |
|---|---|
| POSITION 요청 전 | 원래 이륙점 대비 FC XY 0.15m 이내, UWB XY 0.25m 이내 |
| POSITION 뒤 5초 | 대기 기준점 대비 같은 XY 범위, 연속 신선한 입력 |
| 두 안정 구간 | 수평·수직 속도 각 0.1m/s 이하, 높이 오차 0.15m 이하 |
| 별도 START 전 | 원래 이륙점 대비 0.6m 초과 이탈 보호 유지 |

따라서 이륙점으로부터 22cm 이탈이 계속 남으면,
첫 조건을 통과해 POSITION으로 전환하지 못할 수 있다.
시작점 확정 정책이 이륙 단계의 오차를 허용한 것은 아니다.
실제 이동·추정 오류·좌표 정렬을 기록으로 구분해야 한다.

미션 AI는 시작점에서 경로 송신을 시작한다.
작업 경유점을 역순으로 돌아 원래 이륙점에 도착한다.
호버 작업의 XY 이동 길이는 0m다.
시작점이 옮겨졌다면 작업 뒤 복귀 이동은 생긴다.
원래 이륙점을 덮어쓰면 복귀 목적지를 잃으므로 보존한다.

## 검증

실물 FC에 명령하지 않고 가상 FC로 검증한다.
Jetson 시험은 격리 ROS domain 99를 사용한다.

동일 시험의 후속 실행은 통과했다.
