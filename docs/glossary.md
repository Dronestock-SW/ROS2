# 용어 사전 (Glossary)

> 프로젝트에 등장하는 기술 용어 설명. 새 용어가 코드/문서/회의에 등장하면 여기에 추가한다.
> 형식: 정의 → 비유 → 우리 프로젝트에서의 의미

## 위치추정 (Localization)

### UWB (Ultra-Wideband)
초광대역 전파의 도달 시간으로 거리를 재는 실내 측위 기술. GPS가 안 되는 실내에서 수십 cm 정확도로 위치를 잡는다.
- 비유: 방 모서리마다 서 있는 심판들(앵커)이 "소리 지른 지 몇 초 만에 들렸나"로 선수(태그)의 위치를 삼각측량하는 것.
- 우리 프로젝트: 앵커(고정국) 여러 개 + 드론 탑재 태그 1개(DWM3000EVB). 결과는 /uwb_pose (x, y만).

### 앵커 / 태그 (Anchor / Tag)
UWB의 두 역할. 앵커 = 위치를 아는 고정 기준국(최소 3~4개), 태그 = 위치를 알고 싶은 이동체 부착 장치.
- 우리 프로젝트: 태그는 확보(DWM3000EVB 1개), 앵커 세트 보유 여부 확인 중.

### EKF (Extended Kalman Filter, 확장 칼만 필터)
노이즈 낀 여러 센서 값을 "예측 + 관측 보정"으로 융합해 진짜 상태를 추정하는 알고리즘.
- 비유: 시계가 여러 개인데 다 조금씩 틀릴 때, 각 시계의 못 믿을 정도를 반영해 가중 평균으로 진짜 시각을 추정하는 것. 단순 평균과 달리 "방금 전 추정치"도 근거로 쓴다.
- 우리 프로젝트: (1) PX4 내부 EKF가 IMU+TFmini를 융합해 고도 유지, (2) Phase 1에서 UWB 필터링을 EKF급으로 설계, (3) Phase 2에서 UWB+스캔매칭+IMU 통합 융합.

### 스캔매칭 (Scan Matching)
LiDAR의 이번 스캔과 직전 스캔(또는 지도)을 겹쳐 맞춰보고, "얼마나 움직였는지"를 역산하는 기법.
- 비유: 어두운 방에서 눈 감고 걸으며, 손으로 더듬은 벽 모양의 변화로 내가 얼마나 이동했는지 알아내는 것.
- 우리 프로젝트: Phase 2에서 UWB 드리프트 보정용으로 도입. scan-to-scan(직전과 비교) → scan-to-map(누적 지도와 비교) 순.

### SLAM (Simultaneous Localization and Mapping)
지도를 만들면서 동시에 그 지도 안에서 내 위치를 추정하는 기술. 스캔매칭을 지도 구축까지 확장하면 SLAM이 된다.
- 우리 프로젝트: 구 WBS는 배제했으나 전면 재설계에서 Phase 2 방향으로 채택.

### 광학 흐름 (Optical Flow)
카메라 영상에서 바닥 무늬가 흘러가는 방향/속도로 수평 이동을 추정하는 기법.
- 비유: 기차 창밖 풍경이 뒤로 흐르는 속도로 기차 속도를 짐작하는 것.
- 우리 프로젝트: PMW3901 센서 보유(BOM). Phase 2에서 융합 후보로 평가.

## 제어 (Control)

### 자세제어 vs 위치제어 (Attitude vs Position Control)
자세제어 = 기체의 기울기/회전을 밀리초 단위로 잡는 안쪽 루프. 위치제어 = "어디로 갈지" 속도/위치를 명령하는 바깥 루프.
- 비유: 자세제어는 소뇌(균형 반사), 위치제어는 대뇌(어디로 걸을지).
- 우리 프로젝트: 자세제어는 PX4 전담(건드리지 않음, 확정). companion(Jetson)은 위치제어만.

### PID 제어
오차에 비례(P), 누적(I), 변화율(D)로 반응하는 고전 제어기. P만 쓰면 P-control.
- 비유: 목표까지 남은 거리만큼 액셀(P), 계속 못 미치면 조금 더(I), 너무 빨리 접근하면 브레이크(D).
- 우리 프로젝트: Phase 1에서 위치제어를 P → PID로.

### 게인 스케줄링 (Gain Scheduling)
상황에 따라 제어기 게인(민감도) 세트를 갈아끼우는 기법.
- 비유: 고속도로에서는 둔감한 핸들, 주차장에서는 민감한 핸들로 자동 전환.
- 우리 프로젝트: 목표 근접 시 감속 게인 세트 등. "자세제어 AI" 항목의 실제 의미가 이것으로 확정됨.

### Offboard 모드
PX4의 비행 모드 중 하나. 외부 컴퓨터(companion)가 보내는 setpoint를 따라 비행하는 모드.
- 우리 프로젝트: Jetson의 /cmd_vel → MAVROS → PX4 Offboard가 기본 제어 경로.

### Loiter
PX4 비행 모드. 현재 위치·고도를 스스로 유지하며 제자리 비행(호버링)하는 모드.
- 우리 프로젝트: 이륙 시퀀스의 목표 상태. arm → 상승 → Loiter 진입까지가 Phase 1의 자동화 구간.

### FSM (Finite State Machine, 유한 상태 기계)
시스템이 가질 수 있는 상태들과 상태 간 전환 조건을 명시한 설계. 
- 비유: 신호등. 빨강→초록→노랑, 각 전환에는 조건(타이머)이 있고 동시에 두 상태일 수 없다.
- 우리 프로젝트: 임무 로직의 시작점. IDLE → TAKEOFF → LOITER → GOTO → ARRIVED → LAND.

### Behavior Tree (BT, 행동 트리)
행동을 트리 구조로 조합하는 임무 설계 기법. FSM보다 복잡한 임무(재시도, 우선순위, 병렬 감시)를 깔끔하게 표현한다. 게임 AI와 로보틱스의 표준.
- 비유: FSM이 "역마다 정해진 다음 역이 있는 노선도"라면, BT는 "상황 보고 하위 계획을 갈아끼우는 작전 트리".
- 우리 프로젝트: 임무가 다중 목표 순회 + 마커 시퀀스로 복잡해지는 시점(Phase 3~4)에 FSM에서 전환.

### 비주얼 서보잉 (Visual Servoing)
카메라에 보이는 대상(마커 등)의 위치 오차를 직접 제어 입력으로 써서 기체를 정렬시키는 기법.
- 비유: 주차 카메라의 가이드라인이 가운데 오도록 핸들을 트는 것.
- 우리 프로젝트: Phase 3. 마커가 화면 중앙·정면에 오도록 드론 위치를 미세 조정.

## 마커 / 비전 (Markers / Vision)

### ArUco 마커
pose(위치+기울기) 추정 전용으로 설계된 흑백 격자 마커. 프린터로 출력해 붙이면 되는 종이 한 장이다.
- 왜 QR이 아니라 이것인가: QR은 근거리 정면 판독용이라 멀리서/비스듬히/흔들리며 보면 검출이 잘 깨진다. ArUco는 굵은 격자라 몇 픽셀만 잡혀도 검출되고, OpenCV 내장 검출기가 꼭짓점을 서브픽셀 정밀도로 준다. 내장 ID(숫자)로 선반 구분도 가능.
- 실전 규칙: 한 변 10~15cm(대략 변 길이의 100배 거리까지 안정 검출), 무광 용지, 평평하게 부착, 인쇄 후 실측 크기를 파라미터로 입력(프린터 축소 오차 보정).
- 우리 프로젝트: 하이브리드 라벨(ArUco=정렬용 + QR=데이터용)로 사용. 단 Phase 3에서 QR 단독 pose 실험을 먼저 하고 한계를 문서화한 뒤 전환.

### AprilTag
ArUco와 같은 목적의 마커. 로보틱스 연구계 표준에 가깝고 검출 강건성이 다소 우수. ArUco 대안으로 언제든 교체 가능.

### solvePnP
"모양과 실제 크기를 아는 무늬"의 꼭짓점들이 영상 어디에 찍혔는지로부터, 카메라와 무늬 사이의 3D 위치·각도를 역산하는 OpenCV 함수. 마커 기반 자세보정의 수학적 심장.
- 이것 때문에 마커의 "실측 크기"가 반드시 필요하다.

### QR 코드
데이터(문자열) 저장·판독용 2D 코드. 세 모서리의 파인더 패턴 꼭짓점으로 pose 추정도 가능은 하나(QRCodeDetector + solvePnP), 검출 거리/각도/연산량에서 ArUco에 밀린다.
- 우리 프로젝트: 재고 데이터 운반 담당. USB 스캐너(DE2110)는 문자열만 출력하므로 pose 추정에는 사용 불가 — pose는 카메라(IMX219) 몫.

## 통신 / 미들웨어

### MAVLink / MAVROS
MAVLink = 드론 업계 표준 통신 언어(Pixhawk가 말하는 말). MAVROS = MAVLink를 ROS2 topic으로 번역해주는 통역사 패키지.
- 우리 프로젝트: Jetson과 Pixhawk 사이의 다리. /mavros/state의 connected: true가 연결 성립의 증거(heartbeat).

### Topic / Node (ROS2)
Node = 하나의 일을 하는 프로그램 단위. Topic = 노드들이 데이터를 주고받는 방송 채널. 발행(publish)하는 쪽과 구독(subscribe)하는 쪽이 서로를 몰라도 채널명만 맞으면 통신된다.
- 이 분리 덕에 센서를 교체해도 구독자 코드는 불변 — 본 프로젝트 아키텍처의 근간.

### Launch 파일
여러 노드 실행 + 설정 파일 연결 + 옵션을 한 번에 수행하는 실행 대본. `옵션이름:=값`으로 대본을 안 고치고 설정만 갈아끼울 수 있다.

### baudrate (통신 속도)
시리얼 통신에서 초당 신호 수. 장치와 다르게 설정하면 통신 자체가 깨진다.
- 우리 장비: T-mini Pro = 230400, TFmini Plus = 115200, Pixhawk USB = 115200.

### ToF (Time of Flight)
빛을 쏘고 돌아오는 시간으로 거리를 재는 원리. T-mini Pro(회전 스캔)와 TFmini Plus(단방향 거리계) 모두 ToF 방식.
- 주의: 프로젝트 문서에서 "ToF 센서"는 보통 하방 TFmini Plus를 지칭.
