# UWB 공중 공백 후속 분석
확보한 세 비행 기록의 재생 결과다.
공백 수정 범위와 남은 실측을 판단할 때 읽는다.

## 결론

B4 XY를 높이 발행과 분리해 불필요한 공백을 줄였다.
전체 공중 공백을 해결한 것은 아니다.
점프 보호·B3 재획득에 의한 긴 공백은 남았다.
운영 배포·FC 설정 변경·추가 비행은 하지 않았다.

## 수정 근거

같은 높이의 앵커 네 개는 ToF 없이 XY를 구한다.
기존 B4 계산도 이미 이 성질을 사용한다.
두 앵커의 거리 제곱을 빼면 공통 높이 항이 사라진다.

```text
r_i² = (x-a_ix)² + (y-a_iy)² + (z-a_z)²
r_i²-r_j² -> 공통 (z-a_z)² 항 소거

RAW -> TDMA/시각/점프 검사 -> B_TF
                              ├─ B4 XY -> /uwb/btf_pose
                              ├─ B3 XY -> 기존 ToF/연속성 검사 -> pose
                              └─ 측정 높이 있음 -> /uwb/btf_xyz
```

순차 거리의 시간 처리는 기존 H80을 그대로 쓴다.
앵커별 원래 시각을 보존한다.
네 앵커 높이가 다르면 기존 생성 단계가 거부한다.
H80 적합 통과가 실제 위치 정확도의 증명은 아니다.

기존 ROS 발행기가 ToF 누락 시 B4 XY도 막았다.
이는 B4의 계산 입력보다 강한 결합이었다.
새 경로는 `unchanged_B4`만 예외로 인정한다.
신선한 네 관측·전체 앵커 적합·유한 XY를 요구한다.
원래 시각·150ms 발행 만료 조건은 유지한다.
XYZ가 없으면 XY 메시지 z=0과 큰 Z 분산을 유지한다.
`/uwb/btf_xyz`에 가상 높이를 만들지 않는다.
비행 승인·브리지 활성·공분산 교정은 별도다.

`allow_b4_xy_without_tof` 기본값은 true다.
false면 기존 높이 발행 정책을 재현한다.
`require_height_for_pose`에는 이 B4 예외가 적용된다.
기존 지상 전용 예외는 호환성을 위해 남긴다.
B3의 ToF·후보 유일성·연속성 기준은 바뀌지 않는다.

## 같은 입력의 재생 비교

변경 전후 좌표 계산 결과는 같다.
발행 조건 두 개를 같은 결과에 적용했다.
기록 순서는 실제 콜백 순서와 다를 수 있다.
조각 시작 전의 내부 상태도 확보되지 않았다.
따라서 정확한 실기 복제나 정확도 시험은 아니다.

| 기록 | 이전 XY | 수정 XY | 추가 XY | 재생 최대 공백 |
|---|---:|---:|---:|---:|
| C1 | 590 | 816 | 226 | 12.350s, 끝에서 잘림 |
| C2 | 225 | 372 | 147 | 16.450s, 끝에서 잘림 |
| C3 | 1,230 | 1,579 | 349 | 10.751s |

추가 722개는 모두 기존 B4 XY다.
추가 XYZ는 0개다. 사라진 기존 출력도 0개다.
C3 최초의 약 7.9초 높이 공백은 재생에서 제거됐다.
수정 후 시작 구간에는 250ms 초과 공백이 없었다.
긴 최대 공백은 세 기록 모두 그대로다.

위 최대값은 재생 결정의 수신 시각으로 계산했다.
이전 보고서는 실제 pose·상태 토픽 시각을 사용했다.
따라서 실제 C3 최대값 10.742s와 약간 다르다.
C2 실제 pose 226개와 재생 225개도 구분한다.
끝에서 잘린 공백은 복구까지의 시간이 아니다.

## 남은 원인

긴 공백은 원시 패킷 단절만으로 설명되지 않는다.
C3 실제 10.742초 동안 RAW 429개가 들어왔다.
그 안의 RAW 최대 간격은 약 49ms였다.
하지만 네 거리 모두 정상이라는 뜻은 아니다.

| 원인 | 확보한 근거 | 현재 한계 |
|---|---|---|
| ToF 하한 | 선언된 최소 거리 0.10m. 초기 0.01–0.05m 수신 | 낮은 거리의 실제 정확도는 승인하지 않음 |
| ToF 전달 주기 | 세 기록의 원본 시각 간격 중앙값 약 102ms | 허용 나이 100ms와 맞지 않음 |
| ToF 긴 간격 | C1 1.607s, C2 5.475s, C3 1.207s | 센서·FC·전송·수집 원인을 모두 분리하지 못함 |
| 점프 기준 정체 | C3 거부 283개, 기준 나이 중앙값 4.525s·최대 8.425s | 실제 이동과 UWB 편향을 구분할 독립 XY 없음 |
| 앵커 누락 | C3 A1/A2/A3/A4: 20/2/208/218회 | A3/A4 문제를 NLOS나 고장으로 확정하지 못함 |
| B3 재획득 | 신선한 직전 좌표 만료·유일 후보 실패 | 조용한 점프를 허용하지 않고 재획득할 근거 부족 |

텔레메트리 요청 코드는 이미 ToF 40Hz를 요청한다.
요청 ACK가 실제 40Hz 수신을 뜻하지 않는다.
기존 ULog 거리 기록은 약 1Hz로 저장됐다.
이 파일만으로 FC 센서의 실제 발행률은 알 수 없다.
따라서 100ms 제한을 늘리는 변경은 하지 않았다.

점프 거부 중에도 높이·거리 입력을 남기도록 수정했다.
기존 조기 반환은 그 진단 정보를 생략했다.
`raw_pair_residual_max_m`는 거리 차분 잔차다.
기존 `raw_fit_rms_m` 이름은 실제 RMS가 아니었다.
호환 키를 남기고 정확한 이름을 추가했다.
`raw_height_rms_m`는 ToF를 반영한 거리 RMS다.
순차 표본에 같은 raw XY를 대입한 진단값이다.
이를 실제 XY 오차나 새로운 승인 게이트로 쓰지 않는다.

## 검증·보존

| 구분 | 결과 |
|---|---|
| 합성 상승·점프·결측 | 높이 없는 B4 XY 복원, Z 생성 없음, 점프 거부 유지 |
| Jetson 격리 pytest | ROS 콜백 포함 84개 통과 |
| 격리 colcon symlink 빌드 | drone_uwb 성공, setup 적용 후 노드 import 성공 |
| 기존 C1/C2/C3 재생 | 위 비교 결과, 원본 입력 보존 |
| 운영 서비스·FC 설정 변경 | 없음 |
| 새 SITL·실물 지상·비행 | 미실시 |

저장공간 부족으로 수집기가 대기 중인 것도 확인했다.
PC 압축본·해제본·Jetson 원본의 SHA256을 대조했다.
종료·쓰기 완료·열린 파일 없음도 확인했다.
검증된 C1/C2/C3 원격 사본만 306,103,388바이트 정리했다.
PC 원본·압축본은 모두 보존했다.
Jetson 여유 공간은 약 1.2GiB에서 1.5GiB가 됐다.
수집 supervisor가 `collecting`으로 복귀했다.
이 정리는 과거 비행의 UWB 공백 수정과 별개다.

원본 해시는 [이전 보고서](hover_gap_analysis_20261010.md)에 있다.
원본·재생 결과·해시 대조 기록은 Git 밖에 둔다.

## 재현

다음 명령은 파일만 읽고 ROS에 접속하지 않는다.
세 조각에 각각 같은 재생을 수행한다.

```bash
PYTHONPATH=src/drone_uwb OPENBLAS_NUM_THREADS=1 \
  python3 src/drone_uwb/tools/replay_manual_btf.py /private/C3 \
  --output /private/C3-xy-separated.jsonl
python3 src/drone_uwb/tools/analyze_btf_gaps.py /private/C1 /private/C2 /private/C3 \
  --replay /private/C1-xy-separated.jsonl /private/C2-xy-separated.jsonl /private/C3-xy-separated.jsonl \
  --output /private/gap-followup.json
```

추가 실측은 [최소 측정 절차](../runbooks/uwb_gap_measurements.md)를 따른다.
먼저 알려진 정지점·받침대 이동으로 남은 원인을 분리한다.
수동 비행이 있어야만 이 작업을 진행할 수 있는 것은 아니다.
