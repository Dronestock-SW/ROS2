## 변경 파일과 동작

PX4는 외부 저장소이므로 소스 패치로 보관한다.
기존 LiDAR PX4 패치와 같은 관리 방식이다.
기존 현장 펌웨어 파일·부팅 스크립트는 수정하지 않았다.

| 파일 | 변경 |
|---|---|
| [PX4 소스 패치](../../src/drone_uwb/tools/px4_tfmini_plus.patch) | TF02PRO.hpp/cpp/main과 새TFMiniPlus.hpp |
| [전달 요청 코드](../../src/drone_uwb/drone_uwb/integration/ros/manual_streams.py) | DISTANCE_SENSOR40→50Hz, 실패·timeout의 제한 재시도 |
| [C++ 검사](../../src/drone_uwb/test/firmware/test_tfmini_plus.cpp) | 실제 수정 드라이버의 I²C·시계 대역 검사 |
| [C++ 검사 도구](../../src/drone_uwb/tools/check_tfmini_plus_driver.py) | 수정 소스와 API 대역 컴파일·실행. 장치 접근 없음 |
| [companion 검사](../../src/drone_uwb/test/integration/test_manual_streams.py) | 가짜 ROS 서비스로 ACK·재시도·연결·ARM 경계 확인 |

`-T`에서만 TFmini Plus 프로필을 선택한다.
같은 주기에 결과를 요청·읽고20ms 절대 기준으로 예약한다.
지나간 주기는 건너뛰며 다음 실행 때 몰아 읽지 않는다.
요청 실패 후 읽기·발행을 하지 않는다.
헤더·checksum·신호·범위를 검증한다.
요청·읽기·발행 시각, 주기 지연, 오류별 수를 status에 남긴다.
이는 내부 계수다. 매 표본 파일 기록은 추가하지 않았다.

`-T -C`는 일회성 정상 모드100Hz 설정·저장 경로다.
설정 응답 대기100ms·저장 대기1초는 비동기다.
새 DISARMED 상태와 각 응답을 확인한다.
오류 시 발행을 시작하지 않고 수동 재시작을 요구한다.
시작 때 최초 요청의 I²C 응답도 검사한다.
설정 경로에서는 그 거리 응답을 읽어 버린다.
거리 프레임이 설정 ACK로 오인되는 일을 막는다.
응답 성공은 모델 식별이나 유효 거리 수신의 증거가 아니다.
연속5회 실패는 status에 `NO_VALID_SAMPLE`로 표시한다.
기준 PX4 commander는500ms마다 상태를 발행한다.
상태 변경 때도 즉시 발행하는 코드를 확인했다.
매 부팅 저장·공장 초기화·주소 변경을 하지 않는다.
이번에는 해당 명령을 실기에 실행하지 않았다.

companion은 한 번에 명령511 요청 하나만 보낸다.
서비스success와result0을 모두 만족해야 수락으로 본다.
실패는 같은 항목을1초 간격으로 최대3회 시도한다.
초과 시 실패를 표시하고 다음 항목으로 넘어간다.
연결이 끊기면 pending을 해제한다.
ARM·오래된 상태에서는 새 요청을 보내지 않는다.
수락과 실제50Hz 달성을 로그에서 구분한다.

## 품질 변경의 해석

모델별 품질 검사도 이번 패치에 포함했다.
이는 주기 변경만의 실험이 아님을 명시한다.
범위·신호·통신·프레임 오류를 따로 집계한다.
품질 기준 강화는 유효 표본 수를 줄일 수 있다.
실제 범위 밖 측정을 허용해 공백만 줄이지 않는다.
기존 TF02PRO 기본 프로필의 검사는 유지했다.

## 검사와 한계

로컬 단위 검사는 재생이나 실기 시험이 아니다.
수정 드라이버의 실제 C++를 API 대역과 연결했다.
센서의 물리 응답과 PX4 전체 빌드는 대체하지 않는다.

| 검사 | 현재 결과 |
|---|---|
| C++ 드라이버 | 6개 검사 묶음 통과. Zig0.13.0, C++17, Wall/Wextra/Werror |
| companion | 5개 단위 검사 통과. pytest8.3.5 |
| CLI 코드 | `tf02pro_main.cpp`를 API 대역으로 별도 object 컴파일 통과 |
| 패치 적용 | 깨끗한 기준 사본에서 적용 검사·적용 성공. 4개 소스의 바이트 일치 |
| Claude | 8~9차 설정·오차, 10차 설계, 11~13차 코드 리뷰 완료. 지적 보완 |
| 전체 PX4·colcon 빌드 | 별도 Jetson 사본에서 ROS7개·FMUv6C 타깃 성공. [결과](tof_full_build_20261014.md) |
| 재생·실기 검증 | 미실시·보류 |

초기 C++ 컴파일 때 Zig 자체 libunwind 경고가 있었다.
수정 드라이버의 경고는 Werror로 검사했다.

[소스 해시·검사 요약](evidence/tof_100_50_50_20261014.json)을 보존한다.
Claude는 제공한 소스를 검토했다. 실제 실행자는 아니다.
11차의 장치 부재 감지·출력 자료형 지적을 수정했다.
12차의 초기 응답 잔류 가능성도 코드로 제거했다.
13차는 코드·문서 범위에서 중대한 오류 없음으로 마쳤다.
실제 환경에서의 합격 판정은 아니다.
14~16차로 실제 빌드 결과와 경고를 추가 검토했다.
ToF 이미지 증가는 같은 도구 기준2,920B다.
최종 플래시 여유28,068B를 확인했다.
빌드·링크 기준으로 추가 소스 수정은 필요하지 않았다.
