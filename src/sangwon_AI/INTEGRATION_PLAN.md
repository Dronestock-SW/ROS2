# 연동 준비와 설계 완료 기준
이 문서는 외부 자료·환경·구현의 선행 관계를 정리한다.
어느 작업을 진행할 수 있고 무엇을 기다리는지 검토할 때 읽는다.

상태: 내부 설계 v1.0, 외부 연동·실기체 적용 조건 분리 / 2026-10-02.
2026-10-05 구현 보완: 정적 지도 경계가 제공된 REPLAY의 제한된 XY 우회·필수 방문·복귀를 검증했다. 실제 LiDAR 갱신·합집합 경로·고도 변경점 선정·PX4/UWB 실장 검증은 후속이며 [현재 구현 상태](IMPLEMENTATION_STATUS.md)가 검증 범위의 기준이다.
핵심 C++·보조 Python 분담, BT 정책·실행 계약·모의 시험 기준을 확정했다.
웹 회신과 UWB 사양은 해당 어댑터 단계에서 적용한다. 실기체 승인은 별도다.

## 2. 진행 순서

```text
내부 설계 v1.0 -> C++ 핵심/Python 보조 구현 -> 재생·SITL 검수
                                                |
웹 담당자 회신 -> 웹 어댑터·계약 시험 ------------+
UWB 전체 사양 -> 장치 어댑터·융합 시험 -----------+-> 실장 통합
Jetson 환경·PX4 품질·실측 프로파일 승인 -----------+      |
                                                    제한 실비행
```

외부 사양을 기다리는 동안 내부 계약과 합성 입력으로 핵심 구현을 진행할 수 있다.
UWB 모의 입력을 쓰더라도 실제 장비 검증이 완료됐다고 표시하지 않는다.
사용자 합의대로 코드 구현은 MD 검토 이후에 진행한다.

## 3. 내부 확정과 외부 적용의 구분

| 항목 | 완료 판단 | 현재 남은 일 |
|---|---|---|
| 행동 정책 | 상태별 진입·완료·실패·선점·복구 명세 | 확정. 구현 후 실패 주입으로 검수 |
| 웹 계약 | 양측이 같은 버전·샘플·오류 의미를 수락 | JSON 구체안·10초 시험값·URL·인증·지도 형식 회신 |
| UWB 계약 | 전체 사양과 실제 로그로 어댑터 설계 가능 | 전체 자료 수령, 소유자·메시지·시간 결정 |
| 좌표·품질 | 지도·UWB·PX4·기체 측정점 관계와 검사 방법 명확 | 측량 방법·오차 모델·허용값 검증 |
| 실행 구조 | 출력 소유권·watchdog·동시성·언어 경계 | 확정. C++ 핵심·BehaviorTree.CPP 4, Python 보조, 별도 guard |
| 환경·기록 | 설치·기동·용량·복구·수집 절차 재현 가능 | J02~J09 및 로그 수집 경로 검증 |
| 검수 | 요구사항마다 재현 입력·기대 결과·증거 지정 | 미수행 시험을 수행 결과로 바꾸는 단계 |

일부 수치가 실측을 기다리면 설정 후보와 측정 방법을 남길 수 있다.
미확정값을 운영 기본값으로 채워 넣지는 않는다.
실기체 출력을 활성화하려면 관련 수치와 시험 승인이 모두 필요하다.
