# 전체 미션 가상 시험의 연결 범위
명령부터 복귀·착륙까지의 연결을 설명한다.
2026-10-08 가상 시험과 실물 경계를 구분할 때 읽는다.

`MissionChain`은 PX4의 XY·yaw 명령을 순서대로 요청한다.
추정·자세·고도 제어는 PX4가 맡는다.
스캔 센서가 없어도 명시적 모사 worker로 계약을 시험한다.
실물 스캔 성공이나 실제 비행 완료를 뜻하지 않는다.

```text
HTTP START -> Platform link -> /mission/assignment
                                |
              기존 C++ native 지도·경로 검사 (명령 권한 없음)
                                |
RAW DS-TWR -> Measured B_TF -> 관측 격리 -> MAVROS -> PX4 EKF2
ToF + IMU --------^                              ^
flow + range + IMU ------------------------------+
                                |
                     MissionChain 단일 명령 writer
                                |
3초 지상 정지 -> AUTO.TAKEOFF 확인 -> ARM 확인
 -> PX4 상승 완료·속도 안정 -> XY/yaw 목표 실제 적용
 -> 도착·정지 -> ArUco 정렬 창 -> SCAN -> 결과 저장
 -> 대기점 복귀 확인 -> 다음 작업 -> 역경로 출발점 복귀
 -> LAND -> 새 ON_GROUND + disarmed -> END
                                |
                      WebSocket -> 웹 결과 표시
```

## 센서는 측정과 명령을 서로 섞지 않는다

관측을 거부할 때 예전 XY를 새 시각으로 보내지 않는다.
이유: 같은 위치를 새 측정으로 위장하면 EKF가 잘못 보정된다.

| 입력·동작 | 역할 | 사용하지 않는 정보 |
|---|---|---|
| UWB RAW | 네 거리·개별 시각·TDMA 계약 | FC 추정 위치, 가상 truth |
| ToF·IMU 자세 | 거리 기하·바닥·장착 보정 | IMU 위치 적분 |
| Raw 관측 격리 | H80 이전의 일관된 큰 좌표 점프 거부 | 강제 새 원점 |
| Bridge 관측 격리 | 출력 좌표의 급변·중복 시각 거부 | 예전 관측 재발행 |
| Optical flow | PX4의 수평 속도 보조 | companion 별도 속도 융합 |
| PX4 위치·속도 | 도착·정지·복귀 상태 확인 | UWB 보정의 정답 입력 |
| 단절 때 HOLD | 현재 PX4 XY에 한 번 이동 요청 | 새 센서 관측 생성 |

큰 좌표 점프를 반복해도 새 원점으로 받아들이지 않는다.
순간 단절은 기본 3초 동안 정지·회복을 기다린다.
회복에는 0.5초 연속 정상 관측이 필요하다.
회복 실패는 LAND와 실패 보고로 끝난다.
ToF나 시간 동기화 단절도 같은 관측 공백이다.
기체 추정·FC 연결·좌표 범위 상실은 즉시 중단한다.
수동 모드와 PX4 failsafe는 먼저 제어권을 갖는다.

## 작업 결과와 비행 결과는 다르다

`END`는 복귀·착륙·시동 해제를 확인한 종료다.
모든 스캔 성공까지 확인해야 `mission_complete=true`다.

| 상황 | 비행 상태 | 작업 판정 |
|---|---|---|
| 스캔 모사 성공·복귀·착륙 | END | ALL_SUCCEEDED |
| 마커·스캐너 시간 제한 후 복귀·착륙 | END | INCOMPLETE |
| 관측 장기 단절 뒤 착륙 | FAILED | INCOMPLETE |
| 모드 수동 전환 | PILOT_OVERRIDE | 자동 재획득 없음 |
| 명령 응답·착륙 완료를 확인 못 함 | UNCONFIRMED | 완료로 표시하지 않음 |

START는 명령을 보내기 전에 ledger에 저장한다.
재시작·반복 요청으로 다시 시동하지 않는다.
기존 세션 없이 공중에서 시작하면 LAND를 요청한다.
실행 로그를 쓸 수 없으면 진행을 중단한다.
전체 미션은 heading_control_confirmed도 요구한다.
실물 1.3m에서 yaw 제어 가능 여부를 별도로 확인해야 한다.
가상 v1.17은 1.5m 자력계 정렬 문턱 때문에 1.7m를 사용했다.
착륙·시동 해제 요청은 로그 오류로 막지 않는다.

## 스캔 좌표와 창의 계약

scan x/y는 라벨 좌표다. 기체 목표는 별도로 받는다.
대기점·경로 검증은 계획 단계에서 준비해야 한다.
이유: 라벨 위치로 기체를 이동시키면 선반과 충돌한다.

| 필드 | 의미 |
|---|---|
| `x`, `y` | 라벨 위치 |
| `staging_xy_m` | 승인된 기체 대기점 |
| `path_validation_ref` | 계획 단계 경로 검증의 참조 |
| `yaw_deg` | 지도 기준 기체 전방 방향 |
| `marker_id`, `label_id` | 대상 식별 |
| `calibration_ref`, `mounting_ref` | 카메라 보정·장착 참조 |
| `execution_id`, `task_id`, `window_id` | 실행·작업·스캔 창 문맥 |

마커 adapter는 검증된 지도 XY/yaw 제안을 보낸다.
원본 촬영 시각의 나이는 0.1초 이내여야 한다.
제안은 대기점 0.1m·yaw 10도 안이어야 한다.
정렬 이동은 PX4에 0.05m/s로 요청한다.
일반 이동 0.3m/s와 구분한다.
기체가 0.03m·3도·속도 0.03m/s 안에서 1초 정지하면 SCAN을 요청한다.
정렬을 잃으면 기존 창을 취소하고 새 창을 만든다.
결과는 창·대상·저장 식별자와 원본 시각을 검사한다.
마커와 결과의 증가 시각은 입력별로 검사한다.
새 촬영 메시지가 먼저 와도 유효한 저장 결과를 버리지 않는다.
성공·실패 뒤 대기점 복귀를 확인해야 다음 작업으로 간다.
실패한 스캔은 기록하고 남은 작업을 순서대로 계속한다.
스캔 실패만으로 출발점 복귀를 시작하지 않는다.
모든 작업을 시도한 뒤 출발점으로 복귀한다.
남은 작업·시도한 작업·실패한 스캔을 웹으로 보낸다.
route_complete는 전체 경로 수행·복귀·착륙 확인이다.
실패한 스캔이 있으면 mission_complete는 false다.
기존 ArucoDetection·QR String을 그대로 성공으로 받지 않는다.
카메라·장착·재투영 품질을 검증하는 실물 adapter는 후속이다.

## 현재 AI와 운영 경계

이번 PX4 연결의 실행기는 Python MissionChain이다.
기존 C++ geometry를 `sangwon_native_plan`에 연결했다.
실측 지도의 hash·배치·높이·경계·장애물을 검사한다.
기체 여유 공간과 마커 보정 0.1m도 검사한다.
실물은 SURVEYED 지도만 받는다. VIRTUAL은 domain 99 전용이다.
실제 기체의 출발점 XY로 경로를 검증한다.
지도 높이는 native 호버의 바닥 기준 기체 높이를 실측한다.
MIS_TAKEOFF_ALT에 기체 바닥 높이를 임의로 더하지 않는다.
FC의 home·고도 기준에 따라 두 값의 관계가 달라진다.
이 값은 지도 검사에만 쓰며 z 지령을 만들지 않는다.
지도와 경로 참조는 실행 로그에 저장한다.
`path_validation_ref` 문자열만 믿는 입력 공백을 없앴다.
한 높이의 직선 구간과 역경로 복귀를 지원한다.
장애물 우회는 승인된 경유점으로 명시한다.
동적 장애물 회피·여러 고도 미션은 이 경로에서 지원하지 않는다.
기존 C++ BT·스캔 정책은 별도 REPLAY 검사를 유지한다.
C++ BT의 실물 출력 금지를 해제하지 않았다.
두 실행기가 동시에 FC 명령을 보내지 않는다.
운영 웹 1.1 snapshot과 실물 스캔 adapter 연결은 남았다.
현재 native 시험은 한 평면의 짧은 경로를 다룬다.
직사각형 시험 범위와 다각형 지도 검사를 함께 적용한다.
스캔 실패는 비행 완료와 구분해 보고한다.

## 오차 모델의 한계

갑작스러운 큰 점프와 느린 공통 편향은 다르다.
느리게 쌓이는 일관된 편향은 UWB만으로 관측할 수 없다.
PX4의 flow·IMU 융합도 장기 절대 위치 보장을 뜻하지 않는다.
독립 마커·실측 위치·innovation 검증이 추가로 필요하다.
DW3000 계약에는 carrier phase 값이 없다.
가상 위상 영향은 거리 잔차·시각 차이로만 주입한다.
실제 RF 위상·NLOS 환경에서의 성능은 미측정이다.
