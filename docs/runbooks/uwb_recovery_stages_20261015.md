# UWB 복구 개선: 구현 순서와 완료 조건
복구 로직을 코드로 옮길 때 따르는 절차다. 2026-10-15 운영 대조 이후에 읽는다.
[필수 설계 검토](../architecture/uwb_gap_recovery_20261015.md)와 [현재 운영값](../reference/uwb_recovery_baseline_20261015.md)을 전제로 한다.

**다음 수정은 복구 판단에 필요한 FC 관측을 연결하는 일이다.** 감속 상태부터 추가하면 현재 입력으로는 위치 보정과 좌표계 변경을 구분할 수 없다. 아래 순서에서 1단계의 소프트웨어·설정 대조를 마쳤고, 2~6단계는 구현·검증 전이다. 운영 파라미터와 제어 코드는 이번 문서 커밋에서 바꾸지 않는다.

## 1단계. 수정 대상을 고정한다 — 조회 완료

통합본과 `0110da8 + A-cache` 운영 슬롯을 구분했다. FC 수평 상한 1.0m/s, 상승 0.5m/s, 하강 0.25m/s를 실제 조회했다. Optical flow 융합 스냅샷도 확보했다. 하드웨어 실측과 실제 제동 성능은 별도 남은 항목이다.

현재 코드는 UWB 나이 0.25초, FC 위치 나이 0.2초를 기준으로 진행을 멈춘다. 도착 인정은 FC 오차 15cm·UWB 오차 25cm·속도 0.1m/s 이하가 1초 지속될 때다. 이 기준을 통과했다고 실제 최대 오차 10cm를 달성한 것으로 기록하지 않는다.

## 2단계. FC 상태 입력을 먼저 보강한다

현재 `field_executor_node.cpp`는 같은 `/mavros/local_position/odom`에서 위치와 속도를 얻는다. 둘은 같은 원본 시각을 사용하며 좌표 변환도 이미 있다. 속도 수신 시각이 없다는 이유로 중복 경로를 만들 필요는 없다. 부족한 것은 어떤 추정기의 어떤 좌표계인지, 새 UWB가 실제 융합됐는지를 설명할 정보다.

| 필요한 입력 | 확보할 의미 | 없거나 오래됐을 때 |
|---|---|---|
| FC 부팅 식별·선택된 estimator instance | 이전 기동·다른 추정기의 상태를 혼합하지 않음 | 자동 재출발 판단 보류 |
| XY·heading reset counter와 delta, 해당 시각 | 물리 이동과 좌표 표현 변경의 후보 구분 | 점프를 정상 복구로 임의 승인하지 않음 |
| EV·flow·LiDAR의 현재 활성 상태와 최근 융합 시각 | 토픽 수신과 실제 추정기 사용을 구분 | 해당 관측을 대기 유지 근거로 세지 않음 |
| XY·속도·heading 유효성 및 불확실성 | 그 상태로 제동·대기를 계획할 수 있는지 판단 | 기존 FC 실패 처리와 조종자 전환 정책 유지 |
| UWB 원본 시각·sequence·센서 시계 구간 | 새 관측인지와 거부 뒤 새 승인인지 판정 | 오래된 승인을 재사용하지 않음 |
| 마지막 실제 송신 목표·송신 시각·좌표계 식별 | 리셋 전후 어느 목표가 전송됐는지 연결 | 목표를 보정했다고 추정하지 않음 |

먼저 해당 PX4의 메시지 송신 경로를 확인하고, 필요한 정보가 현재 MAVROS에 노출되지 않으면 읽기 전용 진단 메시지를 설계한다. NSH `listener` 반복 호출을 비행 제어 루프의 입력으로 사용하지 않는다. 지금 확보한 지상 조회는 입력 설계의 근거다.

새 상태가 유효하려면 수신 시각뿐 아니라 FC 원본 시각, 선택된 instance, 부팅 구간이 맞아야 한다. counter 증가도 wrap과 재부팅을 구분한다. `time_last_fuse`는 복구 시작 때의 값보다 전진했는지와 현재 융합 상태를 함께 본다. 한 제어 주기 동안 값이 같았다는 이유로 융합 실패로 판정하지 않는다. 융합 지연 지평과 메시지 주기를 반영한 별도 신선도 기준을 정한다. B_TF의 150ms 제한을 그대로 복사하지 않는다.

이 단계에서는 판단 결과를 기록만 하고 기존 제어 동작을 유지한다. 입력 누락·역순·중복·instance 전환·FC 재부팅·오래 남은 `fused=True`를 구성한 단위 검사에서 정상 복구가 잘못 승인되지 않으면 입력 계약을 완료한다. 이 검사는 원본 로그 재생과 구분한다.

## 3단계. 수평 감속 경로를 독립 모듈로 만든다

원래 목적지, 임시 정지 목표, 실제 송신 목표를 분리한다. 모듈은 수평 경로만 생성한다. PX4의 상태 추정·자세 제어·고도 제어 책임은 유지한다. 첫 버전은 현재 위치·yaw 송신 계약을 유지한다.

| 입력·출력 | 구체적인 계약 |
|---|---|
| 초기 조건 | 마지막 송신 위치 목표, 경로의 속도·가속도 상태, 현재 FC 위치·실측 속도, 일관된 좌표계 |
| 제약 | 경로속도·가속도·jerk 제한, 실제 제동감속 하한, 측정된 지연 및 오차 예산 |
| 출력 | 다음 수평 위치 목표, 경로 상태, 예상 정지 구간, 경로 생성 불가 사유 |
| 시간 공백 | 경과시간을 한꺼번에 적분해 멀리 도약하지 않음. 공백 후 현재 상태로 다시 계획 |
| 공간 부족 | 경로를 억지로 잘라 안전하다고 선언하지 않음. 상위 판단에 생성 불가를 전달 |

실제 속도를 0으로 가정하지 않는다. 그렇다고 경로 속도를 실측 속도로 갑자기 덮어쓰면 목표의 미분이 불연속이 될 수 있다. 경로의 연속 조건은 이전 송신 상태에서 이어 붙이고, 실측 속도는 추종 오차와 정지거리 계산에 사용한다. 두 조건을 동시에 만족하는 경로가 없으면 재출발을 보류한다.

제동감속과 jerk의 숫자는 기체에서 검증할 값이다. 기존 문서의 0.5·1.0m/s² 계산 예를 실측값으로 기본 적용하지 않는다. 단위 검사에서는 임의의 양수 제약으로 연속성·제약 준수·정지 가능성·잘못된 입력 거부를 확인한다. 실제 기체의 정지거리 통과는 별도다.

## 4단계. 임무와 송신기에 함께 연결한다

감속·대기·재진입을 기존 임무 단계와 독립적인 `motion_state`로 둔다. 임무가 MOVING인지 RETURNING인지는 보존하고, 수평 목표가 어떻게 생성되는지만 바꾼다. 용어는 [용어집](../glossary.md)의 수평 이동 상태를 따른다.

| 이동 상태 | 진입 조건 | 동작과 다음 전환 |
|---|---|---|
| TRACK | 적격 관측과 정상 추정 | 기존 목적지 방향 경로 생성. 관측 공백·최신 거부 시 BRAKE 검토 |
| BRAKE | 현재 추정으로 제동 계획 가능 | 임무 도착·대기시간 누적 정지. 감속 경로 생성. 실제 속도·오차·공간 조건이 맞으면 HOLD |
| HOLD | 정지 유지 가능한 상태와 여유 확보 | 임시 정지 목표 유지. 적격 UWB는 추정기로 즉시 전달하되 임무 재개는 기다림 |
| REENTRY | 새 융합·좌표 일관성·공간 여유 확인 | 현재 상태에서 원래 목적지로 경로 연결. 관측이 다시 나빠지면 BRAKE 재평가 |

어느 상태에서든 추정 무효·설명 불가능한 좌표 변화·공간 부족은 정상 HOLD로 처리하지 않는다. 기존 조종자 우선권과 FC 실패 처리를 유지한다. UWB 단독 공백 0.7초를 일률적인 LAND 조건으로 새로 넣지 않는다. 총 임무시간·배터리 조건도 별개로 유지한다.

수정 순서는 다음 세 지점을 함께 다룬다.

1. `field_mission.hpp`의 기존 추종 오차 검사 전에 좌표 이벤트를 분류한다. 현재는 MOVING/RETURNING의 0.5m 추종 오차 검사가 복구보다 먼저 LAND를 요청할 수 있다. 설명 가능한 리셋은 같은 좌표계로 비교한 뒤 판단하며, 실제 추종 이탈 보호를 없애지 않는다.
2. `field_executor.hpp`의 점프 검사와 목표 채택을 연결한다. 지금은 MOVING/DWELL/RETURNING일 때만 `stream_xy`를 목표로 채택한다. BRAKE를 바깥 `phase`로 추가하는 것만으로는 새 목표가 송신되지 않을 수 있다. `motion_state`를 독립 필드로 두고 실제 채택을 검사한다.
3. `field_executor_node.cpp`의 송신 기록과 리셋 처리 순서를 연결한다. PX4의 기존 리셋 보정과 companion의 변환이 같은 목표에 두 번 적용되지 않아야 한다. 반대로 새 시각을 붙인 옛 목표가 PX4 보정을 되돌리는 순서도 검사한다.

완료 조건은 “FSM에 새 이름이 생김”이 아니다. 복구 전후 실제 송신 목표가 원래 물리 목적지를 유지하고, 감속 목표가 송신기에 도달하며, 같은 리셋을 한 번만 처리해야 한다. 좌표계 변경과 단순 위치 추정 보정은 서로 다른 검사 사례로 만든다.

## 5단계. 설정과 입력 원인을 각각 개선한다

설정은 18:01 조회값을 기준으로 한 번에 한 목적씩 비교한다. 수평 상한 1.0→0.25m/s는 보정속도 억제 후보로 다룬다. 상승·하강은 이미 사용자 기준과 맞으므로 같은 변경 묶음에 넣지 않는다. 위치 공분산을 줄여 원하는 정확도가 나오는 것처럼 만들지 않는다.

UWB 거리 모순은 앵커·태그의 알려진 위치에서 ID·단위·거리 편향을 확인해 개선한다. 계산 지연은 원본 관측 시각과 수신·계산·발행 시각을 연결해 줄인다. GC 두 사건과 기하 거부 공백은 다른 원인이므로 각각 효과를 판정한다. 거부 기준 완화나 원본 시각 갱신으로 발행률을 높이지 않는다.

## 6단계. 실제 오차와 여유를 확인한다

비행 검증 전에는 변경별 단위 검사와 격리된 송신·리셋 통합 검사를 마친다. 원본 로그 재생은 사용자 요청 범위에 포함하지 않는다. 실제 기체 평가는 질량·프로펠러·장착·센서 신원과 제동 성능을 확인한 뒤 별도 절차로 진행한다.

| 통과시킬 항목 | 측정과 판정 |
|---|---|
| 수평 위치 오차 10cm | 드론 자체 EKF/UWB와 독립적인 기준으로 목표 도착·호버의 수평 반경 측정. 평균만으로 최대 오차 통과 처리하지 않음 |
| 장애물 외곽 여유 30cm | 기체 중심이 아닌 외곽 기준. 제동 이동·위치 추정·지도 정렬·추종 오차를 함께 포함 |
| 공백 후 복귀 | 원래 목적지 보존, 목표 연속성, 실제 최고속도·정지거리·재진입 오차 측정 |
| 관측 열화 | UWB만 끊긴 경우와 flow/수평 추정까지 무효인 경우를 분리 |

`eph`나 공분산을 그대로 절대 오차 상한으로 쓰지 않는다. 별도 기준과 비교해 불확실성 예산을 검증해야 한다. 모델의 정지거리 계산이 30cm보다 작아도 실제 제동감속·반응시간·오차 예산이 미측정이면 통과로 표시하지 않는다.

각 단계가 끝나면 변경 파일, 입력 계약, 확인 결과, 운영 적용 여부를 기록한다. 다음 코드 작업의 첫 산출물은 **2단계 입력 계약과 기록 전용 연결**이다. 감속 로직 적용은 그 이후다.
