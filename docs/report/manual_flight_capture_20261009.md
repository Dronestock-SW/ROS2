# 수동 비행 수집기 확인 — 2026-10-09

수집기 구현·시험 결과를 기록한다.
현장 수동 비행 로그를 준비할 때 읽는다.
실제 비행 또는 보정 확정 결과는 아직 없다.

## 구현

`uwb_manual_capture`는 관측만 구독한다.
원본 UWB와 B_TF 계산 결과를 함께 보존한다.
ROS 원본 메시지와 두 수신 시각을 저장한다.
FC 수신 MAVLink 원본도 구독해 보존한다.
파라미터·ARM·모드 명령 경로는 없다.
절차는 [실행 문서](../runbooks/manual_flight_capture.md)에 있다.

## 단위 시험

Windows 순수 Python 시험 10개를 통과했다.
시각·원본 값·NaN·누락을 보존했다.
용량 제한과 디스크 오류를 불완전 기록으로 표시했다.
ARM 전 또는 상태 만료 때 자동 종료하지 않았다.
새 ARM 뒤 최신 지상·DISARM의 종료 조건을 시험했다.
기존 세션 덮어쓰기와 다른 부팅의 마커를 거부했다.

```bash
PYTHONPATH=src/drone_uwb python3 -m pytest -q \
  src/drone_uwb/test/integration/test_manual_capture.py
```

## 실기 사전 조사

현재 MAVROS allowlist에는 광류 plugin이 없다.
ROS graph에서도 광류 토픽은 발견되지 않았다.
MAVLink 원본 광류 수신 여부를 별도로 표시한다.
FC 내부 융합 확인에는 같은 시행의 ULog가 필요하다.
수집을 위해 MAVROS를 재시작하지 않는다.

## Jetson 수신 시험

Jetson 패키지 빌드와 Linux 시험 10개를 통과했다.
15초 지상 수집을 실행했다.
필수 토픽 누락·기록 오류·큐 거부는 없었다.
ARM·모드·파라미터는 변경하지 않았다.

지상 ToF는 센서 최소 거리 아래였다.
실측 XYZ 토픽은 없었고 요약에 누락으로 표시했다.
광류 원본 수신과 EKF 광류 융합을 구분했다.
이 부팅의 내부 읽기에서는 광류 `fused=false`였다.
FC logger는 `Not logging` 상태였다.
이 값을 수집기가 자동 변경하지 않았다.

PC 복사 파일은 11,359,984바이트였다.
전체 복사와 327,680바이트 이후 이어받기를 시험했다.
두 결과의 SHA256이 원본과 같았다.
해시는 `a4bf1dc185e70f6ce5a63905f88a76913f72cfca29dfcfdc6960d3619cdd2630`이다.

## 배터리 교체와 재개

20:04 KST부터 지상 기록을 시작했다.
교체 전에 79,342,153바이트 기록을 정상 마감했다.
PC는 61,022,208바이트까지 복사한 뒤 연결이 끊겼다.
RAM의 나머지는 재부팅으로 사라졌다.
이를 완전 백업으로 기록하지 않는다.
관측 상태는 DISARM·지상이었고 실제 비행 기록은 없다.

새 부팅에서 Tag B·FC와 SSH를 확인했다.
관측·웹을 복구하고 20:10 KST 새 기록을 시작했다.
FC bridge와 mission execute는 false로 유지했다.
수집기 외의 중복 대용량 기록은 사용하지 않았다.
MAVROS·UWB·B_TF는 동일 현장 설정을 사용한다.

초기 수집기의 명령 sink 구독이 문제를 드러냈다.
기존 FC 진단은 sink 구독자 1개를 요구했다.
수집기가 이를 2개로 만들어 진단이 거부됐다.
FC 수신 source와 EV 입력 토픽만 구독하도록 수정했다.
단일 라우터 조건을 완화하지 않았다.
실제 비행·자동 보정·START 활성은 아직 미실시다.
