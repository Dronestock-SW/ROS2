# UWB 기능별 비교 시험 명세 작성 기록

2026-09-26 명세 작성 범위와 확인 결과를 기록한다. 다음 구현 작업의 시작점과 자료 대기 상태를 확인할 때 읽는다.

## 요청과 완료 범위

**아이디어별 명세 17개와 공통 문서 4개를 작성했다.**
사용자는 기능을 시험한 뒤 가장 적합한 모델을 선택할 예정이다.
이번 작업은 그 시험을 준비하는 프로젝트 명세 작성이다.
[전체 색인](../specs/uwb/README.md)에서 개별 문서를 찾는다.

| 산출물 | 내용 |
|---|---|
| 기능별 명세 17개 | 입력·출력의 형식/단위, 설정, 산식, 처리 구조, 실패 처리, 시험 |
| 공통 입출력 | 시간·좌표·기준점·출처·오류·단계/모델 결과 규칙 |
| 비교·선정 절차 | 기준선·모듈 조합, 자료 분리, 평가 지표, 선정 기록 |
| 근거·상태 기록 | ZIP 주장, 코드 확인, 논문 확인 범위, 새 설계 구분 |
| 색인·기존 문서 | 로드맵·파이프라인 기준·대화 기록에 현재 상태 연결 |

입력·시간, ToF Z, 편향·거리 게이트, H80, Q_S10을 나눴다.
세 앵커 조합·중간 교점·가중 결합도 각각 명세를 작성했다.
GNSS 원리 기반 가중 풀이·배치·이상 검출, RF/CIR도 포함했다.
시간 필터·위치 게이트·LiDAR·GNSS 보조·출력 경계를 분리했다.

## 적용한 결정과 값

ToF 기반 Z는 추후 사용자 자료로 연결한다.
입력 누락을 숫자로 대체하지 않고 `blocked`와 사유를 기록한다.
실제 센서의 좌표·장착값·교정값·선정 임계값은 새로 확정하지 않았다.
참고 소스의 수치는 `source_reference`, 시험안은 `experiment_candidate`다.
실측 교정값은 `measured`로 별도 식별한다.

거리 보정은 `RAW - 편향`을 유지한다.
네 앵커의 세 개 조합은 네 묶음이다.
묶음별 교점 슬롯을 포함한 12개는 독립 관측 12개가 아니다.
공유 입력과 Z 오차의 상관을 모델·공분산 설계에 반영했다.
입력에 쓰는 ToF Z와 평가에 쓰는 독립 기준 위치를 구분했다.

기존 파일 파이프라인의 계산·전달 제한은 유지했다.
향후 시험 실행기는 파일만 기록하도록 명세했다.
모델 선택과 실운용 출력 허가는 별개의 단계다.
현재 `selected_model=null`이며 후보 성능 순위를 제시하지 않았다.

## 남은 작업

1. 공통 자료형과 독립 파일 시험 실행기를 구현한다.
2. 개별 함수·상태 전환을 합성 입력으로 검증한다.
3. 사용자 제공 ToF Z의 시각·단위·기준점·좌표계를 확인해 연결한다.
4. 교정·조정·평가 세션과 독립 기준 위치를 준비한다.
5. 설정을 잠근 동일 입력에서 오차·가용률·지연·복구를 비교한다.
6. 다른 세션에서 재확인한 뒤 모델과 보조 모듈 조합을 선택한다.

자료가 없는 기능은 입력 대기로 두고 가능한 시험부터 진행한다.
구체적인 시작 조건은 [비교·선정 절차](../specs/uwb/90_evaluation.md)를 따른다.

## 후속 정리 — 단계별 적용과 선택

사용자 요청으로 [단계별 선택안](../specs/uwb/stage_selection.md)을 추가했다.
공통 준비·위치 계산·결과 판정·기록을 다섯 단계로 나눴다.
서로 대체할 모델과 추가할 게이트·필터를 구분했다.
Q_S10의 H80 복구 분기와 추가 센서의 준비 조건도 명시했다.
현재 기능별 명세 17개와 공통 문서 5개로 총 22개다.
추가·갱신 문서 3개의 형식과 로컬 링크 27개를 검사해 통과했다.
`git diff --check`도 통과했다.
문서 구조를 보완했으며 새 구현·모델 시험·게이트 변경은 미실시다.
