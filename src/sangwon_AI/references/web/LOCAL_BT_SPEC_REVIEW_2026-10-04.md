## 연결과 저장

- 장치 telemetry: 기존 `WS /ws/drones/{id}/`의 서명된 draft.4 연결을 사용. BOOT 단계의 readiness 수신도 유지.
- `contracts/web_v1_1_draft4/telemetry.json` 형식. 서명하지 않은 새 계약 자료는 기존 UWB 저장 경로로 보내지 않음.
- 종료 결과: 기존 `POST /api/drones/{id}/companion-phase/`에서 draft.4 헤더일 때만 `execution_result.json` 형식 수신. W02와 같은 현재 세션 포함 7줄 HMAC.
- 브라우저: 로그인·기체 배정 권한을 확인하는 조회용 `GET /api/drones/{id}/behavior-state/`.
- `0025_behavior_reports`는 세션별 telemetry 및 실행별 결과 개정을 저장하는 테이블 추가. 기존 비행 위치·임무/재고 완료 데이터를 자동 변경하지 않음.
- 3초는 웹 연결 표시의 만료 기준이며 BT의 T_*나 실제 센서 승인 기준을 대신하지 않음.

## 남은 항목

문서 전체 또는 C++ BT가 완료된 것은 아니다. 이 저장소에는 Jetson C++ 행동 트리 소스가 없다.

- 실제 B01~B21 실행, tick/enter/선점/행동 generation, 출력 중재기, 8초/10초 단조 타이머, RC/PX4 제어권 처리는 Jetson 측 작업.
- 현재 계약 telemetry에는 명시적인 BT node ID/반환 상태/행동 세대가 없어 노드 실행 이력을 새 계약인 것처럼 만들지 않았음. 해당 장치 보고 계약과 enter/exit/선점 사건 연결은 별도 합의 필요.
- 실제 지상·비행·센서 상실·늦은 arm 응답·복구 잠금 시험은 미실시.
- 최종 결과는 현재 실행에 해당하는 기록 조회까지 구현. 전체 실행 이력 탐색·원본 ULog 업로드·실기체 제어 버튼은 이번 범위 밖.
- 신규 계약의 FLIGHT/SITL 지원은 남아 있으며 현재 수신은 W01과 동일한 격리 REPLAY 범위.
- 실제 기체에는 합성 보고나 가짜 통과/완료 상태를 저장하지 않음. 장치 연동 전에는 미수신/미확인으로 표시.
