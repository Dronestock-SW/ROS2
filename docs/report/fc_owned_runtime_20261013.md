# FC 유효성 기반 실행·연속 기록 — 2026-10-13
이 문서는 보고 지연에 의한 미션 중단을 수정한 기록이다.
통합 브랜치의 새 실행 정책과 검증 범위를 확인할 때 읽는다.

## 결과와 적용 범위

FC가 유효하면 보고 지연만으로 LAND하지 않는다.
`anchor_trial`·`local_xy` 경로에 적용했다.
Python 실행기와 실제 C++ 실행기를 함께 수정했다.
PX4가 자세·위치 추정·고도 제어를 계속 맡는다.
고정 출발 XY·1.7m·상승 제한 0.5m/s를 유지한다.
EV_DELAY와 실물 FC 파라미터는 바꾸지 않았다.
LiDAR 연구·실물 융합도 이번 변경에서 제외했다.

이 정책은 FC 위치 입력과 유효 플래그를 사용한다.
실제 FC 추정 무효·연결 상실은 중단한다.
FC 위치 입력의 0.2초 기준은 시작과 진행 판정에 쓴다.
비행 중 위치 전달 공백은 고정 목표 유지로 처리한다.
수동 모드와 RC 인계가 자동 명령보다 우선한다.
실제 밀림 원인 해결과 실비행 성공은 아직 미확인이다.

## 시작 검사와 비행 중 판단

시작 검사를 비행 중 보고 검사와 분리했다.

| 조건 | 시작 전 | 비행 중 |
|---|---|---|
| UWB 송신 연결·좌표 변환·최신 관측 | 필수 | 늦은 보고는 경고 |
| 직접 UWB 관측 공백 | 시작 거부, ARM 전 재확인 | 승인 목표 유지·미션 판정 보류 |
| FC 추정기 상태 보고 지연 | 최신 상태 필요 | 최신 FC 위치와 마지막 유효 플래그로 수행 |
| FC가 추정 무효를 명시 | 시작 거부 | 중단 |
| FC 위치 입력 상실 | 시작 거부 | 목표 유지·미션 판정 보류 |
| 최신 위치의 좌표 경계 이탈 | 시작 거부 | 중단 |
| 목표 회신 지연 | Offboard 모드 ACK로 송신 연결 확인 | 진단 경고, 실제 위치로 미션 판정 |
| 웹 보고·Python 메타데이터 지연 | 새로운 START 거부 | 이미 승인된 미션 유지 |
| AI 판단 지연 | 준비 완료 전 시작 불가 | 마지막 승인 목표 유지·새 판단 대기 |
| 실제 좌표 계약 변경 | 시작 거부 | 최신 관측을 가진 보고로 확인되면 중단 |
| 명령 ACK 효과 미확정 | 재명령하지 않음 | UNCONFIRMED, 자동 재시작 없음 |

누락·잘못된 보고는 좌표 변경 증거가 아니다.
늦은 보고의 설정 불일치도 먼저 경고로 기록한다.
새로운 실제 좌표나 시각을 만들어 보완하지 않는다.
FC 추정 위치를 UWB 관측으로 재발행하지 않는다.

UWB 공백 동안 도착·호버·복귀 완료를 인정하지 않는다.
복구 후 연속 10초 호버 시간을 새로 계산한다.
FC 위치 피드백이 없을 때도 완료 시간은 보류한다.
목표 회신만 늦으면 실제 위치·속도로 판정한다.
이 대기만으로 구간 제한시간을 소모하지 않는다.
전체 300초 미션 제한과 배터리 보호는 유지한다.
추정 위치의 실제 이탈 보호도 대기 중 유지한다.

C++의 0.15초 판단 유효 시간은 새 판단 적용 기준이다.
20Hz 송신기는 승인된 고정 목표를 유지한다.
갱신이 늦으면 미관측 호버 시간을 초기화한다.
경로 보간의 dt도 최대 0.1초로 제한한다.
그래서 지연 시간을 한 번에 이동 거리로 쓰지 않는다.

## 중복 검사 정리

Offboard에서 AUTO 전용 설정을 요구하지 않는다.

| 삭제·분리한 검사 | 이유 |
|---|---|
| local_start 체크리스트 | pose 검사와 같은 조건이었다 |
| Offboard의 MIS_TAKEOFF_ALT 일치 | 이 경로는 설정된 고정 로컬 높이 목표를 쓴다 |
| Offboard의 COM_TAKEOFF_ACT=0 | AUTO 이륙 후 동작 설정이다 |
| Offboard의 AUTO RC 인계 비트 | Offboard RC 인계 비트와 실제 매핑을 검사한다 |
| Offboard의 MAG_TYPE 숫자 일치 | FC 유효 플래그와 검증된 관측·명령 변환을 사용한다 |
| 보고 나이·AI 갱신 간격의 즉시 LAND | 실제 FC 입력·수동 인계와 분리한다 |

별도 native AUTO 이륙은 관련 FC 설정을 계속 검사한다.
관측 송신기의 좌표·레버암·EV_DELAY 일치 검사도 유지한다.
단일 실행기·중복 명령 영구 기록을 유지한다.
C++ 실행기의 실제 FC 상승 제한 검사도 유지한다.

| 경로 | 이전 체크리스트 | 현재 체크리스트 |
|---|---:|---:|
| C++ 실행기·합친 START | 35 / 필수 29 | 30 / 필수 24 |
| Python 실행기·별도 local_position 이륙 | 35 / 필수 29 | 30 / 필수 24 |
| Python 실행기·별도 native AUTO 이륙 | 35 / 필수 29 | 34 / 필수 28 |

정보용 6개는 그대로다.
[이전 제한 검토](constraint_audit_20261013.md)는 과거 소스 기준이다.
그 문서의 집계 JSON은 역사적 증거로 보존했다.

## 기록 보완

비행 기록을 상태 전환 중심에서 연속 표본으로 늘렸다.

| 기록 | 추가 내용 |
|---|---|
| Python 실행기 | 비행 5Hz·지상 1Hz, 비동기 파일 저장 |
| Python 관측 어댑터 | 원래 센서 시각·수신 시각·입력 나이·보고 원문 |
| C++ 실행기 | 약 10Hz 표본, 원래 FC/UWB 시각·수신 시각 |
| C++ 스레드 | 실행·20Hz 송신·상태 발행·기록·명령 전달을 분리 |
| 명령 | 요청 주체·판정 이유·입력 전체·ACK |
| 시각 대응 | ROS·monotonic·wall 시각, FC timesync offset·RTT |
| 실행 신원 | 설정·실제 C++ 바이너리 SHA-256 |
| 파라미터 | 읽기 결과만 저장, EV_DELAY·EV/flow/range 제어·Offboard timeout 포함 |

원래 관측 stamp를 현재 시각으로 덮어쓰지 않는다.
기록 순번·실제 저장 시각도 남긴다.
느린 디스크가 상태 발행과 목표 송신을 막지 않게 했다.
종료 기록은 fsync 뒤에 성공 END로 발행한다.
저장 실패를 비행 성공으로 표시하지 않는다.

관측 송신 상태에도 생성·입력 수신·송신 시각을 추가했다.
이로써 입력 지연과 상태 보고 지연을 나눠 계산한다.
FC의 실제 EV·광류 융합과 innovation은 ULog가 필요하다.
MAVROS 유효 플래그만으로 융합 센서를 확정하지 않는다.

## 검증 상태

Windows의 ROS 제외 범위를 먼저 확인했다.
최종 선택 범위는 398개 통과·18개 제외였다.
선택 범위에 정책·기록·관측 시각 시험을 포함했다.
Windows 전체 수집은 rclpy 부재로 실패했다.
ROS 시험은 Linux에서 별도로 수행한다.

실제 C++ 빌드와 지연 주입 검증이 통과했다.
[성공 CI](https://github.com/Dronestock-SW/ROS2/actions/runs/38340165422)의 소스는
`654bc6b2a49f8380ddf4465a386ef56ba2d1ad13`이다.

| 검증 단위 | 결과 |
|---|---|
| ROS 패키지 | 4개 빌드 성공 |
| Linux Python 계약 | 266개 통과 |
| 실제 C++ AI + Python 실행 경로 | 9개 통과, LiDAR HTTP 3개 제외 |
| C++ 계약 | 3그룹·49개 unittest 메서드 통과 |
| HTTP→ROS→실제 C++→합성 FC | 16개 기대 결과 통과 |
| 정상·지연·공백 복구 | 13개 END |
| 명시적 FC 추정 무효 | FAILED, 자동 LAND·실제 지상/DISARM 확인 |
| 지속 위치 전달 공백 | 목표 유지 후 사용자의 명시적 웹 LAND로 FAILED |
| 조종자 모드 인계 | PILOT_OVERRIDE, 추가 LAND 없음 |
| 실제 수신한 목표 송신 간격 | 전체 최대 53.248ms |
| C++ 연속 기록 | 2,998개, 표본 간격 최대 151.170ms |

지연 시험에는 1.2초 보고 나이와 보고 중단·손상이 있다.
Python 5초 정지와 추정기 보고 중단도 포함했다.
UWB 2초 공백·위치 2초 공백·이륙 중 2.5초 공백을 주입했다.
목표 회신 중단·1Hz FC 상태·실제 플랫폼 왕복도 확인했다.
영구 위치 공백을 자동 LAND 시험으로 해석하지 않는다.
그 경우 마지막 목표를 유지하다 명시적 취소를 받았다.

각 실행 기록의 바이너리 SHA-256을 대조했다.
16개가 모두 같은 빌드임을 확인했다.
`a0dd65b183e178089daebcc24fe60d066ac1af14ab752b9b07f18a56adf51618`이다.
원래 source stamp·수신 시각·ACK·END 저장도 확인했다.
[검증 요약 JSON](evidence/fc_owned_runtime_20261013/verification.json)을 보존했다.
원본 CI 아티팩트는 별도 outputs 디렉터리에 보존했다.

이전 실패도 덮어쓰지 않았다.
f648441 실행은 취소 응답을 START로 잘못 검사한 fixture였다.
1e35b81 실행은 모사 파라미터의 float/int 형식 오류였다.
두 원본 로그를 보존하고 수정 후 전체 흐름을 다시 실행했다.
시뮬레이션의 FC 동작은 합성 입력이다.
실제 PX4 비행 물리를 검증한 결과로 읽지 않는다.

SSH는 직접 접속과 Tailscale ping에 응답하지 않았다.
Online 표시만으로 장치 조회 성공을 주장하지 않는다.
현재 Jetson 배포·FC 실제 값·실비행은 미확인이다.
