> 본 문서는 중간보고서 SW팀 분량 초안.

> 기준 시점 2026-08-16 / 기준 커밋 `7438c17`.

## 1. 본 절의 범위

- 대상: companion 컴퓨터(Jetson Orin Nano) 상의 ROS2 소프트웨어 및 SW가 접하는 하드웨어 인터페이스(디바이스 노드, 시리얼 파라미터, 토픽, MAVLink 경계)
- 제외: 기구부·프레임·배선·부품 조달·비행 성능(비행시간·페이로드) — 전부 HW팀 작성분
- 제외: PX4 펌웨어 내부 설정 및 EKF2 파라미터 튜닝 — 자세·고도 제어는 PX4 전담(설계 결정 4·10)이므로 HW팀 작성분
- 포함 경계 예시: TFmini Plus·PMW3901은 PX4 직결 구성이므로 SW 서술 대상 아님. UWB 태그·LiDAR·CSI 카메라는 companion 직결이므로 SW 서술 대상

## 2. SW 개발 목적 및 필요성

### 2.1 목적

- 야간 무인 재고 스캔 임무의 자율 수행 — 웹 좌표 명령 수신부터 지정 랙 도달·마커 판독·결과 송신까지 전 과정의 자동화

### 2.2 기술 제약에서 도출된 필요성 4가지

**(1) 실내 GPS 부재 → 대체 측위 체계 필수**

- 창고 실내 운용으로 GPS 신호 사용 불가
- 대체 수단: UWB 앵커 4기 기반 절대 좌표 + LiDAR 스캔매칭 상대 이동
- 두 관측치를 PX4에 공급하는 변환·전처리 소프트웨어 필요 → SW 개발의 1차 필요성

**(2) 상태추정기 단일화 원칙 → companion 역할의 명시적 한정**

- 원칙: PX4 EKF2가 비행제어의 유일한 상태추정기(설계 결정 10)
- 근거: companion 측 이중 융합 시 (a) 상관 오차 이중 계상에 따른 공분산 과신, (b) SLAM/UWB pose 되먹임 시 정보 순환, (c) 고장 시 책임 필터 분리 불가
- 결과: companion SW는 "관측치 공급자"로 한정. 추정기 미구현이 결함이 아니라 설계 준수

**(3) 장치 식별 충돌 → 소프트웨어적 고정 수단 필수**

- 실측 문제: LiDAR와 UWB 태그가 동일 칩(CP2102, `10c4:ea60`), 동일 공장 serial(`0001`)
- 결과: `VID:PID:serial` 조합으로 구분 불가. USB 열거 순서에 따라 `/dev/ttyUSB*` 번호 반전
- 대응: USB 포트 위치(`KERNELS`) 기반 udev 규칙 + 노드 기동 시 첫 줄 `type` 검증 이중화
- 미대응 시 위험: LiDAR 데이터를 위치 정보로 오인한 상태의 비행

**(4) 군집 확장 → 코드 무변경 배포 구조 필요**

- 요구: 2호기를 1호기와 동일 코드로 배포
- 채택: `ROS_DOMAIN_ID` 분리(1호기=1, 2호기=2). 토픽 네임스페이스 접두어 미도입
- 효과: 드론 간 ROS2 상호 불가시 상태 확보. 소스 분기 불요

### 2.3 SW 파트 담당 범위 확정 결과

| 기능 | 담당 | 근거 |
|---|---|---|
| UWB 수신·변환 | SW | 설계 결정 10 관측치 공급 |
| LiDAR 드라이버·스캔매칭 | SW | 동일 |
| 카메라 구동·마커 인식 | SW | Phase 3 |
| 임무 FSM·위치제어 | SW | 설계 결정 4 |
| 자세제어·고도제어 | HW팀 작성분(PX4) | 설계 결정 2·4 |
| 앵커 bias 교정·안테나 지연 보정 | HW팀 작성분 | 앵커·안테나 단위 작업 |

## 3. 현재까지의 개발 진행 상황

### 3.1 전체 요약

- 저장소 구성: 자체 패키지 1개(`drone_bringup`, launch·파라미터 전용) + 제조사 서브모듈 1개
- 자체 작성 ROS2 실행 노드: 0개 — 현재까지의 산출물이 기동 구성과 설계 확정에 집중된 결과
- 실기 검증 완료 데이터 경로: 2개(`/scan`, `/camera/image_raw`)
- 빌드 상태: 정상(2 packages, 종료코드 0)

### 3.2 모듈별 상세

**측위 — UWB**

- 상태: 인터페이스·설계 확정 완료 / 노드 구현 미착수
- 완료분: 시리얼 인터페이스 확정(`/dev/uwb`, 921600 8N1, JSON 1줄/샘플, 약 43Hz), 줄 종류 2종(압축 13필드 / 상세 94필드) 분석, udev 규칙 작성, 노드 설계 문서(파라미터 8종·금지사항 7종·테스트 절차 7단계)
- 미완분: `drone_uwb` 패키지 및 `uwb_node` 전체
- **착수 가능 여부: 가능.** 앵커 bias 교정(HW팀 작성분)은 값의 정확도에만 영향. 노드는 태그 출력을 ROS 메시지로 옮기는 통과(pass-through) 구조이므로 교정 전에 구현·검증 가능
- 근거: [uwb_node_design.md](../uwb_node_design.md), [evidence/06_uwb_fail.txt](evidence/06_uwb_fail.txt)

**측위 — LiDAR**

- 상태: 드라이버 구현 완료 / 스캔매칭 미착수
- 완료분: `lidar.launch.py`, `lidar_tmini.yaml`, 제조사 코드 서브모듈 정식 등록
- 실측: `/scan` 평균 9.9743 Hz(192메시지 / 19.149초), `range` 0.03~12.0 m, QoS BEST_EFFORT
- 미완분: scan-to-scan / scan-to-map 매칭(Phase 2)
- 근거: 커밋 `bf3c96d`, [evidence/04_lidar_launch.txt](evidence/04_lidar_launch.txt)

**측위 — 광학흐름**

- 상태: SW 범위 외(PX4 직결 구성, 설계 결정 8). 파라미터 설정은 HW팀 작성분

**비행제어 연동(MAVROS / PX4)**

- 상태: 환경 준비 완료 / 연동 코드 미작성
- 완료분: MAVROS 2.14.0 설치, geoid 데이터셋(`egm96-5.pgm`) 배치, PX4+MAVROS2 채택 결정 확정
- 미완분: MAVROS launch·파라미터, vision_pose 변환 노드, `/cmd_vel` 발행부
- 실행 확인: 불가(기체 미연결)
- 근거: [pixhawk_decision.md](../pixhawk_decision.md), [evidence/07_mavros_fail.txt](evidence/07_mavros_fail.txt)

**인식 — 카메라**

- 상태: 스트림 발행 완료 / 캘리브레이션 미착수
- 완료분: `camera.launch.py`, `camera_imx219.yaml`, `/camera/image_raw` 발행(rgb8 1640×1232)
- 실측: `/camera/camera_info` 평균 29.9985 Hz(578메시지 / 19.234초) — 카메라 파이프라인 30fps 동작 확인
- 해상도 선정 근거: 1640×1232가 30fps 이상 모드 중 전체 화각 유지 유일 모드
- 미완분: 렌즈 초점 조정 → 내부 파라미터 캘리브레이션 → `camera_info` 실값 발행 → `base_link → camera_link` TF 정의
- **담당 재확인 필요**: 저장소는 초점 조정을 HW팀 작성분으로 표기하나 그 사유가 미기재. 렌즈 방식(수동 초점 여부) `[확인필요]` — 5장 참조
- 근거: 커밋 `3f7f136`, [evidence/05_camera_launch.txt](evidence/05_camera_launch.txt)

**인식 — QR / ArUco**

- 상태: 미착수
- 선행 조건: 카메라 캘리브레이션(내부 파라미터 부재 시 solvePnP 기반 거리·각도 산출 불가)
- 가용 자원: OpenCV 4.5.4(`QRCodeDetector`·`aruco` 모듈 사용 가능)
- 근거: [evidence/08_qr_marker_fail.txt](evidence/08_qr_marker_fail.txt)

**통신**

- Tailscale: 구현 완료(개발 채널). `tailscaled` active, 피어 3대 확인
- `ROS_DOMAIN_ID` 격리: 구현 완료(`~/.bashrc`에 값 1 고정)
- LoRa 텔레메트리: 미착수(Phase 1)
- 웹 API 경계 토픽 5종: 계약 확정 / 구현 미착수
- 근거: [evidence/09_comm.txt](evidence/09_comm.txt)

**임무제어(FSM / BT)**

- 상태: 전 항목 미착수(Phase 1 이후)
- 대상: 임무 FSM, Behavior Tree 전환, 가상벽·keepout 검사, 위치제어 PID, 게인 스케줄링

## 4. 계획 대비 진행 상황

### 4.1 달성률 산정 범위

- 산정 대상: **Phase 0(기반 구축) 항목만**. 로드맵이 정의한 현 단계 목표 범위
- 제외: Phase 1~4 항목 — 착수 시점이 도래하지 않은 후속 단계이므로 현 시점 달성률의 분모에 미포함

### 달성률 산정 기준

- 분모: **Phase 0의 SW 담당 항목**. HW팀 작성분 3건(#10~12)은 SW 달성률 산정에서 제외
- 100%: 저장소에 코드·설정 존재 + 의도한 출력의 실행 확인 완료
- 60%: 산출물 작성 완료, 적용·반영 절차 미완
- 30%: 설계 문서 완료, 구현 미착수
- 0%: 저장소에 해당 코드 부재
- `[확인필요]`: 완료 표기는 있으나 검증 근거 부재. **달성률 산정에서 제외**하고 별도 표기
- Phase 1~4 항목: 착수 시점 미도래로 분모에 미포함. 이를 분모에 포함할 경우 산정치가 실제 진척과 무관하게 하락

### 5.2 `uwb_node` 구현 (#7, 30% → 100%)

| 항목 | 내용 |
|---|---|
| 기존 표기 | "HW팀 앵커 교정 대기" |
| **정정 사유** | 앵커 bias 교정은 좌표값의 **정확도**에만 영향. 노드가 수행하는 작업(시리얼 개방·첫 줄 type 검증·라인 프레이밍·JSON 파싱·발행 판정·메시지 조립·watchdog)은 어느 것도 교정 결과에 의존하지 않음 |
| 설계상 근거 | 노드를 통과(pass-through) 구조로 규정. 전처리를 섞지 않도록 명시 |
| 하드웨어 의존도 | 파싱·프레이밍·watchdog은 기록된 샘플 줄로 단위 검증 가능. 태그 연결은 최종 실기 검증 단계에만 필요 |
| 필요 작업 | `drone_uwb` 패키지 신설 → `uwb_node` 구현 → 태그 연결 → 설계 문서 7단계 테스트 절차 수행 |
| 완료 시 효과 | 자체 작성 ROS2 노드 0개 → 1개. 측위 갱신 주기 지표 측정 가능 상태 진입 |
| 근거 | [uwb_node_design.md](../uwb_node_design.md) §4·§5, [03_metrics_plan.md](03_metrics_plan.md) §2 |

> 태그 출력의 `fix:false` 상태에서도 노드 구현·검증은 진행 가능. 다만 `fix=false` 프레임은 설계상 미발행이므로, **정확도 지표(측위 RMSE) 산출은 HW팀 교정 완료 이후**로 유지.

### 성능 지표 작성 원칙

- 실측 로그가 없는 값은 생성하지 않음. 미측정 항목은 목표치·측정 계획만 기재
- 목표치가 `[확인필요]`인 이유: 로드맵이 완료 판정을 정성 기준("반복 재현", "오차 감소를 로그로 입증")으로 규정하고 있으며 수치 목표 미정의
- 측정 조건 미확정 항목 9건 존재(앵커 설치 높이, 태그 장착 높이, 기준 위치 확보 수단, 체커보드 보유, QR 규격, lux 계측기 보유, 랙 규격, 정답 재고 목록 확보 방법, 외부 측위 장비 보유) → [03_metrics_plan.md](03_metrics_plan.md) §8
- HW팀 실측치와의 구분: UWB 오차 약 0.66 m 및 갱신율 약 43 Hz는 태그 시리얼 로그 기준의 **HW팀 작성분**. ROS2 경로를 거치지 않은 값이므로 SW 성능 지표로 미기재
- 측정 도구는 자체 검증 완료([evidence/metrics_selftest/](evidence/metrics_selftest/)). 대상 노드 완성 즉시 동일 절차로 측정 가능

## 7. SW 기술적 기대효과

- 상태추정기 단일화(PX4 EKF2 전담) 구조 확립으로 융합 로직 이중화에 따른 공분산 과신·정보 순환·고장 원인 분리 불가 문제의 사전 차단
- `ROS_DOMAIN_ID` 기반 격리 채택으로 2호기 배포 시 소스 분기 없이 동일 코드 재사용 — 군집 확장 비용의 설정값 1개 수준으로 축소
- 관측치 공급자 역할로의 companion 한정 및 제조사 코드 무수정 원칙 유지로 센서·드라이버 교체 시 영향 범위를 launch·파라미터 계층에 국한
- 웹 API 경계 토픽 계약의 사전 고정으로 웹 구현체 교체가 드론 측 코드에 무영향인 구조 확보
