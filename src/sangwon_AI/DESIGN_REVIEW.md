# 설계 공동 검수 기록
이 문서는 설계 충돌·미결정 사항과 사용자 답변을 추적한다.
질문 순서와 구현 착수 조건을 검토할 때 읽는다.

상태: 2026-10-04 1차 검수 진행 중.
제안은 사용자 합의·실측 완료와 구분한다.

## 1. 검수 항목

| ID | 발견한 문제·근거 | 처리 상태 |
|---|---|---|
| RV01 | 마커와 QR의 관계가 미정이면 판독 위치를 계산할 수 없음 | 사용자 확정: QR마다 ArUco 고정 배치. 상대 배치 치수는 수령 필요 |
| RV02 | 웹 XYZ가 기체 위치인지 라벨 위치인지 scan 계약에 구분이 없음 | 사용자 확정: scan XYZ는 QR 라벨 위치. 이동 XYZ와 분리하고 장착 변환·거리·방향으로 기체 pose 도출. 웹 JSON 반영 필요 |
| RV03 | 경계 미제공 때 선분 이동만 허용하나 미세 조정은 선분 밖으로 나갈 수 있음 | 사용자 확정: 웹에 라벨별 접근·작업 허용 구역 요청(QS-W8). 검증 구역 안에서만 스캔, 전체 경계 전 일반 자동 우회 보류. JSON 회신 필요 |
| RV04 | B11 체류 뒤 바로 다음 점으로 넘어가는 기존 표에 Scan 단계가 없음 | 명세를 B21 ScanTask 경유로 보완. 구현은 아직 없음 |
| RV05 | 정렬 위치에서 다음 경로로 연결하는 이탈 규칙이 없음 | 사용자 확정: 결과 저장→접근 대기점 복귀→다음 목표. 지나온 구간 재검사, 이탈 실패는 이동 실패로 처리 |
| RV06 | 시각 없는 QR String으로 이전 지점의 지연 판독을 새 결과로 채택할 수 있음 | 소스 시각·세션·시도 경계 계약 필요. 단순 수신 시각 추가로 해결됐다고 보지 않음 |
| RV07 | 카메라 대체 판독과 ArUco 정렬이 같은 카메라에 의존 | 사용자 확정: 마커 획득 한도 실패·카메라 고장은 실패 기록→대기점 복귀→다음 목표. 비행·이탈 정상 조건, 사전 카메라 불량은 READY 거부 |
| RV08 | 스캐너 3회만 정해졌고 시간·전체 작업 한도가 미정 | QS-M1~M5 실측. 무한 재정렬/카메라 대기 방지 |
| RV09 | ±10° 이동 yaw 허용값을 근접 스캔 안정 기준으로 오용할 수 있음 | 스캔 상대 정렬·각속도·안정 시간은 별도 승인 |
| RV10 | 다른 라벨을 읽었을 때 대상 일치와 여러 QR 규칙이 미정 | 웹 정답 라벨·marker ID 매핑·실제 QR 샘플 필요 |
| RV11 | Jetson 전용 env·통일된 ROS 실행 환경이 없었음 | 전용 환경·실행기 추가. 개발 검사·5개 CTest 통과. 장치·권한·전체 운영 준비는 남음 |
| RV12 | 오프라인 저장·서버 거부·재고 업무 성공이 혼동될 수 있음 | 로컬 결과와 서버 수락 분리. 보존·재전송·임무 부분 실패 표시 회신 필요 |
| RV13 | 라벨 위치만으로 어느 면에서 판독할지 결정할 수 없음 | 사용자 결정: 라벨 정면 방향 제공 방식은 웹 담당자 협의. QS-W7 회신 필요, 방향·접근 공간 미검증이면 scan READY 금지 |

## 2. 검수 순서

좌표 의미·라벨별 작업 구역 요청·스캔 후 이탈·마커/카메라 상실 정책은 사용자 답변을 반영했다.
남은 우선 검수는 판독 문맥(RV06), 시간 한도(RV08), 웹의 작업 구역·대상 라벨·결과·방향 자료(RV03/RV10/RV12/RV13)다.
실측할 값을 질문 답변만으로 비행 승인값으로 만들지 않는다.
UWB 세부 사양 질문은 전체 사양 수령까지 보류한다.
환경 적용 결과는 [JETSON_ENV.md](JETSON_ENV.md)를 따른다.
스캔 상세 기준은 [QR_SCAN_SPEC.md](QR_SCAN_SPEC.md)를 따른다.
