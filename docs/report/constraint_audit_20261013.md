## EKF2_EV_DELAY의 역할

EV_DELAY는 나이 허용치가 아니다.
IMU 기준 실제 관측 시각에 맞추는 보정값이다.
단위는 ms다.

고정 PX4 소스는
`d6f12ad1c4f70ad3230afd7d86e971421e02fef4`다.
이 소스의 파라미터 범위는 0–300ms다.
실물 펌웨어 버전과 현재 값은 이번에 조회하지 못했다.
FC 파라미터 쓰기나 ARM 명령은 하지 않았다.

PX4는 EV 표본 시각에서 이 값을 뺀다.
현재 UWB 송신기는 원래 ROS 관측 stamp를 보낸다.
관측과 실제 측정 시각의 잔여 차이를 구해야 한다.
상태 보고가 늦은 시간을 그대로 넣으면 안 된다.
stamp가 이미 실제 측정 시각을 표현한다면,
추가 보정은 같은 지연을 두 번 반영할 수 있다.
평활로 생긴 측정 시각 차이는 별도로 확인한다.

공식 설명은 [PX4 EV 시각 보정 문서](https://docs.px4.io/main/en/ros/external_position_estimation#tuning-ekf2_ev_delay)에 있다.
동적 기록에서 시차와 EKF innovation을 비교한다.
정지 기록만으로 이동 중 지연을 식별하기 어렵다.

FC 값만 바꾸면 새 관측 공백을 만들 수 있다.
`local_odometry.parameter_gate()`가 예상값을 검사한다.
다르면 `parameter_mismatch:EKF2_EV_DELAY`로 송신을 거부한다.
미션도 송신 설정과 같은 예상값을 요구한다.
FC 값·송신 설정·미션 설정을 함께 맞춰야 한다.
정렬 증거의 부팅·시각 기준도 다시 확인해야 한다.
이 문서는 새 EV_DELAY 값을 제안하지 않는다.

## FC와 companion의 책임 검토

자세·위치 추정·저수준 제어는 FC의 책임이다.
companion은 웹 미션과 명령 소유권을 알아야 한다.
PX4는 웹 명령의 중복·좌표 계약을 알 수 없다.
미션 완료·복귀 완료 기록도 companion이 맡는다.

반면 모든 센서 나이를 즉시 LAND로 연결할 필요는 없다.
관측 상태 보고 지연과 실제 FC 융합 상실은 다르다.
이는 앞으로 분리할 정책이며 아직 구현하지 않았다.

| 검토 대상 | 확인한 문제 | 다음 변경 방향 |
|---|---|---|
| 전달 관측 보고 나이 | 지연된 상태 보고만으로 LAND 가능 | 원래 표본·실제 송신·FC 수신을 분리 기록 |
| UWB 0.25초·추정기 0.5초·위치 0.2초 | FC 유효성과 별개인 고정 정책 | FC 융합 상태·실제 입력 지연 분포로 역할 검토 |
| AI 판단 0.15초·갱신 0.2초 | 계산·IPC 지연으로 출력과 미션 중단 가능 | 제어 출력과 미션 판단 주기를 분리 검증 |
| Offboard에서 AUTO용 설정 확인 | MIS_TAKEOFF_ALT·COM_TAKEOFF_ACT·AUTO 인계 비트까지 요구 | 사용 중인 모드에 적용되는 조건만 선택하도록 검토 |
| 웹 heartbeat 2초 | 웹 지연이 비행 중단에 직접 연결 | 명령 freshness와 진행 중 미션 정책 분리 검토 |

FC 추정이 유효할 때 경고·미션 진행 보류로 바꿀 후보가 있다.
그 판단에는 실제 FC aiding·innovation 기록이 필요하다.
MAVROS의 estimator_valid 한 비트만으로 판단하지 않는다.
이번에는 동작이나 나이 기준을 바꾸지 않았다.
고정 출발 XY·1.7m·상승 제한 0.5m/s를 유지했다.

## 기록의 현재 빈틈

기록만으로 모든 중단 원인을 분리하기는 어렵다.

Python `flight_sample`은 약 5Hz로 저장한다.
목표·FC 위치·속도·UWB 위치와 나이는 있다.
전달 관측 나이·추정기 나이·상태 보고 나이는 빠져 있다.
단계 전환 기록에는 더 많은 상태가 있다.
하지만 경계 전후의 연속 표본을 대신하지 못한다.

C++ 파일은 단계 전환과 명령 사전 기록 중심이다.
상태 topic에는 관측 나이와 최대 송신 간격이 있다.
그 topic의 모든 표본을 파일로 저장하지는 않는다.
전체 FC 속도·센서 시각도 매 표본 남기지 않는다.
명령 사전 fsync는 별도 작업 스레드에서 한다.
저장 오류와 입력 지연은 별도로 구분해야 한다.

다음 기록 보완에서 필요한 필드는 아래와 같다.
이 보완은 이번 문서 변경에 포함하지 않았다.

| 기록 지점 | 필요한 필드 |
|---|---|
| 관측 계산 | 원시 수신·관측 대표 시각·계산 시작/끝·거절 이유 |
| FC 관측 송신 | 원래 stamp·수신·송신 시각·발행 sequence·거절 이유 |
| AI·실행 판단 | 전체 입력 나이·FC 상태·목표 XY·판정한 모든 조건·선택한 조치 |
| 명령 실행 | LAND 요청 주체·이유·요청·ACK·실제 모드 전환 시각 |
| FC ULog | EV 표본·수신 시각·fusion·innovation, 광류 융합, 추정 위치·속도·목표 |
| 시각 비교 | ROS·monotonic·FC 시각의 대응값·부팅 ID |

이 기록을 같은 시간축으로 대조해야 한다.
센서·송신·보고·AI·FC 융합 지연을 각각 계산한다.
그 결과로 EV_DELAY와 companion 정책을 정한다.

## 이번 확인 범위
