## 1. 요청의 목적과 경계

웹이 임무를 전달하면 Jetson이 검증하고 실행한다.

```text
운영자 -> 웹 화면 -> Platform 서버
                       |
              HTTP 임무·명령 조회
                       v
               Jetson 검증·행동 트리 -> PX4
                       |
                WS 상태 / HTTP 결과
                       v
                 서버 저장 -> 웹 표시
```

| 담당 | 책임 |
|---|---|
| 웹 화면 | 지도·경유점 편집, 운영자 확인, 명령 요청·결과 표시 |
| Platform 서버 | 버전 저장, 기체별 명령 전달, 결과·사건 저장 |
| Jetson | 입력 재검증, 임무 선택, 경로·목표 생성, 실행 결과 판정 |
| PX4 | 위치·고도·방향 제어, 기체 상태와 비상 동작 |

화면의 시작 버튼은 요청을 만든다.
실제 이륙은 Jetson 검증과 PX4 상태 확인 뒤 이뤄진다.
웹의 좌표 도착 추측으로 경유점을 완료 처리하지 않는다.
Jetson이 보내는 방문 결과를 표시한다.

## 2. 웹에 요청할 개발 항목

아래 완료 조건으로 웹·Jetson 연동을 검수한다.
필수 항목은 첫 자율 임무 연동에 필요하다.
조건부 항목은 해당 기능을 활성화할 때 필요하다.

| ID | 우선 | 요청 | 완료 조건 |
|---|---|---|---|
| W01 | 필수 | v1 확장 계약 버전·지원 기능 구분 | 구형 수신기가 새 필드를 무시하고 비행하지 않음 |
| W02 | 필수 | 임무·지도·좌표 변환 참조를 묶어 전달 | Jetson이 같은 개정의 전체 자료를 저장·검증함 |
| W03 | 필수 | 이동 기체 XYZ·scan 라벨 XYZ의 유형 구분과 순서, 별도 이륙 높이, 호버 시간 입력 | 이동점 순서 보존, scan 라벨 좌표 직접 비행 금지, z 누락은 오류 |
| W04 | 필수 | 선택 시작 yaw·경유점 yaw와 현재 방향 확인 | 현재 방향과 목표 방향을 따로 표시, 각도 기준 명시 |
| W05 | 필수 | 장애물 외곽·높이, 선반·천장 형상, 구역별 z 제한 | 이동·회전·상승·하강 공간을 Jetson이 검사할 자료 제공 |
| W06 | 필수 | 시작·일시정지·재개·취소·긴급 착륙 요청 | 요청 ID별 수락·거부·실행 결과를 조회 가능 |
| W07 | 필수 | 임무 상태·기체 상태·명령 결과 분리 | 명령 수락을 착륙 완료나 임무 성공으로 표시하지 않음 |
| W08 | 필수 | 현재 위치·활성 목표·센서 출처 표시 | PX4 융합 위치와 UWB 관측을 구분, 낡은 값 표시 |
| W09 | 필수 | 실행 중 임무·지도 개정 고정 | 일시정지 중에도 경로 교체 금지, 새 개정은 다음 임무 |
| W10 | 필수 | 방향 검증 구역·변환본·상부 공간 확인 관리 | 승인 자료를 해당 지도·임무·기체 설정과 연결 |
| W11 | 필수 | 단절·재연결·중복 요청 처리 | 재접속으로 재이륙·재개·이전 비행 착륙 명령이 재실행되지 않음 |
| W12 | 필수 | 로그 수집·저장공간 상태 표시 | ULog 실패 경고와 새 비행 기록 공간 부족을 구분 |
| W13 | 조건부 | 비행 가능 경계·금지 구역 | 제공·검증 전 자동 우회는 비활성화 |
| W14 | 필수 | 합성 예제·오류 응답·연동 시험 환경 | 정상·거부·단절 사례를 같은 계약 버전으로 재현 |
| W15 | 필수 | 전원 투입부터 시스템 자동 점검 상태 표시 | 부팅·장치 연결·점검·시스템 준비를 단계별로 표시, 프로세스 생존만으로 정상 표시 금지 |
| W16 | 필수 | 시스템 준비와 특정 임무 준비 분리 | 필수 점검·승인·지도·현재 상태 검증 뒤 해당 임무에만 준비 ID 발급, 부팅만으로 시동하지 않음 |
| W17 | 필수 | READY 신선도와 시작 요청 문맥 결합 | boot/runtime/control 세션·준비 ID·준비 개정 일치 및 신선도 확인, 오래된 초록 표시와 시작 금지 |
| W18 | 필수 | 점검 완료·준비됨 알림 및 원인/조치 화면 | PASS/FAIL/UNKNOWN/WARN·출처·최종 관측·운영자 조치 표시, 같은 상태 알림 중복 방지 |

전체 JSON 키·URL·신규 버전 번호는 구체안을 작성했으며 협의 대상이다.
기존 v1을 현재 요구에 맞게 구현했다고 가정하지 않는다.
이번 요청서의 추가 항목은 구현 필요사항이다.

## 3. 웹에서 지원할 임무 동작

첫 버전은 자동 이륙·호버·좌표 이동·복귀·착륙을 다룬다.

| 화면 동작 | Jetson에 요청할 의미 |
|---|---|
| 시작 | 저장한 전체 임무를 실행. 기본은 Jetson 자동 이륙 |
| RC 이륙 후 시작 | 예외 모드. 수직 이륙·제자리 호버 상태에서 인계 |
| 단일 좌표 이동 | 경유점 1개 임무. 완료 후 출발점 복귀·착륙 |
| 일시정지 | 현재 진행 보존, 재개·취소까지 위치 유지 |
| 재개 | 현재 상태와 남은 경로를 재검사한 뒤 진행 |
| 취소 | 지상 준비는 중단, 이륙 상승 중에는 현 위치 착륙, 임무 중에는 복귀·착륙 |
| 긴급 착륙 | 복귀 없이 현재 위치에서 PX4 Land 요청 |

취소는 공중 시동 해제나 임무 기록 삭제를 뜻하지 않는다.
긴급 착륙도 모터 정지 명령이 아니다.
지상 준비 취소는 실제 지상·시동 상태까지 확인한다.
이륙 상승 중 취소는 이륙 높이 도달을 기다리지 않는다.
RC 비상 인계 뒤에는 같은 비행의 자율 재개를 거부한다.
착륙 후 새 임무를 받아야 한다.
RC 연결이 없어도 자동 이륙 시작은 허용할 수 있다.
웹은 수동 인계 불가를 경고하고 Jetson 준비 결과를 따른다.
복귀·착륙에 진입하면 일시정지·재개도 거부한다.
화면 버튼 상태와 Jetson 거부 응답을 같은 규칙으로 맞춘다.
복귀 중 긴급 착륙과 RC 비상 인계는 계속 처리한다.

경유점 yaw는 지도에 그린 절대 도착 방향이다.
시작 목표 yaw는 선택이며 이륙 후 회전한다.
현재 기체 방향 화살표는 측량본의 확인용이다.
복귀 착륙 때는 이륙 직전 방향을 복원한다.
회전 공간이 막히면 현재 방향으로 착륙한다.
필드가 없는 yaw와 숫자 0인 yaw를 구분한다.

QR 스캔은 [QR_SCAN_SPEC.md](QR_SCAN_SPEC.md)로 설계를 보완한다(2026-10-04).
ArUco 미세 정렬·호버 뒤 스캐너 최대 3회, 실패하면 카메라로 판독한다.
성공·최종 판독 실패 모두 결과 기록 후 접근 대기점으로 돌아와 다음 목표로 진행한다.
마커 획득 한도 실패·카메라 고장도 같은 순서를 따른다. 비행·이탈 실패 정책은 우선한다.
기존 판독 코드는 있으나 새 BT 연결은 미구현이다.
웹은 QS-W1~W8의 작업 유형·라벨·마커·접근 방향·허용 구역·결과 계약 자료를 회신한다.
구현·검증 전 scan 임무를 이동 임무처럼 실행하지 않는다.

scan XYZ는 QR 라벨이 붙은 위치이며 z는 공통 바닥에서 라벨까지 높이다.
일반 waypoint XYZ는 기체 위치다. 동일한 XYZ 이름이라도 유형 없는 변환·실행을 금지한다.
라벨 정면 방향과 기준점 표현은 웹 담당자와 협의한다. 선택 도착 yaw로 대신하지 않는다.
Jetson은 장착 변환·판독 거리로 기체 목표를 별도로 산출한다.
라벨·접근 대기점·현재 기체 판독 목표를 화면에서 구분하고 진입/이탈 진행도 표시한다.
정면 방향·접근 공간·변환이 미검증이면 해당 scan 임무의 시작 불가 이유를 표시한다.
사용자 결정에 따라 라벨별 접근·작업 허용 구역을 추가 요청한다(QS-W8).
구역 ID·지도/라벨 참조·개정·평면 외곽·최저/최고 z·기하 의미·진입/이탈 연결·승인 참조를 포함한다.
웹은 구역을 제공하고 Jetson은 기체 여유·장애물·경로를 검사해 대기점과 판독 pose를 산출한다.
전체 비행 경계가 없을 때도 이 국소 구역을 검증해야 스캔할 수 있으며 일반 자동 우회 권한은 생기지 않는다.

## 4. 지도와 운영자 확인

웹은 실제 형상을 보내고 Jetson은 기체 여유를 계산한다.

| 자료 | 필요한 내용 | 준비되지 않았을 때 |
|---|---|---|
| 지도 | ID·개정·단위·원점·직교 축 | 임무 거부 |
| 장애물·선반 | 외곽과 바닥 기준 점유 높이 구간 | 관련 공간의 통과 검증 불가 |
| 천장·상부 구조 | 외곽과 아래면·점유 높이 | 관련 고도 변경 검증 불가 |
| 고도 제한 | 구역 외곽과 기체 중심 기준 z 최저·최고 | 관련 경로 거부 |
| 방향 검증 구역 | 경계·승인 근거·지도 및 기체 설정 버전 | 구역 밖 자동 임무 거부 |
| 변환본 참조 | 승인된 지도↔제어 좌표 변환 버전 | 자동 임무 거부 |
| 비행 경계·금지 구역 | 실제 제공 여부와 영역 | 자동 우회 보류 |
| 상부 공간 확인 | 운영자·확인 시각·대상 임무와 지도 개정 | 시작 거부 |

지도 영역이 비어 있는 경우와 자료가 없는 경우를 구분한다.
경계가 없으면 검증한 웹 경로만 실행한다.
복귀는 기록한 진행 경로를 역추적한다.
지정 경로가 있어도 점 사이 구간까지 검사한다.

고도 검증 전에는 선반 위 비행을 보류한다.
거의 평평한 한 층 바닥을 z 기준으로 쓴다.
상부 공간 확인은 새 상부 장애물 감지를 대신하지 못한다.
운용 중 새 상부 장애물은 현재 2D LiDAR로 확인할 수 없다.

웹 도면 XY와 UWB XY는 기준점 측량으로 연결할 계획이다.
UWB 전체 사양 수령 뒤 어댑터·측량 수치를 검토한다.
운용 중 앵커 이동은 가정하지 않는다.

## 5. 상태 화면에 필요한 표시

웹은 마지막 수신 사실과 현재 실행 결과를 구분한다.

| 표시 | 요구 |
|---|---|
| 임무 진행 | 임무·실행 ID, 경로 개정, 현재 단계, 활성 경유점 |
| 기체 | PX4 연결·모드·시동·착륙 상태, 제어권 |
| 위치·방향 | 지도 기준 값, 출처·유효성·관측 나이 |
| 실제 목표 | 기체 이동점·접근 대기점·판독 목표·복귀점·정지점 중 현재 출력 목표. 라벨 위치는 별도 표시 |
| 명령 | 전송 대기·결과 미확인·수락·거부·실행 완료 |
| 연결 | 마지막 갱신 시각, 단절 상태, 받은 임무 계속 수행 정책 |
| 복귀·착륙 | 사용자 취소·저전력·센서 상실 등 원인 |
| 경고 | LiDAR 단절, RC 인계 불가, 배터리 자료 누락, 로그 수집 실패 |
| 기록 실패 복귀 | 비행 중 필수 기록 실패를 원인으로 복귀·착륙 중임을 표시 |
| 시작 불가 | 이유와 해당 경유점·구역·입력 항목 |
| 시스템 점검 | 현재 부팅/실행기 ID, 부팅 단계, 필수 체크별 결과·출처·최종 관측·실패 원인 |
| 임무 준비 | 특정 snapshot/preparation ID, 준비 개정, 사용 프로파일, 시작 가능 여부·유효기간 |
| 준비 알림 | 시스템 준비와 임무 준비 알림 분리, READY 상실 시 즉시 해제·원인 표시 |

Wi-Fi 단절 중 받은 임무는 계속 수행한다.
화면은 마지막 위치를 실시간 위치처럼 표시하지 않는다.
명령 응답이 없으면 결과 미확인으로 표시한다.
전달되지 않은 긴급 착륙을 완료로 표시하지 않는다.
단절 중 미전달 요청은 재접속 때 자동 실행하지 않는다.
현재 상태와 기존 요청 결과를 대조한 뒤 다시 요청한다.
신규 수락 유효시간은 생성 후 10초를 초기 시험값으로 사용한다.
이미 수락한 임무 실행과 결과 조회에는 이 10초 한도를 적용하지 않는다.

ULog 자동 수집 실패는 경고다.
다음 임무 시작을 그 이유만으로 막지 않는다.
행동·센서 기록 공간 부족은 새 임무 거부 사유다.
비행 종료 72시간이 지난 검증된 Jetson 사본만 정리한다.
실패·미검증 파일과 Pixhawk SD 원본은 그 삭제 대상이 아니다.
웹은 보존 상태를 표시할 수 있어야 한다.
웹으로 원본 ULog를 업로드하는 기능은 별도 협의다.

## 6. 기존 v1과 맞춰야 할 차이

기존 URL은 비교 기준이며 새 의미는 확장 합의가 필요하다.

| v1 근거 | 이번 요청 | 연동 시 주의 |
|---|---|---|
| HTTP 임무 조회 2Hz, WS 상태 10Hz | 기본 통신 구조 재사용 | 실제 지연·주기 보장은 시험으로 확인 |
| ACTIVE 상태로 이륙 조건 판단 | 검증된 임무와 새 시작 요청 연결 | 서버 재조회만으로 재이륙 금지 |
| return_to_home·land 요청 | 시작·일시정지·재개·취소 의미 추가 | 기존 action 이름과 새 의미 대응표 필요 |
| HOLD/착륙 후 경로 배포 문구 | 실제 착륙·시동 해제 뒤 새 임무 | PAUSED를 경로 교체 허가로 쓰지 않음 |
| 일부 잘못된 경유점 제거 가능 | 한 점이라도 잘못되면 전체 거부 | 필수 경유점을 조용히 생략하지 않음 |
| x/y는 UWB 관측 | 주 화면은 변환된 PX4 융합 위치 | 기존 x/y 필드 의미를 몰래 바꾸지 않음 |
| UWB_ANCHOR_LOCAL 축 정의 | 웹 도면과 승인 변환본 사용 | 직교 축·단위·원점을 재협의 |
| ACK는 상태 진입 수락 | 수락·실행 결과를 모두 추적 | HTTP 성공과 물리 완료를 구분 |
| 오래된 요청 결과 409 처리 | 알려진 수락 결과·사건의 재전송 보존 | 다음 단계로 넘어가도 결과 유실 방지 |
| FAILSAFE_LAND가 failed_returning | 실제 착륙 단계와 실패 원인 표시 | 비상 착륙을 복귀 중으로 오표시하지 않음 |
| 조회 실패 3초 감시 | 연결 경고, 받은 임무 계속 수행 | Jetson↔PX4 단절 정책과 구분 |
| 재접속 후 남아 있는 control_action | 미수락 요청의 자동 실행 차단 | 기존 수락 결과는 같은 ID로 조회 |
| waypoint 0.7초 등 기존 대기값 | 호버 시간·도착 안정 시간 분리 | 실측 전 자동 도착 성능으로 승인하지 않음 |

## 7. 웹팀에 요청할 회신 자료

아래 자료를 받으면 확장 계약과 연동 검수를 진행할 수 있다.

| ID | 요청 자료 | 포함할 예 |

| D02 | 전체 임무 응답 | 대기, 시작 준비, 단일 좌표, 다중 z·yaw·호버 |

## 10. 자동 부팅·준비 표시 추가 요구

기본 흐름은 전원 투입→Jetson 서비스 자동 기동→장치 자동 연결→자동 점검→시스템 준비→임무 준비→새 웹 START다.
전원 투입·점검 통과·서버 ACTIVE 상태만으로 arm/이륙하지 않는다.
웹은 준비 보고를 보여 주며, 실제 점검과 최종 수락은 Jetson/PX4가 담당한다.

| 구분 | 의미 | 화면 표시 |
|---|---|---|
| 시스템 준비 | 현재 실행 프로파일의 필수 장치·프로세스·설정·기록 기능을 사용할 수 있음 | ‘시스템 점검 완료’, 임무가 없으면 시작 버튼 비활성 |
| 임무 준비 | 특정 임무·지도·승인과 현재 기체 상태를 확인해 시작 요청을 받을 수 있음 | ‘임무 시작 준비 완료’, 준비 문맥과 남은 유효성 표시 |
| 점검 미상 | 미구현·미수신·만료·출처 불명 | UNKNOWN, 필수 체크이면 시작 금지 |
| 경고 | 정책상 시작을 허용하는 명시된 제한 | WARN과 실제 영향 표시, 웹이 임의로 필수 오류를 경고로 낮추지 않음 |
| 단절 | 현재 기체 상태를 새로 확인하지 못함 | 마지막 확인 값·시각, 시작 비활성, READY 배지 해제 |

준비 완료 표시는 우선 웹 상태 배지·이벤트 알림으로 제공한다.
LED/부저는 장치·배선·출력 패턴 합의 후 별도 연동한다.
준비 표시를 위해 기체를 회전시키거나 모터를 구동하는 동작은 요구하지 않는다.
상태 전이 알림의 문구·코드·증거는 WEB_HANDOFF와 WEB_JSON_DRAFT에 정의한다.
