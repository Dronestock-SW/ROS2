# TFmini Plus 100/50/50Hz 기준

하향 ToF 주기와 지연 오차의 코드 수정 기준이다.
2026-10-14 승인한 수정과 후속 검증 때 읽는다.

## 채택한 설정

**센서100Hz → PX4읽기50Hz → 전달요청50Hz를 채택한다.**
사용자가 [운영 기준본 r1](../report/tof_operational_baseline_20261014.md)으로 확정했다.
실기 적용은 보류한다. 실제 주기·지연은 미검증이다.
기존 A1/B1 수신 구조 비교와 별도 변경이다.

| 구간 | 수정 기준 | 확인 수준 |
|---|---|---|
| Benewake TFmini Plus | 정상 모드100Hz, I²C400kHz·주소0x10 | 제조사 기본을 설계 전제로 사용. 실물 readback 아님 |
| PX4 | TFmini Plus 전용20ms읽기 | 결과 요청·읽기를 같은 주기에서 처리 |
| MAVLink | message132, interval20000µs 요청 | ACK는 수락 증거. 실제50Hz 증거와 구분 |
| MAVROS | 수신 메시지를 Range로 전달 | 거리 발행 타이머를 추가하지 않음 |
| B_TF | ToF100ms, IMU20ms 유지 | 정상 지연 목표와 거부 상한을 구분 |
| EKF·제어 | 현재 설정 유지 | 이번 수정 대상 아님 |

```text
TFmini Plus 내부10ms
  → PX4: 20ms마다 요청/읽기, 읽기 직전 시각 보존
  → MAVLink: 20ms 전달 기회 요청
  → MAVROS: 메시지 시각 동기화
  → B_TF: 각 UWB 앵커 시각에 대응하는 과거 ToF/IMU
```

PX4 기준은 `d6f12ad1c4f70ad3230afd7d86e971421e02fef4`다.
`tf02pro`의 기존100ms 예약은 모델별로 분리한다.
`-T`를 선택한 TFmini Plus만 새 경로를 사용한다.
일반 TF02PRO 경로는 기존 동작을 유지한다.
밀린 읽기를 몰아 실행하지 않고 지난 주기를 건너뛴다.
실패한 요청의 이전 응답을 새 측정으로 발행하지 않는다.

요청5+응답9+주소2바이트에ACK를 포함하면144클록이다.
400kHz에서0.36ms/회, 50Hz에서 버스 점유 약1.8%다.
다른 장치·재시도·clock stretch는 제외한 계산이다.
이는 처리량 판단이며 실제 지연 보장은 아니다.

## 제품 제약과 설정

TFmini Plus의 지원 범위 안에서 설정한다.

| 제약 | 적용 |
|---|---|
| I²C최대100Hz | UART1000Hz 사양과 구분 |
| 저전력최대10Hz | 정상 모드 설정 뒤100Hz 명령을 별도로 보냄 |
| 설정 응답 대기100ms | 비동기 예약. 공유 워크큐에서 sleep하지 않음 |
| 거리 결과는 즉시 읽기 가능 | 같은 수집 주기 안에서 요청·읽기. 실물 확인은 남음 |
| 0.1~12m@반사율90%, 0.1~4m@10% | 최대12m를 모든 바닥의 보장 거리로 해석하지 않음 |
| 기본 strength<100 또는65535는 신뢰불가 | TFmini Plus 경로에서 거부 |
| 9바이트 거리 프레임 | 헤더0x59/0x59, checksum 검사 |

TFmini Plus 경로의 범위 선언은0.1~12m, FOV3.6°다.
strength·범위·프레임 거부는 별도 계수로 기록한다.
품질 기준 강화가 주기 변경 효과와 섞일 수 있다.
후속 비교에서 두 원인을 별도로 집계한다.
지상10cm 미만·어두운 바닥은 유효값을 보장하지 않는다.
TF02PRO의 기존35m·strength60 기준은 그대로다.

`-C`는 `-T`와 함께 선택하는 일회성 설정 옵션이다.
정상 모드 →100Hz →저장 순서로 명령을 보낸다.
응답의 길이·명령·내용·checksum을 확인한다.
저장 뒤1초를 예약하고 성공 응답을 확인한다.
새 DISARMED 상태가 없거나 사라지면 설정을 중단한다.
실패 상태에서는 거리 발행을 시작하지 않는다.
주소·인터페이스·공장 초기화 명령은 보내지 않는다.
저장 자동 재시도·매 부팅 저장도 하지 않는다.

일반 `-T` 시작은 설치된100Hz 설정을 전제로 한다.
status에 이 전제와 이번 설정 ACK 여부를 구분한다.
비동기 start 반환만으로 설정 성공을 판정하지 않는다.
설정 ACK도 재부팅 후 반영 확인과는 다르다.
이번 작업에서 이 옵션을 실기에 실행하지 않는다.

근거: [A07 데이터시트](https://en.benewake.com/uploadfiles/2024/04/20240426135842086.pdf),
[설명서 §5.6·§7.4](https://en.benewake.com/uploadfiles/2025/04/20250430175221028.pdf).

## 지연 오차 기준

**100ms는 오래된 표본의 거부 상한이다.**
이번 공급 변경 비교에서는 기존 값을 유지한다.
40ms를 새 거부 임계값으로 적용하지 않는다.

```text
header_age = 변환된 UWB 앵커 측정 시각 − 선택 ToF stamp
시간차 높이 오차 ≈ |수직 속도| × 실제 측정 시각 차이
```

UWB ClockMap과 MAVROS TIMESYNC의 오차가 들어간다.
센서 내부 측정→FC읽기의 지연도 별도로 남는다.
현재 stamp는 읽기 직전 시각이며 물리 측정 시각은 아니다.
전달 지연은 최신 과거 표본이 도착했는지를 바꾼다.
전달 지연을 age식에 무조건 더하거나 무관하다고 하지 않는다.

| 실제 시각 차이 | 0.5m/s의 시간차 오차 | 1m/s의 시간차 오차 |
|---|---:|---:|
| 20ms | 1cm | 2cm |
| 40ms | 2cm | 4cm |
| 100ms | 5cm | 10cm |

시간차 오차2cm@0.5m/s를 설계 목표로 제안한다.
이에 대응하는 전체 시각 차이 예산은40ms다.
사용자가 확정한 최종 비행 정확도 요구는 아니다.
내부 측정 지연·시계 정렬 오차도 예산에 포함한다.
header_age40ms만으로 목표 달성을 판정하지 않는다.
미측정 오차가 남으면 합격을 선언하지 않는다.

이는 평탄 바닥·수직 이동을 단순화한 계산이다.
센서 자체 거리 오차와 기울기·바닥 변화는 별도다.
hover에서도 기울기·진동에 따른 오차는 남을 수 있다.
B3 거리 RMS6cm는 높이 오차6cm 허용이 아니다.
근거 없는timestamp 이동·현재 시각 덮어쓰기는 하지 않는다.
고정 지연 보정도 측정 근거가 있을 때 후속 적용한다.
