## 먼저 실행 위치 확인

Windows 로컬에서 명령을 실행하는 Codex 작업을 사용한다.
SSH 프로젝트 대화의 명령은 Jetson에서 실행된다.
화면을 띄운 컴퓨터와 명령 실행 컴퓨터를 구분한다.
이는 [공식 SSH 설명](https://learn.chatgpt.com/docs/remote-connections#connect-to-an-ssh-host)과 같다.

Windows PowerShell에서 다음을 확인한다.

```powershell
$env:COMPUTERNAME
wsl --list --verbose
```

목록에서 실제 배포판 이름을 확인한다.
확인한 배포판과 사용자로 WSL 명령을 실행한다.
WSL 안에서 다음을 확인한다.

```bash
hostname
uname -srm
id -un
pgrep -a -x px4
timeout 10s gz topic -l
```

각 명령의 종료 코드도 기록한다.
Gazebo 조회가 무출력이면 시간 초과와 정상 종료를 구분한다.
PX4가 실행 중이면 프로세스와 로그를 이어서 사용한다.
중복 실행은 하지 않는다. 인스턴스 충돌을 막기 위해서다.
WSL 종료나 기존 프로세스 일괄 종료로 점검을 시작하지 않는다.
이유: 현재 상태와 기록을 잃을 수 있다.

| 환경 | 알고 있는 경로·버전 |

| PX4 | ~/github/PX4-Autopilot |
| 마지막 보고 버전 | v1.18.0-beta1-700-gc4e4ef98e9 |

## 실제 시험을 이어갈 순서

센서·장착·좌표·시계의 근거를 먼저 확인한다.
초기 설정의 확인 플래그를 일괄 true로 바꾸지 않는다.
근거가 없는 입력을 유효 관측으로 보낼 수 있기 때문이다.
SITL 전용 설정 복사본에 확인한 값만 반영한다.
사용자는 시뮬레이션 구현과 시험 진행을 요청했다.
이미 허용된 조사·수정·시험을 반복 승인 대상으로 삼지 않는다.
실제 기체 파라미터는 이번 범위에서 변경하지 않는다.

먼저 A 관측의 실제 EKF 융합을 검증한다.
메시지 수신뿐 아니라 사용·기각·innovation·reset을 확인한다.
GNSS·광학흐름 등 유지한 다른 위치원도 기록한다.
고도·자세·비행 상태추정은 PX4가 담당한다.
정답은 가상 센서 생성과 독립 평가에만 사용한다.

그 뒤 짧은 목표 이동과 정지·복귀를 시험한다.
현재 목표 실행기는 공중 Hold에서 시작한다.
시동·이륙을 자동으로 수행하는 실행기로 오해하지 않는다.
시뮬레이터 준비 상태와 기존 PX4 절차를 확인해 진행한다.
수치·안전 동작을 실행 전에 설정 파일에 남긴다.
중단한 임무의 자동 재개는 구현하지 않았다.
새 관측의 연속성을 확인하고 다음 시행으로 다시 시작한다.

A와 B 0.4초 후보를 같은 조건·시드로 비교한다.
실제 피드백 비행은 궤적이 같다고 가정하지 않는다.
같은 기록의 모델 비교와 실제 비행 비교를 구분한다.
보조기능은 관찰한 실패 원인에 맞춰 하나씩 더한다.
독립 평가 자료를 보고 조정했으면 새 평가 자료를 마련한다.

매 시행마다 RAW·ToF·자세·정답·ULog를 묶는다.
설정·시드·명령·코드 해시·실패 원문도 남긴다.
새 run_id로 만들고 이전 결과는 덮어쓰지 않는다.
시행표에 성공·기각·실패·미실시를 모두 기록한다.
측위·연결·이동 완료는 각각 근거를 확인한 뒤 판정한다.
