# 바닥 XY 초기화·연속 지상 EV 기록

바닥에서 첫 UWB XY가 막힐 때 읽는 검증 기록이다.
2026-10-09 수정과 실제 배포 결과를 구분한다.

## 수정

유효3앵커 후보에도 이전 XY를 요구하던 순환을 해소했다.
기본 경로는 유지한다. 현장 설정으로만 선택한다.
`ground_subset_initialization=true`를 사용한다.
지상 높이 모델이 활성인 순간에만 초기화한다.
같은 제외 앵커·유일 후보를2초 이상 확인한다.
최소30표본·최대 공백0.1초·반경0.05m를 요구한다.
기존 거리 RMS·후보 차이 검사를 유지한다.
재획득은 마지막 유효 XY의0.1m 안에서만 한다.
공중·유효 ToF 경로의 초기화 정책은 바꾸지 않았다.
FC 위치를 UWB 해로 복사하지 않는다.

`ground_ev_trial.py --continuous-ground`를 추가했다.
45초 종료 대신 이번 부팅의 지상 관측을 계속한다.
DISARM·지상·RC kill ON·명령 출력 비활성을 요구한다.
시각 동기화·원본 시각·공분산 검사를 유지한다.
짧은 입력 공백에는 새 관측을 발행하지 않는다.
명령 권한 조건이 바뀌면 종료한다.
출력 잠금을 소유해 비행 실행기와 동시에 쓰지 않는다.
새 부팅에는 이전 후보 좌표를 사용하지 않는다.
요약 기록은 교체하며 원본 표본은 최근1000개만 보관한다.
동적 정렬·고정 지연 확인 플래그는 false다.
이 모드는 비행용 상시 bridge의 승인과 별개다.

## 검증

Windows 관련 시험67개를 통과했다.
ROS 전용3개는 Jetson 검증 대상으로 남았다.
이전 바닥 거리442개를 지상 높이 모델로 재생했다.
수정 전은 초기화되지 않았다.
수정 후300개를 수락하고 마지막 XY를 반환했다.
마지막 후보는 약(5.266,2.134)m였다.
이는 재생 결과다. 절대 위치 정확도 실측은 아니다.


실제 배포·융합 결과는 후속 기록으로 추가한다.
ARM·이륙·동적 정렬 검증은 이 수정의 증거가 아니다.

## 첫 실물 적용

Jetson 관련 시험70개·빌드를 통과했다.
웹에서 바닥 XY 약(5.28,2.10)m를 확인했다.
지상 높이0.15m는 계속 추정으로 표시했다.
새 원점은156개의 현재 부팅 정지 표본에서 정했다.
사용자 보고 -X heading을 사용한 임시 후보 변환이다.
동적 정렬·시간 지연 확인 플래그는 false다.
실측 장착 EV_POS를(-0.1,0,-0.1)m로 적용했다.
EV_CTRL=1·EV_DELAY=0·EV_NOISE_MD=0은 유지했다.
지상 연결을 위해 호버 실행기는 관측 전용으로 전환했다.

두 EKF에서 `cs_ev_pos=true`를 확인했다.
EV 위치 관측의 `fused=true`, `innovation_rejected=false`였다.
관측 나이는 약0.02초였다.
`cs_valid_fake_pos=false`로 실제 UWB를 융합했다.
웹의 위치 추정과3초 정지 항목도 통과했다.
첫 연속 세션은60.65초 동안2,190개를 발행했다.
그 뒤 RC 수신 조건 만료로 종료했다.
직후 실제 kill ON·DISARM 상태를 다시 확인했다.
동시 ROS 수신 공백도 기록에서 확인했다.

수신 만료와 실제 권한 변경을 구분하도록 수정했다.
만료 중에는 발행하지 않는다. 최신 입력 복구 후 재개한다.
유효한 ARM·공중·kill OFF·다른 실행기 활성은 종료시킨다.
종료한 세션은 정상 값이 돌아와도 재개하지 않는다.

## 재적용 후 연속 관측

Jetson 관련 시험76개를 통과했다.
소스는 `d84e618`, 프로세스 PID43323이다.
세션은 `ev-continuous-ground-091008`이다.
관측 웹과 MAVROS를 재시작하지 않고 새 전달기만 실행했다.
이번 부팅의 좌표 후보를 새로 취득했다.
지상 전달기는 종료 시간을 두지 않고 실행 중이다.
자동 부팅 등록과 실기 비행 출력은 포함하지 않는다.

90초 추가 관측에서2,899개가 증가했다.
마지막 기록은124.90초·3,984개·gate=ready였다.
프로세스는 수신 만료 때도 살아 있다가 발행을 재개했다.
그러나 원본 관측 발행 간격 최대10.025초가 있었다.
수신 상태와 시각 동기화 재획득 대기가 함께 관측됐다.
공백 원인은 아직 확정하지 않았다.
과거값을 반복 발행해 이 간격을 숨기지 않았다.
따라서 이 결과는 무중단 수신·실비행 승인 근거가 아니다.
실물 수신 공백과 동적 좌표·시간 보정은 남아 있다.

웹8350은 지상 관측 중 명령 출력을 비활성으로 둔다.
PX4 위치 추정·3초 정지 검사는 실제 입력으로 통과했다.
웹8351의 XY는 실제 UWB 관측이며 z=0.15는 지상 추정이다.
ARM 또는 kill 해제 시 지상 발행기를 종료한다.
비행에 쓰려면 검증된 비행용 bridge로 전환해야 한다.

## 웹 START 요청 시 남은 실제 조건

체크 표시 대부분이 통과해도 명령을 활성화하지 않았다.
현재 발행기는 ARM·kill 해제 시 종료되는 지상 전용이다.
이 상태에서 웹 출력만 켜면 이륙 전에 EV 입력이 사라진다.
비행용 bridge의 동적 정렬·시각 보정은 미확인이다.
확인 플래그를 변경하거나 지상 종료 조건을 지우지 않았다.

10초 공백의 원본 입력을 대조했다.
해당 구간에도 UWB는 매초80개 원시 메시지를 받았다.
MAVROS의 IMU·ToF·FC 상태·timesync가 함께 지연됐다.
timesync RTT는 최대1,794ms였다.
그 뒤 시각 동기화·지상 XY 재획득이 이어졌다.
이 구간을 사람의 NLOS로 판단할 근거는 없다.
FC 통신 지연의 근본 원인은 아직 확정하지 못했다.

현재 FC USB CDC 상태는 txerr=0, rx loss=0.1%였다.
전송량은 약31.7kB/s, 설정 상한은100kB/s였다.
FC CPU idle은67.4%, FC logger는 기록하지 않는 상태였다.
Jetson USB autosuspend는 이미 OFF(control=on)였다.
FC 포트 소유자는 현재 MAVROS 한 개였다.
이 확인으로 과거의 간헐 지연이 해결됐다고 보지 않는다.
ARM·이륙 명령은 여전히0건이다.

따라서 이번 재발은 초기XY 계산 실패가 아니다.

웹에 지상 발행기 기록 상태를 추가했다.

## 관측과 명령 실행 권한 분리

정식 브리지는 ARM 뒤에도 관측을 유지해야 한다.
기존 launch는`ground_only=not execute`로 묶었다.
미션 명령을 끄면 관측도 지상 전용이 됐다.
이 결합을`bridge_ground_only` 인자로 분리했다.
정식 브리지의 기본 scope는continuous다.
기본 발행 활성은 여전히false다.
지상 전용 진단은 명시적으로true를 지정한다.
임시 ground_ev_trial의 진단 경계는 보존했다.

ARM·DISARM은 정상 관측을 차단하지 않는다.
RC·미션 명령에는 관측 브리지가 관여하지 않는다.
오래된 시각·무효 공분산·수신 중단은 계속 거부한다.
원래 시각을 보존하며 과거 좌표를 반복하지 않는다.
XY의z=0은 계속 미관측 자리값이다.
FC의 수직 추정과 이륙 고도 제어를 변경하지 않는다.

실제 설정의 alignment·timing 확인은false다.
기존 왕복 기록의 시간 지연 적합도도 재확인했다.
동등 오차의 지연 범위가-0.5~+0.35초 이상이었다.
이 기록으로 고정 지연을 확정할 수 없다.
코드상 연속 관측과 실기 활성 완료를 구분한다.

Jetson의drone_uwb·drone_mission 빌드를 통과했다.
관련 ROS·단위시험59개를 통과했다.
ARM→DISARM 전환 중 관측 지속을 합성 입력으로 확인했다.
명령execute 변경도 브리지 설정을 바꾸지 않았다.
실제 FC에ARM·비행 명령을 보내지 않았다.
현재 현장 프로세스는 재시작하지 않았다.
실제 관측 발행 재개와 비행 활성은 미완료다.
