# Gazebo 비행 기록의 독립 평가
이 문서는 실제 궤적과 항법 기록을 비교하는 평가 구조다.
목표 도착과 UWB 정확도를 구분해 검토할 때 읽는다.

## 구현 상태

독립 평가기 `drone_demo.flight_evaluation`을 구현했다.
합성 기록과 모의 통신 시험까지 확인했다.
사용자 WSL의 실제 비행 기록 평가는 미실시다.
평가기 자체의 구현과 비행 성공은 별개다.

```text
가상 UWB 생성기: poses·truth·RAW
                           ┐
관측 기록기: 같은 RAW·송신 관측 ├→ 종료 후 파일 비교
임무 기록기: PX4 위치·목표·판정 ┘
 → 같은 세션·시각·기준점 대조
 → 측위·추종·실제 도착 오차를 각각 계산
 → 누락·가용률·공백·지연·도착 근거 기록
```

Gazebo 정답은 이 오프라인 평가기에서만 읽는다.
새 평가기는 항법 입력이나 비행 명령을 만들지 않는다.
실시간 임무 판정은 계속 PX4 위치·속도를 사용한다.

## 비교하는 네 가지 값

모든 비교 기준점은 설정에 명시한 PX4 기준점이다.
Gazebo 기체 기준점에 장착 오프셋을 더한다.
오프셋은 해당 정답 자세로 회전한 뒤 더한다.
전방 14cm를 항상 세계 x축에 더하지 않는다.

| 평가 | 두 값의 차이 | 의미 |
|---|---|---|
| UWB 측위 | 송신 UWB 관측 − Gazebo 정답 | 7cm 수치 기준의 대상 |
| PX4 측위 | PX4 추정 위치 − Gazebo 정답 | 융합 후 위치의 정확도 |
| 추정 위치 기준 추종 | PX4 추정 위치 − 요청 목표 | FC가 얼마나 목표에 가까운가 |
| 실제 이동·도착 | Gazebo 정답 − 요청 목표 | 실제 기체가 얼마나 목표에 가까운가 |

각 차이의 수평 길이는 다음과 같다.

`e_xy = sqrt((x_1 − x_2)^2 + (y_1 − y_2)^2)`

PX4 추종 오차가 0이어도 실제 도착 오차는 클 수 있다.
시험에서는 FC 추정에 30cm 편향을 넣었다.
PX4 추종 오차는 0, 실제 목표 오차는 30cm로 나왔다.
평가기는 이때 FC의 도착 주장을 확인된 도착으로 인정하지 않았다.

## 기록 연결과 시각 조건

수신 RAW의 seq·time_us·실제 거리값을 원본과 대조한다.
수신기에 추가된 호스트 시각 항목만 비교에서 제외한다.
수신 RAW가 없는 송신 관측도 거부한다.
시각만 같은 다른 시뮬레이터 기록을 섞지 않는다.
생성기의 pose·truth·RAW 개수도 같아야 한다.
정답의 장착 위치와 기하학적 거리도 다시 대조한다.

가상 UWB와 정답은 같은 Gazebo 시각을 쓴다.
PX4 위치 시각은 별도 부팅 시각이다.
평가에는 독립 확인한 두 시계의 차이가 필요하다.

`gazebo_sample_us = px4_sample_us + px4_to_gazebo_offset_us`

| 시계 설정 | 의미 |
|---|---|
| confirmed | 시계 차이의 검토 여부 |
| px4_to_gazebo_offset_us | PX4 시각에 더할 오프셋 |
| uncertainty_us | 검토한 오프셋 불확실도 |
| valid_start/end_px4_us | 해당 정렬이 유효한 PX4 구간 |
| evidence | 근거 파일·검토 기록의 위치 |

기본 시계 설정은 미확인 상태다.
기본 불확실도 허용 상한은 10ms다.
값이 없거나 유효 구간을 벗어나면 PX4 평가는 누락으로 남긴다.
UWB와 정답 비교는 별도로 계산할 수 있다.
시계 설정을 true로 바꾸는 행위가 측정을 대신하지는 않는다.
수신 시각 차이나 위치 오차 최소화로 오프셋을 맞추지 않는다.
이유: 지연이나 위치 오차를 시계 차이로 숨길 수 있다.
이 기준을 만족하는 실제 WSL 시계 근거는 아직 없다.

임무 기록에 새 필드를 추가했다.
평가 시점의 Gazebo·PX4 시각을 따로 남긴다.
FC 위치에는 원래 PX4 표본 시각을 함께 남긴다.
시계가 유효하지 않으면 null과 원인을 기록한다.
이전 runtime ZIP에는 이 후속 필드가 없다.

## 평가 격자와 누락

평가 구간의 정답 표본 시각을 기준으로 비교한다.
UWB 송신 관측은 같은 시각의 표본을 사용한다.
PX4 위치는 앞뒤 표본 사이에서 선형 보간한다.
앞뒤 간격은 최대 0.1초다.
기록 앞·뒤로 외삽하거나 긴 공백을 연결하지 않는다.
이 보간은 출력 수신률을 높인 결과가 아니다.

새로 송신하지 않은 UWB 값은 누락으로 남긴다.
관측 거부·미송신을 좋은 오차 표본으로 바꾸지 않는다.
각 오차에는 유효 표본 수와 누락 수를 함께 적는다.
기록 중 원점 reset·시각 역행은 한 정렬로 평가하지 않는다.
시행을 나누고 새 근거를 갖춰야 한다.

| 구간 수치 판정 | 초기 평가값 |
|---|---:|
| UWB 최대 수평 오차 | 0.07m 미만 |
| 새 송신 관측 가용률 | 95% 이상 |
| 최대 새 관측 공백 | 0.15초 이하 |
| 최대 시뮬레이션 관측 지연 | 0.15초 이하 |
| 정답 최대 기록 간격 | 0.1초 이하 |

구간 양끝의 공백도 포함한다.
계획한 구간을 정답 기록이 덮지 못하면 통과시키지 않는다.
7cm와 정확히 같은 값은 실패 표본으로 센다.
반올림 전 m 단위 값으로 판정한다.
지연이 기록되지 않은 관측을 지연 0으로 취급하지 않는다.

위 통과는 해당 기록 구간의 수치 판정이다.
다점·동적 조건·반복·독립 자료의 전체 통과가 아니다.
`full_7cm_goal_achieved`는 자동으로 true가 되지 않는다.
`flight_valid`, `fusion_verified`도 false로 유지한다.
EKF 융합과 실제 비행 완료는 ULog 등을 함께 검토해야 한다.

## 실제 도착 재검사

요청 목표마다 정답 위치와 거리를 비교한다.
정답 속력은 연속된 기준점 위치의 차분으로 구한다.
처음 표본과 0.1초 초과 공백의 속력은 미상이다.
미상 속력을 0으로 바꾸지 않는다.

진입 0.15m, 이탈 0.20m를 초기값으로 쓴다.
속력은 0.10m/s 이하여야 한다.
그 조건을 새 정답 표본으로 1초 유지해야 한다.
FC가 도착을 선언한 시각에도 조건이 맞는지 다시 본다.
실제 도착 시간·목표 방향 초과 이동·유지 중 이탈도 남긴다.
중단한 구간은 aborted로 표시한다.

위치 차분은 구간 평균 속력의 근사다.
표본 사이에서 생긴 짧은 움직임까지 보장하지 않는다.
시계 오차와 보간 오차도 남는 한계다.
따라서 원래 표본·간격과 판정 근거를 함께 보존한다.

## 정상·이상·복구 구간

전체 평가와 구간별 평가를 함께 보존한다.
단절 구간을 빼서 전체 가용률을 높이지 않는다.
구간마다 같은 네 오차·누락·공백·지연을 계산한다.
`flight_fault_evaluation` 모듈이 이 분리를 담당한다.

| 구간 | 기준 |
|---|---|
| normal | 명시된 이상 계획의 주입·복구 밖 |
| fault | 계획의 start_s 이상, end_s 미만 |
| recovery | 주입 종료 뒤 사전에 정한 관찰 구간 |
| unclassified | 이상 계획이 없는 과거 기록 |

기준 시각은 생성기의 첫 기록 pose다.
계획이 있으면 주입 전 RAW와 발행 기록을 요구한다.
같은 이상을 원본 거리값에 다시 적용해 대조한다.
발행 후보·주입 ID·생략 여부·발행 상태도 대조한다.
자료가 맞지 않으면 평가 결과를 쓰기 전에 오류를 낸다.
빈 이상 계획은 정상 구간으로 분류한다.
계획 자체가 없으면 정상이라고 추정하지 않는다.

각 정답 표본은 구간 하나에만 속한다.
구간 끝 시각은 다음 구간에 포함한다.
전체 평가의 마지막 시각만 포함 경계다.
그 시각에 이상이 시작하면 한 표본 구간으로 남긴다.
시간 길이가 0인 구간을 통과로 판정하지 않는다.

| 복구 설정 | 초기값 | 의미 |
|---|---:|---|
| recovery_window_s | 2.0초 | 주입 종료 뒤 관측을 평가할 길이 |
| recovery_settle_s | 0.5초 | 정확도·신선도 조건의 연속 유지시간 |

두 값은 시행 전에 평가 계획에 적는다.
새 관측의 지연은 기존 0.15초 상한을 쓴다.
먼저 신선한 관측을 본 표본 시각을 기록한다.
그 뒤 오차 7cm 미만의 연속 유지시간을 계산한다.
중간에 누락·오차 초과·지연 초과가 있으면 다시 시작한다.
정답 또는 관측 간격이 허용값을 넘겨도 다시 시작한다.

`first_fresh_observed_delay_s`는 첫 신선 표본의 지연이다.
`accuracy_settled_delay_s`는 정확도 안정화 확인까지의 시간이다.
두 값 모두 주입 종료와 관측 표본 시각의 차이다.
FC가 수신한 시각이나 실제 기체 회복 시간이 아니다.
복구를 못 봤으면 null로 남긴다.
뒤의 이상이나 짧은 기록으로 잘린 구간도 표시한다.
정답 공백이 있는 구간을 전부 기록했다고 표시하지 않는다.

의도한 단절 구간은 정확도와 고장 대응을 함께 검토한다.
구간 통계만으로 제동·착륙·임무 재개를 완료 처리하지 않는다.
`flight_recovery_verified`는 false로 유지한다.

## 실행과 결과 파일

실시간 기록이 끝난 뒤 실행한다.
nav 폴더와 range 폴더는 같은 시행이어야 한다.
범위는 실행 전에 평가 계획에 적는다.
기본 계획의 start/end는 null이다.
이를 임의로 채워 결과를 계산한 것으로 표시하지 않는다.

```bash
python3 -m drone_demo.flight_evaluation \
  --navigation-run runs/navigation_01 \
  --range-run runs/ranges_01 \
  --plan runs/evaluation_plan_01.json \
  --clock runs/evaluation_clock_01.json \
  --output runs/evaluation_01
```

이 명령은 ROS·Gazebo·pymavlink 연결을 열지 않는다.
Python·NumPy와 두 패키지의 소스 경로를 사용한다.
기존 출력 폴더가 있으면 덮어쓰지 않는다.

| 파일 | 내용 |
|---|---|
| metrics.json | 네 오차·가용률·공백·지연·목표별 도착 평가 |
| scenario_metrics.csv | 정상·이상·복구별 네 오차·수신·발행·누락 |
| results.jsonl | 정답 표본별 네 위치·오차·속력·구간 ID |
| failures.jsonl | UWB·PX4·정답 속력 누락 이유 |
| manifest.json | 평가 범위·시계 근거·장착값·환경·소스 해시 |
| input_index.json | 원본 경로·입력 사본 경로·바이트 수·해시 |
| inputs/ | 계산에 실제 사용한 입력 바이트의 사본 |

후속 이상 시험에서는 fault_plan·emission·주입 전 RAW도 보존한다.
계획된 단절과 실제 수신 기록의 모순도 검사한다.
전체 구간의 누락·가용률 계산은 유지한다.
[실시간 주입 절차](uwb_gazebo_fault_trials.md)를 따른다.
복구 시간은 metrics.json의 recoveries에 기록한다.
CSV의 미상 값은 빈칸이다. 0으로 채우지 않는다.
7cm 이상 비율의 분모는 유효 관측 수다.
관측 누락 수와 전체 정답 수를 별도로 함께 보존한다.
