# ToF 변경본 PX4·ROS 전체 빌드 기록

전체 빌드 결과다. 재생·배포 재개 판단 전에 읽는다.

## 범위

**ROS7개와 PX4 FMUv6C 타깃 빌드를 통과했다. 실기 적용은 보류한다.**
이 결과로 [운영 기준본 r1](tof_operational_baseline_20261014.md)을 확정했다.
사용자가 이번 단계의 전체 빌드를 승인했다.
운영 경로와 분리한 Jetson 사본을 사용한다.
ROS 노드와 재생 실행 파일은 실행하지 않는다.
센서 설정·FC 파라미터·부팅 설정을 바꾸지 않는다.

## 직전 변경 전후

100/50/50Hz는 수정본의 설정 목표다.
현재 실기가 이 값으로 바뀌었다는 뜻이 아니다.

| 구간 | 기존 | 수정본 |
|---|---|---|
| TFmini Plus 내부 측정 | 공장 기본100Hz를 설계 근거로 사용. 현재 기기 readback 없음 | 명시적 `-T -C`에 정상 모드·100Hz·1회 SAVE 경로 추가. 미실행 |
| PX4 읽기 | TF02PRO 경로100ms 예약. 당시 간격 약102ms | `-T`에서20ms 절대 예약·같은 회차 요청/읽기. 지연 시 지난 슬롯 생략 |
| MAVLink 전달 요청 | DISTANCE_SENSOR40Hz | 50Hz. 수락과 실제 출력 주기를 구분 |
| 센서 품질 | TF02PRO의 strength60·범위35m 기준 | TFmini Plus에서 strength100·범위0.1~12m·헤더·체크섬 검사 |
| 설정 요청 처리 | 기존 요청 처리 | 직렬 요청·success/result0 확인·3초 timeout·최대3회 시도 |
| 내부 진단 | 기존 드라이버 계수 | 요청·읽기·발행·예약 지연·오류별 계수 추가 |
| B_TF 거부 기준 | ToF100ms·IMU20ms·출력150ms | 유지 |
| 전체 시간차 목표 | 별도 측정 필요 | 0.5m/s에서 추가 오차2cm에 해당하는40ms. 달성값·새 차단값 아님 |

센서 자체 거리 정확도와 시간차 오차를 구분한다.
기존 TF02PRO 기본 실행 경로는 유지한다.
IMU 큐·수신 분리 변경은 이전 B1에 속한다.
이번 ToF 수정과 B1 비교를 섞지 않는다.

## 결과

전체 빌드와 패치의 최종 포함을 확인했다.
빌드·링크 기준으로 추가 소스 수정은 필요하지 않았다.
Python 동작 확인은 앞선 단위 검사 범위에 한정한다.

| 항목 | 상태 |
|---|---|
| ROS | 전체7개 성공. 종료 코드0. 21분16초 |
| Python·설치 경로 | 505개 문법 검사·전송25개 해시 일치. 수정 모듈 설치 경로 확인 |
| 실제 ROS API | 요청 취소 API·MAVROS success/result 필드 확인. 노드 생성 없음 |
| PX4 | 전체1246단계·ELF/bin/px4 생성 성공. 최종 재빌드 종료0 |
| 보드 기능 포함 | 생성된 boardconfig에서 TF02PRO·CRSF·EKF2_AUXVEL 모두y |
| 패치 포함 | 실제 TF02PRO/CLI object·라이브러리와 최종ELF의 새 함수 확인 |
| 용량 | 같은 도구의 기존/수정 빌드 성공. 증가2,920B, 최종 여유28,068B |
| Claude14차 | 전후 설명·빌드 범위 검토. 포함 증거·동일 도구 용량 비교 반영 |
| Claude15~16차 | 전체 결과·경고 처리 검토. 완료 범위 문구 보완 |

ROS 명령은 `colcon build --symlink-install`이다.
순차 패키지 빌드와 C++ 작업2개로 부하를 제한한다.
PX4 명령은 `make px4_fmu-v6c_lidar2d -j2`다.
새 설정을 장치에서 실행하는 명령은 포함하지 않는다.

ROS 패키지는 아래7개다.
`drone_platform_link`, `drone_uwb`, `sangwon_ai_replay`,
`ydlidar_ros2_driver`, `drone_bringup`, `drone_demo`,
`drone_mission`을 모두 빌드했다.
C++의 재생·실기용 바이너리도 컴파일만 했다.

외부 YDLIDAR 코드에 unused-parameter 경고6개가 있다.
Empty 서비스 콜백 인자에 해당한다.
colcon은 해당 경고를 요약에서 다시 출력한다.
서로 다른 경고12개로 중복 집계하지 않는다.
이 경고는 ToF 수정으로 발생한 오류가 아니다.

처음의 환경 오류도 구분해 기록한다.
다른 계정 소스의 Git 소유권 검사에서 복사가 막혔다.
읽기 사본의 Git 메타데이터로 분리했다.
원본의 shallow 경계 때문에 bundle 복제는 실패했다.
새 사본에만 기준 파일을 복원해 패치를 적용했다.
Arm 도구의 해제 폴더명은 `13.2.Rel1`이다.
빌드 스크립트의 `rel1` 경로를 수정했다.
이는 센서·제어 코드 변경이 아니다.

실행 중인 빌드 스크립트의 PATH도 덮어썼다.
이 때문에 펌웨어 생성 뒤 후처리가 실패했다.
빌드 도중인 스크립트를 바꾸지 않도록 바로잡았다.
확정된 스크립트로 다시 실행해 종료0을 확인했다.
이어서 기준·수정본 재빌드도 모두 성공했다.
최초 후처리 실패를 컴파일 실패로 집계하지 않는다.

data/bss는 정적 메모리 배치다.
실행 중 heap·stack 최대 사용량은 측정하지 않았다.
13일 실기 이미지와는 컴파일러 동일성이 미확정이다.
그 이미지와의 크기 차이를 ToF 효과로 해석하지 않는다.

최종 수정 이미지 SHA256:
`a8e1cb208c2314503383cdcb0accf2cb38ab8b629b7d9581987b927fe6df2a9b`

ELF에서 `run_tfmini_plus`와 `run_configuration`을 확인했다.
기준 빌드 뒤 ToF 패치를 다시 적용해 빌드했다.
현재 빌드 사본은 수정본이다.

| 남은 경고 | 판단 |
|---|---|
| 외부 YDLIDAR unused-parameter6개 | 기존 Empty 서비스 콜백 인자. 외부 고정 SHA 유지 |
| Kconfig ARCH_CHIP_UNSET1개 | 실제 NuttX 설정은 STM32H7·STM32H743VI. 타깃 확인 |
| NuttX jobserver19개 | 하위 make가-j1로 실행. 빌드 병렬성 경고 |

드라이버의 새 C++ 컴파일 경고는 없었다.
경고를 숨기는 옵션이나 링크 설정 변경은 하지 않았다.
두 증분 비교 빌드에서 직접 대조한 경고는 RWX다.
Kconfig·jobserver는 최초 전체 빌드의 경고다.
이 둘의 깨끗한 기준 빌드 대조는 별도로 하지 않았다.
