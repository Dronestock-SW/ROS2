# 1부. UWB 이야기

## 1-1. UWB가 뭘 하나

창고 네 귀퉁이에 상자를 하나씩 붙여 놨다. 이걸 **앵커**라고 한다. A1, A2, A3, A4 네 개다.

드론에는 작은 발신기를 달았다. 이걸 **태그**라고 한다.

```text
    A3 ●───────────● A4
       │           │
       │    ★      │      태그가 "야!" 하면 앵커 4개가 "어!" 한다
       │  (태그)   │      대답이 돌아오는 시간을 재면 거리를 안다
    A1 ●───────────● A2
```

거리 4개를 알면 위치가 나온다. 종이에 원을 4개 그려서 **겹치는 점**을 찾는 것과 같다.

## 1-2. 지금 문제: 원 4개가 안 겹친다

```text
   되어야 하는 모습            지금 모습

      ╭─╮                      ╭───╮
     ╭┼─┼╮                   ╭─╯   ╰─╮
     │╰★╯│                   │  ???  │   ← 겹치는 데가 없다
     ╰┼─┼╯                   ╰─╮   ╭─╯      컴퓨터: "위치 모르겠음"
      ╰─╯                      ╰───╯
```

앵커 4개가 서로 다른 답을 말하기 때문이다. 실제로 재보니 이랬다.

| 앵커 | 진짜 거리 | 앵커가 말한 거리 | 결과 |
|---|---:|---:|---|
| A1 | 1.93 m | 1.93 m | 정확 |
| A2 | 4.66 m | 5.47 m | **81 cm 더 길게 말함** |
| A3 | 2.79 m | 3.12 m | 34 cm 더 길게 말함 |
| A4 | 5.08 m | 5.28 m | 21 cm 더 길게 말함 |

세 개가 실제보다 멀다고 말한다. 그래서 원이 안 겹친다.

## 1-3. 중요: 흔들리는 게 아니라 밀려 있다

A2는 **항상 똑같이** 81cm 길게 말한다. 어떨 땐 맞고 어떨 땐 틀리는 게 아니다.

```text
흔들리는 문제        밀려 있는 문제

 4.6  5.1  4.4       5.47  5.47  5.47
 4.9  4.5  4.7       5.46  5.48  5.47
  ↑ 평균 내면 해결     ↑ 평균 내도 그대로 5.47
```

이걸 **bias**라고 한다. 저울이 항상 5kg 더 나오는 것과 같다. 열 번 재서 평균 내도 5kg 더 나온다.

## 1-4. 그래서 필터로는 못 고친다

"값이 이상하면 필터를 넣으면 되지 않나?" — 안 된다.

```text
필터가 하는 일   :  들쭉날쭉한 선 → 매끈한 선
필터가 못 하는 일 :  매끈하게 81cm 밀린 선을 제자리로 옮기기
```

실제로 필터를 통과시켜 봤더니, 흔들림은 4.1cm → 3.8cm로 조금 줄었고 **81cm는 1cm도 안 줄었다.**

> 고치는 방법은 하나뿐이다. **앵커 눈금을 다시 맞추는 것**(교정). 이건 HW 파트 작업이다.

## 1-5. 시스템이 엉뚱한 앵커를 자르고 있다

드론에는 "말 안 맞는 앵커는 빼자"는 기능이 있다. 그런데 결과가 이렇다.

```text
제일 많이 틀린 앵커  : A2 (81cm)
실제로 잘린 앵커     : A3 (34cm)   ← 33번 중 33번
```

**왜 억울한 A3가 잘렸나?**

컴퓨터는 정답을 모른다. 정답을 알면 UWB가 필요 없다. 컴퓨터가 할 수 있는 건 "누가 나머지랑 말이 안 맞나" 보는 것뿐이다.

친구 4명한테 지금 몇 시냐고 물었다고 하자.

```text
A1: 3시 00분   ← 정답
A2: 3시 40분   ← 제일 많이 틀림
A3: 3시 17분
A4: 3시 10분
                    넷의 평균 = 약 3시 17분
                    → 이 평균에서 보면 A2는 별로 안 튀어 보인다
                    → 오히려 정답에 가까운 쪽이 이상해 보인다
```

A2가 너무 크게 틀려서 **평균 자체를 자기 쪽으로 끌고 가버렸다.** 그래서 A2는 정상처럼 보이고 A3가 대신 잘렸다.

> 정리: 지금 드론은 앵커 4개 중 3개로, 그것도 **엉뚱한 걸 빼고** 위치를 구하고 있다.

## 1-6. 로그 볼 때 속기 쉬운 것 3가지

### ① 화면에 좌표가 떠 있어도 새로 잰 값이 아닐 수 있다

위치를 못 구하면 시스템은 화면을 비우지 않는다. **직전 값을 최대 0.5초 동안 그대로 붙들고 있는다.**

```text
[성공][성공][실패][실패][실패][성공]
  ↓     ↓     ↓     ↓     ↓     ↓
 새값  새값  전값  전값  전값  새값    ← 화면엔 계속 숫자가 떠 있다
```

15초 동안 잰 568줄 중 **225줄(40%)** 이 "새 위치를 못 구한 줄"이었다. 화면만 보면 전혀 티가 안 난다.

**볼 것**: `fix`가 false면 숫자가 보여도 쓰면 안 된다. `hybrid_source`가 `none`이면 새 위치가 없다는 뜻이다.

### ② 점수 100점이 정확하다는 뜻이 아니다

로그에 `qscore`라는 100점 만점 점수가 있다. 실측에서 100점이 딱 한 번 나왔는데, 그 줄을 열어보니:

```text
점수         = 100점
쓴 앵커      = 0개      ← 위치 계산을 아예 못 했다
실제 오차    = 57 cm
```

이 점수는 "잘했나"가 아니라 **"감점당할 짓을 했나"** 를 재는 점수다. 계산을 아예 안 하면 감점당할 짓도 없어서 100점이 나온다.

```text
숙제를 아예 안 냈다  →  감점 0점  →  근데 잘한 건 아니다
```

### ③ 칸이 비어 있는 것과 "아니오"는 다르다

로그 줄은 두 종류다.

```text
짧은 줄 (10줄 중 9줄) : 칸이 13개  ← 위치만 적혀 있다
긴 줄  (10줄 중 1줄)  : 칸이 94개  ← 거리·품질까지 다 적혀 있다
```

짧은 줄에는 통신 상태 칸이 **아예 없다.** 이걸 보고 "통신 실패"라고 하면 틀린 얘기다.

```text
시험지에 4번 답이 비었다   →  틀린 것
그 시험지에 4번 문제가 없다 →  해당 없음     ← 지금 상황은 이쪽
```

칼만 필터 관련 칸 6개도 568줄 전부에 없다. 이걸 "아니오"로 표시하면 **있지도 않은 고장**을 만들어내게 된다.

## 1-7. 그래서 순서가 이렇다

```text
1. 앵커 4개가 진짜 그 자리에 있는지 줄자로 재본다
2. 벽에 붙은 그 상자가 정말 A1인지 눈으로 확인한다   ← 두 개 바꿔 꽂아도 같은 증상이 난다
3. 앵커 눈금을 교정한다                              ← 지금 이게 아예 안 되어 있다
4. 다시 재서 확인한다
5. ← 필터 손보는 건 여기서부터. 그 전엔 해봐야 소용없다
```

# 2부. PX4 이야기

## 2-1. 등장인물

```text
Jetson   = 드론의 뇌.    어디로 갈지 정한다.  우리(SW)가 맡는다
Pixhawk  = 드론의 손발.  모터를 돌린다.       PX4라는 프로그램이 돈다
MAVROS   = 통역사.       둘 사이 말을 옮긴다
EKF2     = Pixhawk 안의 계산기. 센서를 섞어서 "지금 위치"를 정한다
```

## 2-2. 제일 중요한 규칙: 선 두 개를 섞지 마라

드론에 넣어야 할 정보는 성격이 완전히 다른 두 가지다.

```text
① "너 지금 어디 있어"  ← UWB가 알려주는 현재 위치
② "너 저기로 가"       ← 우리가 정하는 목표 위치
```

이 둘은 **다른 문으로** 들어가야 한다.

```text
① 현재 위치 ──→ [현재 위치 문] ──→ EKF2      (지금 위치를 계산하는 데 쓴다)
② 목표 위치 ──→ [목표 위치 문] ──→ 비행 제어기 (거기로 날아가는 데 쓴다)
```

**섞으면 이렇게 된다.**

```text
드론: 나 지금 (1, 2)에 있어
명령: (1, 2)로 가!
드론: ...나 이미 거기 있는데?      → 영원히 안 움직인다
```

## 2-3. OFFBOARD = "Jetson 말 듣기" 모드

드론에는 비행 모드가 여러 개 있다. 그중 **OFFBOARD**는 Jetson이 시키는 대로 나는 모드다.

규칙 하나만 기억하면 된다. **계속 말을 걸어야 한다.**

```text
Jetson: "(3,2)로 가"  "(3,2)로 가"  "(3,2)로 가" ...   ← 1초에 최소 3번
```

가만히 있으라고 할 때도 계속 보내야 한다. 이 신호는 명령이면서 동시에 **"Jetson 아직 살아있음"** 표시이기 때문이다.

```text
등산 무전: "이상 없음" "이상 없음" "이상 없음" ...(끊김)
                                              ↑ 1초 지나면 구조대 출동
```

1초 넘게 말이 없으면 PX4는 Jetson이 죽었다고 보고 비상 조치에 들어간다. **그 조치를 우리가 미리 골라야 한다.**

| 고를 수 있는 것 | 뭘 하나 | 실내에서 |
|---|---|---|
| Land | 그냥 내려앉는다 | **안전 — 지금은 이걸 권장** |
| Hold | 그 자리에 떠 있는다 | 지금 위치를 정확히 알아야만 가능 |
| Return | 출발점으로 날아간다 | 위험 (선반에 부딪힌다) |
| Disarm | 모터를 즉시 끈다 | 공중이면 추락 |

지금은 위치가 66cm 틀리므로 Hold가 성립하지 않는다. **Land가 안전하다.**

## 2-4. 설정에서 꼭 짚을 것 3개

### 높이는 UWB한테 묻지 않는다

우리 UWB는 앞뒤·좌우(x, y)만 알려준다. 높이는 모른다. 높이는 바닥을 보는 거리센서(TFmini Plus)가 담당한다.

```text
설정값 1 = "앞뒤·좌우만 UWB한테 받겠다"   ← 우리는 이게 맞다
설정값 3 = "높이도 UWB한테 받겠다"        ← 오지도 않는 값을 기다리게 된다
```

### 값이 늦게 도착하는 만큼 알려줘야 한다

UWB가 재고 → 계산하고 → Jetson 거치고 → 통역사 거치고 → 케이블 타고 도착. 이 사이에 시간이 걸린다.

```text
진짜로 그 자리에 있던 순간  : 0.00초
그 값이 도착한 순간        : 0.05초    ← 드론은 이미 다른 데 있다
```

이 시간차를 설정으로 알려준다. **감으로 넣지 말고 실제로 재서 넣어야 한다.**

### 위아래 방향이 서로 반대다

시스템마다 "위"가 다르다.

```text
ROS  : 위쪽이 +
PX4  : 아래쪽이 +    ← 반대다!
```

통역사(MAVROS)가 이 변환을 알아서 해준다. **그런데 우리가 코드에서 한 번 더 뒤집으면 두 번 뒤집혀서 원래대로 돌아온다.** 그러면 위로 가라는데 아래로 간다.

```text
맞음 : 우리는 그대로 → 통역사가 1번 뒤집음 → 정상
틀림 : 우리가 뒤집음 → 통역사도 뒤집음    → 원위치 (사고)
```

# 3부. 그래서 우리가 뭘 하나

## 지금 당장

```text
1. UWB 값을 실제 비행에 쓰지 않는다
   → 66cm 틀린다. 선반 사이 통로에서 66cm는 부딪히는 거리다
   → 교정이 끝날 때까지는 프로펠러 빼고 배선·경로만 확인한다

2. 비상 조치는 Land로 둔다
   → Hold는 "지금 위치를 안다"는 전제가 필요한데 그 전제가 지금 안 선다

3. 파이프라인은 미리 만들어 둔다
   → 교정된 값이 오면 바로 흘려보낼 수 있게
```

## HW 파트에 요청할 것

```text
- 앵커 4개의 실제 위치를 줄자로 잰 값
- 벽에 붙은 상자와 A1~A4 번호가 맞는지 확인 (사진)
- 앵커 눈금 교정
- 태그에 올라간 프로그램 버전   ← 지금 우리가 아는 버전과 다른 것 같다
```

## 다음에 정해야 할 것 하나

HW 문서는 **Pixhawk가 위치 제어를 다 한다**고 보고 있다. 우리 로드맵(결정 4)은 **Jetson이 위치 제어를 한다**고 되어 있다. 서로 다르다.

이대로 두면 로드맵에 있는 "게인 스케줄링"을 넣을 자리가 없어진다. 설계 논의에서 한 번 정리해야 한다.
