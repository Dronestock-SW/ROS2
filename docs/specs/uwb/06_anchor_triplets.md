# M06 세 앵커 조합별 위치 후보

네 앵커를 세 개씩 묶어 후보를 만드는 명세다. 조합별 풀이와 공통 거리 풀이를 비교할 때 읽는다.

## 목적과 현재 상태

같은 시점의 거리에서 최대 네 위치 후보를 생성한다.
2026-09-27에 `C_uniform4` 파일 계산을 구현했다.
기존 `rawxy.py`는 초기 참고 함수다.
논문의 세부 가중치 수식을 재현했다고 표시하지 않는다.

2026-09-27에 B 완료 후 착수 명세를 구체화했다.
첫 구현은 `C_uniform4`로 이름을 붙인다.
네 조합의 동일 가중 풀이와 균등 평균만 비교한다.
기준은 [B와 함께 재생한 A](../../report/uwb_h80_b_20260927.md)다.
이후 코드·정지 실측·합성 비교를 완료했다.
[C/D 결과](../../report/uwb_subsets_cd_20260927.md)에 검증을 남겼다.
같은 시각 A/C의 RMSE는 8.71/9.11cm다.
현재 균등 평균으로 개선했다고 판단하지 않는다.

## 첫 비교군과 조합

**네 후보가 모두 성립할 때 균등 평균을 출력한다.**
후보별 가중치 변경은 후속 비교군으로 분리한다.

| 후보 ID | 사용하는 앵커 | 후보 풀이에 쓰지 않는 앵커 |
|---|---|---|
| `S123` | A1, A2, A3 | A4 |
| `S124` | A1, A2, A4 | A3 |
| `S134` | A1, A3, A4 | A2 |
| `S234` | A2, A3, A4 | A1 |

후보 ID는 앵커 번호를 정렬해 만든다.
입력 순서를 바꿔도 같은 네 후보를 계산한다.
후보마다 위치는 하나다. 총 후보는 네 개다.
각 앵커는 세 후보에 중복 사용된다.
네 후보를 네 독립 측정으로 취급하지 않는다.

## 입출력

다음 표는 확장용 공통 인터페이스 구상이다.
첫 파일 구현의 실제 필드는 그 아래 표를 따른다.

| 방향 | 파라미터 | 형식·단위·조건 |
|---|---|---|
| 입력 | `frame`, `anchors`, `z_sample` | RangeFrame·AnchorMap·안테나 Z |
| 입력 | `range_covariance` | 4×4 m²/null. 동일 가중 기준선은 null 허용 |
| 입력 | `initial_xy_m` | float[2]/null. 결정적 초기화 정책 |
| 출력 | `candidate_set` | 최대 네 Candidate와 실패 묶음 |
| 출력 | `subset_ids`, `omitted_anchor_id` | 조합과 남겨둔 앵커 식별 |
| 출력 | `residuals_all_anchors_m` | 남겨둔 앵커를 포함한 진단 |

첫 파일 실행기에서는 다음 필드를 구체적으로 보존한다.
기준 XY는 후보 계산에 전달하지 않는다.

| 방향 | 필드 | 첫 구현의 계약 |
|---|---|---|
| 입력 | `input_line`, `seq` | 원본 파일 행과 수신 주기 식별. 파일 해시는 manifest |
| 입력 | `source_ref_us` | 해당 주기의 `cycle_end_us` |
| 입력 | `sample_time_us[4]` | 앵커별 Report 읽기 시각. 장치 시계는 원본 status에서 확인 |
| 입력 | `raw_slant_m[4]`, `bias_m[4]` | 원본과 잠근 편향. 편향은 calibration.json에 보존 |
| 입력 | `cal_slant_m[4]` | `raw_slant_m - bias_m`. 차감은 한 번만 수행 |
| 입력 | `anchors_xyz_m[4][3]` | A/B와 같은 지도·앵커 순서 |
| 입력 | `heights` | 함수 인수: 높이 m, 스칼라 또는 표본별 길이 4 배열 |
| 입력 | `height_source_C_D` | summary의 출처. 첫 실측은 당시 수기 기록 |
| 출력 | `candidates[4]` | 성공·실패 모두 ID별 보존 |
| 출력 | `candidate.xy_m[2]` | 후보 위치 m. 실패하면 null |
| 출력 | `candidate.used_obs_ids[3]` | 세 원본 관측 식별자 |
| 출력 | `candidate.omitted_residual_m` | 남은 앵커 잔차. 선택에 사용하지 않음 |
| 출력 | `candidate.rank`, `candidate.fit` | 성공 시 rank 2. fit에 condition·iterations·잔차 |
| 출력 | `models.C.xy_m[2]` | 네 후보 성공 시 평균. 나머지는 null |
| 출력 | `weights` | ID별 가중치 dict. 성공 시 각각 0.25 |
| 출력 | `dispersion_m2[2][2]` | 후보 간 산포. 오차 공분산과 구분 |
| 출력 | `covariance_kind` | `unknown`. PX4에 보낼 공분산 아님 |
| 출력 | `ok`, `reason` | 결과·판정. 과거 후보 재사용 없음 |
| 출력 | `timings.jsonl`의 `C_ms` | 계산 경과시간. 결정적 위치 파일과 분리 |
| 출력 | `flight_valid`, `external_output_allowed` | 파일 시험에서 둘 다 false |

정지 파일 시험은 당시 안테나 높이 기록을 사용한다.
동적 센서 시험은 표본 시각에 맞춘 높이가 필요하다.
높이의 기준점은 FC가 아니라 UWB 안테나다.
자료가 없으면 `missing_z`로 풀이를 차단한다.
다른 날 비행 로그를 같은 시각 자료로 붙이지 않는다.
서로 다른 세션의 센서가 동시 관측이 아니기 때문이다.

## 설정

| 파라미터 | 단위·범위 | 초기 상태 |
|---|---|---|
| `triplets` | ID 목록 | S123, S124, S134, S234 |
| `solver` | unweighted/weighted_slant | 각각 별도 variant |
| `iterations`, `step_tol_m` | 정수, m | 첫 비교는 40 / 1e-7. A와 동일 |
| `condition_max` | 무차원 | 첫 비교는 1e6. A와 동일 |
| `max_frame_skew_s` | s | 첫 비교 0.04. 수신 검사와 동일 |
| `require_four_inputs` | bool | 기본 true |
| `fusion_policy` | 문자열 | 첫 비교 `uniform` |
| `min_candidate_count` | 정수 | 첫 비교 4 |
| `max_range_m` | m | 첫 비교 80. A/B 공통 입력 검사 |
| `fallback_to_A` | bool | false. 실패를 A로 대체하지 않음 |

이 값은 비교 조건이다. 최적 운용값은 미선정이다.
첫 비교에는 거리·위치 게이트를 추가하지 않는다.
후보 선택에 기준점이나 구간 정답을 사용하지 않는다.
정답 정보가 계산에 새어 들어가면 평가가 왜곡되기 때문이다.

## 처리 구조와 산식

```text
같은 수신 주기의 RAW·시각·앵커 ID
                 ↓
        입력 검사·편향 1회 차감
                 ↓                  높이 출처·시각
       네 거리 + 앵커 지도 ←─────────────┘
                 ↓
       조합 생성: S123 / S124 / S134 / S234
                 ↓
       조합별 세 거리 XY 풀이·기본 수치 검사
                 ↓
       네 후보와 실패·전체 앵커 잔차 기록
                 ↓
       네 후보 모두 성공? ── 아니오 → 결합 차단·사유 기록
                 │ 예
                 ↓
       0.25씩 평균 → 후보 산포·결합 결과 기록
                 ↓
       A/B와 같은 평가 시각의 오차·가용률 비교
```

각 묶음 S에 대해 다음 오차를 최소화한다.

```text
e_i(x,y) = sqrt((x-ax_i)^2+(y-ay_i)^2+(z_i-az_i)^2)-r_cal_i
p_S = argmin e_S^T * inverse(C_S) * e_S
```

구현은 선형계 풀이를 사용하고 역행렬을 직접 만들지 않는다.
첫 `C_uniform4`에서는 `sum(e_i^2)`를 최소화한다.
위 식의 거리 공분산 가중은 후속 비교군이다.
Z가 없으면 묶음 생성까지만 하고 풀이를 차단한다.
각 묶음은 같은 원본 거리와 Z를 사용한다.
기준 앵커 순서만 바꾼 결과는 별도 측정으로 세지 않는다.
후보 간 공통 관측을 `used_obs_ids`로 추적한다.

세 앵커의 제곱 거리 차로 시작 위치를 구한다.
그 후 거리 잔차를 반복해서 줄인다.
초기화 기준 앵커는 조합에서 번호가 가장 작은 앵커다.
직전 후보나 A/B 출력을 초기값으로 넣지 않는다.
그래야 C 자체의 결과를 독립적으로 비교할 수 있다.

```text
h_i² = r_cal_i² - (z_i - az_i)²
2*(a_i_xy - a_base_xy) · p_initial
  = h_base² - h_i² + ||a_i_xy||² - ||a_base_xy||²

J_i = [(x-ax_i)/predicted_range_i,
       (y-ay_i)/predicted_range_i]
J * delta ≈ -e                         # SVD 최소제곱
p_next = p + step_scale * delta        # 비용 감소 확인

p_C = (p_S123 + p_S124 + p_S134 + p_S234) / 4
D_C = sum((p_S - p_C)*(p_S - p_C)^T) / 4
```

단계 축소는 A와 같이 최대 20회 시도한다.
수렴·rank 2·조건수·유한값을 확인한다.
`D_C`는 후보 간 산포만 나타낸다.
이 값으로 위치 정확도나 공분산을 보장하지 않는다.
네 후보가 같은 방향으로 틀릴 수도 있기 때문이다.

첫 C는 한 주기 안에서 XY가 같다고 근사한다.
기준 시각 표시는 A/B와 같은 주기 종료 시각이다.
비동기 측정 중 이동 오차는 별도 합성 시험에서 확인한다.
시간창이나 속도 추정으로 이를 숨기지 않는다.
그 기능은 B와 비교할 핵심 차이이기 때문이다.

## 구현 모듈

후보 생성·풀이·결합·평가를 나눈다.
다음 함수는 파일 비교에서 사용하는 구현이다.

| 위치 | 함수·역할 | 입력 → 출력 |
|---|---|---|
| `processing/triplets.py` | `make_triplets` | 앵커 ID 네 개 → 정렬된 네 조합 |
| `processing/triplets.py` | `solve_triplet_xy` | 지도·세 거리·표본별 높이·설정 → 후보·진단 |
| `processing/triplets.py` | `make_candidates` | 지도·거리·높이·시각·ID → 네 후보·결합·실패 |
| `processing/candidate_fusion.py` | `uniform_fuse` | 네 유효 후보 → 평균·가중치·산포 |
| `processing/range_solver.py` | `solve_slant_xy` | A/C 공통 수식. 요구 앵커 수는 호출자가 지정 |
| `processing/experiments/subset_comparison.py` | `run` | 잠근 파일 설정 → A/B/C 또는 A/B/C/D 비교 |
| `config/subsets_cd_static_20260906.json` | 시험 설정 | 같은 평가 RAW·지도·교정·이전 A/B 해시 |

기존 A 함수는 네 거리 입력 계약을 유지한다.
공통 풀이를 추출하고 A/B 결과의 완전 일치를 확인했다.
세 앵커 허용으로 A의 입력 계약을 느슨하게 바꾸지 않는다.
기준선이 달라지면 개선 여부를 판단하기 어렵기 때문이다.
수신부와 ROS 연결부에는 C 수식을 넣지 않는다.
실행기는 파일 입출력만 소유한다.

## 실패와 상태

세 앵커의 배치가 나쁘면 해당 후보만 거부한다.
한 앵커 누락 시 기본 비교군은 blocked다.
가용한 세 앵커만 쓰는 축소 모드는 별도 variant다.
이 모드는 네 후보 결합과 같은 이름으로 집계하지 않는다.
남겨둔 앵커 잔차는 점수용 진단이다.
독립적인 기준 위치 오차로 부르지 않는다.

첫 비교군의 실패 정책은 다음과 같다.

| 조건 | 후보·결합 처리 | reason 예시 |
|---|---|---|
| 네 입력 중 하나 누락·무효 | 네 조합 비교를 차단 | `four_anchors_required` |
| 높이 없음·시계 미대응 | 풀이 차단 | `missing_z`, `clock_unmapped` |
| 중복 주기·시각 역행 | 새 좌표 출력 없음 | 수신 검사 reason 보존 |
| 조합이 일직선·rank 부족 | 해당 후보 실패 | `degenerate_anchor_geometry` |
| 조건수 초과·분해 실패 | 해당 후보 실패 | `ill_conditioned`, `solver_failed` |
| 반복 상한·비용 감소 실패 | 해당 후보 실패 | `iteration_limit`, `no_descent` |
| 후보 하나 이상 실패 | 성공 후보도 보존하고 결합 차단 | `incomplete_candidate_set` |
| 같은 관측이 없는 과거 후보 | 재사용 차단 | `stale_candidate` |

성공 후보 세 개만 평균내는 방식은 별도 비교군이다.
기본 C 결과와 같은 이름으로 집계하지 않는다.
남은 앵커 잔차로 후보를 골라 버리는 기능도 이번에는 없다.
후보 생성 효과와 선택 효과를 따로 평가하기 위해서다.

## B 결과를 반영한 시험 순서

B의 약점이 드러난 방향 반전을 C에서도 확인한다.
정지 결과 하나로 모델을 선정하지 않는다.

| 순서 | 시험 | 완료 기준 |
|---|---|---|
| 1 | 조합·입력 순서 | 정확히 네 ID. 순열을 바꿔도 같은 후보 |
| 2 | 무잡음 정지 | 네 후보와 결합 XY 오차 1µm 미만 |
| 3 | 표본별 시각이 다른 이동 | 주기 내 XY 근사 오차 기록. 무잡음 0을 강제하지 않음 |
| 4 | 앵커별 +0.20/+0.50/+1.00m | 각 앵커를 차례로 오염. 네 후보·결합 결과 모두 기록 |
| 5 | 두 앵커 이상·공통 편향 | 후보 평균이 실패하는 경우도 보고 |
| 6 | 입력 누락·배치 퇴화·수치 실패 | 후보와 결합의 정확한 차단 사유 |
| 7 | 정지→이동·정지·방향 반전 | A/B/C의 p95·최대 오차·전환 직후 오차 |
| 8 | 현재 1분 실측 로그 | A의 2,540개 좌표 유지. 같은 입력으로 C 평가 |
| 9 | 동일 파일 재생 | 좌표·실패·조합·가중치 바이트 일치 |
| 10 | 독립 위치·동적 실측 | 모델 선정 전 새 자료로 재확인 |

첫 실측 비교는 B와 같은 입력 해시를 사용한다.
편향 산출에 2차 로그를 다시 사용하지 않는다.
A/B/C 공통 유효 시각과 각 모델 전체 가용률을 함께 보고한다.
A/C만 비교한 시각 수와 A/B/C 공통 시각 수도 구분한다.
후보 네 개를 네 번의 성공 관측으로 세지 않는다.
수신 주기 하나에서 C 결합 출력은 최대 하나다.

## 기대 효과와 선택 판단

C는 현재 한 주기의 거리만 사용한다.
따라서 B의 시간창 추종 특성과 다른 결과를 기대한다.
다만 과거 표본을 평균하는 B보다 잡음이 클 수 있다.
아래 내용은 시험 전 예상이다.

| 상황 | 예상 효용 | 확인할 한계 |
|---|---|---|
| 한 앵커의 이상 | 어느 조합이 달라지는지 진단 | 그 앵커를 포함한 세 후보가 함께 오염됨 |
| 급정지·반전 | 시간창 이력에 따른 응답 지연을 줄일 가능성 | 단발 잡음에 민감할 수 있음 |
| 정지 잡음 | 후보 결합 효과 비교 | 공유 관측 때문에 평균만으로 이득이 보장되지 않음 |
| 앵커 외곽·나쁜 배치 | 조합별 민감도 차이 확인 | 일부 후보 실패로 기본 C 가용률 감소 가능 |
| 지속 편향 | 조합 불일치의 진단 자료 확보 | 균등 평균만으로 원인 앵커를 교정하지 못함 |

선택은 [공통 평가 기준](90_evaluation.md)을 따른다.
RMSE·p95·최대 오차·가용률·시간을 함께 비교한다.
성능이 나쁘면 그 결과도 모델 선택의 근거로 남긴다.
이번 명세에서 목표 cm나 운용 계수를 새로 확정하지 않았다.

## 완료 상태

입출력·모듈·실패 처리를 구현하고 파일 시험을 마쳤다.
C는 실측 2,540주기 중 2,511개 위치를 출력했다.
S124의 29회 반복 상한 실패를 결과에 보존했다.
UWB 전체 117개 테스트·빌드·재생 검사를 통과했다.
위 시험 계획 중 전체 편향 주입 행렬은 미실시다.
독립 위치·동적 실측 검증도 남았다.
품질 가중·일부 후보 결합·자동 앵커 제외는 후속 아이디어다.
[완료 보고서](../../report/uwb_subsets_cd_20260927.md)에 실제 시험 범위를 구분했다.

## 27일 비행 자료 반영

27일 ULog는 C의 센서 입력 준비 자료로 등록했다.
사용자는 같은 시간의 UWB RAW가 없다고 확인했다.
[준비 프로파일](../../../src/drone_uwb/config/c_flight_inputs_20260927.json)은 실행 가능한 C 설정이 아니다.
원본·센서 추출물의 해시와 누락 입력을 담았다.

| 비교 경로 | 현재 가능한 작업 | 남은 입력 |
|---|---|---|
| 기존 정지 UWB의 C | A/B와 같은 RAW·편향으로 구현·비교 완료 | 독립 위치와 동적 실측 |
| 27일 센서 준비 | 거리·자세 원본과 시각·품질 보존 | 좌표 변환·장착 확인 |
| 27일 비행의 A/B/C | 센서 준비까지 | 같은 비행 UWB RAW·시계 대응·교정 |

자세의 FRD→NED 회전을 창고 `R_WB`로 바로 쓰지 않는다.
거리의 품질 미상·분산 미상을 0오차로 바꾸지 않는다.
이 ULog의 거리 기록은 약 1초 간격이다.
높이 보간·나이 상한을 임의로 바꿔 계산을 열지 않는다.
[27일 입력 준비 결과](../../report/uwb_flight_inputs_20260927.md)에 확인 근거를 남겼다.
