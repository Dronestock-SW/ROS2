# FINAL 실행 8 — 밀림·관측 공백 분석
실행 8 원본 회수와 시간축 비교 결과다.
원인 조사와 다음 지상 기록 준비 때 읽는다.

**추정 XY 변화는 최종 관측 공백보다 먼저다.**
이 결론은 실제 기체 이동의 시작·거리를 확정하지 않는다.
UWB 계열 관측과 FC 추정 사이의 차이도 커졌다.
사용자가 제공한 영상에서 실제 측면 이동도 보인다.
영상의 정확한 로그 동기화와 당시 B_TF 기록은 남았다.

## 2. 시간축과 좌표

FC와 companion 시간을 명령 사건으로 맞췄다.

| ARM 요청/수신 | 1493.721612575 | 1525.885285 |
| LAND 요청/수신 | 1501.771513521 | 1533.936052 |

## 4. 목표·추정·관측의 비교

OFFBOARD 구간의 목표 XY는 고정이었다.
출발점은 (3.598079441, 2.329428069)m다.
FC trajectory_setpoint의 X·Y 변화폭은 각각 0m다.
LAND 뒤 목표 변화는 PX4 착륙·수동 전환 구간이다.
그 변화를 companion의 이륙 목표 재설정으로 해석하지 않는다.

LAND 이벤트는 약 0.215m를 기록했다.
10Hz ULog 직전 표본은 약 0.205m다.
직후 표본은 약 0.219m다.
서로 다른 표본 시각의 차이를 좌표 오류로 판정하지 않는다.

| 값 | 확인한 변화·차이 | 의미 |
|---|---|---|
| LAND 이벤트의 FC XY | 출발점 대비 약 0.215m | FC 추정 변화 |
| 마지막 LAND 전 EV aid 관측 | 출발점 대비 약 0.596m | EKF가 처리한 외부 위치 관측 |
| 같은 EV의 innovation N/E | +0.3077 / +0.2357m | 관측과 EKF 예측의 불일치 |
| 관측·융합 | 해당 EV 행 fused=true, rejected=false | 그 행은 융합 수용 상태 |
| 광류 | 3.188초 뒤 LAND까지 활성 | 광류 전체 미사용은 아님 |

EV aid 관측은 원시 UWB XY와 같지 않다.
PX4는 레버암·좌표·bias 처리를 거친 관측을 기록한다.
[해당 FC 펌웨어의 EV 처리 코드](https://github.com/PX4/PX4-Autopilot/blob/d6f12ad1c4f70ad3230afd7d86e971421e02fef4/src/modules/ekf2/EKF/aid_sources/external_vision/ev_pos_control.cpp#L52)를 대조했다.
0.596m를 실제 이동 거리로 보고하지 않는다.
서로 다른 기록 시각의 두 값을 단순히 빼서 센서 오차로 확정하지 않는다.

9.065초 reset의 NED XY 보정은 약 (−0.926, −0.281)m다.
이후 FC 좌표의 큰 변화에는 추정 reset이 포함된다.
이를 기체가 순간적으로 그 거리만큼 이동한 증거로 쓰지 않는다.

그림은 Git 외부 분석 자료의 timeline.png에 있다.

위 그림의 EV 좌표 점은 `timestamp_sample`에 놓았다.
innovation은 계산·발행 시각에 놓았다.
EV aid 기록은 약 2Hz이고 FC 위치는 약 10Hz다.
EV sample과 처리 시각의 차이는 대체로 약 0.2초다.
로그의 `EKF2_DELAY_MAX=200ms`도 별도로 확인했다.
이 차이만으로 실제 UWB 전송 지연을 확정하지 않는다.

2Hz EV 행 사이 간격을 원시 UWB 수신 공백으로 계산하지 않는다.
이유: 낮은 로그 발행률과 실제 입력률은 다르다.
ULog에는 원시 `vehicle_visual_odometry`가 없다.
이륙 전 2초 전체의 연속 FC 위치 기록도 없다.
사건 순서와 최종 나이는 확보했지만 모든 초기 공백의 시작은 미확정이다.

## 영상 대조와 상승 속도 질문

실제 이동도 있지만 원인은 아직 확정하지 못했다.
영상은 30fps·636프레임·21.2초다.
SHA256: `591b603d8e22fb406c509881270cb0c77cafd5a2fdc8ec4c45b85cabd170472c`.
영상 약 4~8초에 저고도 상승이 보인다.
약 9~13초에는 출발 표식에서 벗어나 측면 이동이 보인다.
이 시각은 영상 기준이며 FC ARM 기준과 같지 않다.
미터 단위 오차나 정확한 밀림 시작은 산출하지 않았다.

1m/s 상승은 비교할 후보지만 현재 해결책으로 확정하지 않는다.
지면효과 가설과 UWB·광류 관측의 불일치를 함께 검사한다.
속도 증가만으로 원시 관측 공백을 해결했다고 볼 수 없다.

| 구간·설정 | 실행 8의 기록 | 해석 |
|---|---|---|
| 지상 정지·OFFBOARD 예열 | START 전 정지·ARM 전 예열 | 공중 저고도 호버 대기가 아님 |
| COM_SPOOLUP_TIME | 1.0초 | FC 모터 준비 시간 |
| MPC_TKO_RAMP_T | 약 1.8초 | FC 상승 제한을 올리는 램프 |
| takeoff_status rampup | ARM 후 1.052~3.025초 | 저고도 초기 응답과 함께 비교 |

Offboard는 FC 상승 제한을 기본 제약으로 사용한다.
[같은 펌웨어의 위치제어 코드](https://github.com/PX4/PX4-Autopilot/blob/d6f12ad1c4f70ad3230afd7d86e971421e02fef4/src/modules/mc_pos_control/MulticopterPositionControl.cpp#L424)를 대조했다.
스풀업·램프는 상승 속도와 별도 설정이다.
[PX4 스풀업 정의](https://docs.px4.io/v1.17/en/advanced_config/parameter_reference#COM_SPOOLUP_TIME)와

따라서 0.5→1m/s 변경과 대기 제거는 같은 변경이 아니다.
실행 8에는 이륙 중 별도 제자리 대기가 없다.
추가 속도 시험은 고정 XY와 관측 연속성을 확인한 뒤 비교한다.
이번 분석에서는 0.5m/s·1.7m 및 추력·램프를 유지했다.
