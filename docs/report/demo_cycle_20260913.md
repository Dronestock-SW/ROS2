# 공용 데모 개발 1사이클 결과
이 문서는 2026-09-13 개발·검증 결과다.
완료 범위와 다음 작업을 확인할 때 읽는다.

## 결론

도착·수신 공백·복구 판단을 구현했다.
자동 테스트 63개와 ROS2 연결 시험을 통과했다.

실제 비행 명령은 이번 구현에 포함하지 않는다.
상태 판단 결과만 `/demo_mission_state`로 발행한다.
판단 기준은 [데모 임무 상태 기준](../demo_mission_design.md)을 따른다.

## 구현 결과

같은 데모 입력을 새 판단 노드에 연결했다.

| 항목 | 이번 결과 |
|---|---|
| 목표 접근 | 0.50m 진입, 0.60m 이탈 판정 |
| 도착 | 0.15m 진입, 속력 0.10m/s 이하 |
| 정착 유지 | 0.20m 이내에서 1초 유지 |
| 수신 공백 | 위치 0.20초, UWB 0.25초 초과 탐지 |
| 복구 | 0.50초 연속 정상 수신과 각 3개 표본 |
| 도착 후 공백 | `arrival_valid=false`로 해제 |
| 중복·과거 메시지 | 새 수신으로 세지 않음 |
| 잘못된 목표 | 기존 목표 해제, 목표 대기 |
| 기록 | 상태·사유·거리·속력·입력 나이 JSONL |

거리·속력·시간 조건은 데모 초기값이다.
실기 운용 한계로 검증한 수치가 아니다.

## 파일 재생 결과

세 시나리오 모두 목표 도착 판정을 확인했다.
아래 시각은 실제 경과 시간이 아닌 가상 시간이다.

| 시나리오 | 확인한 전환 | 도착 시각 |
|---|---|---:|
| 정지 | 입력 준비 → 정착 → 도착 | 2.225초 |
| 이동 | 이동 → 접근 → 정착 → 도착 | 8.675초 |
| 1초 공백 | 4.225초 공백 탐지 → 5.000초 복구 확인 | 8.675초 |

공백 시나리오는 5.500초에 정상 판단을 재개했다.
각 시나리오는 12초, 480개 평가 입력이다.
[파일 재생 기록](evidence/demo_cycle_20260913/offline)을 남겼다.

## ROS2 연결 결과

실제 ROS2 프로세스 두 개를 연결해 확인했다.
입력 생성기와 상태 판단 노드를 사용했다.
통신은 로컬 DOMAIN_ID 99에서만 수행했다.

| 항목 | 실제 수신·기록 |
|---|---:|
| 검사 구독자의 데모 위치 | 475개 |
| 검사 구독자의 UWB 관측 | 406개 |
| 공백 구간의 생성기 상태 | 40개 |
| 늦게 구독한 목표 수신 | 1개 |
| 판단 노드 자체 기록 | 248개 |
| 실행 종료 코드 | 0 |

판단 노드 시작 후 경과 시간을 기록했다.
첫 통신 연결 시점은 파일 재생과 다를 수 있다.

| 시각 | 상태 | 확인 의미 |
|---:|---|---|
| 4.251초 | `DEGRADED` | UWB 관측 나이 0.274초 |
| 5.052초 | `RECOVERING` | 새 관측을 받고 복구 확인 시작 |
| 5.601초 | `MOVING` | 연속 수신 조건 충족 |
| 5.701초 | `APPROACHING` | 목표 접근 반경 진입 |
| 7.701초 | `SETTLING` | 거리·속력 조건 충족 |
| 8.701초 | `ARRIVED` | 정착 1초 충족 |
| 12.201초 | `DEGRADED` | 생성기 종료 뒤 위치 입력 만료 |

마지막 도착 해제는 입력 종료에 따른 결과다.
좌표를 붙잡아 도착 상태를 유지하지 않았다.
두 노드는 시험 뒤 종료했다.
[ROS2 원본 기록](evidence/demo_cycle_20260913/ros_gap/mission_state.jsonl)을 남겼다.

## 검증 범위

판단 오류를 일으킬 입력도 함께 시험했다.

| 시험 | 결과 |
|---|---|
| 워크스페이스 빌드 | 5개 패키지 성공 |
| 기존 UWB·데모와 새 판단 테스트 | 63개 통과 |
| 목표 근처를 빠르게 이동 | 도착으로 판정하지 않음 |
| 위치·UWB·전체 입력의 공백 | 도착 판정 해제 |
| 반복된 측정 시각 | 수신 나이를 갱신하지 않음 |
| 새 위치 없는 타이머 호출 | 정착 시간을 늘리지 않음 |
| 다른 좌표계·NaN·미래·오래된 입력 | 도착 판정 차단 |
| 상태 발행 사이의 짧은 이탈 | 정착 시간 초기화 |
| 작은 위치 변화 | 진입·이탈 반경을 구분 |

## 다음 한 사이클

실제 PX4 상태 입력 계약을 먼저 정한다.

1. PX4 위치·속도·유효성 입력을 확인한다.
2. 서버 목표와 현재 위치의 좌표계를 맞춘다.
3. 데모 위치 자리에 검증한 상태 입력을 연결한다.
4. 수평 이동·감속·공백 대응을 SITL에서 검증한다.

지금의 가상 이동 경로는 판단 결과로 움직이지 않는다.
따라서 실제 정지·제어·EKF 성능 검증은 남아 있다.
재현 방법은 [데모 실행 절차](../demo_procedure.md) 7절에 있다.
