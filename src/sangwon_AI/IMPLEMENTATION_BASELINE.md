# 내부 구현 기준과 적용 범위
이 문서는 외부 사양 회신과 분리해 구현할 내부 계약을 정한다.
BT·입출력·상태·시험 모듈을 구현할 때 기준으로 읽는다.

상태: 내부 구현 기준 v1.0 / 2026-10-02 / 실기체 운용 승인 전.
웹은 담당자 전달·회신 전이다. 회신된 계약을 웹 어댑터에 반영한다.
UWB는 전체 사양 수령 전이다. 장치 어댑터 구현은 그때 진행한다.
이 문서의 구현 범위와 실기체 운용 승인을 구분한다.

## 1. 이번에 고정하는 경계

| 항목 | 내부 기준 |
|---|---|
| 행동 모델 | 명시적 BT. 같은 상태·사건 순서·설정에는 같은 전환 |
| 제어 | PX4가 위치·자세·고도·yaw 제어, Jetson은 목표와 행동 선택 |
| 모듈 경계 | 임무 판단·경로계획·외부 연결·비행 출력·기록 분리 |
| 구현 언어 | 핵심 판단·제어 경로는 C++, 웹·로그·보조 어댑터는 Python |
| 웹 변경 | 실제 JSON→내부 명령/임무 변환은 웹 어댑터 한 곳 |
| UWB 변경 | 전체 사양→관측/품질 인터페이스는 별도 어댑터 |
| 출력 | 하나의 비행 출력 프로세스만 MAVROS 목표·모드·시동 요청 |
| 미정 물리값 | 승인 프로파일로 주입. BT 코드에 임의 상수 삽입 금지 |
| 내부 재기동 | 이전 비행·목표 자동 재개 금지 |
| 외부 회신 충돌 | 필드·전송 차이는 어댑터 변경, 행동 의미 변경은 설계 개정 |

웹팀 회신을 적용할 때 임무 순서·좌표 의미·제어권·오래된 명령 차단을 대조한다.
회신이 기존 합의와 충돌하면 자동으로 행동 정책을 바꾸지 않는다.
담당자 회신 전에는 WEB_JSON_DRAFT의 합성 자료를 시험 입력으로 쓴다.

## 2. 모듈과 책임

아래는 목표 모듈 구분이다. 현재 범위는 [구현 현황](IMPLEMENTATION_STATUS.md)에 기록한다.

| 모듈 | 언어 | 단독 책임 | 다른 모듈에 넘기는 값 |
|---|---|---|---|
| mission_runtime | C++ | BT 평가, 필수 방문 순서, 명령 최종 수락·중복·진행 잠금 | ControlIntent·임무 사건 |
| route_planner | C++ | 공간 검사·고도 변경 지점·경로·제동 가능성 | 승인/실패·PathPlan |
| flight_guard | C++ 별도 프로세스 | 목표 검증·lease·제어권·모드 전환·지속 송신 | ControlFeedback·출력 거부·비상 사건 |
| px4_state_adapter | C++ | PX4 제어용 상태·품질 수신 및 정규화 | StateSnapshot, guard가 직접 검사할 품질 |
| web_adapter | Python | JSON·인증·세션·전달/결과 재전송 | MissionSnapshot·CommandEnvelope |
| log_manager | Python | 행동/센서 기록, 비행 후 ULog 수집·검증·보존 | LoggingHealth·수집 결과 |
| 장치별 보조 어댑터 | Python 기본 | 제작 사양을 해석·정규화, UWB는 사양 수령 후 결정 | 관측·품질, C++에서 신선도 재검증 |
| interface_types | ROS IDL | 메시지·enum·버전·단위 | C++/Python 공통 계약 |

mission_runtime과 flight_guard는 서로 다른 프로세스로 실행한다.
flight_guard가 종료되면 PX4 Offboard 상실 대응이 마지막 독립 경로다.
BT는 lease를 발급하지만 실제 송신기는 스스로 그 기한을 연장할 수 없다.
웹·파일 기록·경로계획 호출을 비행 송신 주기 안에서 기다리지 않는다.
언어 분담은 사용자 결정으로 확정했다. 언어만으로 안정성을 보장하지는 않는다.
입력 검증·bounded queue·timeout·예외 격리·선점/실패 주입 시험을 함께 적용한다.

BT 실행기는 BehaviorTree.CPP 4 계열을 채택한다.
C++17·ROS2 Humble rclcpp를 기준으로 하고 정확한 라이브러리 패치 버전은 빌드 기준표에 고정한다.
ROS Humble 배포 목록에 4 계열 패키지가 있으며, Jetson apt 후보·컴파일 호환은 설치 단계에서 확인한다.
근거: [BehaviorTree.CPP](https://raw.githubusercontent.com/BehaviorTree/BehaviorTree.CPP/master/README.md), [ROS Humble 배포 목록](https://raw.githubusercontent.com/ros/rosdistro/master/humble/distribution.yaml).

지속 동작은 StatefulActionNode의 onStart/onRunning/onHalted에 대응한다.
onHalted는 이전 세대 권한을 회수하고 작업 취소만 요청한다. 긴 작업 종료를 tick에서 기다리지 않는다.
입력 포트와 결과는 공통 타입으로 제한하며 blackboard가 실기체 출력을 직접 호출하지 않는다.
BT 라이브러리의 IDLE/SKIPPED 등 내부 상태를 임무 SUCCESS로 바꾸지 않는다.
근거: [비동기 동작·중단 공식 예제](https://www.behaviortree.dev/docs/tutorial-basics/tutorial_04_sequence/).

Python 보조 프로세스가 멈춰도 C++ 출력 주기가 파일/API 응답을 기다리지 않는다.
웹 프로세스 중단은 저장 임무 계속, 필수 기록 프로세스 중단은 복귀 사건으로 처리한다.
UWB 어댑터 중단은 신규 관측 상실로 처리하며 상세 시간은 실제 사양 수령 뒤 정한다.

## 3. 내부 메시지 계약 v1

모든 내부 메시지는 schema_version=1, 출처, 생성 시각, 세션을 가진다.
길이는 m, 각도는 rad, 경과 시간은 s를 사용한다.
서로 다른 장치의 monotonic 시간을 직접 비교하지 않는다.
아래 생성/만료 단조 시각은 동일 Jetson 부팅 세션의 공통 시계 기준이다.

| 메시지 | 필수 내용 | 적용 규칙 |
|---|---|---|
| MissionSnapshot | 실행 문맥, 임무/지도/변환/승인 개정, 유형별 작업 순서·이동 기체 XYZ·선택 yaw·hover_s, 이륙 높이 | 수락 후 불변, 불량 작업 하나라도 전체 거부. scan 라벨 XYZ는 QR_SCAN_SPEC의 별도 확장, 현재 미지원 |
| CommandEnvelope | ID·action·대상·세션·순서·생성/만료 UTC·원문 식별값 | 새 수락만 10초, 기존 결과 조회는 만료 후에도 가능 |
| StateSnapshot | 값·원천 시각·수신 단조 시각·출처·quality·frame_epoch | quality는 VALID/INVALID/UNKNOWN, UNKNOWN을 정상으로 처리하지 않음 |
| PathPlan | plan_id·generation·transform_revision·단계별 구간·검사 근거·유효 범위 | 오래된 계획 결과·다른 세대의 계획은 폐기 |
| ScanPlan (설계) | 라벨 pose·기체 대기점/판독 pose·작업 공간·장착 개정·진입/이탈 구간 | 좌표 유형 분리, 작업 결과 저장과 대기점 복귀 완료를 별도 추적. 현재 C++ 구현 없음 |
| ControlIntent | execution/action/generation·boot_session·sequence·kind·lease·frame_epoch·목표·제한 프로파일 | 동일 대상·현재 세대·증가 순서·미만료·유효 상태일 때만 적용 |
| ControlFeedback | 마지막 적용 sequence·실제 PX4 상태·요청 진행·원인 | 수신 확인과 실제 동작 완료를 별도 표시 |
| LoggingHealth | 필수 기록 스트림 상태·공간·실패 원인·최종 성공 시각 | 필수 기록 실패는 복귀 사건, ULog 수집 실패는 별도 경고 |

ControlIntent.kind는 PRESTREAM_HOLD / POSITION / HOLD / REQUEST_OFFBOARD /
REQUEST_ARM / REQUEST_LAND / ABORT_GROUND / RELEASE로 한정한다.
kind별 필요한 필드를 명시적으로 검증한다. POSITION/HOLD에는 XYZ와 확정된 yaw가 모두 필요하다.
REQUEST_ARM은 지상 준비에서만, ABORT_GROUND의 disarm은 실제 지상 확인 후에만 허용한다.
REQUEST_OFFBOARD/REQUEST_ARM에는 같은 frame_epoch의 검증된 현재 위치 유지 목표를 함께 둔다.
전환 대기 동안 이 유지 목표만 송신하며, 그 의도 자체의 lease가 끝나면 전환도 중단한다.
REQUEST_LAND의 대기 중 정지 목표도 유효 위치·제어권을 확인한 경우에만 사용한다.
제어 요청의 service 응답과 물리 상태 확인에는 같은 action/generation을 연결한다.

의도 채널은 reliable·volatile·depth 1을 기준으로 한다.
오래된 POSITION/HOLD는 새 의도로 대체할 수 있다.
REQUEST_ARM/LAND 같은 전환 의도는 feedback으로 인지될 때까지 같은 ID로 유지·재전송한다.
이미 처리한 요청을 재실행하지 않으며 새 안전 사건은 즉시 이전 요청을 선점한다.
QoS는 정상 전달 편의이며 신선도·중복·물리 완료 검사를 대신하지 않는다.
ROS 토픽명·메시지 타입은 interface_types에서 한 번 정의하고 임의 문자열 복제를 피한다.

## 4. flight_guard의 독립 계약

flight_guard는 BT 결과와 별도로 PX4 제어권·연결·자세/위치 품질·현재 프레임을 읽는다.
다음 검사 순서를 고정한다.

1. RC/PX4 자체 제어가 우선인지 확인하고 해당하면 자율 권한을 반환한다.
2. 지상/공중·Land 진행 상태를 확인한다.
3. 현재 세대·부팅 세션·계획 개정·목표 나이·lease를 확인한다.
4. 목표 숫자·좌표·속도/여유 제한과 필요한 상태 품질을 확인한다.
5. 검사를 통과한 의도만 단일 출력 경로로 보낸다.

오래된 의도는 그때의 XYZ를 계속 따라가지 않는다.
공중에서 유지가 가능하면 현재 유효 상태로 정지 목표를 한 번 고정하고 Land를 요청한다.
유지가 불가능하면 위치 목표를 임의로 만들어 지연시키지 않고 PX4 실패 처리로 넘긴다.
Land 요청과 모드 확인에는 총 시간 예산을 둔다. 무한 재시도하지 않는다.
flight_guard가 살아 있는 동안에도 정상 목표가 없으면 자율비행을 유지하지 않는다.
프로세스 자체 정지는 PX4의 독립 Offboard 상실 처리로 검증한다.

## 5. 실행 프로파일

| 프로파일 | 허용 연결 | 설정 출처 | 실행 조건 |
|---|---|---|---|
| REPLAY | 기록/합성 입력, 가짜 출력 | 시험 사례에 명시한 값 | 실기체 출력 연결 없음 |
| SITL | 명시적으로 선택한 시뮬레이터 | 아래 SIM-01 | 실제 장치 주소·포트 사용 금지 |
| FLIGHT | 확인된 실기체 | 실측·승인된 기체/펌웨어 프로파일 | 필수 값·품질 경로·시험 승인 전부 필요 |

프로파일 구분과 대상 기체 식별을 동시에 검사한다.
SITL 값을 FLIGHT에 자동 상속하지 않는다. FLIGHT에 값이 없으면 시작을 거부한다.
모드 문자열 하나만 바꾸어 모의 시험값으로 실제 기체를 시동할 수 없게 한다.

### SIM-01: 로직 검수용 고정값

아래 값은 시험 재현을 위한 공학적 설정이며 실측 추정값이 아니다.
이 값으로 실제 UWB·실기체 성능을 주장하지 않는다.

| 항목 | SIM-01 값 |
|---|---|
| BT·목표 송신 | 각각 20Hz |
| 목표 lease | 0.5초, 정상 갱신과 별도 만료 검사 |
| 선행 송신 | 1.5초, 연속 구간에서 송신 공백 0.1초 이하 |
| 모드/arm 확인 | 각각 3초, 같은 전환 최대 2회 시도, 총 6초 이내 |
| 계획/준비 | 1초 / 5초 |
| 도착 | XY 0.2m, Z 0.15m, yaw 10°, 수평/수직 속도 각각 0.1m/s 이하, 연속 1초 |
| 위치 복구 안정 | 연속 1초. 8초 복구 예산 안에 재검증까지 완료 |
| 모의 새 위치 관측 나이 | 0.25초. 실제 UWB 기준은 사양·실측 뒤 별도 결정 |
| 모의 PX4 자세/위치·모드·품질 나이 | 0.25초 / 1초 / 1초 |
| 모의 배터리 상태 나이 | 3초 |
| 모의 필수 기록 생존/최종 쓰기 확인 | 2초, 명시적인 쓰기 오류는 즉시 실패 |
| 진행 정체 | 활성 동작 5초 동안 오차 개선이 XY/Z 0.05m 또는 yaw 2° 미만 |
| 구간/수직/yaw 완료 | 해당 제한 속도로 계산한 예정 시간의 3배 + 5초 |
| 이륙 한도 | 20초 |
| 착륙 확인 경고 | 30초. 공중 disarm·완료 처리 없음 |
| 웹 시계 오차/단절 | 0.25초 / 2초, 최초 조회 실패 시 세션 재확인 절차 시작 |
| 모의 탐색 한도 | 격자 0.1m, 최대 20,000노드·총 경로 100m·T_plan=1초 |

단위가 다른 오차를 섞어 진행을 판정하지 않는다.
XY 추종은 경로상의 남은 거리, 수직 동작은 z 오차, 회전은 wrap된 yaw 오차를 쓴다.
도착 범위 안에서 안정 판정 중이면 정체 타이머 대신 안정·전체 완료 한도를 적용한다.
pause로 안전 시간 예산을 늘리지 않는다. 자세한 타이머 규칙은 BT_SPEC을 따른다.

## 6. 구현 순서와 완료 증거

| 순서 | 구현 단위 | 다음 단계로 넘어갈 증거 |
|---|---|---|
| 1 | 공통 타입·설정 검증·가짜 시계/출력 | 누락·오래된 세대·프로파일 혼용 거부 |
| 2 | BT와 명령 처리 | 정상/복구/실패/취소/RC 잠금 재생 시험 |
| 3 | 경로·충돌 검사 | 필수 점·수직 공간·회전·역추적 사례 |
| 4 | flight_guard와 MAVROS SITL 연결 | 제어권·mask·좌표·모드/arm 지연·송신 중단 시험 |
| 5 | 웹/로그 어댑터 | 합의된 API fixture·중복·단절·기록 실패·ULog 수집 시험 |
| 6 | UWB·실장 품질 경로 | 전체 사양 및 실제 위치·시간·불확실성·PX4 수용 증거 |
| 7 | FLIGHT 프로파일 승인 | 실측값·제한 비행·독립 failsafe 시험 결과 |

새 구조는 같은 정책 테스트를 통과해야 한다.
라이브러리 내부의 상태나 예외가 사용자 행동 정책을 바꾸도록 두지 않는다.

## 7. 경로계획·목표 생성의 첫 구현

입력 지도는 다각형 외곽과 높이 구간으로 정규화한다.
형상 검사→기체 외형/오차/제동 여유 확장→구간 검사→경로 탐색 순서를 고정한다.
지도 해상도·최대 탐색 노드·최대 거리·계산 시간은 프로파일 값이다.
탐색 실패나 시간 초과를 ‘장애물 없음’으로 바꾸지 않는다.

| 조건 | 첫 구현 방식 |
|---|---|
| 비행 경계 미제공 | 웹 승인 기체 이동 구간·기록 복귀 경로 사용. scan은 웹 제공 라벨별 허용 구역·진입/이탈 검증 필요(QS-W8). 일반 자동 우회 보류 |
| 같은 z, 자동 우회 허용 | 높이별 점유 격자에서 A* 탐색, 결정적인 동률 처리 |
| 목표 z 변경 | 현재 z/목표 z의 두 수평층과 검증된 수직 구간을 연결한 단계 그래프 |
| 경계 없이 z 변경 | 승인된 구간에서 안전 지점 후보를 찾고 전체 수직 공간 검사. 옆으로 임의 이탈 금지 |
| 수직 구간 | 현재 z→목표 z의 전체 점유 공간·고도 제한·상하 여유 검사 |
| 복귀 | 경계 없으면 기록한 승인 구간 역추적, 현재 장애물과 높이 제한 재검사 |
| 경로 단순화 | 필수 경유점 보존, 새 연결 선분의 전체 충돌 검사 통과 시에만 적용 |

목표 z가 다르면 현재 높이에서 안전 지점까지 이동→정지→수직 이동→정지→목표 XY 이동으로 구성한다.
한 계획에서 장애물 회피를 위해 임의의 제3 고도로 바꾸거나 상하 반복하지 않는다.
격자 점만 검사하지 않고 모서리를 가로지르는 연결 구간과 기체가 차지하는 공간도 검사한다.
해상도보다 얇은 장애물이 사라지지 않도록 교차 셀을 점유 처리한다.
원래 기체 이동점은 격자 근처의 다른 좌표로 옮기지 않고 최종 연결 구간을 별도 검사한다.
scan은 라벨 위치·작업 순서를 보존하고 별도의 기체 pose와 진입/이탈 공간을 생성·검증한다.
스캔 후에는 실제 접근·보정 구간을 재검사해 대기점 복귀 후 다음 목표로 진행한다.
해당 탐색이 길을 못 찾았다는 결과는 탐색 범위 내 실패이며 물리적으로 길이 없다는 증명은 아니다.
BT는 같은 필수 목표를 유지하고 차단/실패 정책으로 넘어간다.

위치 목표 생성은 가속·감속·yaw rate 한도가 있는 시간 진행형으로 구현한다.
PX4 상한과 검증된 경로 여유에서 계산한 한도 중 더 작은 값을 쓴다.
먼 목표를 한 번 던진 뒤 도착만 기다리는 방식으로 제동 성능을 가정하지 않는다.
목표 생성기는 PX4의 위치/자세 PID를 재구현하지 않는다.
SIM-01은 알고리즘 시험 사례에 해상도·형상·속도 한도를 명시한다.
FLIGHT에서는 기체 외형·위치 오차·제동거리 실측이 없는 경로를 승인하지 않는다.

## 8. 데이터 수명과 장애 격리

필수 기록 목록에는 행동/명령/제어권 사건, PX4 제어 상태, 활성 센서의 원시/품질 기록을 둔다.
센서 자체가 끊겼다는 상태 기록과 기록기가 그 상태도 저장하지 못하는 실패를 구분한다.
LiDAR 단절을 정상적으로 기록 중이면 ‘기록 실패’로 재분류해 복귀시키지 않는다.
기록기의 건강 신호는 프로세스 생존뿐 아니라 실제 필수 데이터 쓰기 진전·쓰기 오류·큐 포화를 포함한다.
신호가 없거나 필수 스트림 저장이 실패하면 C++ 임무 관리기가 복귀를 잠근다.
기록/웹 결과 큐에는 크기 상한을 두며 무한 메모리 증가를 허용하지 않는다.
복귀 사건을 디스크에 못 남겨도 실행과 가능한 실시간 보고를 계속한다.

명령 수락·중복 방지 원장은 C++ 임무 관리기가 소유한다.
Python 웹 어댑터가 재시작해도 이전 START를 새로 수락하지 않는다.
원장 기록이 불가능한 새 START/RESUME은 거부한다.
이미 공중에서 필요한 Land·제어권 반환은 저장 성공을 기다리지 않는다.
재시작 뒤에는 이전 비행 자동 재개 금지 규칙으로 처리한다.
72시간 비행 파일 삭제는 명령 원장·미전송 중요 결과의 보존 정책과 분리한다.
