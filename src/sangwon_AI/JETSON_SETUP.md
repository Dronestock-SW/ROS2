이 문서는 현재 환경 점검 결과와 이후 설정 순서를 정리한다.

상태: C++ REPLAY·호스트 점검 서비스 적용, 실장 검증 전 / 2026-10-02.
추가: 작업 폴더에서 C++ REPLAY 빌드를 검증했다.
절차는 [BUILD_REPLAY.md](BUILD_REPLAY.md)를 따른다.
대상: SSH `100.110.163.94`, 계정 `arialhanho`.
저장소: `/home/arialhanho/Desktop/ROS2`, 조회한 HEAD `0257c32`.
최신 적용 결과는 [JETSON_DEPLOYMENT.md](JETSON_DEPLOYMENT.md)를 따른다.

### J02. 실행 환경

다음은 준비 단계에서 사용할 Bash 예시다.
호스트 서비스에는 ROS_DOMAIN_ID=1을 명시했다.
실제 ROS 비행 노드는 별도 기동 검증이 필요하다.

```bash
cd /home/arialhanho/Desktop/ROS2
source /opt/ros/humble/setup.bash
export ROS_DOMAIN_ID=1
command -v ros2
ros2 pkg prefix mavros
```

자체 패키지는 빌드 성공 후 해당 워크스페이스의 install/setup.bash를 적용한다.
향후 서비스에는 같은 환경을 명시한다. .bashrc가 자동 적용된다고 가정하지 않는다.
ROS 환경 적용 방법은 [ROS Humble 공식 설치 문서 원본](https://raw.githubusercontent.com/ros2/ros2_documentation/humble/source/Installation/Ubuntu-Install-Debs.rst)을 참고한다.

### J03. 의존성과 빌드

CMake 프로젝트를 colcon으로 빌드·설치했다.
현재 ROS IDL·운영용 ROS 노드·장치 연결은 미구현이다.
고정 의존성과 재현 절차는 [BUILD_REPLAY.md](BUILD_REPLAY.md)를 따른다.
ROS의 시스템 Python 환경과 외부 Python 패키지의 호환을 확인한다.
전역 pip로 apt의 ROS 의존성을 덮어쓰는 설치는 피한다.
py_trees는 사용하지 않는다. C++ BehaviorTree.CPP 4 계열을 사용한다.
ROS Humble용 behaviortree_cpp 패키지의 설치 후보·C++17 빌드·정확한 버전을 확인한다.
pyulog는 로그 분석·검증 모듈에서 필요 여부와 버전을 정한다.
serial 모듈은 UWB 전체 사양에서 직렬 연결이 확정된 경우 검토한다.
현재 행동 선택 설계에는 신경망 학습용 CUDA 환경을 추가할 근거가 없다.

rosdep은 초기화 파일·사용자 캐시를 확인한 뒤 필요한 초기화만 수행한다.
기존 drone_bringup/package.xml에는 python3-pyzbar·python3-evdev 키 예외가 적혀 있다.
전체 src 의존성 처리가 필요하면 두 실제 패키지 설치를 확인하고 예외를 적용한다.
예외로 건너뛴 것을 설치 완료로 표시하지 않는다.
새 패키지부터 범위를 제한해 빌드하고 기존 작업과의 충돌을 확인한다.

MAVROS의 지오이드 데이터 요구는 [공식 설치 문서](https://github.com/mavlink/mavros/blob/ros2/docs/installation.md)를 따른다.
현재 데이터 파일은 존재하므로 재설치보다 실제 노드 기동 확인이 먼저다.

### J04~J05. 장치와 PX4

장치가 연결되면 모델·USB 경로·권한·사용 프로세스를 먼저 조회한다.
기존 규칙은 UWB와 LiDAR의 동일 CP2102 serial=0001을 USB 포트 위치로 구분한다.
새 장비에서도 같다고 가정하지 않고 전체 사양 및 실물과 대조한다.
규칙을 그대로 복사하거나 두 장치를 같은 포트 별칭으로 열지 않는다.
현재 계정에는 dialout이 없다. 관리자 설정 절차는 배포 문서 4절에 둔다.
설정 뒤 새 로그인 세션에서 권한을 다시 확인한다.
상시 sudo 실행이나 모두 쓰기 가능 권한으로 우회하지 않는다.

PX4 USB/UART/UDP 선택, FCU URL·baud·MAVLink 대상 ID를 확인한다.
UWB는 전체 사양 수령 전 연결 방식을 정하지 않는다.
각 물리 포트의 직접 소유자를 하나로 두고 필요한 데이터는 노드를 통해 공유한다.
진행 중인 수집기와 별도 시리얼 판독기를 동시에 실행하지 않는다.
MAVROS 상태 수신을 확인한 뒤 별도 검증 단계에서만 제어 출력을 연결한다.

### J06. 웹 연결

[WEB_REQUIREMENTS.md](WEB_REQUIREMENTS.md)의 D07 시험 환경을 받는다.
DNS/IP·인증 방법·테스트 기체 ID·지원 계약 버전을 확인한다.
키 원문은 문서·로그·저장소에 넣지 않고 런타임 설정으로 공급한다.
기존 HTTP 조회·WS 상태·결과 보고를 합성 임무로 확인한다.
Wi-Fi 단절·재연결 때 저장 임무와 미전달 명령 정책을 함께 검사한다.

### J07. 시각·기록·용량

PX4·Jetson·UWB는 서로 다른 시계를 쓸 수 있다.
NTP 동기화만으로 측정 시각 정렬이 끝났다고 보지 않는다.
기록에는 원천 시각·Jetson 수신 시각·비행 ID·적용 변환본을 연결한다.
관측 나이·watchdog 같은 진행 시간은 역행하지 않는 시간 기준으로 설계한다.
로그 72시간 보존 판정에는 신뢰 가능한 비행 종료 UTC를 사용한다.
시계가 불명확하면 자동 삭제를 보류한다.

런타임 저장 경로는 구현 전에 정한다. 소스 디렉터리에 대용량 기록을 쌓지 않는다.
비행 기록·ULog 수집 중 파일·검증 완료 파일·요청 처리 이력을 구분한다.
검증된 Jetson 사본만 비행 종료 72시간 후 정리한다.
미검증 파일과 Pixhawk SD 원본은 자동 삭제 대상에서 제외한다.
명령 중복 방지 이력은 비행 로그 정리로 지우지 않는다.

용량 기준은 ‘최장 임무 기록량 + 수집 중 ULog + 보존 파일 + 여유 공간’으로 산정한다.
실제 기록률·최장 임무 시간이 없으므로 12G가 충분하다고 승인할 수 없다.
공간이 모자라면 새 임무를 거부한다. ULog 수집 실패만 있으면 경고 후 시작을 허용한다.
비행 중 필수 행동·센서 기록 실패는 복귀 후 착륙이며, 복귀 불가 시 현 위치 착륙이다.
이미 복귀 중이면 계속 복귀하며 기록 복구만으로 임무를 재개하지 않는다.

### J08~J09. 실행과 자동 기동

UWB 모의 입력과 웹 샘플을 쓰는 시험은 실기체 비행 출력에서 격리한다.
BT·통신·기록·출력·감시의 중단과 과부하를 각각 주입해 본다.
목표값이 같아도 정상 호버 생존 신호는 갱신될 수 있어야 한다.
PX4의 Offboard 상실 대응과 Jetson의 목표 신선도 감시는 별도 경로로 검증한다.
구현 언어만으로 두 경로의 독립성이 보장된다고 가정하지 않는다.

호스트 점검 서비스는 기동·장애 재시작을 검증했다.
전체 연결·점검 순서는 [BOOT_PREFLIGHT_SPEC.md](BOOT_PREFLIGHT_SPEC.md)를 따른다.
프로세스 자동 재시작이 임무 자동 재개를 의미해서는 안 된다.
재부팅 뒤 지상/공중·PX4 제어권을 재확인하고 기존 목표를 재송신하지 않는다.
자동 기동 검증은 SITL과 지상에서 먼저 한다.

## 3. 준비 완료 기록

J01~J09마다 설정 개정·확인 명령·결과·미해결 문제를 남긴다.
설치/설정 변경 시 적용 전 사본과 되돌리는 절차를 함께 기록한다.
UWB 전체 사양, 웹 샘플, PX4 연결 정보가 없으면 해당 항목은 대기로 둔다.
환경 준비 완료와 실비행 승인은 서로 다른 단계다.
실비행 조건은 [VALIDATION_PLAN.md](VALIDATION_PLAN.md)를 따른다.

## 4. 확정된 구조에 따른 추가 준비

C++ mission_runtime·route_planner·flight_guard, Python web_adapter·log_manager를 별도 실행 단위로 준비한다.
flight_guard의 PX4 상태 수신은 Python 웹/로그 프로세스에 의존하지 않는다.
출력은 MAVROS만 사용하고 추가 품질 정보는 uXRCE-DDS 수신 경로로 준비한다.
실제 PX4 펌웨어와 px4_msgs 형식·토픽 버전·Agent 호환을 함께 고정한다.
현재 SSH 조회로 DDS Agent 설치·실제 연결까지 확인한 것은 아니다.
실제 통신 채널을 확인한 뒤 MAVLink와 같은 시리얼 포트를 두 프로세스가 직접 열지 않게 설정한다.
PX4 v1.17 문서는 v2.x Client와 v3.x Agent의 비호환을 명시한다.
Humble 워크스페이스 빌드 표의 Agent v2.4.2를 검토 기준으로 삼고 실제 펌웨어에 맞춰 검증한다.
[PX4 uXRCE-DDS 공식 문서](https://docs.px4.io/v1.17/en/middleware/uxrce_dds).
호스트 서비스만 적용했으며 비행 포트·펌웨어·PX4/RC 파라미터는 미변경이다.
