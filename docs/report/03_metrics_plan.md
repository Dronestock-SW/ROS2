# SW 성능 지표 측정 계획 (중간보고서용)

> 이 문서는 SW가 산출하는 성능 지표 6종의 측정 가능 여부와 측정 절차다.
> 보고서의 "성능 지표" 항목 작성 전에 읽는다. **실측값은 이 문서에 없다** — 측정 후 별도 기재한다.
> 기준 시점: 2026-08-16 / 기준 커밋 `7438c17`

---

## 결론 3줄

```text
1. 지금 측정 가능한 지표 = 2개(갱신 주기, 노드 처리 지연). 그것도 /scan·/camera/image_raw 두 경로만.
2. 나머지 4개(측위 RMSE, QR 인식률, 1랙 스캔 시간, 재고 집계 정확도)는 측정 대상 코드 자체가 없다.
3. 측정 도구는 만들어 뒀다 → docs/report/scripts/. 하드웨어 연결 즉시 실행 가능.
```

**산출 금지 원칙**: 이 문서와 보고서 어디에도 추정값·문헌값·목표치를 실측치로 적지 않는다.
측정 전 항목은 `[미측정]`으로 남긴다.

## 1. 측위 RMSE

### 1.1 현재 산출 가능한가 — 불가

| 필요 요소 | 상태 | 근거 |
|---|---|---|
| 추정 위치 스트림 | 없음 (`/uwb_pose` 미발행) | [evidence/06_uwb_fail.txt](evidence/06_uwb_fail.txt) |
| 기준 위치(ground truth) | 수단 미정 | 저장소에 측량·기준점 기록 없음 |
| UWB 태그 | 미연결 | `ls /dev/uwb` 실패 |

> **HW 파트 실측치와 혼동 금지**
> [hw_handoff/uwb_serial_log_operator_guide.md](../hw_handoff/uwb_serial_log_operator_guide.md)에
> 2026-08-09 오차 약 0.66m가 기록되어 있으나, 이는 **HW 파트가 태그 시리얼 로그로 잰 값**이다.
> SW가 산출한 지표가 아니고 ROS2 경로를 거치지도 않았다. 보고서 SW 절에 SW 성과로 적지 않는다.
> 인용 시 "HW팀 작성분"으로 출처를 명시한다.

### 1.2 필요한 것

| 구분 | 항목 | 비고 |
|---|---|---|
| 코드 | `drone_uwb` 패키지 + `uwb_node` | 설계 완료: [uwb_node_design.md](../uwb_node_design.md) |
| 기록 | `ros2 bag record /uwb_pose` | rosbag2 0.15.16 설치 확인 |
| 기준값 | 정지 기준점 좌표 (측량) | 아래 1.3 참조 |
| 후처리 | RMSE 계산 스크립트 | [scripts/](scripts/)에 골격 포함 (입력 토픽만 추가) |

기준 위치 확보 방안 3가지 — 어느 것을 쓸지 **미결정**:

| 방안 | 장점 | 단점 |
|---|---|---|
| 바닥 마킹 정지점 N개 (줄자 실측) | 장비 불요, 즉시 가능 | 정지 상태만 측정. 이동 중 RMSE 불가 |
| LiDAR 스캔매칭 결과를 기준으로 사용 | 이동 중 측정 가능 | Phase 2 필요. 스캔매칭 자체 오차가 섞임 |
| 외부 측위 장비 도입 | 정확 | 보유 여부 **[확인필요]** |

### 1.3 측정 조건 정의 초안

앵커 배치는 저장소에 확정 기록이 있다 ([uwb_node_design.md:248-255](../uwb_node_design.md#L248-L255)).

```text
A3(0, 4.5) ●───────────● A4(5, 4.5)
           │           │
         y ↑           │      x축 = A1 → A2
           │           │      y축 = A1 → A3
A1(0, 0)   ●───────────● A2(5, 0)
              x →
```

| 조건 | 값 | 근거 / 비고 |
|---|---|---|
| 앵커 수 / 배치 | 4기, 5.0 m × 4.5 m 직사각형 모서리 | uwb_node_design.md:248-255 |
| 앵커 설치 높이 | **[확인필요]** | 저장소에 기록 없음. HW팀 확인 필요 |
| 측정점 | 직사각형 내부 정지점 9개 (3×3 격자, 1.25 m / 1.125 m 간격) | 초안. 모서리·중앙·변 중앙 포함 |
| 점당 수집 시간 | 60초 | 43Hz × 60s ≈ 2,580샘플 |
| 태그 높이 | 기체 장착 높이와 동일하게 고정 | 값 **[확인필요]** |
| 판정 대상 | `fix=true` 프레임만 | uwb_node가 `fix=false`는 미발행 (설계 §4) |
| 산출식 | `RMSE = sqrt(mean((x-x_ref)² + (y-y_ref)²))` | 점별 + 전체 |
| 부가 기록 | 앵커 배제 마스크 분포 | 3기 해법은 **설계된 동작**이라 이상으로 보지 않음 (udev 규칙 57-61행) |

> **주의**: 현 UWB 오차의 정체는 흔들림이 아니라 **일정하게 밀린 bias**라고 HW 파트가 판단했다
> ([uwb_node_design.md:189](../uwb_node_design.md#L189)). RMSE 하나만 적으면 bias와 산포가 구분되지 않는다.
> **평균 오차 벡터(bias)와 표준편차를 함께 보고한다.**

## 2. 위치 추정 갱신 주기

### 2.1 현재 산출 가능한가 — 부분 가능

| 토픽 | 산출 가능 | 산출 방법 | 근거 |
|---|:---:|---|---|
| `/uwb_pose` | ✗ | 발행자 없음 | [evidence/06_uwb_fail.txt](evidence/06_uwb_fail.txt) |
| `/scan` | **✓** | `ros2 topic hz /scan` 또는 bag 후처리 | [evidence/04_lidar_launch.txt](evidence/04_lidar_launch.txt) |
| `/camera/image_raw` | **✓** | 동일 | [evidence/05_camera_launch.txt](evidence/05_camera_launch.txt) |
| `/mavros/local_position/odom` | ✗ | MAVROS 미기동 | [evidence/07_mavros_fail.txt](evidence/07_mavros_fail.txt) |

UWB 갱신율의 **센서 단 값**은 HW 파트 실측이 있다 — 중앙값 23ms ≈ 43Hz, 최대 55ms
(2026-07-30, 230샘플, [udev 규칙 46-48행](../../config/udev/99-dronestock.rules#L46-L48)).
이는 시리얼 라인 기준이며 **ROS2 토픽 발행 주기가 아니다.** 두 값은 별도로 보고한다.

### 2.2 필요한 것

`/uwb_pose` 측정 → `uwb_node` 구현이 유일한 선행 조건. 기록·후처리 도구는 준비 완료.

### 2.3 측정 조건 정의 초안

| 조건 | 값 |
|---|---|
| 측정 길이 | 120초 (짧으면 드문 지연 스파이크를 놓침) |
| 동시 기동 노드 | (a) 단독, (b) LiDAR+카메라+UWB 전체 동시 — **2회 측정** |
| 산출값 | 평균 Hz, 중앙값 간격, p95 / p99 간격, 최대 간격, 결손(설정 주기의 2배 초과) 횟수 |
| 기록 방식 | `ros2 bag record` 후 후처리 (`ros2 topic hz`는 구독자 부하가 값에 섞임) |
| 판정 기준 | UWB: EKF2 권장 30~50Hz 충족 여부 ([roadmap.md:97](../roadmap.md#L97)) |

> **평균 Hz만 적지 않는다.** 2026-08-16 카메라 측정에서 평균은 21.6Hz였으나 최대 간격이
> 0.302초(정상 0.033초의 9배)였다. 평균만 보면 이 스파이크가 보이지 않는다.

## 3. QR 인식률 / 인식 거리·각도

### 3.1 현재 산출 가능한가 — 불가

| 필요 요소 | 상태 | 근거 |
|---|---|---|
| QR 인식 노드 | 없음 | [evidence/08_qr_marker_fail.txt](evidence/08_qr_marker_fail.txt) |
| 카메라 내부 파라미터 | 빈 값 (`k: [0.0 ×9]`) | [evidence/05_camera_launch.txt](evidence/05_camera_launch.txt) |
| 렌즈 초점 | 미조정 (HW팀 작성분) | [companion_setup.md:83](../companion_setup.md#L83) |
| 마커 실물 | **[확인필요]** | 저장소에 인쇄 규격·크기 기록 없음 |

**거리·각도 산출은 캘리브레이션 없이는 불가능하다.** solvePnP에 넣을 `camera_matrix`가 없다.
인식률(검출/시도)만이라면 캘리브레이션 없이도 산출 가능하나, 거리·각도 라벨을 붙일 수 없어
"어느 거리에서 몇 %"라는 형태의 지표가 성립하지 않는다.

### 3.2 필요한 것 (순서 고정)

```text
① 렌즈 초점 조정          ← HW팀 작성분. 이걸 먼저 안 하면 ②가 무효
② 카메라 캘리브레이션      ← ros2 run camera_calibration cameracalibrator
③ camera_info_url 활성화   ← camera_imx219.yaml:59 주석 해제
④ QR 인식 노드 작성        ← cv2.QRCodeDetector (OpenCV 4.5.4 확인됨)
⑤ 마커 인쇄 + 크기 실측
⑥ 거리·각도별 반복 촬영 → 인식률 집계
```

②의 전제: 체커보드 패턴 보유 여부 **[확인필요]**

### 3.3 측정 조건 정의 초안

| 조건 | 값 | 비고 |
|---|---|---|
| 해상도 | 1640×1232 @30fps 고정 | [camera_imx219.yaml:11-24](../../src/drone_bringup/params/camera_imx219.yaml#L11-L24) — 이 모드만 전체 화각 유지 |
| 인코딩 | `rgb8` 수신 → `cv_bridge`로 `bgr8` 변환 | camera_imx219.yaml:34-37 |
| 거리 구간 | 0.5 / 1.0 / 1.5 / 2.0 / 2.5 / 3.0 m | 초안. 랙 접근 거리 확정 후 조정 |
| 각도 구간 | 0° / 15° / 30° / 45° (광축 대비 마커 법선) | 초안 |
| 조도 구간 | 주간 실내 / **야간 무조명** / 야간 + 기체 조명 | **야간 조건 필수** — 임무 시나리오가 야간 재고 파악 ([roadmap.md:131](../roadmap.md#L131)) |
| 조도 실측 | lux 계측기로 각 조건 기록 | 계측기 보유 **[확인필요]** |
| QR 규격 | 버전·크기·오류정정 레벨 **[확인필요]** | 인쇄 전 확정 필요 |
| 시도 횟수 | 조건당 100프레임 | 인식률 = 검출 성공 / 100 |
| 산출값 | 조건별 인식률(%), 검출 한계 거리, 검출 한계 각도, 프레임당 검출 소요 시간 |

> 참고 수치 — `camera_imx219.yaml:14`에 "캡처+ArUco 검출 실측 33.4ms/프레임(120프레임 측정, 2026-08-12)"이
> 기록되어 있다. 다만 그 측정 스크립트가 저장소에 없어 **재현 불가**하며, ArUco 기준이라 QR과 다르다.
> 보고서에 쓰려면 재측정한다.

## 4. 1랙 스캔 소요시간

| 항목 | Phase | 상태 |

| 이륙 시퀀스 자동화 | 1 | 미착수 |

| 마커 정렬 (비주얼 서보잉) | 3 | 미착수 |
| QR 판독 | 3 | 미착수 |

### 4.2 필요한 것

Phase 1~3 완료. 그 전에는 **측정 계획만 세우고 값은 비워 둔다.**

측정 가능 시점에 필요한 기록 수단:

| 항목 | 방법 |
|---|---|
| 구간 시각 기록 | FSM 상태 전이 시각을 `/system_log`에 남기고 bag 기록 |

→ **FSM 설계 시 상태 전이 로그를 처음부터 넣는다.** 나중에 붙이면 재측정이 필요하다.

## 6. 노드 처리 지연

### 6.1 현재 산출 가능한가 — 부분 가능

**자체 노드가 0개이므로 "우리 노드의 처리 지연"은 정의상 존재하지 않는다.**
현재 측정 가능한 것은 드라이버 노드의 발행 특성뿐이다.

| 측정 항목 | 산출 가능 | 방법 | 주의 |
|---|:---:|---|---|
| `/scan` 발행 간격 및 지터 | **✓** | bag의 수신 시각 차 | — |
| `/camera/image_raw` 발행 간격 및 지터 | **✓** | 동일 | — |
| `header.stamp` → bag 기록 시각 차 | **✓** | bag 후처리 | 아래 해석 주의 참조 |
| 센서 노출 → 토픽 발행 지연 | ✗ | 측정 수단 없음 | `use_gst_timestamps: false`라 GStreamer 시각이 헤더에 없음 |
| 노드 간 end-to-end 지연 | ✗ | 소비 노드가 없음 | 자체 노드 작성 후 |

> **`header.stamp` 해석 주의**
> `camera_imx219.yaml:51`에 `use_gst_timestamps: false`가 설정되어 있다. 즉 `header.stamp`는
> 카메라 노출 시각이 아니라 **gscam이 프레임을 받은 시각**이다.
> 따라서 이 값으로 잴 수 있는 것은 "발행 → 기록" 경로 지연뿐이며, **센서 지연은 포함되지 않는다.**
> 보고서에 "지연 Xms"로만 쓰면 과소 보고가 된다. 측정 구간을 반드시 병기한다.
