# B_TF ClockMap 보존·RAW 복사 시험본
시험 사본의 변경과 검증 결과를 기록한다.
운영본과 비교하거나 후속 검증을 재개할 때 읽는다.

## 범위

코드 수정·단위 검사·커밋·푸시만 진행한다.
재생과 실기 배포는 사용자 요청으로 보류한다.
기준 커밋은 통합 브랜치의 `0110da8`이다.
시험 브랜치는 `codex/btf-clockmap-snapshot-20261014`다.
이 작업에서 운영 서비스·FC 설정을 바꾸지 않았다.

## 1. ClockMap 보존

입력 만료와 실제 시계 불연속을 구분한다.

```text
입력 150ms 초과 → 해당 입력·pending·기하 모델 폐기
                       ├─ 마지막 적격 맵 동결 → 새 3쌍 확인 → 재적합
                       └─ 첫 새 쌍부터 새 맵 학습 → 기존 30표본 검사
                                     ↓ 먼저 적격한 맵
                          기존 시각·기하·발행 검사
```

| 항목 | 기존 | 시험본 |
|---|---|---|
| 단순 입력 만료 | ClockMap도 초기화 | 적격 TDMA 맵을 조건부 보존 |
| 재개 | 새 30표본부터 시계 적격 가능 | 3쌍 재검증 또는 새 맵 적격 |
| 반복 만료 | 학습도 반복 초기화 | 새 맵 학습 유지. 확인 연속성만 해제 |
| 실제 불연속 | 전체 초기화 | 전체 초기화. 작은 ROS 역행도 검출 |
| 실제 발행 시각 | 별도 저장 없음 | 실제 pose 발행 뒤 저장. 초기화에도 보존 |

| 보존·재검증 조건 | 시험값·의미 |
|---|---|
| 대상 | 유효한 완전 TDMA 쌍. 같은 boot/session |
| 최대 보존 | 마지막 적격 쌍부터 2초 |
| 시간 기준 | 원래 수신 monotonic과 현재 로컬 monotonic 모두 |
| 확인 개수 | 새 완전 쌍 3개 |
| 확인 구간 | 첫 쌍~셋째 쌍 100ms 이하. 두 시간축 모두 |
| 개별 예측 잔차 | −2ms 이상, +50ms 이하 |
| 잔차 중앙값 | 20ms 이하 |
| ROS−monotonic 변화 | 마지막 적격 기준에서 절댓값 5ms 이하 |
| 순서 | ESP·수신 시각 전진. seq wrap 허용. 순방향 건너뜀 허용 |
| 재적합 | 기존 alpha·p95·queue age 검사 유지 |

잔차는 전송 대기까지 포함한다.
센서의 절대 시각 오차를 측정한 값이 아니다.
보존 기한은 만료 입력이나 heartbeat로 연장하지 않는다.
잘못된 쌍·관측된 TDMA 누락은 3쌍 확인을 다시 시작한다.
정상 status·sideband·RAW 대기는 확인을 깨지 않는다.
새 맵 학습은 보존 기한 만료를 기다리지 않는다.
재적합 실패도 새 맵 학습을 중단시키지 않는다.
기하 모델 재획득 시간은 별도로 남는다.

boot/session 변경·host 역행은 보존 맵도 버린다.
ROS 실제 역행도 보존 맵을 버린다.
기존 ROS offset 250ms 초과 변화 검사도 유지한다.
검증되지 않은 legacy RAW에는 보존을 적용하지 않는다.
status의 기존 10초 만료 기한은 유지한다.

마지막 실제 발행 stamp는 전체 reset에도 남긴다.
ROS 시각이 뒤로 이동하면 과거 stamp 발행을 막는다.
새 시각이 직전 발행 시각을 넘으면 다시 발행 가능하다.
그동안 내부 시계·기하 학습은 계속한다.
명시적 시간 epoch 재기준 기능은 이번 범위에 없다.
발행 시각은 `BtfNode`가 소유한다.
`MeasuredBtf`의 Python/C++ 계산 경로 모두에 적용한다.
C++는 기하 계산을 담당한다. 시계 처리는 공통 Python 경로다.
다른 독립 노드의 시계 정책은 이번 범위가 아니다.

## FREEZE와의 관계

새 LAND 조건이나 타이머를 추가하지 않는다.
FREEZE는 기존의 마지막 목표 유지 경로를 쓴다.
보존 맵만으로 좌표를 발행하지 않는다.
입력·출력 150ms, ToF 100ms, IMU 20ms는 유지한다.
companion의 고도·자세 제어는 추가하지 않는다.

## 검증 기록

| 검사 | 결과 |
|---|---|
| Windows Python3.12 관련 합성 단위 검사 | 83개 통과 |
| ROS 어댑터 검사 모듈 | rclpy 부재로 1개 모듈 건너뜀 |
| 처리부 전체 검사 수집 | 기존 JSON 링크·yaml/scipy 환경 문제로 6개 오류 |
| 전체 ROS/PX4 빌드 | 이번 변경에서는 미실시 |
| 원본 로그 재생·지연 측정 | 미실시. 사용자 보류 |
| 실기 배포·운영 서비스 변경 | 미실시. 사용자 보류 |

관련 검사는 ClockRecovery·ClockMap·TDMA·MeasuredBtf다.
한계값·두 시간축·중앙값·학습 병행을 확인했다.
소스 변경·시계 역행·발행 시각 보존도 확인했다.
ROS 의존성을 대역으로 바꾼 어댑터 계약 검사도 포함한다.
실제 어댑터 메서드는 호출한다. ROS/DDS는 구동하지 않는다.
발행 성공·실패와 만료 boot status를 확인했다.
Jetson SSH는 연결 시간 초과로 추가 검사하지 못했다.
Claude27차 코드 검토의 발행 경계 지적을 반영했다.
발행 차단이 기하 모델까지 초기화하지 않도록 고쳤다.
잔차 단위·만료 boot status 검사도 보완했다.
코드 검토와 단위 검사는 비행 적격 판정이 아니다.
재생에서 최장 공백과 발행 수를 확인해야 한다.
