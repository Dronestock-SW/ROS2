# Gazebo UWB 이상 주입 시험
이 문서는 실시간 가상 RAW에 이상을 넣는 절차다.
정상 연결·비행을 확인한 뒤 단절 대응을 시험할 때 읽는다.

## 현재 가능한 시험

거리 편향과 전체 UWB 발행 단절을 구현했다.
2026-10-02 로컬 모의 Gazebo 시험까지 확인했다.
실제 WSL 비행에서의 대응 검증은 미실시다.
옵션을 주지 않으면 기존 정상 발행을 유지한다.

| 계획 파일 | 초기 시험 조건 | 확인할 동작 |
|---|---|---|
| gazebo_fault_bias_01.json | 시작 후 8~12초, A2에 +0.50m | 위치 오차·잔차·모델 기각·PX4 반응 |
| gazebo_fault_drop_01.json | 시작 후 8~9초, 발행 생략 | 관측 만료·정지 요청·실제 감속·복구 |

두 설정은 별도 시행으로 사용한다.
처음부터 편향과 단절을 겹쳐 적용하지 않는다.
겹치는 계획은 실행기가 거부한다.
원래 앵커 지도·잡음·교정 설정은 그대로 기록한다.
편향값과 단절 시간은 초기 시험값이다.
실제 NLOS 통계에서 얻은 값이 아니다.

벽·CIR·RF 전파 모델을 추가한 기능은 아니다.
거리 숫자 또는 발행 여부에 명시적인 이상을 넣는다.
Gazebo 정답 위치와 비행 제어기를 직접 바꾸지 않는다.

## 시각과 데이터 흐름

기준 시각은 생성기가 처음 기록한 pose다.
PX4 시동·이륙·목표 시작 시각이 아니다.
계획의 start_s는 포함하고 end_s는 제외한다.
판정에는 Gazebo 시각만 사용한다.

```text
Gazebo pose → 원래 가상 RAW + 별도 정답
           → 예약 이상 적용 → 발행 후보 RAW
                            → 단절 구간이면 발행 생략
                            → 정상 구간이면 Gazebo에 발행
```

단절 중에도 pose·원래 거리·정답은 계속 기록한다.
복구 시에는 그 시점의 새 거리와 시각을 쓴다.
보내지 않은 과거 표본을 나중에 몰아서 보내지 않는다.
편향은 선택한 앵커 한 곳에만 더한다.
거리 범위를 벗어나면 잘라내지 않고 valid_mask에 반영한다.

## WSL 실행

현재 갱신본은 `uwb_gazebo_fault_evaluation_v2_20261002.zip`이다.
[반영 절차](uwb_gazebo_navigation_runbook.md#갱신본-반영)로 설치한다.
기존 관측·목표·독립 평가 기능을 함께 포함한다.

먼저 정상 시험의 시작·이동 시각을 확인한다.
시험하려는 이동 구간과 주입 구간이 겹치도록 계획한다.
첫 예시의 8초가 실제 비행 구간이라고 가정하지 않는다.
지상에서 주입이 끝났다면 비행 고장 시험으로 인정하지 않는다.
새 설정·새 시행 ID로 다시 기록한다.

기존 생성기를 종료한 뒤 하나만 실행한다.
같은 토픽에 두 생성기를 동시에 띄우지 않는다.
이유: 같은 시각·seq의 서로 다른 RAW가 섞일 수 있다.
관측·임무 실행기는 별도 창에서 계속 기록한다.

아래는 WSL Ubuntu 셸의 UWB 단절 시험 예시다.
`runs/equipment_02/trial.json`을 그대로 사용한다.

```bash
export PYTHONPATH="$PWD/src/drone_uwb:$PWD/src/drone_demo${PYTHONPATH:+:$PYTHONPATH}"
/usr/bin/python3 -m drone_uwb.integration.gazebo_ranges \
  --config runs/equipment_02/trial.json \
  --fault-plan src/drone_uwb/config/gazebo_fault_drop_01.json \
  --duration-s 20 \
  --output runs/ranges_drop_01
```

편향 시험은 fault-plan과 출력 폴더를 바꾼다.
`gazebo_fault_bias_01.json`, `runs/ranges_bias_01`을 쓴다.
관측 계산기에는 기존 trial.json을 계속 전달한다.
이상 계획은 생성기의 별도 인자다.
계산기에 같은 편향을 다시 더하지 않는다.
trial.json의 faults 목록은 기존처럼 비워 둔다.

`--duration-s`는 시뮬레이션 시간 기준 종료 조건이다.
생략하면 기존처럼 Ctrl+C로 저장·종료한다.
시뮬레이터가 정지하면 벽시계만으로 표본을 만들지 않는다.
새 pose가 없는 경우에는 기존 idle timeout으로 끝난다.

## 보존하는 기록

| 파일 | 의미 |
|---|---|
| config.json | 지도·편향·잡음·시드의 원래 설정 |
| fault_plan.json | 이번 시행의 이상 종류·구간·값 |
| raw_before_fault.jsonl | 이상 주입 전 거리 |
| raw_ranges.jsonl | 이상 적용 후 발행 후보. 생략한 표본도 포함 |
| emission.jsonl | 주입 ID·바이어스·발행 시도·성공·생략·오류 |
| poses.jsonl / truth.jsonl | 단절 중에도 유지한 평가용 정답 |
| manifest.json | 실행 인자·환경·코드 커밋·소스 해시 |
| capture.json | 기록 수·발행 수·단절 수·오류·종료 원인 |
| input_index.json | 결과 파일의 바이트 수·해시 |

`raw_ranges.jsonl`의 모든 행이 전송된 것은 아니다.
실제 발행 시도는 emission.jsonl로 대조한다.
발행 성공도 소비자의 수신 성공을 뜻하지 않는다.
소비자 RAW와 seq·시각·거리값을 다시 대조한다.
전송 예외의 published는 미상인 null로 기록한다.

| 기록 원인 | 의미 |
|---|---|
| scheduled_drop | 계획대로 발행을 생략함 |
| published | Gazebo 발행 함수가 성공을 반환함 |
| publish_failed | 발행 함수가 실패를 반환함 |
| publish_exception | 전송 중 예외. 전달 여부는 미상 |

발행 실패는 정상 종료 코드로 숨기지 않는다.
오류가 나도 가능한 원본과 요약·해시는 남긴다.
Git 없는 ZIP 실행에서는 code_commit이 null일 수 있다.
그때도 실행한 소스의 SHA-256은 기록한다.

## 대응과 독립 평가

현재 임무 실행기는 관측 만료 시 상태를 확인한다.
유효한 PX4 위치·속도·Hold이면 제동점을 요청한다.
그 외에는 PX4 착륙을 요청한다.
요청 자체를 실제 정지·착륙 성공으로 처리하지 않는다.
중단한 경로는 자동 재개하지 않는다.
실제 복구·재시작 검증은 다음 시행에서 한다.

[독립 평가기](../architecture/uwb_gazebo_flight_evaluation.md)는
이상 계획·발행 기록·주입 전 RAW도 입력 사본에 보존한다.
단절했다고 기록한 RAW가 수신 기록에 있으면 거부한다.
수신 RAW가 없는데 관측을 송신했다는 기록도 거부한다.
단절 구간을 삭제해 오차를 좋게 보고하지 않는다.
전체 구간의 가용률·공백을 계속 계산한다.

정상·편향·복구 구간의 정확도와 고장 대응은 따로 읽는다.
독립 평가기는 구간별 scenario_metrics.csv를 만든다.
복구 시간은 새 관측의 표본 시각 기준으로 기록한다.
발행 계획·원래 RAW·변경 RAW가 일치하는지도 대조한다.
고장 구간의 의도된 누락이 7cm 정확도 성공을 뜻하지 않는다.
모델이나 보조기능을 바꾸면 A·직전 구성과 다시 비교한다.

## 확인 결과와 남은 작업

관련 로컬 시험 54개가 통과했다.
가짜 Gazebo 메시지와 실제 생성·주입·기록 코드를 연결했다.
경계 시각·복구 표본·원본 보존·전송 오류를 확인했다.
정답 분리·기존 모델 재생·독립 평가의 회귀 시험도 포함한다.
실제 Gazebo·PX4를 띄운 시험은 아니다.
전체 빌드의 5개 패키지도 성공했다.
설치 경로에서 주입·평가 모듈 import를 확인했다.

27일 기본 ZIP에 현재 갱신 파일을 겹쳐 확인했다.
저장소와 분리한 폴더에서 54개 시험이 통과했다.
소요 시간은 14.18초다.
주입·평가·목표 실행기의 도움말도 통과했다.
실제로 그 폴더의 모듈을 불러오는지 확인했다.
기존 벽 collision 이름 수정도 누적본에 포함한다.
설치된 월드·모델을 자동으로 덮어쓰지는 않는다.

이후 구간별 평가와 관측 복구 시간 계산을 추가했다.
이 변경은 관련 시험 44개와 5개 패키지 빌드를 통과했다.
초기 주입 ZIP은 보존했다. 현재 반영 파일명은 위를 따른다.
누적본을 별도 폴더에 적용한 시험은 68개가 통과했다.
