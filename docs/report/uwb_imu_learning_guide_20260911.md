# UWB·IMU 드론의 위치추정과 학습 제어
이 문서는 위치추정·상태 전환·강화학습의 설명서다.
실내 드론의 보상과 시뮬레이션을 설계할 때 읽는다.

## 1. 먼저 이해할 결론

**권장 출발점은 PX4 EKF2와 규칙 기반 상태 전환이다.**
UWB는 현재 위치의 관측을 제공한다.
서버는 가야 할 목표 위치를 제공한다.
두 정보의 용도가 다르다.
목표는 측정 오차를 알아내는 정답이 아니다.
아직 목표에 도착하지 않았을 수 있기 때문이다.

기존 설계에서는 PX4가 상태추정을 전담한다.
companion은 UWB 관측과 수평 이동 명령을 공급한다.
드론의 고도·자세 제어도 PX4가 담당한다.
이 구조를 유지하며 학습 기능을 비교한다.[^1]

| 질문 | 판단 |
|---|---|
| 위치와 시간으로 이동 경향을 알 수 있나? | 가능하다. 차분은 잡음과 지연에 민감하다. |
| 상태 전환으로 UWB 편향을 없앨 수 있나? | 전환만으로는 어렵다. 교정과 독립 기준이 필요하다. |
| Decision Tree에 보상이 필요한가? | 일반적인 결정 트리·FSM·BT에는 필수가 아니다. |
| 정상 각도에 계속 보상하면 되나? | 목표를 무시하고 체류하는 행동도 점수를 얻는다. |
| 강화학습을 어디에 넣나? | 검증된 이동 모드나 수평 속도 선택부터 연구한다. |
| 첫 시뮬레이터는 무엇인가? | PX4 v1.16.0 SITL + Gazebo Harmonic을 권장한다. |

이 보고서의 제안은 아직 시험하지 않은 설계다.
표의 보상·임계값은 실제 비행 설정이 아니다.
연구 결과, 현장 기록, 설계 제안을 구분해 적었다.
장비 정보의 확인 날짜도 함께 표시한다.

### 읽는 순서

3~5절에서 위치·속도·제어를 이해한다.
6~7절에서 상태 전환의 역할을 구분한다.
8~10절에서 보상과 학습 문제를 설계한다.
11~12절에서 시뮬레이터와 센서 모델을 고른다.
13~16절에서 논문·검증·공부 순서를 확인한다.

이 단계에서는 새 비행용 EKF를 만들지 않는다.
PX4 추정 결과를 UWB 관측으로 다시 넣지도 않는다.
이유는 같은 정보를 새 관측처럼 세는 것을 막기 위해서다.[^1]

기본 모드는 RAW 거리 재계산이다.
PX4 전달 브리지는 기본 비활성이다.[^4]

태그와 FC는 마지막 확인 때 분리 시험 중이었다.
예정 장착은 FC 위 30cm, 앞 5~7cm다.
고정 후 안테나 기준으로 다시 측정해야 한다.
기체 질량·관성·프로펠러·추력 곡선은 미확정이다.
따라서 실기 정상 각도 범위도 아직 확정할 수 없다.

## 3. 좌표·시간·편향을 구분하기

**같은 좌표가 반복돼도 정확한 위치라는 뜻은 아니다.**
UWB의 절대 위치는 설치한 앵커 지도 기준이다.
지구 좌표나 오차 없는 정답이라는 뜻이 아니다.
우리 지도는 A1이 원점이다.
+y는 A1에서 A3를 보는 방향이다.[^4]

### 위치를 차분하면 속도 경향을 얻는다

```text
관측 위치: z(k) = 실제 위치 p(k) + 편향 b(k) + 잡음 n(k)
차분 속도: v(k) = [z(k) - z(k-1)] / 시간 간격
```

편향이 일정하면 차분에서 상쇄될 수 있다.
따라서 차분 자체가 반드시 편향을 만드는 것은 아니다.
하지만 위치에 남은 편향은 사라지지 않는다.
가림이나 방향에 따라 편향이 바뀌면 속도도 틀어진다.
이 구분이 교정 방법을 정한다.

독립된 위치 잡음의 표준편차가 2cm라고 가정하자.
25ms 간격 차분의 속도 표준편차는 약 1.13m/s다.
계산은 √2 × 0.02 / 0.025다.
실제 UWB 잡음에는 시간 상관도 있을 수 있다.
이 수치는 원리를 설명하는 계산 예제다.
짧은 구간의 직선 맞춤은 잡음을 줄일 수 있다.
대신 지연과 급격한 이동을 놓치는 정도를 함께 잰다.

| 오차 종류 | 예 | 대응 |
|---|---|---|
| 일정한 편향 | 항상 오른쪽 25cm | 기준점·앵커·거리 교정 |
| 무작위 잡음 | 같은 곳에서 ±몇 cm 흔들림 | 관측 불확실성·필터 검토 |
| 지연 | 1m/s 이동 중 0.1초 늦음 | 약 10cm 차이. 시각 정합 |
| 가림 오차 | 사람 뒤에서 거리 급증 | 품질 검사·거부·복귀 검증 |
| 좌표 오정렬 | +x 이동이 +y로 보임 | 고정 회전·원점 확인 |

### 목표 위치는 교정 정답이 아니다

실제 위치에 +0.25m 편향이 붙는다고 가정하자.
목표가 2.00m이면 제어기는 관측 2.00m에서 멈출 수 있다.
그러나 실제 위치는 1.75m다.
상태를 MOVE에서 HOLD로 바꿔도 이 오차는 남는다.
기준점을 직접 재거나 독립 위치 관측이 필요하다.
목표와 관측의 차이를 모두 센서 오차로 빼면 안 된다.
이유는 아직 이동하지 않은 거리까지 지워지기 때문이다.

기존 정지 기록도 이 구분이 중요했다.
사용자 기준점에서 평균 약 20~25cm 벗어났다.
통과 관측의 축별 흔들림은 약 1.2~2.4cm였다.
매끄러운 출력과 정확한 위치는 다른 성능이다.[^4]

## 4. EKF2가 결합하는 정보와 신뢰도

**EKF2는 움직임을 예측하고 UWB 위치로 보정한다.**
PX4는 IMU와 자세 정보를 사용한다.
companion은 유효한 x·y·시각·공분산을 보낸다.
두 IMU를 companion에서 평균 내는 단계는 없다.[^6]

공분산은 추정 오차의 퍼짐을 표현한 수치다.
비유하면 위치 주변에 그리는 불확실성 영역이다.
우리 시스템에서는 UWB를 얼마나 반영할지에 관여한다.
실제 오차가 그 영역과 맞는지 따로 검증해야 한다.

```text
IMU 예측 -> 예상 위치와 불확실성
UWB 관측 -> 같은 시각·좌표에서 비교
         -> 허용 가능한 차이면 보정
         -> 이상 관측은 거부할 수 있음
```

한 방향에서는 반영 비율을 P / (P + R)로 이해할 수 있다.
P는 예측 위치의 분산이다.
R은 UWB 위치 관측의 분산이다.
이는 선형·독립 오차를 가정한 설명용 식이다.
실제 EKF2는 여러 상태의 관계를 함께 계산한다.
위치 관측은 상태 간 관계를 통해 속도에도 영향을 준다.

예측과 관측의 차이를 innovation이라 부른다.
비유하면 두 증언이 얼마나 어긋나는지 보는 값이다.
우리 시스템에서는 거부·재수용 판단을 확인하는 지표다.
그 차이가 작아도 두 정보가 함께 틀릴 수 있다.[^6]

| 확인할 신뢰도 | 실제 확인 항목 |
|---|---|
| 관측 신뢰도 | 정상 앵커, 거리 일관성, 나이, 가림 |
| 필터 동작 | 실제 융합 여부, 거부, 마지막 보정 시각 |
| 통계의 일치 | 예상 오차 영역과 실제 오차의 포함 비율 |
| 최종 정확도 | 독립 기준의 평균 오차·p95·최대 오차 |

현재 x·y 불확실성의 기본값은 0.30m다.
잔차·측정 시차에 따라 분산을 더하는 구현이다.
이는 시험용 규칙이며 검증된 확률 모델이 아니다.[^4]
UWB 공백에서는 새 관측을 만들지 않는다.
같은 좌표를 새 시각으로 반복하면 과신을 부를 수 있다.
공백 뒤에는 재수용과 위치 재설정도 확인한다.
지연·축·장착 위치는 외부 위치 설정과 맞춘다.[^7]

## 5. 정상 각도와 정상 비행은 다르다

**작은 기울기는 정지의 충분조건이 아니다.**
roll은 좌우 기울기, pitch는 앞뒤 기울기다.
yaw는 수평 방향이다.
각도가 작아도 옆으로 이동할 수 있다.
속도가 일정하면 가속도는 거의 0일 수 있다.

수평으로 이동하려면 추력 일부를 옆으로 써야 한다.
이를 위해 기체가 기울어진다.
수평으로 정지한 기체도 바람을 버티며 기울 수 있다.
정상 여부는 각도·속도·위치·추력 여유를 함께 본다.[^10]

공기 저항을 무시한 단순 모델은 다음과 같다.
θ는 총추력과 수직 방향 사이 각도다.
T는 총추력, m은 질량, g는 중력가속도다.

```text
고도 유지 조건: T × cos(θ) = m × g
필요 추력 비율: T / (m × g) = 1 / cos(θ)
수평 가속도 크기: a ≈ g × tan(θ)
```

| 기울기 | 고도 유지에 필요한 추력 비율 | 해석 |
|---|---:|---|
| 0° | 1.000배 | 이상적인 정지 호버 |
| 10° | 1.015배 | 이동·외란 대응에 쓰일 수 있음 |
| 20° | 1.064배 | 더 큰 수평 가속도와 추력 필요 |
| 30° | 1.155배 | 추력 여유 확인이 더 중요 |

위 값은 물리식의 계산 결과다.
우리 기체의 허용 각도 제안이 아니다.
배터리·하중·모터·프로펠러가 한계를 바꾼다.
우리 기체의 정상 범위는 조립 후 시험으로 정한다.

### 위치제어와 자세제어의 관계

목표 위치와 추정 위치의 차이가 이동 요구를 만든다.
속도 오차는 가속 요구로 연결된다.
PX4는 이를 자세·추력 요구로 바꾸어 제어한다.[^8]
학습기가 각도 점수만 높이려고 하면 이동을 방해할 수 있다.
따라서 위치 오차와 정지 속도를 주목적으로 둔다.
과도한 기울기는 비용과 제한 조건으로 다룬다.

## 6. Decision Tree·FSM·Behavior Tree·RL

**상태 전환 구조와 학습 방법은 서로 다른 선택이다.**
조건에 따라 행동을 바꾸는 구조는 학습 없이도 만든다.
점수로 그 선택을 개선하려 할 때 강화학습이 등장한다.

| 방식 | 정의와 비유 | 우리 시스템의 후보 역할 |
|---|---|---|
| Decision Tree | 조건을 분기하는 결정 트리. 질문지와 같다. | 센서 품질 분류나 이동 모드 선택 |
| FSM | 상태와 전환 조건을 정한다. 신호등과 같다. | 대기·이동·감속·도착 관리 |
| Behavior Tree | 행동을 계층으로 실행한다. 작업 순서표와 같다. | 우선순위·재시도·복합 임무 |
| 강화학습(RL) | 행동 결과의 누적 보상을 높이도록 배운다. 반복 연습과 같다. | 조건별 속도·이동 모드 선택 학습 |

일반적인 학습형 Decision Tree는 지도학습이다.
정답이 붙은 사례로 분류나 수치를 예측한다.
보상을 주며 학습하는 RL과 목적이 다르다.[^12]
결정 트리를 RL의 정책 표현으로 쓸 수도 있다.
그 경우에도 학습 문제와 알고리즘을 따로 정한다.

BT의 행동 노드는 성공·실패·실행 중을 반환한다.
Sequence는 필요한 행동을 순서대로 실행한다.
Fallback은 가능한 대안을 순서대로 시도한다.
현재 작업을 중단하고 조건을 다시 볼지도 설계한다.[^11]

```text
상위 의사결정
  +-- 상태 신뢰도 확인
  +-- 이동 가능한 경우: 목표로 이동
  +-- 목표 근처: 감속 후 도착 확인
  +-- 복구 가능한 관측 공백: 검증된 제한 동작
  +-- 상태추정 무효: 지정된 PX4 대응으로 인계
```

‘HOLD’라는 상태 이름만으로 정지가 보장되지는 않는다.
위치와 속도 추정이 유효해야 위치를 유지할 수 있다.
관측 공백과 추정 무효는 다른 조건이다.
두 경우를 같은 분기로 처리하지 않는다.

초기 구현은 적은 수의 FSM 상태가 적합하다.
기존 로드맵도 FSM에서 시작하도록 정했다.
다중 목표와 재시도가 복잡해질 때 BT를 검토한다.[^1]
학습 여부는 이 규칙 기반 기준선과 비교해 결정한다.

## 7. 서버·companion·PX4의 책임

**서버는 목표를 주고, 기체 내부가 빠른 판단을 수행한다.**
서버가 보내는 목표에는 좌표계와 식별자가 필요하다.
오래된 목표나 취소된 목표를 구별해야 한다.
네트워크 지연이 자세 제어 주기를 좌우하지 않게 한다.

```text
로컬 서버 -- 목표·취소 --> companion 의사결정
                             |
                             +-- 수평 위치/속도 목표 --> PX4 제어
                             ^                            |
                             |                            v
                      상태·품질 정보 <--- PX4 EKF2 <--- 내부 IMU
                                              ^
UWB -- 거리/좌표 --> 관측 전처리 -- x·y·시각·공분산 --+
```

PX4 추정치를 의사결정 입력으로 읽는 것은 필요하다.
이를 새로운 위치 관측으로 되먹이는 것은 다르다.
후자는 같은 정보를 중복해서 믿게 만든다.[^1]

| 후보 상태 | 들어가는 조건 | 하는 일 |
|---|---|---|
| READY | 목표·좌표·추정 유효 | 임무 시작 조건 확인 |
| MOVE | 목표가 멀고 통로가 허용됨 | 제한된 수평 이동 명령 |
| APPROACH | 목표 근처 | 속도 상한 감소 |
| SETTLE | 거리·속도가 도착 범위에 있음 | 일정 시간 지속되는지 확인 |
| DEGRADED | UWB 공백, 추정은 아직 유효 | 검증된 감속·제한 정책 |
| RECOVERY | 새 UWB가 다시 수용됨 | 위치 급변·건전성 확인 |
| ABORT | 추정 무효 또는 제한 위반 | 지정된 PX4 대응·운용자 인계 |

이는 구현 전 검토할 상태 전환 초안이다.
출입 조건을 다르게 두어 잦은 왕복을 줄인다.
이를 히스테리시스라고 부른다.
비유하면 온도조절기가 작은 변화마다 꺼졌다 켜지지 않게 하는 것이다.
우리 시스템에서는 복구 확인 시간도 함께 둔다.

Offboard 명령의 생존 신호는 목표 갱신과 별개다.
PX4 v1.16은 2Hz 초과의 지속 입력을 요구한다.
MAVLink와 직접 ROS 2 입력의 신호 방식은 다르다.[^9]
실제 명령 발행은 BT나 학습 호출이 멈춰도 감시한다.
학습기의 주기는 5~10Hz부터 시험하는 안이다.
명령 발행 20~50Hz와 구분한 예시이며 확정값은 아니다.

## 8. 강화학습 문제를 정의하는 법

**먼저 관측·행동·보상을 정하고 알고리즘을 고른다.**
정책은 관측을 보고 행동을 고르는 규칙이다.
비유하면 상황별 운전 습관이다.
우리 시스템에서는 이동 속도나 모드 선택을 담당한다.[^13]

| 구성 | 우리 문제의 연구용 정의 |
|---|---|
| 관측 | 목표 오차 x·y, 추정 속도, 기울기, 각속도 |
| 품질 관측 | UWB 관측 나이, 유효 앵커, 잔차, EKF 상태 |
| 추가 관측 | LiDAR 통로 여유, 직전 행동, 현재 임무 상태 |
| 첫 행동 후보 | 미리 검증한 느림·보통·감속 모드 중 선택 |
| 다음 행동 후보 | 제한된 수평 속도 vx·vy 또는 속도 상한 |
| 보상 | 목표 도달·정착을 높이고 시간·위반·급변을 줄임 |
| 에피소드 | 시작 위치와 목표를 정한 한 번의 시험 |
| 종료 | 목표 정착, 충돌·실패, 시간 제한을 구분 |

전체 실제 상태를 관측에서 모두 알 수는 없다.
UWB의 숨은 편향과 미래 가림도 알 수 없다.
이런 문제를 부분 관측 문제라고 한다.
짧은 관측 이력과 측정 시각을 입력할 수 있다.
다만 이력이 독립 기준의 부재를 해결하지는 않는다.

시뮬레이터의 실제 위치는 평가와 보상 계산에 쓸 수 있다.
배포할 정책 입력에는 실물에서 얻을 값만 넣는다.
이유는 정답 좌표에 의존하는 정책을 막기 위해서다.
성공 판정도 숨겨진 정답 없이 가능한지 따로 확인한다.

### 알고리즘은 다음 단계다

PPO는 새로 모은 경험으로 정책을 반복 갱신한다.
학습 절차를 비교적 단순하게 시작하는 후보이다.[^15]
SAC는 이전 경험을 재사용하는 연속 행동 후보이다.[^16]
어느 쪽도 우리 드론에서 더 우수하다고 검증되지 않았다.
초기 이산 모드 선택에는 PPO 같은 방법을 검토한다.
연속 속도 선택을 할 때 SAC를 비교 후보에 넣는다.

실기에서 보상을 받으며 계속 탐색하게 두지 않는다.
먼저 시뮬레이션에서 학습하고 정책을 고정해 평가한다.
이유는 학습 중의 탐색 행동이 검증되지 않았기 때문이다.[^28]

## 9. 각도 보상만 주었을 때의 실패

**각도는 안전·운동 상태의 일부이며 임무 성공 자체가 아니다.**
정상 각도 안에서 매번 +1을 주면 다음 행동도 보상받는다.
목표를 향해 가지 않고 시작점에서 머무는 행동이다.
이는 보상 정의에서 생기는 예상 가능한 결과다.

### 숫자로 보는 체류 보상

가상의 시험은 최대 60초, 평가 주기 10Hz다.
정상 각도에 매번 +1을 준다.
목표 도달 즉시 시험을 끝내고 별도 성공 보상은 없다.
할인을 적용하지 않은 합계다.

| 행동 | 목표 달성 | 정상 각도 보상 |
|---|---|---:|
| 10초 만에 도착 | 성공 | 최대 100점 |
| 출발점에서 60초 대기 | 실패 | 최대 600점 |
| 바닥에 수평으로 놓임 | 비행 아님 | 비행 조건 검사가 없으면 점수 획득 |

이 표는 실험 결과가 아닌 보상 규칙의 계산 예제다.
상태 판정과 종료 조건이 목표와 맞아야 한다.
‘살아 있는 동안 계속 양수’인 점수도 같은 함정이 있다.

| 보상 허점 | 왜 문제가 되는가 | 설계 방향 |
|---|---|---|
| 각도만 보상 | 수평 이동·정지 여부를 구분 못 함 | 위치·속도·정착을 주목적으로 둠 |
| 목표 거리만 사용 | 빠르게 통과해도 도달로 인정 | 거리와 속도의 지속 조건 |
| 모든 상태에 저속 보상 | 이동 자체를 피할 수 있음 | 목표 근처에서 정착 속도 평가 |
| 관측 거부마다 감점 | 가림 위치를 피하는 것과 안전 거부가 섞임 | 거부의 원인·최종 성능을 별도 기록 |
| 행동 급변만 감점 | 필요한 제동까지 약해질 수 있음 | 제한 조건·비용 크기 검증 |

각도 허용 범위는 하드 제한으로도 다룬다.
하드 제한은 점수와 교환하지 않는 경계다.
큰 보상을 얻었다고 충돌을 허용하지 않는다는 뜻이다.
다만 제한기가 항상 안전하다는 보증도 아니다.
입력 추정 오차와 제동 가능 범위를 검증해야 한다.[^28]

## 10. 우리 문제의 보상 초안

**목표 도달과 정착을 보상하고, 위험은 별도로 제한한다.**
아래 식은 연구용 후보이다.
가중치와 정상 범위는 시험으로 정한다.
실제 기체에 적용된 설정은 아니다.

```text
r = 성공 보상 - 실패 비용
    - Δt × [시간 비용 + 위치 비용 + 정착 속도 비용
            + 과도한 기울기 비용 + 명령 급변 비용]
    + 선택적 목표 접근 보상
```

| 항목 | 계산 개념 | 주의점 |
|---|---|---|
| 성공 | 거리와 속도가 기준 안에서 일정 시간 유지 | 첫 성공에 한 번만 지급 |
| 실패 | 충돌·추정 무효·제한 위반 등의 종료 | 원인별 수를 별도 기록 |
| 위치 비용 | 목표 거리 / 기준 거리의 제곱 | 먼 초기 위치가 결과를 지배하지 않게 정규화 |
| 정착 속도 비용 | 목표 근처에서 속도 제곱 | 먼 구간까지 정지를 보상하지 않음 |
| 기울기 비용 | max(0, θ−θ_soft)의 정규화 제곱 | 작은 각도마다 무조건 양수 보상하지 않음 |
| 명령 급변 비용 | 연속 속도 명령의 변화율 제곱 | 상태 전환과 제동을 방해하는지 확인 |

비용에 Δt를 곱해 초당 의미를 맞춘다.
그렇지 않으면 10Hz와 100Hz의 점수가 달라진다.
명령 변화율도 실제 행동 간격으로 나눈다.
할인율은 시간 간격과 함께 고정한다.
후보 행동 주기는 0.1초이며 예시일 뿐이다.

목표 접근 보상을 더할 수도 있다.
이론적으로는 F = γΦ(s_next) − Φ(s) 형태를 검토한다.
Φ는 상태의 목표 근접도를 나타내는 함수다.
잠재함수 기반 보상 설계라고 부른다.
원 논문의 조건에서 최적 정책 보존 성질이 있다.[^14]
부분 관측과 시간 제한에서도 자동 보장되지는 않는다.
종료 상태의 Φ 처리와 평가 조건을 맞춰야 한다.

초기 비교는 복잡한 항을 줄여 시작한다.
성공·실패·시간·위치 비용부터 기준선을 만든다.
기울기·급변 비용을 하나씩 추가해 효과를 비교한다.
각 항의 합계를 따로 기록해 보상 독점을 찾는다.
보고 지표는 보상 합계와 실제 성공률을 분리한다.

Gymnasium은 정상 종료와 시간 잘림을 구분한다.
성공·충돌은 terminated로 정의할 수 있다.
외부 시간 제한은 truncated로 구분한다.
이 차이는 학습의 다음 상태 처리에 영향을 준다.[^17]

## 11. 시뮬레이터 선택과 버전

**첫 통합 시험은 PX4 v1.16.0과 Gazebo를 기준으로 한다.**
SITL은 비행 소프트웨어를 PC에서 실행하는 방식이다.
비유하면 실제 PX4가 가상 기체를 운전하는 연습장이다.
우리 시스템에서는 EKF2와 MAVROS 경로를 시험한다.[^27]

| 후보 | 강점 | 우리에게 남는 작업 | 권장 용도 |
|---|---|---|---|
| Gazebo + PX4 SITL | PX4 제어·EKF·가상 센서 통합 | UWB 오류 모델, 실기 기체 값 반영 | 첫 통합 기준선 |
| gym-pybullet-drones | 작은 RL 환경과 보상 실험 | PX4 동등성·ROS 연동 별도 | RL 개념 학습 |
| safe-control-gym | 제약·외란·기존 제어와 비교 | 주로 단순화된 모델, 전체 기체 통합 별도 | 안전·비교 실험 공부 |
| Isaac Sim + Pegasus | 드론 물리·영상과 PX4 연동 | GPU PC, 버전·기체·UWB 검증 | 영상·복잡한 장면 확장 |
| Isaac Lab | 병렬 로봇 학습 환경 | PX4 유지한 학습 환경을 별도 설계 | 대량 학습 필요 시 검토 |

소형 학습 환경의 범위는 원 프로젝트를 따른다.[^18][^24][^25]

PX4 v1.16 문서는 Ubuntu 22.04에서 Harmonic을 사용한다.
기본 X500 실행 예시는 make px4_sitl gz_x500이다.[^20]
이는 실행법을 설명한 예시이며 이번에 실행하지 않았다.
X500 모델의 질량·관성은 우리 기체의 실측값이 아니다.

ROS 2 Humble의 공식 기본 조합은 Fortress다.
Harmonic용 ros_gz는 별도 패키지 조합이다.
기존 ros-humble-ros-gz 계열과 충돌할 수 있다.[^21]
PX4↔Gazebo 통신과 ROS↔Gazebo 브리지는 다른 경로다.
MAVROS로 PX4에 연결한다고 ros_gz가 자동 필요한 것은 아니다.
LiDAR·가상 UWB를 ROS로 읽는 경로에서 따로 검토한다.

Pegasus 문서는 Isaac Sim 5.1.0과 PX4 1.14.3 시험을 명시한다.
우리 PX4 1.16.0과 같은 조합은 아니다.[^22]
Isaac Lab 열람 문서는 Sim 5.1.0을 권장한다.[^24]
Isaac Sim latest 요구사항은 6.0 계열 내용도 포함한다.
별도 버전 문서를 섞어 설치하지 않는다.[^23]

현재 Jetson은 Isaac Sim 학습 PC의 대체재로 보기 어렵다.
열람한 x86 요구사항은 RAM 32GB·VRAM 16GB 이상이다.
ARM 지원 목록의 DGX Spark를 Jetson 지원으로 해석하지 않는다.[^23]

## 12. 가상 UWB와 실물에 가까운 시험

**화면이 사실적이어도 UWB 오차가 사실적이지는 않다.**
첫 모델은 실제 앵커 좌표에서 거리를 계산한다.
그 뒤 교정 오차·가림·지연·공백을 넣는다.
가짜로 완벽한 좌표만 보내면 핵심 문제를 시험하지 못한다.

```text
시뮬레이터 실제 기체 상태
  +-- 보드/IMU 모델 -> PX4 SITL
  +-- 안테나 위치 -> 앵커별 거리 -> 오류·공백·시각 모델
                                      |
                                      v
                                실제 UWB 입력 계약
                                      |
                                      v
                          companion 관측 노드 -> PX4 EKF2

실제 기체 상태 -> 평가기·보상 계산 전용
```

앵커 높이는 네 기 모두 2.2m를 기준으로 한다.
같은 높이의 거리 제곱 차는 태그 높이 항을 지운다.
높이 불일치는 별도의 시험 조건으로 넣는다.
태그 안테나와 FC 중심의 차이도 회전 시 반영한다.[^4]

| 바꿔 볼 조건 | 필요한 모델 |
|---|---|
| 앵커 설치 오차 | 앵커별 위치·높이 오차 |
| 거리 교정 오차 | 앵커별 고정 오프셋 |
| 금속·사람 가림 | 연속된 편향 구간·큰 이상치·결손 |
| 측정 시차 | 앵커 순차 측정·재시도·주기 길이 |
| 통신 지연 | 시각 오프셋·전송 지연·버퍼 적체 |
| IMU 차이 | 축별 잡음·바이어스·온도·진동 영향 |
| 기체 차이 | 질량·관성·모터 지연·외란 |

가림을 매 샘플 독립인 작은 잡음으로만 만들지 않는다.
실제 기록에는 시간적으로 이어지는 가림이 있다.
기존 A4 가림 기록을 조건 구성에 활용한다.[^4]
금속의 전파 다중경로는 일반 물리 엔진만으로 보장되지 않는다.
실측 분포와 길이를 반영하는 오류 모델이 필요하다.

PX4 기본 시뮬레이션의 GPS도 확인해야 한다.
정확한 GPS나 정답 위치가 함께 융합되면 UWB 손실을 숨긴다.
시험 조건별로 켜진 센서와 융합 상태를 기록한다.
정답 좌표를 정책 입력으로 우회 공급하지 않는다.
이유는 실기에서 같은 정보를 얻을 수 없기 때문이다.

MAVROS 경로를 첫 통합 기준으로 유지한다.
직접 ROS 2 연동은 uXRCE-DDS 경로의 별도 선택이다.
그 경우 PX4와 px4_msgs 정의의 호환성도 맞춘다.[^26]

## 13. 읽어야 할 연구와 적용 한계

**열차 논문은 공백 보완 원리를 보여주는 참고 자료다.**
드론의 보상·정상 각도·상태 전환을 검증한 논문은 아니다.
선로의 1차원 제약과 독립 레이저 기준이 핵심 전제다.[^5]

| KCI 논문 결과 | UWB 단독 | UWB+IMU |
|---|---:|---:|
| RMSE | 1.316m | 0.484m |
| 최대 절대오차 | 7.441m | 1.073m |
| 논문의 유효 출력률 | 6.52Hz | 19.50Hz |

출처는 원문 99쪽 Table 1이다.
50ms 간격 예측이 출력 공백을 줄였다.
UWB 무선 측정률이 세 배가 됐다는 뜻은 아니다.
우리 정지 실험의 20~25cm와 직접 비교하지 않는다.
공간·이동·기준 장비·비교 시각이 다르기 때문이다.

초기 정지 교정·시간 정합·독립 기준 평가는 적용할 만하다.
반면 가속도 크기가 g에 가깝다는 조건만으로 정지를 선언하면 안 된다.
일정한 속도의 이동에서도 그 조건이 나올 수 있다.
논문의 ZUPT 후보 판정을 드론에 그대로 옮기지 않는다.
ZUPT는 정지를 확인해 속도 0을 알려주는 보정이다.

논문 식 (6)은 공백이 길수록 IMU 속도 관측 R을 줄인다.
이는 그 논문의 가중 전략이다.
공백 중 관성 위치가 더 정확해진다는 근거가 아니다.
우리 EKF2에 별도 IMU 적분 속도를 다시 넣지 않는다.
이유는 PX4가 이미 쓴 IMU 정보를 중복 융합하기 때문이다.[^1]

| 추가 자료 | 공부할 핵심 | 우리 적용 범위 |
|---|---|---|
| Ng 등, 1999 | 보상 변화가 정책에 미치는 영향 | 목표 접근 보상 설계 |
| Schulman 등, 2017 | PPO의 정책 갱신 | 학습 알고리즘 후보 |
| Haarnoja 등, 2018 | SAC의 경험 재사용 | 연속 행동 비교 후보 |
| safe-control-gym, 2022 | 제어 성능·외란·제약 비교 | 실험 설계 기준 |
| Agarwal 등, 2021 | 여러 학습 실행과 통계 평가 | 단일 최고 성적 과신 방지 |

이 자료들은 학습이 우리 기체에서 성공한다는 증거가 아니다.
각각 보상·알고리즘·평가 방법의 근거로 사용한다.[^14][^15][^16][^18][^19]

## 14. 신뢰도를 입증하는 비교 실험

**보상 증가와 실제 비행 개선을 별도로 확인한다.**
모든 방법에 같은 시작점·목표·오류 조건을 준다.
학습에 쓴 배치와 평가용 배치를 분리한다.
최고 성적 한 번보다 반복 시험의 분포를 본다.[^19]

| 비교 단계 | 바꾸는 것 | 확인하려는 효과 |
|---|---|---|
| A: 기록 재생 | UWB 원본과 전처리 | 이상치 감소·편향 잔존 |
| B: SITL 기준선 | PX4 EKF2 + 규칙 기반 이동 | 융합과 기본 제어 성능 |
| C: 상태 전환 추가 | 감속·복구 FSM | 공백·도착 시 행동 개선 |
| D: 학습 모드 선택 | 같은 제한 안에서 정책만 교체 | 규칙 대비 추가 이득 |
| E: 보상 항 제거 | 각도·급변 등 한 항씩 제거 | 어느 항이 효과를 만들었는지 |

| 측정 지표 | 읽는 법 |
|---|---|
| 위치 정확도 | 평균 오차 벡터·RMSE·p95·최대 |
| 정착 성능 | 목표 범위 안에서 속도가 낮게 유지된 시간 |
| 도달 성능 | 성공률·소요 시간·지나침 거리 |
| 관측 공백 | 마지막 수용 뒤 시간별 실제 위치 오차 |
| 복구 | 재수용 시간·위치 급변·필터 재설정 |
| 제한 위반 | 충돌·기울기 초과·추력 포화·인계 횟수 |
| 실행 품질 | 정책 지연·주기 누락·계산 자원 사용 |

첫 공백 시험 조건은 0.1·0.5·1·2초로 제안한다.
이는 안전하다고 인정한 시간이 아니다.
속도·장소·센서 조합별로 허용 오차를 넘는지 잰다.
위치 추정이 무효일 때 HOLD를 성공으로 세지 않는다.
PX4에 정의한 대응이 실행됐는지도 별도 시험한다.

초기 비교는 학습 seed 5개 이상을 제안한다.
정책별 미학습 조건 100회 이상도 출발점이다.
이 수치는 인증 기준이 아닌 연구 계획이다.
성공률과 신뢰구간을 보고 시험 수를 늘린다.
100번 충돌이 없었다고 충돌 확률 0은 아니다.
같은 분포의 독립 시험이라도 95% 단측 상한은 약 3%다.
이는 1−0.05^(1/100)의 이항 계산이다.

실물에서는 별도 기준점과 동적 기준이 필요하다.
UWB와 같은 원시 거리로 만든 값은 독립 정답이 아니다.
LiDAR로도 이동 방향이 구분되는 환경인지 확인한다.

## 15. 확장 센서와 실기로 옮기는 조건

**새 센서는 관측의 약점을 보완해야 한다.**
센서 수를 늘리는 것만으로 편향이 없어지지는 않는다.
장착·지연·좌표·오류 상관을 함께 확인한다.

| 관측 | 기대 효과 | 한계와 전제 |
|---|---|---|
| UWB | 앵커 지도 기준 수평 위치 | 배치 교정·가림·시각 필요 |
| IMU | 빠른 운동 예측 | 오차 누적·진동·자세 영향 |
| LiDAR 스캔매칭 | 벽·물체를 이용한 상대 이동·yaw | 긴 균일 통로, 기울기, 동적 가림 |
| PMW3901 | 바닥 무늬의 움직임으로 수평 운동 보조 | 조도·무늬·높이·기울기 조건 |
| TFmini Plus | 하방 거리와 고도 보조 | 수평 위치 편향을 직접 제거하지 않음 |
| 고정 마커 | 특정 지점의 독립 위치·정렬 기준 후보 | 지도·카메라 교정·시야 필요 |

LiDAR·광학흐름은 이후 비교할 관측 후보이다.
위 역할은 장비 문서와 현재 설계 범위에 따른다.[^1][^2]
이 보고서에서 각 센서의 실기 성능을 새로 측정하지 않았다.
여러 관측을 PX4 외부 입력으로 조합하는 인터페이스는 별도 설계한다.
한 입력 topic에 서로 다른 출처를 무계획으로 섞지 않는다.
이유는 좌표·시각·리셋·오차 상관을 구분해야 하기 때문이다.

시뮬레이션에서는 조건을 조금씩 바꿔 학습할 수 있다.
이를 도메인 랜덤화라고 부른다.
비유하면 맑은 날과 비 오는 날을 바꿔 연습하는 것이다.
우리 경우에는 지연·편향·가림 길이·질량을 바꾼다.
조건 범위는 실제 측정과 장비 한계로 정한다.
무작위 폭을 크게 잡는 것만으로 실기 이전을 보장하지 않는다.[^18][^28]

### 실기로 옮기기 전 확인할 것

상태 전환과 보상은 우선 시뮬레이션에서 비교한다.
다음으로 실제 RAW 기록 재생과 지상 장착 시험을 한다.
실기와 같은 입력·좌표·시각으로 정책을 실행한다.
출력은 먼저 기록만 하여 제한 위반을 찾는다.
그 뒤 검증된 단계의 제한 시험으로 진행한다.
이번 보고서는 설치·기동·비행 작업을 수행한 결과가 아니다.

각 드론은 독립 상태추정과 의사결정을 유지한다.
서버나 다른 드론의 지속 통신을 자세 제어에 요구하지 않는다.[^1]

## 16. 공부 순서와 연구 질문

**학습 알고리즘보다 오차와 제어 경계를 먼저 익힌다.**
아래 순서는 달력 일정이 아닌 학습 단계다.
각 단계의 질문에 답할 수 있으면 다음으로 넘어간다.

| 단계 | 읽을 내용 | 확인 문제·산출물 |
|---|---|---|
| 1 | 이 보고서 3~5절, MIT 동역학 | 수평 각도에서 이동할 수 있는 이유 설명 |
| 2 | PX4 EKF2·외부 위치 문서 | 측정·추정·목표 좌표 흐름 그리기 |
| 3 | FSM·BehaviorTree.CPP 기초 | MOVE·APPROACH·RECOVERY 조건표 |
| 4 | Spinning Up RL 기초 | 관측·행동·보상·종료 조건 한 장 |
| 5 | Gymnasium API와 작은 RL 환경 | 각도 보상의 체류 허점 재현 |
| 6 | PX4 SITL·Gazebo 문서 | 실제 경로와 같은 UWB 입력 시험 설계 |
| 7 | 보상 설계·평가 논문 | 규칙 기준선과 학습 정책 비교표 |

### 핵심 질문 다섯 개

1. UWB가 항상 25cm 틀리면 목표 도달도 틀리는가?
그렇다. 독립 교정 없이 관측 위치만 맞출 수 있다.

2. 목표 좌표를 이용해 UWB를 교정하면 되는가?
아직 도착하지 않았다면 목표는 정답 관측이 아니다.
물리적으로 도착을 확인한 기준점은 교정에 쓸 수 있다.

3. FSM을 잘 만들면 강화학습이 필요 없는가?
가능하다. 규칙이 충분한 성능을 내면 유지한다.
학습의 이득은 같은 시험에서 추가로 입증한다.

4. 드론의 각도가 작으면 정지한 것인가?
아니다. 속도와 위치 변화도 확인해야 한다.
호버 가능 여부에는 추력 여유도 필요하다.

5. UWB가 끊겨도 좌표가 계속 나오면 성공인가?
아니다. 실제 오차와 추정 유효성이 기준 안에 있어야 한다.

### 첫 연구 질문 제안

‘UWB 가림과 지연이 있을 때, 수평 이동 모드를 학습하면
규칙 기반 FSM보다 목표 정착과 제한 준수가 좋아지는가?’

이 질문은 기존 PX4 EKF2와 자세 제어를 유지한다.
오류 조건과 학습기의 역할도 분명하다.
첫 비교는 규칙 FSM과 동일한 행동 선택지를 사용한다.
성공률·오차·복구·계산 부담을 함께 보고 판단한다.

미확인 사항은 학습 PC 사양, 실기 질량·추력이다.
태그 고정 위치와 독립 기준점도 다시 확인한다.
이 정보가 정상 범위와 시뮬레이션 범위를 결정한다.
