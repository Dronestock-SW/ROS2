# 고도(z) 처리 원칙

이 문서는 고도의 측정·제어 책임을 정한다.
고도 입력이나 데모 값을 연결할 때 읽는다.

1. UWB는 x, y 수평 위치만 제공한다.
   `/uwb_pose`에는 메시지 형식상 z 필드가 있다.
   현재 값 0은 미관측 자리값이다. 실측 고도가 아니다.
2. 고도는 TFmini Plus(하방 거리) + Pixhawk IMU/EKF가 유지한다. (EKF 융합 확정 — roadmap 결정 2)
3. companion(Jetson)은 z를 직접 제어하지 않는다.
4. z 유효성 검사는 개발하지 않는다.
   - virtual_wall_node에 아래 한 줄만 유지:
   - `# TODO: z 범위 검사 (예외처리, 후순위)`

## 센서 역할
- UWB (DWM3000EVB 태그 + 자체 제작 앵커 4기): x, y 수평 위치
- TFmini Plus: 하방 고도 측정 (PX4 EKF 융합)
- T-mini Pro (YDLIDAR): 전방 장애물 감지 + Phase 2 스캔매칭 (고도 아님)
- PMW3901 광학흐름: PX4 직결 — 실내 위치 유지 보조 (roadmap 결정 8)
- Pixhawk IMU/EKF: 고도·자세 제어 전담

## 장비 도착 전 공용 데모

비행 전 기능 시험에는 고정 z를 쓸 수 있다.
`drone_demo`의 `fixed_z_m`에서 임시값을 정한다.
첫 기본값은 1.2m다. 실측값이 아니다.
표시 출처는 `demo_fixed`로 기록한다.
앵커 높이 2.2m와는 별개의 값이다.

데모 입력은 DOMAIN_ID 99에서만 사용한다.
PX4에 고도 관측이나 제어 명령으로 보내지 않는다.
이유: 임시값은 실제 움직임을 측정하지 않는다.
실측 전환 때는 검증한 PX4 고도 출력을 연결한다.
UWB x·y의 자리값 z를 고도로 바꾸는 작업이 아니다.

범위와 입력 계약은 [공용 데모 기준](demo_design.md)을 따른다.
