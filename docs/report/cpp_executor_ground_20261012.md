# C++ 실행기와 관측 공백 분리

2026-10-12의 실행기 변경과 시험 근거를 설명한다.
웹 START 경로를 점검하거나 현장에 인계할 때 읽는다.

13일 통합·전달 나이 설정은 [새 기록](sangwon_integration_20261013.md)을 따른다.
아래 바이너리·성공 수치는 12일 당시 기록이다.
현재 변경본의 검증 결과와 혼합하지 않는다.

**C++가 판단·실행 단계·FC 송신을 담당한다.**
선택 경로는 `--cpp-executor-binary`다.
기존 Python 실행기와 동시에 실행하지 않는다.
동시 명령이 출발 XY와 모드를 바꿀 수 있기 때문이다.

```text
기존 웹 / 플랫폼 연결 (Python)
  → 미션 계약·원장·센서 보조 어댑터 (Python)
  → C++ 실행 단계 + 공통 C++ BehaviorTree
  → 독립된 20Hz MAVROS 송신
  → PX4 위치·고도·자세 제어
  → 실제 착륙·DISARM 확인 → END
```

Python 라이브러리는 유지했다.
Python 어댑터는 FC 비행 명령을 보내지 않는다.
파라미터 읽기와 메시지 주기 요청은 수행한다.
UWB와 LiDAR 원본 시각을 보존한다.
C++는 FC·UWB·브리지 상태를 직접 구독한다.
Python 처리 지연을 새 FC 관측으로 숨기지 않는다.

## 송신 지연 개선 범위

기존 Python 호출 주기에서 185ms·217ms를 관찰했다.
217ms는 200ms 보호 기준을 넘었다.
이때 ARM을 보내지 않고 중단했다.
원인을 Python 언어로 단정하지 않는다.
OS 스케줄링·기록·센서 계산을 더 구분해야 한다.

C++ 송신 콜백을 계산 콜백과 분리했다.
송신 콜백은 LiDAR 정합·JSON 분석을 수행하지 않는다.
명령 응답도 비동기로 처리한다.
실행 단계에서 웹 상태 발행·디스크 I/O도 분리했다.
상태 발행은 최신 값 1개를 전달한다.
`/flight_state`는 best-effort 상태 갱신이다.
구독자는 기존 reliable 발행도 수신한다.
완료 결과 topic은 reliable을 유지한다.
완료 상태도 새 센서 상태와 함께 반복 발행한다.

명령 기록 작업과 상태 표시 작업도 분리했다.
명령 기록은 별도 `.commands` 파일에 남긴다.
기록을 fsync한 뒤 현재 토큰을 다시 검사한다.
취소·만료된 토큰은 늦게 송신하지 않는다.
판단 유효 시간 150ms는 유지했다.
실행 주기 보호 기준 200ms도 유지했다.
만료 시 송신을 계속 살리는 방식은 사용하지 않는다.
낡은 판단으로 비행할 수 있기 때문이다.

Python 보조 입력은 원본 나이를 더한다.
FC·UWB·브리지는 C++의 직접 수신으로 검사한다.
웹 생존 확인은 기존 2초 기준을 유지한다.
Python 장기 중단은 정상 상태로 취급하지 않는다.

## 관측 공백과 초기 밀림

LiDAR 보완은 기존 승인 조건을 유지했다.
SDK PointCloud의 점별 시각을 사용한다.
독립된 상대 이동으로 최대 0.8초를 보완한다.
공백 중에는 기존 XY 목표를 유지한다.
도착·호버·복귀 완료 판정은 보류한다.
UWB 복귀 시 LiDAR와 불일치하면 중단한다.

이 보완은 FC의 새로운 EKF 관측 송신이 아니다.
실측·방위·시각·이동 검증이 끝나지 않았다.
물리 설정에서 LiDAR 보완은 여전히 비활성이다.
실측 값 대신 가상의 승인을 넣지 않았다.

실행 8의 추정 이탈이 UWB 최종 공백보다 먼저다.
FC 자세 요구는 출발 XY로 복귀하는 방향이었다.
따라서 관측 공백만으로 밀림을 설명하지 않는다.
실제 이동량과 추정 오류의 분리는 아직 남았다.
지면효과·축 오차·방위·장착은 가설이다.
속도·추력·임계값은 변경하지 않았다.

AUTO.TAKEOFF로 전환하지 않았다.
동일한 PX4 위치·자세 제어기가 동작하기 때문이다.
로컬 위치 유효성이 필요한 점도 동일하다.
자세 추종·초기 광류 융합의 추가 대조가 필요하다.
근거는 [실행 8 자세 분석](run8_offboard_attitude_20261012.md)에 있다.

## 검증 근거

C++ 계약 시험은 최종 착륙 결과 보강 후 다시 확인한다.

종료는 실제 모사 FC의 새 지상·DISARM 상태로 판정했다.
플랫폼 시험은 직접 텔레메트리 주입을 사용하지 않았다.
