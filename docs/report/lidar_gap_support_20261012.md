# 상단 LiDAR의 UWB 공백 보완
2026-10-12 상대 이동 관측과 미션 연결 기록이다.
FINAL-TEST1-SANGWON을 설치하거나 검증할 때 읽는다.

상단 YDLIDAR를 C++ 미션 판단에 연결했다.
실기 기본값은 진단 모드다.
장착·시각·환경 근거가 있어야 공백 보완을 켠다.
새 실비행과 PX4의 LiDAR 융합은 미실시다.
실제 밀림 제거를 입증한 결과는 아니다.

## 구현과 책임

단일 실행기가 C++ 판단을 PX4 명령으로 전달한다.
LiDAR는 상대 이동을 관측한다.
FC 위치를 LiDAR 측정값으로 사용하지 않는다.

```text
웹 START -> C++ FieldMission -> 단일 Python 실행기 -> PX4
             ↑                       |
UWB 원본 XY·시각 ---------------------+
YDLIDAR /scan + 시각에 맞춘 FC 자세
       -> 광선별 회전 보정 -> C++ 상대 스캔매칭
       -> UWB에 고정한 독립 상대 이동 검사
       -> 제한된 공백 동안 기존 목표 유지
```

| 항목 | 구현 |
|---|---|
| 스캔매칭 | C++ 점-직선 SE(2), 상위 잔차 20% 제외 |
| 기하 검사 | 40개 대응점·겹침률 0.6·법선 다양성 0.08 이상 |
| 정합 잔차 | RMS 0.035m 이하 |
| 불확실성 | 정보 행렬의 회전 상관 포함. 표준편차 최소 0.025m |
| 스캔 단위 | 40–2048개 거리. NaN·Inf·범위 밖 제외 |
| 방향 | FC 자세는 회전 변환에만 사용 |
| 좌표 | map_y_axis_sign을 포함. 반사 좌표도 시험 |
| 장착 | 센서 yaw와 FLU XYZ, 상단 레버암 보정 |
| 수평면 | roll·pitch 각각 약 2.86도 이하 |
| 자세 이력 | 최대 2초·256개. 외삽 금지 |
| 광선 시각 | 원래 첫 광선 시각+원래 time_increment |
| 기준 시각 | 실제 마지막 광선 시각. 첫 광선 시각도 보존 |
| 회전 보정 | 각 광선 시각에 맞춘 quaternion 사용 |
| 병진 보정 | FC 위치·속도로 스캔을 변형하지 않음 |
| UWB 기준점 | 스캔 시각과 30ms 이내인 원본 UWB |
| 관측 출력 | 미션 진단·판단 입력. FC aiding=false |

평행 벽만 보이는 통로는 거부한다.
이유: 벽을 따라 움직인 양을 구분할 수 없다.
높이에 따라 스캔 면이 달라지는 환경도 검증해야 한다.
회전 보정은 병진 보정이나 전체 SLAM이 아니다.

## 공백 중 동작

검증된 LiDAR가 있어도 출발점과 목표는 그대로다.

| 조건 | 동작 |
|---|---|
| UWB 0.25초·브리지 0.35초 이내 | 기존 직접 관측 경로 |
| UWB 공백 + 검증된 LiDAR | 마지막 송신 XY 유지 |
| 공백 중 | 도착·연속 호버·복귀 완료 판정 정지 |
| 새 UWB 복구 | LiDAR 위치와 0.2m 이내인지 확인 |
| 복구 불일치 | 실패를 고정하고 LAND 요청 |
| 센서·기하·시각·FC 상태 불량 | 기존 중단 경로 |
| UWB 기준점 나이 0.8초 초과 | 보완 불허 |
| LiDAR 나이 0.15초 초과 | 보완 불허 |
| LiDAR 표준편차 0.08m 초과 | 보완 불허 |
| FC와 상대 관측 차이 0.2m 초과 | 보완 불허 |
| FC 수평 속도 0.15m/s 초과 | 보완 불허 |

직접 UWB 만료 임계값을 바꾸지 않았다.
대체 관측이 검증된 구간만 별도로 허용한다.
이 보완은 이륙·이동·호버·복귀 중에만 허용한다.
지상 START·ARM은 여전히 실제 UWB를 요구한다.
장시간 관측 없이 비행하는 기능이 아니다.
복구 후 호버 10초는 새로 연속 확인한다.

UWB 원본 좌표와 원본 시각은 유지한다.
과거 UWB를 새 시각으로 재발행하지 않는다.
LiDAR 좌표는 UWB 기준점과 상관이 있다.
독립 절대 좌표나 독립 UWB 검사로 위장하지 않는다.
새 EV 송신자와 companion EKF는 만들지 않았다.
PX4 수평 추정·제어의 품질은 별도 확인해야 한다.
MAVROS 일반 추정 상태만으로 광류 융합을 단정하지 않는다.

## 장착과 현장 자료

사용자는 Pixhawk 위 약 15cm라고 알려주었다.
예제의 Z=+0.15m는 미확인 장착 정보다.
X·Y·yaw와 스캔 면 평행 여부는 미확인이다.
기존 전방 14cm 기록은 과거 기록으로 보존한다.

예제의 lidar_gap.enabled는 false다.
센서가 켜졌다는 이유만으로 활성화하지 않는다.

| 활성화 설정 | 필요한 근거 |
|---|---|
| mount_confirmed / mount_ref | 센서 기준점 XYZ·yaw·스캔 면 실측 |
| timing_confirmed / timing_ref | 설치된 SDK의 첫 광선·광선 간 시각 검증 |
| vertical_structure_confirmed / scene_ref | 상승 중에도 같은 수직 벽을 관측하는 환경 시험 |
| scan_plane_parallel_to_body_xy | 센서 평면 장착 확인 |

근거가 없거나 값이 null이면 C++가 활성화를 거부한다.
임의 TF나 가짜 확인 문자열로 통과시키지 않는다.
이유: 잘못된 관측으로 실제 밀림을 숨길 수 있다.

최근 보존 기록의 스캔은 430개 거리였다.
광선 간 시간은 약 0.25ms였다.
첫 광선부터 수신까지 약 100ms였다.
이는 앞선 11일의 time_increment=0 기록과 다르다.
제조사 ROS 노드는 SDK 값을 그대로 전달한다.
광선 시각 0을 수신 주기로 대체하지 않는다.

첫 광선과 최신 FC 자세의 차이는 약 77ms였다.
최신 자세 하나를 쓰는 초기 진단은 300개 모두 거부했다.
이후 원래 광선 시각에 맞춘 자세 이력을 연결했다.
같은 300개를 새 경로로 재생했다.
298개 MATCHED·1개 초기 기준점·1개 시각 거부였다.
최대 왕복 시간은 13.22ms였다.
이는 거리 정확도나 새 비행 성공의 증거가 아니다.

## 검증과 한계

실제 C++ 실행 파일과 모사 FC를 구분한다.
합성 성공은 실제 기체 성공의 증거가 아니다.

| 검사 | 결과 |
|---|---|
| 기존 C++ 미션 계약 | 11개 통과 |
| C++ LiDAR 계약 | 10개 통과 |
| 실제 C++·HTTP·WebSocket·모사 FC | 미션·웹·ROS·플랫폼 회귀 300개 통과 |
| 보존 LiDAR 기록 재생 | 300개 중 298개 정합. 승인·FC 명령 0 |
| ROS 패키지 빌드 | 4개 성공 |
| 원래 UWB 처리 경로 | 변경 없음. 이력 오염 후보는 연구 단계 |
| 실기 LiDAR 활성화·PX4 융합·비행 | 미실시 |

시험은 0.6초 공백의 유지·복구·END를 확인한다.
통로·잡음·NLOS 복구 불일치·센서 손실도 확인한다.
센서 손실이나 긴 공백은 END로 처리하지 않는다.
C++ 입력 만료나 RC 인계도 성공으로 처리하지 않는다.

일부 회귀 실행에서 0.15초 결정 만료를 관측했다.
기존 실행 주기 0.2초 보호도 간헐적으로 작동했다.
기준을 늘려 성공으로 바꾸지 않았다.
파이프 쓰기까지 0.1초 제한에 포함하도록 고쳤다.
HTTP 시험의 WebSocket 송신도 FC 모사 루프와 분리했다.
실제 플랫폼 연결은 원래 별도 프로세스를 사용한다.
마지막 왕복 시간과 최대 왕복 시간을 기록한다.
최종 분리 시험 묶음은 300개 모두 통과했다.
LiDAR 공백 미션의 최대 AI 왕복은 15.48ms였다.
현장 부하에서 반복 안정성 검증은 별도로 필요하다.

## 다음 세션의 순서

1. 이 브랜치와 설치 바이너리 SHA를 확인한다.
2. 장착 X·Y·Z·yaw와 스캔 면을 실측한다.
3. 실제 스캔 시각·자세 보정 진단을 수집한다.
4. 배터리 분리 상태에서 이동·회전 대조를 한다.
5. 구조물·유리·사람·통로에서 오승인을 확인한다.
6. 근거를 보존한 뒤 활성화 설정을 만든다.
7. 현장 조종자와 같은 고정 XY 호버를 검증한다.

높이 1.7m·상승 제한 0.5m/s를 유지한다.
이 문서의 활성화는 실제 비행 명령이 아니다.
[C++ 연결 기록](cpp_field_mission_integration_20261012.md)과
[설치 절차](../runbooks/final_resume.md)를 함께 읽는다.

## 입력 정의의 출처

LaserScan의 header는 첫 광선 측정 시각이다.
각 광선의 시각은 time_increment로 구분한다.
[ROS 메시지 원문](https://raw.githubusercontent.com/ros2/common_interfaces/humble/sensor_msgs/msg/LaserScan.msg)을 따른다.
PX4 외부 관측은 별도 시각·frame·센서 위치를 요구한다.
[PX4 외부 관측 안내](https://docs.px4.io/main/en/ros/external_position_estimation)를 따른다.
이번 구현은 그 FC aiding 경로를 활성화하지 않는다.
